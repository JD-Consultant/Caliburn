# Duty 動態分組

## 適用時機

- 已有一個或多個 Task，可先提出暫定責任區域。
- 新 Task 使現有 Duty 名稱或分組不再合理。
- 需要建立、改名、合併、拆分 Duty 或重新歸類 Task。

## 所需證據

- Task 的 action、object、meaningful outcome、本人責任與工作關係。
- 員工對責任範圍、主要功能、上下游與分組意義的說法。
- 現有核准 Task／Duty 及仍待員工決定的結構變更。

## 產出

- Duty 新增、改名、合併、拆分候選。
- 一個或多個 Task reassignment；必要時以有依賴性的原子子群組交員工審核。
- 仍無法合理歸組的 Task 可維持未分組並留下 gap。

Duty 是**可修訂**的工作假說與文件實體，**不得成為早期固定盒子**。Task 增加、合併、拆分或改變邊界時，分組可重新計算。

## 缺口

- Task 太少，無法辨識穩定的共同責任目的。
- 分組只依工具、部門、時間順序或字面相似，沒有功能意義。
- 同一 Task 似乎跨兩個主要成果，應先重開 Task 邊界。
- Duty 建立與 Task reassignment 尚待員工決定，阻擋依賴它的分析分支。

## 防止臆測

- 不要求每個 Task 立即有 Duty，也不為了匯出整齊而硬塞。
- 不由職稱或公版猜出標準 Duty。
- 不把暫定責任區域說成員工已接受的正式職責。
- 不把無關變更綁成全收全退；原子性只由結構依賴決定。

## 重新開啟

新增／撤回 Task、Task merge／split、責任更正、員工拒絕分組，或 completion red-team 發現過度合併、過度拆分或重複時重新使用。
