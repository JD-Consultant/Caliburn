# 工作產出 O

## 適用時機

- 一個 Task 已透露交付物、文件、圖表、紀錄、決策結果或其他關鍵產出。
- 需要判斷「結果」是獨立 O、P 的結果部分，還是 Task 邊界線索。

Task 不必永久穩定後才可分析 O；有足夠局部證據即可提出，後續 Task merge／split 時再重驗 linkage。

## 所需證據

- 員工描述的具體 Task、過程／最終產出、交付對象及用途。
- 可精確定位的員工來源與 quote anchor。
- 對應 Task identity；每個 O 在文件語意上只連到一個 Task。

## 產出

- 名詞性的關鍵工作產出候選，優先採有形交付標的。
- 一個 O 對應 exactly one Task。
- 若操作型工作只有行動或狀態結果，明確標記「無獨立 O」，把成果留給 P 或 Task purpose_result。

## 缺口

- 只有工具、輸入或過程材料，不知道員工真正產生什麼。
- 產出來自他人，員工只負責其中一段。
- 所謂產出其實只是模型依常識補出的文件名稱。

## 防止臆測

- **操作型工作可合法沒有獨立 O**；不得為了填滿欄位虛構報表、紀錄或文件。
- 不把輸入、工具或每個中間步驟都列成 O。
- 具體名稱、數量、格式、法規或 SOP 必須有精確員工 quote anchor。
- 模型產生的候選不是證據，也不能直接進核准文件。

## 重新開啟

Task 邊界改變、員工更正交付物、P 顯示不同成果，或 O 缺乏來源／被員工拒絕時重新使用。
