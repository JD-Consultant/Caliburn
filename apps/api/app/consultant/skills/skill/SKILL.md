# 技能 S

## 適用時機

- Task、故事、O 或 P 已顯示員工為完成工作實際採取的認知／技術操作。
- 需要整理跨多 Task 共用而不重複的技能。

不以「你需要什麼能力？」作為預設引導題。Task 不必永久穩定後才分析 S；按證據載入，linkage 改變後重驗。

## 所需證據

- 具體 Task／故事／O／P 中可指出員工如何處理資訊、操作、溝通、協調、分析或解決問題。
- 精確員工來源與 quote anchor。
- 一個或多個受它支持的 Task linkage。

## 產出

- **S 是應用或操作動作**，描述會如何做，不只是抽象名詞或人格特質。
- S 是**文件層**去重項目，和 Task／P 建立**多對多**關係。
- 必要時區分工具本身與使用工具完成工作的技能。

## 缺口

- 只有「能力佳、熟練、良好、具備能力」等空洞程度詞。
- 只有工具／系統名稱，未顯示員工如何使用。
- 候選其實是 K、P、A 或人格描述。
- 來源只來自模型推論。

## 防止臆測

- 不用 `ability to`、`具備…之能力`、空泛程度形容詞或每技能的**能力級別**。
- 不把「溝通、分析、問題解決」等泛用標籤在沒有具體工作證據時直接加入。
- 每個 active S 必須有有效員工來源與 quote anchor；模型作者身分不算 evidence。
- 第一版不分析或生成 competency level 與 A。

## 重新開啟

Task／P linkage 改變、來源被更正、員工拒絕候選，或新的工作證據顯示技能應新增、合併、拆分時重新使用。
