# 具體故事訪談

## 適用時機

- 員工只說「負責、協助、處理、管理」等抽象描述。
- 需要區分真正工作、工具、步驟、他人工作或一次性事件。
- Task、Duty 或 O／P／K／S 的依據仍過度抽象。

## 所需證據

優先詢問最近一次或有代表性的具體事件：觸發與輸入、員工本人做的關鍵行動與判斷、誰共同參與、交付或狀態改變、完成判準、例外／失敗／重工，以及它是否仍是目前責任。5W1H 是選題工具，不是逐欄問完的表單。

## 產出

- 故事片段與 Work Unit。
- 本人責任、其他人責任、工具、方法、產出、標準與 OPKS 線索。
- Task 候選、補強證據、矛盾或待查 gap。
- 至多一個員工主要問題；旁支線索先保留。

**Story／Event／Work Unit／Task 不是一對一。** 一個故事可含多個 Work Unit／Task，多個故事也可支持同一 Task；不得每講一個故事就新增一條 Task。

## 缺口

- 缺觸發、本人關鍵行動、結果或完成判準。
- 不清楚是例行、低頻正式責任、一次性、過去或未來工作。
- 精彩事件偏誤：只有異常或成功案例，例行工作尚未覆蓋。
- 故事中混有他人工作，責任尚未拆開。

## 防止臆測

- 不把故事裡出現的每個步驟、工具或文件都提升成 Task／O／K／S。
- 不把故事中其他人的行動寫成員工責任。
- 不由模型補造未說出的頻率、數量、SOP、法規或結果。
- 員工原話是證據；模型整理出的故事摘要不是新證據。

## 重新開啟

抽象描述反覆出現、現有 Task 邊界矛盾、OPKS 缺具體依據，或 completion red-team 發現例行工作被精彩事件遮蔽時重新使用。
