# Task 邊界分析

## 適用時機

- 新工作線索可能成為 Task。
- 既有 Task 可能過度合併、過度拆分、重複或責任錯置。
- O／P 或新故事顯示 Task 邊界需要重開。

## 所需證據

一個可成立的 Task 至少要有：**action**（員工做什麼）、**object**（對什麼做）、**meaningful outcome**（有意義結果／狀態改變／責任目的）與 **current responsibility**（是員工目前責任）。可同時參考觸發、完成判準、頻率、例外及交付關係。

## 產出

- 新增、修訂、合併、拆分或撤回的 Task 候選。
- action／object／purpose_result／context 等可審文件內容。
- 指出它只是工具、步驟、工作活動、一次性事件、過去工作、他人工作或尚未分類線索。
- 若結構調整會改變後續分析前提，形成需要員工先決定的待審文件變更；不得直接寫入核准文件。

## 缺口

- 缺有意義結果，只有「使用系統、看資料、開會」等動作。
- 本人、共同、協助或他人責任不清楚。
- 一句話包含兩個不同成果，可能需要拆分。
- 多條 Task 其實是同一責任的步驟或重複表述。

## 防止臆測

- **工具**不是 Task；**步驟**不自動是 Task。
- **一次性**、**他人工作**、**過去工作**不自動進入目前 JD。
- 沒有員工證據時不補 outcome、頻率、量化標準、法規或責任角色。
- O 可以合法為空；若沒有有意義結果，先挑戰 Task 邊界，不製造漂亮的 O。

## 重新開啟

新證據改變 action、object、outcome 或 current responsibility；Duty 分組不再一致；O／P 顯示兩種成果；或員工更正、合併、拆分、拒絕相關文件變更時重新使用。
