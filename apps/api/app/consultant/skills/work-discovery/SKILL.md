# 工作範圍盤點

## 適用時機

- 新文件、久後恢復，或目前只知道職稱而不知道實際工作。
- 需要檢查工作範圍是否只被一個精彩故事代表。
- 新回答透露另一項工作，但尚不足以判定是 Task、步驟或他人責任。

本方法是可反覆進出的注意力方法，不是必須先通過的階段。已有明確工作時可直接深入；深入時發現新範圍也可重新使用。

## 所需證據

- 員工對目前、例行、週期、低頻高影響工作的原話。
- 觸發、輸入、本人行動與判斷、交付對象、結果、例外及責任角色。
- 對「他人工作、共同工作、過去工作、一次性事件、未來構想」的明確區分。

不得先用職稱、職業分類或公版內容替員工決定有哪些工作。

## 產出

- 可修訂的工作線索、Work Unit、故事入口與 Task 候選。
- 暫定責任區域，只用於 coverage 導航，不等同核准 Duty。
- 一個最值得深入的焦點及選擇理由；其他線索停放成可見待處理項。
- 當證據足夠時才形成待員工審核的文件變更。

## 缺口

- 例行工作、週期工作或正式低頻工作可能遺漏。
- 本人／他人／共同責任不清楚。
- 只有工具名稱、抽象職能或組織目標，沒有具體工作。
- 線索尚不能安全判定 Task 邊界。

## 防止臆測

- 不依職稱補齊「通常會做」的工作。
- 不把模型常識、分類或未接入的 Reference 當員工事實。
- 不為了看起來完整而製造 Duty、Task、數量、頻率或規則。
- 每個事實性理解與文件候選都要連回員工來源；具體數字或規定需要精確 quote anchor。

## 重新開啟

員工補充新工作、更正責任、現有 Task 無法涵蓋新線索，或完成度檢查發現 routine omission／dramatic-story bias 時重新使用。
