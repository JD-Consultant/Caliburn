# 一句話判準
一條任務=「有意義產出的最小活動單位」(O*NET),句式=動詞+受詞+條件(iCAP);
一組職責=可由一個人獨力完成的一組功能。

# 判別規則
- 層次:主要職責 → 工作任務,以 2 層為主(iCAP 指引 p37)。
- 切分:跨公司共通為原則;每項職責/任務**大小盡量一致**(iCAP p46)。
- 職責檢驗:「每一個功能單元是否皆可由一個人獨力完成」(iCAP p47;UK NOS §5.1
  「一份標準=一個可由個人執行的功能」同理)。
- 句式:「動詞、受詞、條件」(iCAP 功能分析法 p40);O*NET 三段式
  **Action > Object > Purpose**——動詞開頭、越具體越好,目的用「以/來…」帶出。
- 粒度下限:「依層次往下討論,直至『個人』就有能力達成任務,分析就可停止」(iCAP p40);
  再往下就是工作活動,不入任務層。

# 禁則(O*NET Task Writing Guidelines,逐條)
- 禁複合句:一條任務一個動作+一個目的;句中有分號=其實是兩條任務,拆開。
- 禁時間相依:「先做 A 再做 B」=兩條任務。
- 禁「等等/e.g./i.e.」;舉例用「如:X、Y」。
- 寧可拆多條,不寫一條大雜燴。

# 好壞例(成對)
- 壞:「負責品質」——無動詞受詞、範圍不明、無法驗證。
- 好:「執行進料檢驗,依檢驗規範判定物料允收與否」——動詞+受詞+條件。
- 壞:「檢驗物料;記錄結果並回報主管」——分號複合句 → 拆成兩條任務。

# 邊界案例
- 官方**未規定**每職責幾條任務——不硬湊條數,以「粒度一致、跨公司共通」為準
  (iCAP p46;O*NET/NOS/ESCO 皆無官方數量區間)。
- 受訪者講的事橫跨兩個職責時,先問清楚哪個是主體,別硬塞進現有任務。
