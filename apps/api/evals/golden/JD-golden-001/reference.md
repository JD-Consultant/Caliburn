## 任務:執行手動測試與版本回歸(T x.x)

依回歸清單執行手動測試與版本回歸,判定可否放行上線。

### 細項(11 槽)
- 頻率:每天零星測;每兩週上線前密集跑一輪
- 工作比重:約 25%
- 單次耗時:密集回歸約 2 天
- 數量批次:回歸套件約 300+ 條(自動化 ~200、手動 ~100)
- 觸發條件:每日 build 完成由 Slack bot 通知;上線前依 release 排程
- 準備材料:回歸清單、測試環境帳號、該版變更說明
- 工具系統:staging 環境、Postman、自寫 pytest 自動化腳本
- 協作對象:缺陷與開發往返;環境問題找 DevOps;擋版通報組長與開發 Lead
- 等待瓶頸:測試環境僅一套,被佔用需排隊(平均 1–2 小時)
- 例外處理:遇擋版 blocker 立即通報組長與開發 Lead,當天修復後重測
- 完成標準:回歸 100% 跑完、無未解 blocker、本人簽核後放行

### 工作產出(O)
- 回歸測試報告(含簽核紀錄)

### 行為指標(P)
- 依回歸清單執行手動與自動化回歸,於放行前完成 100% 執行並簽核
- 發現擋版缺陷時,當日通報組長與開發 Lead 並於修復後完成重測

### 知識(K)
- 回歸測試策略與放行準則
- 缺陷生命週期與通報流程

### 技能(S)
- Postman API 測試操作
- pytest 自動化腳本撰寫與維護

### 態度(A;文件層)
- A14 謹慎細心(佐證:「簽核那步絕不省」)
