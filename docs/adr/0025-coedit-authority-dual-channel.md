# ADR 0025 — 人機共編權限:雙通道 + 風險分流 + 節點批審

- **狀態**:Proposed(2026-07-05,草案待維護者核可)。
- **研究依據**:[`../specs/2026-07-05-llm-integration-wiring-research.md`](../specs/2026-07-05-llm-integration-wiring-research.md)
  §10.1(C 線:四產品收斂、CHI/CSCW 實證、確認疲勞、與版本化的配合)。
- **關聯**:樂觀並發=ADR 0015;互動模式=ADR 0020;訪談引擎=ADR 0023。

## 脈絡

維護者裁示:AI 是「提議 + 寫」,人可編輯/確認/取消;並質疑早期設計「人改過的段落
AI 只能提議」。研究發現該設計錯在**軸**:

- 業界 2025–26 四家獨立收斂(Word Copilot 詞級 Track Changes、Google Docs Gemini
  suggested edits、Cursor staged diff + checkpoints、GitHub PR suggestions):
  **AI 可以自由地寫,但寫進待審層,不直接覆蓋定稿**。
- CHI/CSCW 實證:territoriality 真實(「討厭它在我不在場時做事」,單次翻車即毀信任);
  **手動整合建議比自動整合帶來更高所有權感**;逐動作確認製造確認疲勞
  (人退化成 rubber-stamp,「既沒安全又煩」——Anthropic 同判)。

## 決定

尊重主導權的實作手段,從「**限制 AI 寫入權**」改為「**分流 AI 寫入目的地**」:

1. **AI 自己寫、人沒碰過的段** → AI 直改 + 輕量「AI 已更新」標記 + 一鍵 undo。
2. **人碰過的段** → AI 照樣寫,但**寫進建議層**(段旁 badge + 新舊對照);
   不彈窗、不阻塞訪談;人的字在核准前一字不變。
3. **審閱在自然邊界批次**:小節談完 / 訪談尾聲總審(顧問收尾儀式「一起過一遍文件」);
   Accept all / 逐條兩檔粒度;實質改動預設展開 diff。
4. **低風險維度豁免**:錯字/格式/術語一致性即使在人碰過的段也可直改 + 標記
   (實證:「不影響我的聲音」)。
5. **不可逆/高風險動作永遠阻斷確認**:刪整節、覆蓋受訪者已口頭確認的事實欄位。
6. **與版本機制同構**:全部改動落版本歷史;段落 provenance 從版本 author 序列推導
   (**不建獨立鎖**);建議 = 未套用的 diff;AI 寫入帶樂觀鎖(0015),
   **撞到人正在編輯 → 版本衝突自動降級為建議**(規則不必硬編,自然湧現)。

v1 粒度:段落 badge + 新舊對照即可,不做字元級 track changes。
信任漸進自動調權(依接受率放寬權限)判 YAGNI,記一行當未來縫。

## 後果

- ✅ AI 優化衝動完整保留(隨時可寫)、人的主導權完整保留(未核准不動人的字)、
  確認集中到自然節點(不疲勞);與 0015/0023 零新機制對接。
- ⚠️ 建議層要 pending-diff 資料模型與渲染(緩解:與版本系統同構,共用 revision 機制);
  建議未審時文件呈雙態(緩解:建議量預算化,尾聲總審清零)。
- ⚠️ 批審也可能 rubber-stamp → 風險分級預設展開 diff;**建議佇列長度列為產品指標**監控。
