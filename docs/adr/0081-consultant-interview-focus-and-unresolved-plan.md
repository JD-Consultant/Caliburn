# ADR0081：顧問長訪談的焦點與未釐清筆記

- 日期：2026-10-07
- 狀態：Accepted；施工與效果驗證進行中
- 議題：INTPLAN
- 詳細契約：[唯一設計](../specs/2026-10-06-consultant-interview-planning-and-focus-design.md)
- 施工：[實作與比較計畫](../plans/2026-10-07-interview-plan-implementation-and-comparison.md)

## 脈絡

長訪談局部深入後，顧問可能遺失同題剩餘範圍、換題後忘記返回，或換窗後漏掉重要未知。最終成果是高品質、完整且有據的 JD；受訪者看到安排是附帶效果。Q001–005 已確認，2026-10-07 三個獨立靜態審查未見剩餘施工阻擋，使用者同意開始實作、完成測試並直接用真實 API 比較只有指引與指引加筆記。

## 決定

1. 同一顧問維護短 Markdown，只記目前焦點、重要未釐清子任務及必要線索；焦點可含訪談、分析及 JD 整理。已解移除、部分解只留剩餘；大綱與已理解內容沿 Memory／原話／context。
2. 新增 read／edit 兩工具，edit 重用既有 V4A 純核心，僅 App 用途政策允許空來源／空結果；Memory 非空規則保持。
3. 本用途 owner 以 PostgreSQL 候選指標與不可變完整正文操作保存原結果。固定初始基底、scope／writer／位置、原操作重播及完成資格沿原責任；取消或失敗不授跨輪資格。
4. 原 captured 能力版本分派；新輪全文、輪中按需讀取與 native compact 後精確投影各有責任，已保存 request／item 不以 latest 重建。UI 唯讀取同份保存內容，終局讀合法採用版。
5. 效果採用須由 P2 相對 P1 在代表性長任務及正式 JD 的對照成立；不能以保存、UI、空筆記或 P0→P2 的收益代替。正式化授權建置與驗證，不預先宣稱增益成立。

## 後果與邊界

新增兩表、窄 metadata owner queries、工具與 HTTP 契約、原能力相容與私有投影接線；不新增 planner、多代理訪談、永久任務清冊或第二份工作事實。純核心的共享變更與恢復交界需代表反例及真 PostgreSQL 驗證。真 API 使用合成材料、有限批次護欄及實際費用紀錄，不輸出 key；若 P2 未勝 P1，保留結果並按設計查原因，不把已實作當效果通過。
