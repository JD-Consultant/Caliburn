# 設計覆蓋、反例與驗證

本章說明如何檢驗資料隔離、保存、恢復與分析效果。讀者可先從反例矩陣找到要驗證的行為，再沿實作驗證入口選取對應測試；離線測試、真資料庫、模型呼叫及使用者旅程各回答不同問題。

本頁定義驗證方法與已知限制。可執行測試及命令由[實作驗證](../implementation/verification-plan.md)、[API README](../../apps/api/README.md)與[Web README](../../apps/web/README.md)維護。各次執行原件與模型比較資料只在本機保存，不隨公開 repository 發布。

本文不構成現行版本全套通過證明；各次統計只支持當時受測版本與範圍，不能推定所有情境或分析品質均已通過。現行產品為 `apps/api`／`apps/web`，切換背景見 [正式產品與選型](design-decisions.md)。

## 3. 驗證層級與證據門檻

1. **文件層級**：透過總圖與專題核對使用旅程涉及的模組、規則一致性及連結；尚未確定的技術細節仍屬待驗假設。

2. **契約層級**：離線測試讀寫 scope、來源資格、候選／快照語意、工具 strict schema／解析與拒絕路徑，能檢驗上述反例的規則表達。

3. **機制層級**：真 PostgreSQL、程序中斷／重開、取消與提交競爭、背景重新派送、checkpoint 接縫；mock 不算持久性證據。

   瀏覽器跨頁的 Web Locks／storage／焦點可由真瀏覽器核對，但攔截 HTTP 的測例只證明前端協調，不能同時宣稱已驗證後端交易。

4. **模型層級**：固定 provider／SDK 的原生接續、compaction 與工具測試，以及真實風格長訪談中的定位、引用與資料充分才改稿的行為。測試紀錄中的外送範圍及費用上限界定該次評測，與產品執行政策不同。

5. **產品層級**：同一檔案端到端，前後稿、證據鏈、候選預覽、暫停／取消／恢復、PDF 都可觀察；分開正確性與品質／耗時／費用報告。

評估一項主張時，先判斷它需要哪一層證據，再確認已有測試是否涵蓋該行為。文件檢查不能代替機制或產品驗證，舊版測試通過也不能證明現行行為正確。前端命令、網路失敗、跨頁刪除、關閉期限及 RAG 連線範圍的代表測試，集中在[Web 與交付測試入口](../implementation/verification-plan.md#51-web-與交付的現行測試入口)，避免另複製一份結果清單。

## 4. 未決事項與重新評估條件

- **內部結構與產品行為的差別：** 資料表、索引、結構遷移、ORM 與套件穩定版本、節點與可持久恢復工作的邊界、工具嚴格傳輸格式、差異排版、既定標題的精確比較方式、部署腳本及 PDF 版面，都可能有不同做法。

  反例關注其對產品的影響；例如字串正規化若改變目標選擇規則，就不再是效果等價的表示差異。

- **已知品質限制：** Luna 仍有跨輪來源漏引、未明確提交依據核對與定位錯誤的反例。JD 短定位改善模型可用的識別方式，不等於來源選擇或語意品質已改善。

- **仍缺實測的效果：** 長文修改、導覽定位、工具效率、儲存容量及不同訪談的壓縮表現，仍有樣本或分支未覆蓋。B1／B2 已補到小型真模型壓縮後發布與固定回讀；正式容量邊界、不同職務長旅程及真人顧問與員工的省時仍未驗。

  容量、壓縮與重試配置見[共用執行與恢復](../implementation/agent-execution.md)；產品不以預估金額攔截正常執行，付費評測另有預算界線。

- **會改變產品承諾的差異：** 降低已保存資料保證、讓取消輸入進來源、變更正式完成效果、增加外送範圍／可觀費用、允許覆蓋後續人工修改、永久刪除已承諾可回查資料，都會改變這些反例所檢驗的行為。

- **目前不包含的機制：** 新增審核角色、事件溯源平台、跨機還原、逐一確認引用的 Memory 流程、模型自行填寫版本，以及每步強制撰寫工作筆記。

規則一致、機制可恢復與分析品質達標是不同結論。即使某條資料或執行路徑已通過測試，仍不能推定模型在不同訪談中都能正確取材與改稿。

## 5. 證據來源與適用範圍

工程驗證由受測版本的程式與測試重現；[驗證責任](../implementation/verification-plan.md)列出 V、E、JDT 接縫及必要層級，元件 README 維護實際命令。比較 Prompt、Tool 或模型時，依[貢獻指南](../../CONTRIBUTING.md#模型品質比較)固定案例、變因與判準。

每次交付記錄受測版本、實際命令、失敗、排除及未驗範圍。執行原件保留本機；公開文件保留責任與已知限制，不集中複製施工年表、逐案模型紀錄或測試數字。缺少公開原件時，不以本文推定某次品質結果可由新 checkout 重現。
