## 3. 施工前與實作後的門檻

1. **文件 gate（本次）**：可從總圖定位每條旅程的 owner；規則無衝突，連結／狀態可追；未選細節標工程驗證，不冒充完成。
2. **契約 gate**：離線測讀寫 scope、來源資格、候選／快照語意、工具 strict schema／解析與所有拒絕路徑；先針對上述反例，不做通用引擎。
3. **機制 gate**：真 PostgreSQL、程序中斷／重開、取消與提交競爭、背景重新派送、checkpoint 接縫；mock 不算持久性證據。
4. **模型 gate**：鎖定 provider／SDK，驗原生接續／compaction／工具；再測真實風格長訪談、定位與引用、資料充分才改稿。測試外送／費用依當次授權，文檔工作不自動授權付費請求。
5. **產品 gate**：同一檔案端到端，前後稿、證據鏈、候選預覽、暫停／取消／恢復、PDF 都可觀察；分開正確性與品質／耗時／費用報告。

實作切片按此順序由小閉環擴展，不一次改完再首次驗收。舊程式可作參考與反例來源，**不要求遷移舊資料，不以舊版測試通過代替新語意驗收**。

## 4. 剩餘問題如何處理，不無限拉長討論

- **工程自行完成**：表／索引／migration、ORM／套件穩定版、節點與 durable task 邊界、工具 strict wire、diff 排版、中文 title 正規化、部署腳本、PDF 版面。研究官方契約後選最簡能滿足反例的做法，更新唯一責任文件。
- **需要實測而非繼續爭論**：context 容量／壓縮門檻、重試與費用上限、長文 fuzzy 唯一性、模型是否善用 map、單輪工具步數、存儲體積。記錄配置和測試分布，不說「某家推薦所以必然最佳」。
- **真正產品變更才問 Owner**：降低已保存資料保證、讓取消輸入進來源、變更正式完成效果、增加外送範圍／可觀費用、允許覆蓋後續人工修改、永久刪除已承諾可回查資料。
- **目前無需擴張**：新 reviewer、事件溯源平台、跨機還原、逐引用確認的 Memory 工作流、模型自填版本、每步強制工作筆記。

文件後續修改同步檢查：產品規則 → 責任 → 跨層流程 → 模型／UI 契約 → 保存 → 本表反例。入口只更新狀態和連結，不抄回各文件正文。證據與測試結果另存，有通過結果再改驗收狀態。
