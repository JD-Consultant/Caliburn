# 設計覆蓋、反例與驗證

離線測試、真資料庫、模型呼叫與使用者旅程能回答不同問題。本章以反例說明資料隔離、保存、恢復與分析效果的驗證方法，並區分已有證據與尚未測到的情境。

截至 2026-10-03，既有證據包含通過、部分通過、僅離線／資料庫驗證及未驗情境，逐項結果見[驗證對照](../history.md#source-d58692bbe6b4baa7267f)與[實驗發現的問題](../reports/experiment-findings.md)。各次統計只支持當時受測版本與範圍，不能推定現行所有情境或分析品質均已通過。現行產品為 `apps/api`／`apps/web`，切換背景見 [ADR0079](../adr/0079-target-rebuild-production-cutover.md)。

## 3. 驗證層級與證據門檻

1. **文件層級**：透過總圖與專題核對使用旅程涉及的模組、規則一致性及連結；尚未確定的技術細節仍屬待驗假設。
2. **契約層級**：離線測試讀寫 scope、來源資格、候選／快照語意、工具 strict schema／解析與拒絕路徑，能檢驗上述反例的規則表達。
3. **機制層級**：真 PostgreSQL、程序中斷／重開、取消與提交競爭、背景重新派送、checkpoint 接縫；mock 不算持久性證據。
4. **模型層級**：固定 provider／SDK 的原生接續、compaction 與工具測試，以及真實風格長訪談中的定位、引用與資料充分才改稿的行為。測試紀錄中的外送範圍及費用上限界定該次評測，與產品執行政策不同。
5. **產品層級**：同一檔案端到端，前後稿、證據鏈、候選預覽、暫停／取消／恢復、PDF 都可觀察；分開正確性與品質／耗時／費用報告。

各層證據各自成立，文件檢查不能代替機制或產品驗證。舊程式可提供反例與比較背景，但現行產品不遷移舊資料，舊版測試通過也不能證明現行行為正確。


## 4. 未決事項與重新評估條件

- **內部結構與產品行為的差別**：資料表、索引、結構遷移、ORM 與套件穩定版本、節點與可持久恢復工作的邊界、工具嚴格傳輸格式、差異排版、既定標題的精確比較方式、部署腳本及 PDF 版面，都可能有不同做法。反例關注其對產品的影響；例如字串正規化若改變目標選擇規則，就不再是效果等價的表示差異。
- **已知品質限制**：Luna 仍有跨輪來源漏引、未明確提交依據核對與定位錯誤的反例。JD 短定位改善模型可用的識別方式，不等於來源選擇或語意品質已改善；細節見[目前決策](../current-decisions.md)與[實驗發現的問題](../reports/experiment-findings.md)。
- **仍缺實測的效果**：長文模糊比對的唯一定位、模型使用導覽的可靠性、工具效率對照、儲存容量及不同訪談的壓縮表現，仍有樣本或分支未覆蓋。B1／B2 輪前壓縮已有受控真模型觀察，但該次批次未能發布，不能宣稱壓縮後發布已完整驗證；真人顧問與員工的省時效果仍未驗。容量、壓縮與重試配置見[共用執行](../specs/2026-09-27-shared-agent-execution-and-state-design.md)；產品不以預估金額攔截正常執行，付費評測另有預算界線。
- **會改變產品承諾的差異**：降低已保存資料保證、讓取消輸入進來源、變更正式完成效果、增加外送範圍／可觀費用、允許覆蓋後續人工修改、永久刪除已承諾可回查資料，都會改變這些反例所檢驗的行為。
- **目前不包含的機制**：新增審核角色、事件溯源平台、跨機還原、逐一確認引用的 Memory 流程、模型自行填寫版本，以及每步強制撰寫工作筆記。

規則一致、機制可恢復與分析品質達標是不同結論。即使某條資料或執行路徑已通過測試，仍不能推定模型在不同訪談中都能正確取材與改稿。
