## 3. 驗證層級與證據門檻

1. **文件層級**：可從總圖找到每條使用旅程涉及的模組；規則無衝突，連結與狀態可追溯；尚未確定的實作細節標示為待驗證，不列為已完成。
2. **契約層級**：離線測讀寫 scope、來源資格、候選／快照語意、工具 strict schema／解析與所有拒絕路徑；先針對上述反例，不做通用引擎。
3. **機制層級**：真 PostgreSQL、程序中斷／重開、取消與提交競爭、背景重新派送、checkpoint 接縫；mock 不算持久性證據。
4. **模型層級**：鎖定 provider／SDK，驗原生接續／compaction／工具；再測真實風格長訪談、定位與引用、資料充分才改稿。測試外送範圍及費用上限須明確記錄，並與產品執行政策區分。
5. **產品層級**：同一檔案端到端，前後稿、證據鏈、候選預覽、暫停／取消／恢復、PDF 都可觀察；分開正確性與品質／耗時／費用報告。

各層證據各自成立，不能以文件檢查代替機制或產品驗證。舊程式可作參考與反例來源，**不要求遷移舊資料，不以舊版測試通過代替新語意驗收**。

## 4. 未決事項與重新評估條件

- **效果等價的實作選擇**：資料表、索引與結構遷移，ORM 與套件穩定版，節點與可持久恢復任務的邊界，工具的嚴格傳輸格式，差異排版，既定標題精確比較的實作，部署腳本及 PDF 版面。依官方契約選擇能通過反例的最簡做法，並更新對應設計文件；字串正規化不得改變既定的目標選擇規則。
- **仍需實測的效果**：長文模糊比對能否唯一定位、模型是否善用導覽、單輪工具效率、儲存容量及不同訪談的壓縮表現。已採用的容量、壓縮與重試配置見[共用執行](../specs/2026-09-27-shared-agent-execution-and-state-design.md)；產品不以預估金額攔截正常執行，付費評測另有預算界線。
- **需由產品決策者評估的變更**：降低已保存資料保證、讓取消輸入進來源、變更正式完成效果、增加外送範圍／可觀費用、允許覆蓋後續人工修改、永久刪除已承諾可回查資料。
- **目前無需擴張**：新增審核角色、事件溯源平台、跨機還原、逐一確認引用的 Memory 流程、模型自行填寫版本，以及每步強制撰寫工作筆記。

文件變更須依序核對產品規則、模組職責、跨層流程、模型與 UI 契約、保存機制及本表反例。導覽頁只維護狀態與連結，各項規則保留在對應文件中。證據與測試結果另行保存，取得通過結果後才更新驗收狀態。
