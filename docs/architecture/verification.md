# 驗證範圍與限制

正式程式位於 `apps/backend` 與 `apps/frontend`。驗證需分開回答工程行為、交付可用性與職務分析品質；單元測試、build、圖面或工具參數合法，不能代替其他層的證據。

| 層級 | 可支持的結論 | 不能推定 |
|---|---|---|
| 靜態、單元、契約與生成檢查 | 受測規則、型別、依賴方向及 wire 生成一致 | 真資料庫交易、瀏覽器旅程或模型效果 |
| 真 PostgreSQL／Qdrant | 受測交易、約束、恢復、索引及來源查讀 | 所有部署環境與完整語料皆正確 |
| 離線模型的真瀏覽器旅程 | 正式 Host、工具、保存與 UI 的受測協作 | 真 provider、逐字串流、真壓縮或內容品質 |
| Docker／原生交付 | 受測環境的建置、啟動、路由及依賴接線 | 每種 GPU、權重與真人使用環境皆可用 |
| 真模型合成旅程 | 受測版本、案例與設定下的模型行為 | 真人訪談品質、穩定提升或省時比例 |

具體命令及跳過條件見[驗證責任](../implementation/verification-plan.md)、[後端 README](../../apps/backend/README.md#安裝與檢查)與[前端 README](../../apps/frontend/README.md)。未提供專用資料庫而 skip，不代表整合驗收通過；離線 root check 也不自動執行付費模型。

## 已知界線

- 真人顧問投入、員工準備與訪談／修正時間尚未驗證，不承諾固定節省比例。
- 真模型品質須覆蓋長訪談、早期細節、補充更正、來源、未知保留及完整 JD；資料格式合法不能代替內容判準。
- 已保存用量不等於全部外送或帳單；缺用量不能當成零。
- 原生恢復可能重做未保存的模型／工具效果，跨模組取消及 Workspace 清理不是單一交易。
- 本機單 worker 的活動鎖不提供多 worker 或多主機保證。

品質比較的資料、費用授權及可重跑證據依[貢獻指南](../../CONTRIBUTING.md#模型品質比較)；內部測試原件不作公開建置的依賴。
