# 設計覆蓋、反例與驗證

本章說明如何檢驗資料隔離、保存、恢復與分析效果。讀者可先從反例矩陣找到要驗證的行為，再沿證據連結查看受測版本、條件與結果；離線測試、真資料庫、模型呼叫及使用者旅程各回答不同問題。

截至 2026-10-04，既有證據包含通過、部分通過、僅離線／資料庫驗證及未驗情境。歷史逐項結果見[驗證對照](../history.md#source-d58692bbe6b4baa7267f)與[實驗發現的問題](../reports/experiment-findings.md)，該輪補測見[報告證據索引](../experiments/product-validation/2026-10-04-report-evidence-audit.md)；後續接線、Memory 及 Plan 補測集中於[證據來源](#5-證據來源與適用範圍)。

各次統計只支持當時受測版本與範圍，不能推定現行所有情境或分析品質均已通過。現行產品為 `apps/api`／`apps/web`，切換背景見 [ADR0079](../adr/0079-target-rebuild-production-cutover.md)。

## 3. 驗證層級與證據門檻

1. **文件層級** ：透過總圖與專題核對使用旅程涉及的模組、規則一致性及連結；尚未確定的技術細節仍屬待驗假設。
2. **契約層級** ：離線測試讀寫 scope、來源資格、候選／快照語意、工具 strict schema／解析與拒絕路徑，能檢驗上述反例的規則表達。
3. **機制層級** ：真 PostgreSQL、程序中斷／重開、取消與提交競爭、背景重新派送、checkpoint 接縫；mock 不算持久性證據。
4. **模型層級** ：固定 provider／SDK 的原生接續、compaction 與工具測試，以及真實風格長訪談中的定位、引用與資料充分才改稿的行為。測試紀錄中的外送範圍及費用上限界定該次評測，與產品執行政策不同。
5. **產品層級** ：同一檔案端到端，前後稿、證據鏈、候選預覽、暫停／取消／恢復、PDF 都可觀察；分開正確性與品質／耗時／費用報告。

評估一項主張時，先判斷它需要哪一層證據，再確認已有測試是否涵蓋該行為。文件檢查不能代替機制或產品驗證；舊程式可提供反例與比較背景，但現行產品不遷移舊資料，舊版測試通過也不能證明現行行為正確。


## 4. 未決事項與重新評估條件

- **內部結構與產品行為的差別** ：資料表、索引、結構遷移、ORM 與套件穩定版本、節點與可持久恢復工作的邊界、工具嚴格傳輸格式、差異排版、既定標題的精確比較方式、部署腳本及 PDF 版面，都可能有不同做法。反例關注其對產品的影響；例如字串正規化若改變目標選擇規則，就不再是效果等價的表示差異。
- **已知品質限制** ：Luna 仍有跨輪來源漏引、未明確提交依據核對與定位錯誤的反例。JD 短定位改善模型可用的識別方式，不等於來源選擇或語意品質已改善；細節見[目前決策](../current-decisions.md)與[實驗發現的問題](../reports/experiment-findings.md)。
- **仍缺實測的效果** ：長文修改、導覽定位、工具效率、儲存容量及不同訪談的壓縮表現，仍有樣本或分支未覆蓋。B1／B2 已補到小型真模型壓縮後發布與固定回讀；正式容量邊界、不同職務長旅程及真人顧問與員工的省時仍未驗。各項主張的證據與缺口見[報告證據索引](../experiments/product-validation/2026-10-04-report-evidence-audit.md)。容量、壓縮與重試配置見[共用執行](../specs/2026-09-27-shared-agent-execution-and-state-design.md)；產品不以預估金額攔截正常執行，付費評測另有預算界線。
- **會改變產品承諾的差異** ：降低已保存資料保證、讓取消輸入進來源、變更正式完成效果、增加外送範圍／可觀費用、允許覆蓋後續人工修改、永久刪除已承諾可回查資料，都會改變這些反例所檢驗的行為。
- **目前不包含的機制** ：新增審核角色、事件溯源平台、跨機還原、逐一確認引用的 Memory 流程、模型自行填寫版本，以及每步強制撰寫工作筆記。

規則一致、機制可恢復與分析品質達標是不同結論。即使某條資料或執行路徑已通過測試，仍不能推定模型在不同訪談中都能正確取材與改稿。

### 4.1 JD 工作計畫後續待辦

2026-10-08 依使用者要求，將[各一場比較](../experiments/product-validation/jd-work-plan-comparison-2026-10-07/runs/comparison-v2/results.md)留下的問題列為後續討論與驗證：同一合成倉儲案例，分別使用「只有指引（P1）」與「指引＋Plan（P2）」各跑一場。以下「本次配對」均指這兩場。已完成的提示、Plan、UI 與 T1–T4 維持結案；下列待辦不代表已選定新的 prompt、資料結構或追加測試批次。元件權責仍沿[系統邊界 §2.1](system-boundaries.md#21-長任務的元件分工)。

- [ ] **辨認尚未探索的重要方向與選問優先順序。** 對照分析／JD／顧問指南，檢查安排是否偏重已知內容入稿，未保留必要專業、工作方法或判斷條件的探索方向。本次配對共同未取得先到期先出、Excel 差異核對與重量判斷；它們是案例證據，不直接變成通用必問題庫。先提出有證據的最小候選，不把尚未採用的選問實驗直接切入正式 prompt。
- [ ] **讓進度短句對得上實際成品。** 核對「已通讀／已核對」時是否仍有重要已知內容或跨欄修正未完成，保留真正剩餘工作。本次配對兩組均到收尾才補部分已知協作；P2 先前的完成短句未保證全稿無漏。完成判斷沿實際 JD 與依據，不新增完成百分比或固定任務狀態。
- [ ] **補足長任務接續的未觀察情境。** 聚焦轉題／跨輪打斷後回收已知待入稿工作，以及執行中途換窗後的有效返回與語意忠實。本次配對只驗到新輪前壓縮後全文接續，未形成上述收益情境；既有保存回歸與舊方案證據分開判讀。後續先界定最小必要案例，不恢復原八場排程。
- [ ] **核對 Plan 維護負擔是否換得成品收益。** 同時保留品質、工具拒絕與恢復、模型呼叫及費用證據。本次配對的 Plan 組費用約多 22%，尚無可辨整體品質優勢；差額亦含不同訪談／編修／壓縮路徑，不能全歸因於 Plan 編輯。討論正文精簡與實質變動才更新的用法，改善須以重要缺口與成品判讀驗證。

### Plan 歷史與現行比較

**歷史方案：焦點／未釐清筆記。** 2026-10-07 的工程反例及真 PostgreSQL 證據沿 [INTPLAN 施工計畫](../plans/2026-10-07-interview-plan-implementation-and-comparison.md)查閱，涵蓋空用途、原操作重播、正式採用資格、建立工作時固定的能力、精確壓縮視窗與筆記投影、完成重入及終局 UI 刷新。其後格式說明／錯誤提示窄修另有 74 個受影響測試及兩輪真 API 短測，不能算入更早的全套測試結果。

[核心真模型比較](../experiments/product-validation/interview-plan-comparison-2026-10-07/results.md)以兩種職務、兩次重複及兩種條件完成八個案例，每案 20 Turn 與共同收束。P1 只有指引，P2 加筆記；四個 P2 合計 78 次編輯成功，正式筆記皆非空。第二次重複（r2）的四案都核過輪中壓縮後的完整視窗接續；其中兩個 P2 另核過同位置筆記投影，兩個 P1 沒有筆記投影。這支持保存正確，不能證明 AI 會有效返回未問完的內容。
