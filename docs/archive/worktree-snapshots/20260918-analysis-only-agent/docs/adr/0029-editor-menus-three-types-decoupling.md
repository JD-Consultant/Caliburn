# 0029. 編輯器選單三型＝純工具;參考集合與文件身分脫鉤

日期:2026-07-11
狀態:Accepted

## 脈絡

編輯器選單長期「帶智慧」:首開自動寫入、選單內建自訂入口、疊 AI 標記;〔選職類〕一次做兩件事
(記參考+把順序 1 寫進文件表頭,`PUT /occupations` 服務端寫 `ocs_profile`),導致「參考了哪些
官方基準」與「本文件是哪份基準」綁死、主基準隱含在勾選順序裡;任務 O/P/K/S 藏在按鈕後,
整份文件無法一眼審。維護者要求:LLM 與人用同一批元件(0028),而元件要簡單到兩者都不會用錯。

## 決定

1. **選單只有三型,全部是純工具**(不自動寫、無自訂入口、無 AI 標記、一律獨立視窗):
   - **控制選單**(不可自訂欄):只能選官方值。單選:職類視窗(表頭基準,代碼+名稱綁定)、
     基準級別、任務職能級別;多選:三分類(職類別/職業別/行業別)。
   - **參考選單**(可自訂欄):多選+列內改名(僅已勾、必註記原名、來源身分不斷);
     自訂一律表格加列。職責/任務/O/P/K/S/A。
   - **素材庫**(自由文欄):點=插入,無勾選狀態。工作描述、說明與補充事項。
2. **參考與文件身分脫鉤**:〔選職能基準參考〕(原選職類改名)只管**無序**參考集合=選單內容,
   不寫文件;文件表頭由**職類視窗**單選寫入,所選那份=**主基準**(相似比對/預設/「選同」視角),
   換選=重算。選單永遠列參考聯集,主基準只換視角不過濾。
3. **首開自動寫全面退場**;批次帶入改為明確的「選同X」鈕(選同職能基準/選同主要職責/
   選同工作任務),職類視窗未選時 disabled。
4. **版式**:卡片殼三層同構包含(職責卡⊃任務卡⊃OPLKS 全展開區),標籤旁 ▾ 開窗,
   編碼採**位置碼**自動連號(身分靠來源 URN),編輯工具 hover 浮現;CellFillerPanel 退役。
5. **AI 共編載體延後**:追蹤修訂(直寫+綠紅標+確認/拒絕)方向已記於研究紀錄 §11,
   本 ADR 不裁;現有 AI 元件僅做保綠的最小適配。0028 的「同一批元件」原則不變,
   其任務盤/徽章載體待 AI 層重設計時另開 ADR 處置。

## 後果

- ✅ 元件單一、行為可預測:選單不可能寫入使用者沒點的東西;控制欄結構上防止非官方值。
- ✅ 主基準顯式化(表頭所選),不再靠勾選順序的隱含約定;參考增減與文件身分互不牽動。
- ✅ 全展開版式=編輯畫面即成品,整份可審、可 Ctrl+F。
- ⚠️ 大改版面與 `PUT /occupations` 語義(停寫表頭),既有測試需隨行為調整(characterization 網)。
- ⚠️ 三分類控制選單暫吃參考池(官方全表未入源,記縫);長文件導航(sticky/大綱)記縫。
- ⚠️ AI 元件過渡期維持舊樣(與新選單視覺暫不一致),直到 AI 層重設計。
