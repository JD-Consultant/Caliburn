### 雲岸課程報名網站

**主要問題：**
使用者快速連續點擊送出，前端可能送出兩次報名請求，造成重複報名風險。

**如何判斷原因：**

- 使用測試帳號重現。
- 查看瀏覽器 Network 紀錄，確認前端確實送出了兩個請求。

**處理方式：**

- 送出後先停用按鈕，避免重複點擊。
- 成功或失敗後恢復按鈕。
- 與後端確認報名 API 的冪等性。
- 由課務窗口依約定情境測試，確認報名紀錄正確。
- 後端 API 的部署由後端負責，你負責前端整合與回歸測試。

**另外的前端操作問題：**

- 鍵盤操作時，Tab 無法順利找到送出按鈕的焦點。
- 你調整焦點樣式，並依序用鍵盤輸入、送出，確認錯誤提示也能正常顯示。
- 這是基本前端操作檢查，不是第三方無障礙認證。

**如何確認完成：**

## 3. 目前多久彙整一次回報，範圍是什麼？

要區分「每日分流」和「正式彙整」：

- **每日：**依影響程度分流客戶回報，會看受影響使用者數、是否中斷登入或報名等核心流程、是否有替代方式，以及付款狀態不一致或重複資料的風險。先確認事實與能否重現，再回覆處理方向。
- **正式彙整：**目前是**每兩週的週五一次**，範圍是**所有專案**，記錄：
  - 問題原因
  - 負責人
  - 下一次追蹤時間或事項

你會持續追蹤到結案，但實際後端修正及客戶決策不屬於你的直接執行範圍。
