結論：保留完整任務敘述，允許同任務有多個成果及多個要求；條件與分工應清楚限定它真正適用的內容，不能一律掛任務、要求或成果。推薦使用「工作成果／產出」與「工作要求」兩個閱讀名稱，時機、條件、分工按需要就近寫。這是澄清原內容，不是再加一組必填欄位。

## 4. 適用範圍的正反例

本節是本案的閱讀與語意推理，不是官方規定的層級演算法。A–E 使用既有 r2；F 明列為新假設例，不能寫入 r2 或員工 JD。

| 例子／原位置 | 正確保留的意思 | 一律掛同一層會造成什麼錯誤 |
|---|---|---|
| A／任務 8：有定期維護約定才執行，含月檢的專案按月 | 合約條件與周期限定**整項定期檢查任務**；任務敘述需可辨識，必要時就近補一句 | 若只當某份檢查紀錄的要求，可能讀成所有案都要月檢，只是部分案不用交紀錄；若只埋在其中一條要求，任務本身又寫得無條件，會擴大服務承諾 |
| B／任務 4：查詢逾時保留輸入並提供重試；訂單結果不明避免重複送出並查狀態 | 兩個情境各自限定**不同的處理要求** | 若只留任務層「逾時可重試」，會抹掉訂單例外；若把「查詢逾時」當全部任務的共同條件，會錯限資料串接與其他狀態處理 |
| C／任務 6：交付版本、交接說明、發布問題與驗收 | 「版本與檢查結果一致」明確指**交付版本**；交接說明有接收者用途；遇服務端部署時是協作；客戶負責驗收確認 | 全塞「任務負責人＝前端工程師」會遮蔽部署與驗收；全塞某項成果下又會讓其他執行／協作要求失去歸屬。兩份成果也不是各只能有一條要求 |
| D／任務 2 及職務邊界：本人估算及建議，專案經理協調範圍、安排與對外承諾 | 職務層可概述**共同責任邊界**，任務 2 就近保留估算前提及不能自行承諾的意義 | 只列「協作對象：專案經理」不能辨識誰建議、誰對外確認；將所有責任都塞每個要求又會重複且模糊主任務 |
| E／工作條件：不承擔人員管理、無固定輪班或例行出差 | 已有依據的**全職務條件**集中可讀；只對某組職責成立時，應明說該組範圍 | 全部各掛任務會造成無益重複；反過來把某次沒出差或某任務不帶人升成全職務條件，也是不成立的泛化 |
| F／額外假設：某項已確認工作需維持一份即時狀態紀錄，另交每月摘要；月摘要有已確認交期 | 兩個成果可有不同更新／交付條件；句子明指哪個成果。是否仍是一任務，要再看工作目的、本人責任及可獨立變動的範圍 | 把「每月交付」當整任務唯一頻率，會將即時維持誤成每月更新；把每個時間差都自動拆成任務，也可能拆碎同一完整工作。此例不提供任何真實頻率或新期限 |

**反證一律掛要求：**A 的合約條件決定這項工作是否承擔，E 是全職務條件；不能為了統一資料位置把它們改寫成某個細項的完成要求。**反證一律掛任務：**B 的條件只適用各自的異常要求，C 的版本一致性只指明特定成果；上提而省略對象會失真。S5 §5.7 與 §5.10 的分別處理亦支持應保存此種差異。[NOS 原文](https://www.ukstandards.org.uk/media/kqppvuwl/sds-nos-quality-criteria-update-13-05-2024.pdf)

「就近」必須包含**語句明確說出適用對象**，不能只靠下一行、同色框或段落位置猜測。此處只是寫作要求；沒有推薦 scope ID、自動繼承、條件優先序或跨段套用機制。

## 5. 具體 findings 與有限修訂建議

### CQ01／避免把多成果、多要求收斂成固定配對

**重要性：高。**現有內容已容納多項；若新格式固定「一任務→一成果→一要求」，會縮減 r2 任務 4／5／6，亦無官方依據。推薦成果與要求均可多項，需要指明對象時用完整文字；不先指定 O／P 之間的機械關係。單一成果可以整合數個工作結果，但不能因版面要求吞掉有意義的差別。

### CQ02／時機、適用範圍、例外與分工不宜各做一個任務通用值

**重要性：高。**資訊面向值得分析，但不都是單一任務層屬性。推薦以 §4 為範圍核對，整任務的限制寫進任務內容，特定成果／要求的限制寫清其對象，真正共通者才集中。這補強既有「局部就近、共通集中」，不新增 scope 欄位或任務固定表格。

### CQ03／閱讀名稱有必要再澄清

**重要性：中。**既有「完成要求」已定義得夠廣，但單看名稱容易被理解成終點驗收；「主要產出」亦容易只聯想到文件。本輪推薦改用：

- **工作成果／產出：**形成、交付或持續維持的有意義結果；必要時列具體成果及用途。
- **工作要求：**執行中、交付、持續維持及例外處理需符合的已確認要求。

兩個中文名稱是 **Local recommendation**，不是 OPM、iCAP、NOS 的統一正式譯名。語意延續 [欄位指南 §4](../2026-09-09-jd-field-and-writing-guide.md#4-成果產出與完成標準不是同一件事)；不變成績效評分，也不自動多出資格門檻。若主線採此名稱，應同步舊名稱的對照，避免讀者誤以為新增第三種 P。

### CQ04／減欄不能連必要資訊一起減掉

**重要性：高。**推薦任務部分用五類閱讀內容：完整任務敘述（可有短標題及說明）、工作成果／產出、工作要求、所需知識引用、所需技能引用。這是對主線格式候選的範圍核對；**本稿不決定 K／S 引用的項目身分、資料關係或已核准狀態。**各類不是必填五格，任務敘述也不能退化成短名稱。

精簡後仍須保留會影響工作的起始輸入、本人判斷、接收者／用途及交接。例如 r2 任務 7 的「收到問題後，了解影響與重現條件，區分……再處理」不能只剩「處理問題」。有必要內容而來源尚不清時留待釐清，不從公版補成事實；不完整文件可保存，具體未知呈現由格式討論決定。

### CQ05／共同要求不是無條件通則

**重要性：高。**重複文字不必每處刪除，因為局部短句可能正在防止誤解。推薦集中真正同範圍的條件，保留必要的局部差異／轉交界線；「所有案件」「通常」「依合約」「僅限……」各有不同含義，改寫時不提高確定程度。來源中的職業通用規範、單次處理結果及已確認職位要求也分開核對，不將職業標準的建議直接變成本人的承諾。

## 6. 供主線整合的通過條件與停止線

格式討論可用以下六個具體閱讀檢查收斂，不要求另開試驗或以分數表示品質：

1. r2 任務 5／6 的多項成果保留；任務 4 的各項要求各有明確對象，沒有被固定配對壓縮。
2. 任務 8 仍只對有約定的專案做定期檢查，任務 7 的事件型處理仍是另一項可辨識責任。
3. 查詢重試與訂單結果不明的差異皆可讀；範圍詞改放位置後，意思沒有擴大或縮小。
4. 估算／對外承諾、部署／協作、驗收／確認的權限仍可分辨；成果接收者不被誤當主管或核准者。
5. 「成果」不只限交付物，「要求」不只限完成終點；保留必要的輸入、判斷與交接，但沒有要求每任務填相同欄數。
