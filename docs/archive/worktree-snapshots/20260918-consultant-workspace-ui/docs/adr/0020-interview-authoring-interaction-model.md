# ADR 0020 — 訪談式撰寫的互動模式:混合載體(文件常駐 + 精靈化訪談面板)

- **狀態**:Accepted（2026-07-02）。
- 研究依據:[`../specs/2026-07-02-llm-interview-authoring-research.md`](../specs/2026-07-02-llm-interview-authoring-research.md)(§0 需求、§2 五軸、§7 勞動部指引精讀、§8 載體研究)。

## 脈絡

終局:LLM 扮演 iCAP 職能顧問訪談**不專業的員工**,自動撰寫職務說明書;人隨時可直接改文件
(混合主導權)。載體三選項:純聊天面板 / 全螢幕精靈(TurboTax 式)/ 混合。

證據(研究 §8):NN/g——精靈適合低領域知識者、聊天在偏離線性流程時失效、重複使用者嫌精靈煩;
CHI 實驗——開放敘事用**對話**資料品質顯著較高、結構化選擇用 **widget** 快且準;
TurboTax/Intuit(小白產專業文件的經典)——主模式是**引導軌道**,AI 是軌道上的加速器;
Canvas/Artifacts(2025–26 共創標準形)——**聊天在側、文件常駐可編**。

## 決定

採**混合載體**:

1. **文件工作台常駐**(主畫面):文件即時長出、人隨時直接編輯;agent 寫入走 staged/版本化
   (回合制,ADR 0015 樂觀鎖為並發地基)。
2. **側邊訪談面板**:**不是自由聊天**——把精靈的軌道紀律放進對話載體:
   - **腳本推進 + 進度可見**(官方五面向:定位→盤點→深掘→彙整→審閱→重要度確認;
     腳本本體以勞動部《職能基準發展指引》為本,研究 §7);
   - **結構化決策 widget 化**(選職類卡片、任務「你是不是有做」勾選);
   - **開放敘事對話化**(STAR/5W2H 追問;停止準則=官方「資料飽和」)。
3. **雙 persona**:員工(一次性)預設開面板被引導;顧問(重複使用者)可收面板直接編。
4. **實作不受既有資產約束——可重新設計**(維護者明示)。既有 authoring graph、CopilotKit seam、
   interrupt 彈選單是**候選材料**而非前提;立項時以本 ADR 的互動模式為準重新評估建置方式。

## 後果

- ✅ 員工有軌道可循(不會面對空白框)、開放敘事保有對話品質、顧問不被精靈綁架、文件透明可控。
- ✅ 目錄類零幻覺(受限選擇)與敘述類 staged 審閱(ADR 0015/北極星 §3)在此載體下自然成立。
- ⚠️ 面板的進度軌道、內嵌卡片、與文件的即時同步需要 UI/狀態設計(立項時另開 spec/plan)。
- ⚠️ 重新設計的自由度意味著既有 graph 可能被改寫/取代——屆時遵守「先研究、ADR、安全網」紀律。
- 📌 本 ADR 只定**互動模式**;訪談引擎(adaptive follow-up、飽和判斷)、品質關(21 條審核指標 rubric)
  的細節設計待該功能立項時開 spec。
