《職能基準發展指引》**為基礎寫的，其 §0 引用的產出完整性清單（指引 p38 審核指標 3.1.1）

## 2. 逐字證據：職能基準代碼

手冊內共三處，互相印證：

| 位置 | 原文 |
|---|---|
| **附錄二、職能基準表填寫說明**（手冊 p.22-23／文字檔 L800） | `職能基準代碼　　（免填）` |
| **陸、執行成果**（L1210） | 表格範本首列即「職能基準代碼」，未給填寫指示 |
| **附件 2-2、職能基準表體例格式**（手冊 p.57／L1926） | `職能基準代碼　（iCAP 計畫執行單位提供）` |

第三處比「免填」更精確：**它指名了代碼的來源是 iCAP 計畫執行單位**，不是申請單位、更不是工具。

**同頁另一個容易漏掉的**：`職類別代碼　（iCAP 計畫執行單位提供）`。
而 `職業別代碼` 依「中華民國職業標準分類代碼」、`行業別代碼` 依「中華民國行業統計分類代碼」。
→ **官方提供的代碼不只一個**，職類別代碼也是。

## 3. 兩種「代碼」不得混寫

這是本稿要釘死的分界。

### 3.1 職能基準代碼（與職類別代碼）＝ 官方發放的識別碼

- 官方填寫說明標為**「免填」**；體例格式標明**由 iCAP 計畫執行單位提供**。
- **本產品不提供輸入框、不列入 readiness 缺漏。**
- **AI 與 application 都不得生成**（既有 ADR 0040 決定 34：不得自行產生看起來像官方認證的
  職能基準代碼）。
- 未來若引入 Reference Challenger，只能**從可信官方 reference source 帶入**，不得推導。

### 3.2 `T1`／`T1.1`／`O1.1.1`／`P1.1.1`（與 `K01`／`S01`／`A01`）＝ 版面位置碼

- 它們是主要職責、工作任務、工作產出、行為指標在**表格版面上的位置編號**，
  由 Duty／Task／O／P 的排序決定。
- **匯出時決定性產生，不持久化。**
- **不取代 `duty_id`／`task_id`／`entity_id`**；內部 identity 一律用後者。
- 手冊在同一張表註明「（表格列數請自行調整）」——列數與序號本來就由填表者決定，
  進一步佐證它們是版面產物而非識別碼。

> 兩者都叫「代碼」，但一個是**別人發的身分**，一個是**我們排版排出來的位置**。
> 混寫的後果是把官方身分碼做成可生成欄位——那正是 ADR 0040 決定 34 禁止的事。

## 4. 與 2022《職能基準發展指引》的適用邊界

| 用途 | 以哪一版為準 |
|---|---|
| **表格版型、欄位有無、填寫說明、代碼權責** | **2026 品質認證作業手冊** |
| 方法論（功能分析法等四類分析方法）、各欄位的定義與撰寫標準、職能級別 1–6 原文 | 2022 職能基準發展指引（仍有效，不重寫） |

**具體差異一處（本次動機）**：2022 指引 p38 審核指標 3.1.1 逐項列出的基本資訊清單
**含「職能基準代碼」**；2026 手冊的對應指標（3.1 產出項目）改為概括表述
——「職能基準產出所應有之內涵項目完備，並符合現有職能基準體例格式」——
**不再逐項列舉基本資訊**，而體例格式本身把代碼標為免填／官方提供。
→ 依 2026 版型，代碼不是填表者的產出項目。

## 5. 2026 手冊的表頭與表格欄位（附錄二）

表頭：`職能基準名稱（職類／職業擇一）`、`所屬類別（職類別／職業別／行業別 ＋ 各自代碼）`、
`工作描述`、`基準級別`。

表格欄位順序：`主要職責 → 工作任務 → 工作產出 → 行為指標 → 職能級別 → 職能內涵 K／S`，
態度另列（`A01…`），最後 `說明與補充事項`。

**態度欄位原文**：「（態度內涵將於後續職能應用時視需求納入考量）」
→ 與 ADR 0048「Attitude 預設留空」一致，官方自己也把它列為**視需求**納入。

## 6. 抽取風險（給下一個核對的人）

`pdftotext -layout` 在「所屬類別」那一區**會把標籤欄與說明欄錯位一行**——附件 2-2 尤其明顯，
「中華民國職業標準分類／中華民國行業統計分類」看起來像掛在錯的列上。
正確對應以**附錄二填寫說明**為準，且與 2022 指引 §1a 一致：

- 職類別 → 依品質認證作業手冊**領域分類**名稱
- 職業別 → 依**中華民國職業標準分類**
- 行業別 → 依**中華民國行業統計分類**

（同類錯位先前在香港 QF SCS 的抽取上也發生過，見 `2026-08-01-opks-raw-*`。）

## 7. 對產品的結論

1. `職能基準代碼`、`職類別代碼`：**不做輸入框、不列缺漏、不生成**；只可從官方 reference 帶入。
2. `T1`／`O1.1.1` 等：**匯出時依排序產生**，不落庫、不當 identity。
3. 完整度提示的措辭用「**iCAP 版型欄位尚有 X 項未填**」，不得用「不完整／不合格／未通過」
   ——我們產出的是 ADR 0040 決定 33 定義的**客製 JD**，不是送審的職能基準。
4. 「工作產出」在官方允許的情況下可合法省略（2022 指引 p37：操作性質任務可不列 O，
   成果併入行為指標）→ **readiness 不得把它機械判成缺漏**。
