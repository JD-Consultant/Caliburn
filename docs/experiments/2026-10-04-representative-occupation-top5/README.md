# 代表員工主要工作的公版：固定需求與前五比較

日期：2026-10-04。狀態：**討論草稿；五份合成需求已記錄，未凍結執行條件、未產生新檢索排名或模型評分。** 獨立 RAG 研究，不修改正式 JD App。

## 1. 問題與本輪目標

使用者要求先寫多份固定員工需求，討論怎麼寫，再比較不同方式的檢索；每位員工、每種方法最後只看排名最高的五份去重公版。目的是找能代表主要工作的職位參考，局部兼任不作主要目標。跨兩個主要領域的員工可以由兩份公版共同代表，例如使用者提出的前端與後端組合。

固定的是員工工作事實，不是期待公版 ID 或唯一職稱。評分逐份列出，不相加；一份 3 分不能被多份 1 分抵銷或超越。當前準則見[評分協定 v2](../../specs/2026-10-04-representative-occupation-scoring-protocol.md)。

## 2. 固定需求怎麼寫

每案用一段第一人稱文字，寫本人持續負責的工作、具體動作、對象／用途、交付結果與責任界線。用自然敘述說明哪些是主業、哪些只是偶爾協助；不只寫職稱、工具清單或單一案件，也不要求列成完整 JD。

- 原件：[cases-v1.json](cases-v1.json)，`employee_statement` 是完整搜尋輸入來源。
- 閱讀版：[cases-v1.md](cases-v1.md)，與 JSON 的員工原話一致。
- 草稿快照：[draft-input-manifest-v1.json](draft-input-manifest-v1.json)，保存案例、閱讀版及評分草稿的 hash 與準備階段核對；不是模型執行 manifest。
- `major_work_facets` 等欄位記錄合成案例的員工工作事實與檢查重點，供討論／評審核對；不是公版答案，也不附加到搜尋文字。
- 本輪未先查 corpus 或既有支持標註來編寫需求。案例仍由代理合成，不是新真人資料或保證無模型知識重疊的盲測。

五案包含兩個主要領域並存、相同詞彙但分工不同、以及三種「主業＋局部協助」情境。它們先作討論與開發案例；一旦用於選方法或調參，就不能再稱為未觀察的驗收集，後續須另寫新案。

## 3. 候選比較：兩個因素分開看

以下是下一輪的候選方法，尚未執行。固定同一需求與同一公版版本／向量正文，讓每組結果都遵守相同的最終前五限制。

| 方法 | 查詢表示 | 搜尋流程 |
|---|---|---|
| A1 | 整段員工需求 | dense 搜尋，取最終前五。 |
| A2 | 整段員工需求 | dense 廣蒐，再 rerank，取最終前五。 |
| B1 | 同段需求拆為保留對象、用途與責任的工作查詢 | 各查詢 dense 搜尋，合併排序、去重，取最終前五。 |
| B2 | 與 B1 完全相同的工作查詢 | 各查詢 dense 廣蒐，再 rerank，合併排序、去重，取最終前五。 |

A1／A2 對照 rerank 的影響；B1／B2 同樣對照。整段與分段則檢查不同主要領域能否一起保留。當前先不用新生成 Memory 取代案例原件，Memory 之後以同一工作事實作另一個受測表示。

**執行前仍須固定**查詢拆分全文、候選深度、分段結果的合併排序／同分規則、模型與參數。跨查詢 cosine 或 rerank 分數不能未經定義就當可直接比較；本稿不暗定合併算法，也不把 v2 評審分數拿來選前五。N20 是舊研究對照初值，還不是本輪已選定參數。

「前五」是**每位員工合併後的最終五份**，不是每句各五份再全部交付。按固定公版來源去重並保留所有命中查詢。若只得到少於五份，明示原因；不得用評分後丟掉低分文件的方式美化搜尋結果。檢索排名分數與 0–3 評審分數各自保存。

## 4. 評判與比較表

按固定員工需求與公版正文判斷是否代表主要領域。評審先隱藏方法、排名、相似度、預期職稱及舊支持標註；不同方法的相同員工／公版組合用相同判讀，再還原各方法的搜尋排名展示。

每案逐方法列出五個位置：公版名稱／來源、檢索排名及原始分數、0–3 評分或不確定、代表哪個主要領域、員工與公版證據、責任不適用或支持重複。公版名稱是顯示 metadata；評分依正文，公版中的其他任務不自動適用本人。

不用總分、平均分或「多少個 1 分加成 3 分」挑贏家。先逐案看能否有強代表、是否缺一個主要領域、是否全擠在同一領域，以及局部參考是否搶走前五位置；再比較查詢數、候選／rerank 比較數、回傳正文量與時間。如果方法間有取捨或五案不足以選出一致優勝，就保留該結論。

沒有完整答案集合，不報全庫 Recall，不把「前五沒看到」寫成已證明語料沒有對應公版。舊 86／86、次要工作保留與平均 12.55 份的結果屬不同目標及額度，不能當本輪成績。

## 5. 執行時要保存的原件

1. 事前執行 manifest：需求／查詢／corpus／向量正文／rubric／Prompt 的版本和 hash，模型／provider／參數、合併與去重規則、最終 K=5、有效模型授權及費用界線。
2. 每個查詢的實際文字、全部初搜排名、送入 rerank 的 pairs、原始回應／分數；合併全序、去重及最終去留。
3. 每個評審實際可見的完整輸入、原始輸出、證據定位、分歧／不確定／失敗及模型 usage；不保存私有思考鏈。
4. 每案每方法的五份結果、逐份評分及主要領域對照，以及檢索與評審分開的時間／成本。

現在只有需求與實驗草稿，沒有虛構排名、評分或成本。討論後凍結新 revision 再執行；修訂保留舊版，不回寫封存實驗。所有五案都逐案報告，不只挑最好看的案例。
