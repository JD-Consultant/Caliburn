日期：2026-10-04。狀態：**隔離研究已執行；未選正式方案、資料庫或參數，未接 JD App。**

本輪較值得保留的基線是 **R01：整段工作原話直接向量搜尋**。加入 rerank 未呈現主要職位代表性與時間上的優勢，還把已有的前端、平面視覺設計參考排出前五。四種方法在全端案例都沒有交付能代表後端主要工作的 2／3 分公版，因此目前不能宣稱檢索足以涵蓋員工主要工作。

這是五案開發比較與單一模型的正文盲評，不是完整正確答案集或真人驗收。原案例、分數與失敗均保留；下面依檢索名次逐份列分，**不計總分或平均分**。

## 失敗發生在哪一階段

[排序階段追蹤](stage-trace.md)只追蹤本輪前五聯集內已評為 3 的五組「員工×公版」，沒有增加答案或調參：

- F01 前端公版：整段初搜第 4，rerank 降至第 7，被最終前五排除。分段初搜各第 9／7，直接融合排第 6；加入 rerank 後才保留在第 5。
- F05 平面視覺傳達設計：整段初搜第 3，rerank 降至第 14。分段初搜第 3／2，rerank 各降至第 6，融合後第 6，也被排除。
- F02 前端、F03 會計的強代表公版四組都保留，顯示 rerank 效果依案例而異。

本輪對照並不支持「加 rerank 一定更適合找主要職位」。低分候選常共享訂單、社群或故障排除等語境，但沒有相同的主要責任；這是待驗證的失敗解釋，尚不能據此確定模型、查詢表示或語料哪一個是唯一原因。

## 評分可靠性的限制

1. **同批七例回歸，並非獨立校準驗收。** 首輪 6／7，修訂 Prompt 加入與 C04 相近的保養例及預期 2 分後，同批 7／7。這只證明規則例可回歸，不能證明新正文判讀可靠；原 Prompt、失配及修訂皆保存。
2. **主要領域粒度影響 3 分。** F01 預先拆為前端／後端，因此前端可獨立得 3；F04 把安裝、檢修、試運轉與保養綁成一個領域，維修公版因不足以涵蓋該組合被給 2。尚未排除模型把可獨立代表的檢修領域降成「整體不足」。不能以 F04 無 3 推論全庫缺少合適來源或檢索失敗。
3. **跨對象的 1／2 邊界仍待判讀。** F04「網路維修助理」的診斷、修復、驗收、紀錄給 2；「電腦設備裝修人員」的故障判斷、換件、測試、保養給 1。理由尚未充分解釋相近跨對象流程的差異。七例未覆蓋此邊界，保留原分並列作新評審驗證反例。
4. **引用正確不等於語意正確。** 正式 49 回應中 48 筆自動逐字驗證通過；J014 漏掉原話中的「也」，按唯一原文只補引句，1 分及理由都沒改，沒有額外模型重評。來源修正見[grading-reconciliation.json](grading-reconciliation.json)。
5. **沒有完整相關來源集合。** 後端前五未有 2／3，不能區分全庫沒有合適來源或檢索漏失；名稱沒有「後端」不能證明正文沒有後端工作。五案已用於開發，未驗真人訪談、已發布 Memory、自動分段、全庫 Recall、ANN 或 JD／PDF 收尾。
