# 客製化JD參考檢索：輸入邊界敏感度

2026-10-04，使用者已將目的確認為：公版僅提供任務與整體JD完整度的參考；員工實際工作可跨多份公版，公版與客製任務允許拆分／合併／多對多。職稱、公版任務ID或任務數量一致，都不作完整度答案。查詢向量資料庫的方式仍待實驗，不因前輪候選通過而正式採納。

本輪為已授權檢索研究的有界延伸，使用brainstorming釐清探題、TDD核資料保全、既有公開模型與唯讀review；不改production、不接决策模型／主LLM或JD停止。問題是：**同一份原話在沒有刪改內容下，合併或細分輸入會不會使前輪涵蓋／資料量結論失效？**

## 固定材料與三種輸入

沿用前輪封存22個已觀察合成情境、805份T/O/P公版正文、86個已核對來源支持主題。其中16個有支持標註正例、6個未評分控制；本輪全部是回歸／敏感度探查，沒有新holdout、真人或專家完整標註。不得用本輪結果重新調參，再稱獨立通過。

1. original_messages：保留原employee_messages邊界；是前輪候選的回歸控制。
2. joined_employee：用兩個換行串起整位員工原話，作一個查詢，保留原順序、全部文字及否定／權責。
3. sentence_pieces：逐原話段在「。！？｣結句切片，保留全部文字、標點、來源段與字元offset，可逐字重建原文。這是切分敏感度反例探查，**句子不是已確認工作事項**；不把代詞、否定或別人的責任當本人工作。沒有LLM或Memory改寫。

前輪N20／每段rerank K5固定在三種輸入上，無絕對cosine／sigmoid門檻，合併後無第二全域K；另保留每段dense K5的同額控制。這不是公平「相同pair量」比較：片數不同，實際工作量不同，必須逐列保存。未重新比較DB廠牌、ANN、embedder、reranker或生成公版。

## 驗證與記錄

準備先固定原話、三種表示、來源標註、程式與hash，再產生新向量／排名。正文、項目名稱保留，OPKS代碼／表頭移除，職位名稱只metadata。相同查詢與正文且模型／分窗契約一致才能重用前輪向量／逐pair scores，缺pair實際補算，不能當0。

保存每個查詢full805 exact排名、真Qdrant原生ID／score／參數／耗時並逐項核對。舊original控制可重用封存原生查詢，清楚區分重用與本輪實跑。公開BGE-M3及bge-reranker-v2-m3 revision／權重hash不變，FP16／batch1／SDPA、8192pair tokens、64重疊分窗，不截斷，GPU有界45分鐘。

評分是每個員工已标註工作主題有沒有留下至少一個已核對參考文件；允許同一文件支持多個主題、同一主題有多份支持，不要求公版task ID與JD一對一。另保存次要主題、已知權責混淆、去重文件／正文字符、查詢數、實際pair數。未知回傳不一律算無關；命中文件不表示抽象公版任務每個子句都適用。

品質分數可快取，時間須另實跑。固定E01（3段）／M04（4段），各種輸入兩次暖機：原話向量已快取後的真DB HTTP＋候選組裝＋檔案交接／等待＋重新tokenize＋GPU＋去重。GPU容器停用網路，本機host執行DB查詢，worker只處理凍結request whitelist。模型冷載入／新embedding另列，文件交接不是產品API；沒有p95／併發／完整產品或LLM費用結論。

## 本輪能與不能回答

這輪可回答固定檢索配置对輸入組織是否敏感，以及跨公版來源支持是否被擠掉，供後續Memory／工作事項查詢設計使用。它**不能**驗證JD任務拆併的語意等價、判斷任務是否由本人負責、把沒命中的工作判成不存在，或證明員工所有工作已說完。那些須在後續各自的模型與完整度實驗處理，公版沒有支持的實際工作仍須保留。
