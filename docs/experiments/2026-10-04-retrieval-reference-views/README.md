# 公版兩層參考：來源與導覽結構核對

2026-10-04。**完成離線結構核對；沒有產生新向量排名，也沒有接入正式 JD App。** 使用者要求先處理向量資料庫與設計，分析方法能否無線索發現未知及正確收尾留待補測。候選責任與後續順序見[設計](../../specs/2026-10-04-public-reference-retrieval-design.md)及[計畫](../../plans/2026-10-04-public-reference-retrieval-design.md)。

本輪確認同一份公版可以提供兩種查閱視角：工作內容參考保留「哪段員工工作找到哪份公版」；職位整體參考提供來源公版的完整已解析任務目錄。職位目錄不再按已知工作做相似度過濾，讓後續顧問能查閱員工尚未提到的其他工作面向；是否適用由後續訪談確認。

## 輸入與方法

沿用[前輪](../2026-10-04-retrieval-input-boundaries/README.md)的 22 個已觀察合成情境、original_messages／quota_rerank／N20／K5 結果，以及[第一輪](../2026-10-04-occupation-retrieval/README.md)凍結的 805 份公版。這些是回歸資料，沒有新增 holdout 或真實員工。本輪不呼叫 embedding、reranker、Qdrant、Memory 模型或付費 API。

[事前協定](protocol.md)與[生成前 manifest](execution-manifest.json)固定輸入、腳本及設計 hash。[prepare.py](prepare.py)逐檔核來源 hash，把原始 JSON 精確保存一次，再建立目錄及兩個導覽。這是研究資料包，不另建 production persistence、validator 或 HTTP／Tool schema。

| 原件 | 內容 |
|---|---|
| [sources.jsonl](sources.jsonl.gz) | 每份公版原始 UTF-8 JSON 保存一次，保留來源路徑及 SHA-256；沒有把整份正文複製到每個員工結果。 |
| [catalog.json](catalog.json) | 所有來源的概述／版本定位、單元及完整任務群組目錄。原始多 T 名稱共用區塊保留為一個群組。 |
| [reference-views.json](reference-views.json) | 22 個情境的工作查詢、全部查詢至文件命中關係、去重職位導覽及目錄定位；原始分數只作搜尋證據。 |
| [verify.py](verify.py)、[核對結果](verification-01.json) | 從原輸入及原始 JSON 獨立重算，不信任摘要的 passed 欄位；也檢查錯換來源與遺失關係的反例。 |

導覽以 `doc_id + source_sha256 + JSON Pointer` 固定定位。來源變動或定位不存在時拒絕讀取，不換成其他版本。任務群組可以沿來源位置讀回完整 O／P／K／S、補充說明及抽取警示；代碼及職位名稱保留為查閱 metadata，這不是新的 embedding 文字。

## 實際結果

| 核對項目 | 結果 |
|---|---:|
| 公版來源精確 bytes／hash／身分一致 | 805／805 |
| 原始任務群組完整可讀 | 7,265 |
| 能力區塊保留 | 7,490 |
| 多 T 名稱共用一組能力區塊的群組 | 20 |
| 情境／查詢／查詢至文件命中邊 | 22／74／370 |
| 各情境內去重職位導覽條目（跨情境累計） | 276 |
| 同份公版保留多個工作查詢的條目 | 73 |
| 回傳來源的完整目錄群組可讀（跨情境累計） | 2,809 |
| 平均回傳公版／既有 TOP 字元 | 12.55／14,934.77 |

公版集合、查詢來源、所有 dense／rerank 排名和分數、正文字符數，均與原 metrics 相符。平均值只是重現前輪結果，沒有證明更多涵蓋或更低模型成本。2,809 是每個來源的全部已解析群組，不代表這些任務均與員工相關。

八個反例均被拒絕：錯 hash、無效位置、負陣列索引、缺來源、少目錄群組、漏查詢命中邊、把文件命中冒充任務匹配、修改來源正文。此次凍結語料沒有缺代碼的任務群組；保留空代碼群組的分支尚未經真實案例驗證。各查詢實際皆有命中，零結果顯示與服務錯誤仍待後續 consumer 測試。

例如 M04 的第四段季度庫房盤點保留五個來源，不因前面寵物美容的主要工作而消失。同一來源若由多段工作找到，只在職位導覽列一次，仍留下各段的搜尋證據。這驗的是既有文件命中關係保真，沒有驗收盤點正文定位或本人責任符合程度。

## 能支持的設計與限制

目前支持「共同來源、兩種導覽、查詢保留來源關係、按公版讀完整目錄」在這批 JSON 與封存結果上的結構可行性。**工作內容命中仍是文件層級**，明寫 `match_level=document`／`task_alignment=not_evaluated`；沒有把公版全部任務標為已匹配、缺口、已詢問或完成。

JSON 目錄保真不等於 PDF 抽取品質或官方最新身分。例如 `MQM1322-001v4` 的 `/ocs_content/ocu_units/0/tasks/1` 有多個 T 名稱共用區塊，來源名稱本身仍有斷句與重複文字；本輪按固定來源保留，沒有宣稱已修正。職位目錄只能提供資料中存在的線索，不能補回資料本身漏掉的內容。

這輪沒有驗證真實 Memory 的檢索、相關任務片段、顧問實際按需讀取、未知工作發現或 JD 完整度；沒有 token／付費 LLM／完整旅程時間比較。N20／K5、Qdrant、文件及任務群組兩條檢索路徑仍是研究候選，未變成正式參數與契約。

下一元件是比較已發布合成 Memory 的正文、保留脈絡分段與原話控制；再比較公版檢索單位及相關內容減量，最後實驗資料庫方案與參數。分析方法的未知探索、rerank 後額外決策模型及從空白訪談到 JD／PDF 的完整旅程，依使用者要求保留為後續測試。
