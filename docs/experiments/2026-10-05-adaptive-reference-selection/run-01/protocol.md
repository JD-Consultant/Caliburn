# 動態公版數量的離線比較

2026-10-05。使用者要求在其他模型測試占用額度時推進檢索優化，考慮用分數區間取代固定 Top 5，減少不相關追問。本輪僅重用已保存分數與評分；不呼叫模型、網路 provider、DB 或 GPU，不改 API 行為。屬探索性比較，既有八案已被觀察，沒有新 holdout。

固定現行控制：員工原話 O、D20/T20 不同父公版完整聯集、既有 BGE-reranker-v2-m3 logit 排序。只改末端選取；不先收緊 dense cosine，避免初搜漏掉的參考無法被 rerank 找回。分數相同沿既有排序，不以評分打破平手。

事前比較族：固定 K=1/2/3/4/5/10 及完整聯集診斷；logit 絕對下限 -8 到 0、每 0.5 一級；距最高分不超過 0.1/0.25/0.5/1/1.5/2/3/4/6；相鄰 logit 首次落差達 0.1/0.25/0.5/1/2 時停止。動態各族上限 5 或 10。上限 10 只作已知代表是否被 K5 截掉的診斷，不因此更改正式 API 上限。絕對下限允許零筆，相對與落差法本身至少一筆，不能判斷全部不適合。

只沿原 0–3 評分逐份保留，不加總／平均代表性分數。分別計數 0、1、2、3、未評：0/1 不能代表主要工作，但 1 不等於完全無關；未評不當負例。原 12 個 case×grade3 及可被其支持的 8 個已知主要面向作回歸清單；疑義來源排除後另列敏感度。H01 無已知 grade3，涵蓋不能評判。回傳公版數不是追問數，也不是實際 token 或延遲。

逐案記選中／排除來源、分數、評分及理由、已知代表／面向損失。保留候選池完整排序，讓任何門檻決策可重算。額外計算每案保留基準 Top5 既有 grade3 所需最短前綴，僅作知道答案的診斷上界，不拿來當部署選法。

跨案例檢查：對 absolute／relative／gap 三族上限5，每次用其他七案挑選「不多丟基準已知 grade3，且總回傳量最少」的參數，再套第八案。打平沿預先列出的參數順序。這只測跨查詢敏感度，不宣稱歷史已觀察資料變成真正 holdout；不據八案調整後宣稱通用最佳。若無可行參數，明示回退 Top5，不偷改保留條件。

保存輸入 SHA256／bytes、舊封存核對、分析程式、所有參數逐案輸出、彙總、跨案例結果及新封存。單元反例只驗確定性選取／未評處理，不代替模型品質。預期效果是減少弱主要參考而不新增已知工作漏失；無法同時成立時保留失敗證據及現行控制，不硬上門檻。

官方依據：[BAAI reranker](https://huggingface.co/BAAI/bge-reranker-v2-m3) 的 sigmoid 是單調分數轉換，沒有本案機率校準保證；[Qdrant search](https://qdrant.tech/documentation/search/) 的 threshold 屬搜尋 metric，不能等同後段 logit；[Choppy 原論文](https://storage.googleapis.com/gweb-research2023-media/pubtools/5594.pdf)支持將排序截斷視為需依標註及效用比較的問題，本輪不訓練其模型。
