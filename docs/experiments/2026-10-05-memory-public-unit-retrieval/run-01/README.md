# B2與原話的公版整份／任務／合併及rerank比較

2026-10-05。隔離研究，十二方法、獨立核對與最後審查已完成，原件已封存。**目前不能只採B2，也不能把rerank一律視為改善。** 原話＋任務chunk＋rerank首次在這批案例的前五找回同時涵蓋前後端的來源；其他案例仍有退步。沒有選正式DB／ANN／相似度線或App接線。

## 核心發現

- **全端：原話＋任務＋rerank將「網站系統設計人員」排第1，模型評3，支持前端及後端兩個主要面向。** 完整公版明寫前端UI、後端資料庫介接、後端業務邏輯與API設計，字面證據可查；職稱不是搜尋文字。這首次補上先前未找到的伺服器功能強代表，但仍是有限合成案例的模型判讀，不能宣稱整個職位或JD已完整。
- 該公版原話整份第40、任務max第15；任務路徑把它帶進N20後rerank才能提升。B2整份第24、任務第41，兩路N20均沒有它；無論rerank多好都不能重排未進候選的來源。
- 原話D＋T聯集含該公版，但M融合列第25、先縮成20後把它排除。因此**合併不自動保證涵蓋**；下一步應有限比較每路候選深度，以及保留聯集至rerank後再縮額度，而非先把M當最佳。
- **B2帳務：**D第一名文書助理0；T及M不加rerank時把會計助理排第1。M仍保留會計人員第4。加rerank後M第一名又成0，兩份會計代表退至第2／5。
- **冷氣：**原話T第1、M第2找到冷凍空調技術人員3；加rerank後都退至第4。B2各法前五仍沒有3，整理並非穩定改善。
- **僅前端／視覺／採購：**rerank會丟掉部分既有強代表。B2僅前端的D與M原本前端第1，加rerank後前五不見；視覺的平面代表在六個rerank法都消失，O-T-R改留多媒體第5；B2採購原D及M的助理第1，加rerank後均消失。不能據全端一案採納必跑rerank。
- **倉庫：**B2-D原有理貨第1／倉儲第4；T／M只留理貨，rerank後B2三法也都只留理貨。課程行政十二法皆無3，不能推論全庫無適用資料。

## 固定方法、時間與成本

原話整段8query、現行發布B2逐理解12query；body／vector／來源完全沿[Memory六組](../../2026-10-04-memory-layer-retrieval/run-01/README.md)，不重新生成或手寫。六案B2單物件，不能當成獨立切分效果證據。公版D805、T8068（含803獨立概述）與BGE-M3 1024 dense沿前輪，不新算embedding；T每父最高chunk分，chunk數不直接加分，max仍可能受長度與粒度影響。

每query D/T各20父；M等權RRF k2融合D/T前20，再取20父；跨B2物件同RRF，最後全域去重K5。M有兩路搜尋，沒有假稱相同成本；M沒有保留全部聯集至rerank。完整D正文用本機固定BGE-reranker-v2-m3重排同20父，非對單一命中chunk判整體職位。628個品質pair共享分數；暖機三輪每方法fresh重新推論，共3,600pair／144任務。GPU載入、tokenization、窗口、logit、全部候選去留保存，沒有截斷正文或默默增加最終額度。
