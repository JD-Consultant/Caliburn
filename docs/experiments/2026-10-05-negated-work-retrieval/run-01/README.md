# 員工回答「沒有做」，仍可能提高檢索分數

2026-10-05，本機 BGE 實測。**三份固定合成工作都出現：加上顧問問題及員工否認後，對應公版的整份 cosine 與 reranker logit 高於原本工作描述；其中兩案的該公版進入最終前五。** 這支持把員工已確認工作與待確認／否認範圍分開處理，不能假設將整段問答丟進向量搜尋就會自動排除否認內容。

這輪測了檢索行為，沒有執行顧問 Agent，不證明顧問一定重問，也沒有修改 API、Memory 或 JD App。公版含多項工作，否認某項不代表整份都不適用。

## 直接回答使用者的情境

每案先固定主要工作，再加入同一個顧問問題及「員工：沒有，這些我沒有做。」。表中 dense 名次是 805 份公版的 D 整份路；最終名次是 D20/T20 完整聯集經 rerank 後排序。原本三案的觀察公版皆不在各自 D20/T20 候選中，因此沒有原本實際 rerank 名次。

| 已確認工作／顧問問的範圍 | 公版 D cosine 原本→否認 | D 公版名次原本→否認 | 否認後實際 rerank 名次 | 是否進最終 Top5 |
|---|---:|---:|---:|---|
| N01 網站前端／SEO策略 | 0.5867→0.7193 | 179→1 | 1 | 是 |
| N02 日常帳務／供應商詢比議價 | 0.5766→0.6269 | 174→17 | 3 | 是 |
| N03 倉庫作業／供應商詢比議價 | 0.6272→0.6626 | 80→18 | 6 | 否 |

N01 員工原本說自己製作頁面、表單、串接 API 及測試操作。顧問問：「你有負責分析關鍵字和競爭網站、制定搜尋引擎優化策略、追蹤搜尋排名及曝光成效嗎？」員工答沒有，SEO 公版仍被拉至第一名。這是實際新增 query 推論，不是從舊分數猜測。

## reranker 有降低分數，但未阻止召回

各案以所有變體候選的聯集加兩個事前指定觀察公版為共同池（70／58／46份），使同一公版能在每種文字下直接比較。以下是原始 logit，越高越靠前，**不是符合率**。

| 案例 | 原工作描述 | 加問題但未答 | 問題＋沒有 | 問題＋有 |
|---|---:|---:|---:|---:|
| N01 SEO公版 | −6.7734 | 0.7705 | −2.6562 | −2.2109 |
| N02 採購公版 | −7.1719 | −0.9482 | −2.7266 | −2.6523 |
| N03 採購公版 | −6.0156 | −1.9775 | −2.1641 | −1.9980 |

短否認的 logit 三案都比「僅加問題」低，也都比肯定略低；不能說模型完全沒有辨別否定。但三案仍比原工作描述高很多，前兩案未被移出前五。「沒有」造成的下降不足以抵消整段新增任務描述的效果。

改為明確重述「我不負責……這些由其他同事處理」時，D cosine 分別升到 0.7512／0.7084／0.7118，D 名次為1／3／4；前兩案最終仍第一名。這三案明確否認的 D cosine 甚至高於短肯定版本。這是完整文字變體的效果，不能將分數增減單獨歸因於某一個否定詞。

重複三次相同問答時，D cosine 都高於原文；reranker 則有下降，N02 被排到第16、N03第15，N01仍第3。分數與排名未必一起改變，也不是否認寫越多一定越差或越好。

## 做了哪些控制

- 3案×8變體：原文、問題未答、短否認、明確否認、短肯定、不確定、重複三次否認、人工已確認工作投影，共24結果／21唯一文字。
- 新算本機 BGE-M3 1024維 query；沿既有805 D／8068 T向量精確 cosine。另保存待確認任務 chunk 的分數及全8068排名：短否認三案的指定 chunk 分數都高於原文；父公版 T最高chunk分數則只有兩案升高，不能混用兩個指標。
- 每案共同 rerank 池逐一評分，再以每變體自己的 D20/T20聯集重現Top5。另保存共同池排名，避免候選變動混淆模型分數效果。
- 人工投影只含原本已確認正文，與原文完全同字並共用快取，是恆等控制，**不是自動 Memory 抽取或否認管理有效的證據**。
- 主要工作監測錨點原文已有2/3進前五；N03倉儲錨點原本就未進，不能全算新增否認造成。N01明確否認／重複否認後原前端錨點掉出前五，但未全面評分其他公版，不能推成整個前端領域完全失去。
- 短肯定只代表有做，不證明是主要工作。未答問題壓測也不代表正式 App 一定會將未答問題加入查詢。

執行22份新embedding（含1份舊F01控制）、1218組新rerank配對。舊向量控制最大分量差0.0000518，小於事前0.001容許值。模型權重、輸入、來源及實際Docker隔離資訊均保存；GPU工作約170秒，含模型載入、hash及整批實驗，不能當API延遲。容器禁網，無LLM評審、無外送／provider費用。初次啟動因映像沒有 `python` 命令失敗，查明後改 `python3`，模型輸入與程式未改；見[執行紀錄](execution.json)。

## 設計含義與尚待測試

建議查詢使用有來源的、員工已確認的主要工作；必要顧問問題用來解釋回答脈絡，不因問題出現就當成新增工作。員工否認仍須留在 Memory／可查的確認記錄，供顧問知道同一範圍已確認不做；不把否認正文當成正向搜尋依據。這是候選做法，尚未實作自動投影。

需要分開驗證：搜尋仍可能找到公版，但 App／顧問是否避免再次拿同一已否認範圍追問。公版中的其他主要相關工作可以繼續參考，不以某任務被否認封鎖整份公版。不確定、拒答、低頻有做、以前做現在沒做、部分否認及本人後來更正，需要後續個別案例；本輪只跑前三個明確否認反例，沒有宣稱否認生命週期完成。

這與 [NevIR原始研究](https://aclanthology.org/2024.eacl-long.139/)所測神經檢索否定弱項方向一致，但其資料與模型不同，不能用該論文替代本輪中文 BGE 實測。[BGE reranker模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)的輸出是 query/passage 相關性分數，沒有承諾員工責任判定或否認排除。
