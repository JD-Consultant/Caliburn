## 一、月報時間與範圍

- **提交時間：每月 5 日前**。
- **涵蓋範圍：上月全部售後案件**，不只退換貨，還包括：
  - 故障案件
  - 到貨破損
  - 缺少附件
  - 安全疑慮
  - 進度查詢
- 整理時以**案件編號去重**，同一訂單、同一台機器的重複詢問應併回原案件。
- 月報會整理：
  - 客戶描述與現象
  - 型號等產品資料
  - 已做的檢查
  - 技師或相關窗口的判定
  - 處理結果
  - 尚未結案原因
  - 代表性案例
- 需要核對 CRM、客服回覆、倉庫簽收、財務匯款等狀態。若系統、倉庫與財務紀錄不一致，會回查交接紀錄並詢問負責窗口，不自行挑一個狀態當作事實。

### 退款案件跨月才收到客戶確認

以**海鷗除濕機退款案**為例：

- 月報期間若只有「已匯款」，但尚未收到客戶確認，不能寫成「客戶已收款」或「已結案」。
- 應保留為：**已匯款、待客戶確認**。
- 隔月收到客戶確認後：
  - 沿用原案件編號；
  - 補上客戶確認日期與確認結果；
  - 更新原案件狀態；
  - 不另開新案件；
  - 不把這次後續確認誤列成另一台機器的故障或新案件。

## 二、五個案例的產品與關鍵差異

| 案例 | 產品 | 關鍵差異 |
|---|---|---|
| **松嶺** | 果汁機 | **啟動後停止**，且是另一個型號；上蓋檢查仍無法排除問題，不能直接套用雲杉的判定或排查方式。 |
| **雲杉** | 果汁機 | 客戶說「不能動」，但必須先區分完全無反應、啟動後停止、或只有特定模式不能用；依適用型號的核准清單做外部檢查，例如確認上蓋卡榫。最後由技師確認機件故障，客戶選擇換貨。 |
| **海鷗** | 除濕機 | 技師判定可以換貨，但**倉庫缺貨**。因此先詢問補貨日期，再讓客戶選擇等待或退款；退款金額由財務主管核准，出納匯款，後續還要等客戶確認收款。 |
| **石橋** | 吸塵器 | **到貨外箱凹陷、機殼破裂**，重點是確認證據與案件對應性。紙箱標籤照片不足以證明商品身分，還要補機身序號、破損位置照片、訂單及時間紀錄。物流責任與賠償金額不是員工判定。若只是缺附件，先核對倉庫出貨清單，確認漏寄後補寄，不一定整台換貨。 |
| **青禾** | 電暖器 | 出現**焦味**，屬產品安全疑慮。先請客戶停止使用並在安全情況下斷電，不要求重新開機或拍攝通電影片；記錄型號、批次、現象及是否有人受傷，立即通知產品安全窗口與值班主管，依指示取回。不能自行宣布原因、召回或承諾賠償。 |

特別要注意：

- **松嶺與雲杉都是果汁機，但不是同一個問題，也不是同一型號。**
- 雲杉的「不能啟動」要先釐清現象並依核准清單排查；松嶺是「啟動後停止」，且需要新的適用排查或技師確認，不能直接沿用雲杉做法。
- 青禾的焦味屬停止使用的安全情況，不能把「不准通電」這個處理方式套用到所有一般故障案件。

## 三、FAQ 何時可以更新、由誰確認

不是看到一個相似案例就可以更新 FAQ。以松嶺案的流程，至少要具備以下條件：

1. 先確認型號、序號、現象與已做過的檢查。
2. 由員工把資料交給技師或產品相關窗口，不能自行推導故障原因。
3. **產品窗口**提供適用的新排查方式或內容。
4. **技師**確認該項檢查是可以執行、且適合交給客戶做的。
5. **營運主管**確認對客戶使用的說法與措辭。
6. 確認適用的型號、排查步驟與版本日期後，才更新 FAQ，並通知客服。

所以，員工可以負責整理、補查、追蹤及依確認內容更新紀錄，但**不能自行決定新的排查方法，也不能因單一案件就修改所有果汁機的 FAQ**。新步驟可能只適用特定型號。

## 四、容易被高頻退換貨蓋掉的工作

高量期間容易只顧著處理「換貨、退款」，但記憶中還有幾類工作不能漏掉：

1. **每日兩次受理與重複案件合併**
   - 每天 09:00、14:00 查看信箱、表單與平台訊息。
   - 在 CRM 核對是否為同一訂單、同一台機器的重複詢問。

2. **未結案案件的持續追蹤**
   - 每天下午查看等待技師判定、取件、庫存、退款的案件。
   - 記錄負責窗口、約定回覆日、下一步與卡點。
   - 在承諾期限前追窗口，若會延遲要先通知客戶。

3. **安全案件**
   - 青禾這類安全疑慮不能因一般退換貨量大而延後，應優先通知產品安全窗口。

4. **案件證據與資料完整性**
   - 例如石橋案的序號、破損照片、訂單、時間紀錄。
   - 不能因客戶一直催就跳過身分、商品或訂單對應的核對。

5. **缺附件與補寄追蹤**
   - 缺附件不一定是整台換貨，要先查倉庫出貨清單，並追到客戶確認收到補件。

6. **月報與跨月補記**
   - 所有售後案件都要納入，不只是退款或換貨。
   - 特別是已匯款但尚未客戶確認的案件，要保留待確認狀態。

7. **產品窗口補查與 FAQ 維護**
   - 包含去識別化案例整理、補件、追蹤回覆日，以及在多方確認後更新適用型號與版本。

8. **新人帶教與代理交接**
   - 有新人時，前五件要檢查 CRM 紀錄、權限界線、交接與回覆措辭。
   - 休假前要交代未結案清單、下一步、窗口與回覆日，不能只寫「待處理」。

目前記憶中，員工也確認**沒有其他固定工作或偶發支援**；以上是售後工作本身容易在高峰期被退換貨量掩蓋的部分。

## 五、已知的權限界線與仍未知的例外

### 已知不能自行決定的事項

- 不判定故障原因。
- 不改變技師判定。
- 不自行核准退款金額。
- 不談定物流賠償金額或判定物流責任。
- 不自行承諾未核准的例外方案或額外補償。
- 不自行決定新的排查方法。
- 不自行宣布產品原因、召回或安全賠償。
- 不自行指派人力。
- 不能把個案預估時程當成所有案件的保證。
- 客戶長期不回覆時，不能自行決定直接特殊結案。

### 記憶中仍不知道或沒有實際經驗的部分

1. **物流損失賠償的最終核定者是誰**，目前仍不清楚。
2. 客戶同時不接受等待、也不接受退款時，應由誰決定、具體怎麼處理，沒有實際案例。
3. 客戶對技師判定有爭議時，最終決定者與標準尚未確認。
4. 客戶長期不回覆時，特殊結案的具體條件與期限，記憶中只有「要問主管」，沒有明確規則。
5. FAQ 的最終發布或版本控管權限，記憶中可確認產品窗口、技師、營運主管各自參與確認，但未明確記載是否還有更高層或正式系統審批者。
6. 公司是否有正式的數值 KPI 或考核表，員工也不知道；不能把每天案件量或目前排序方式說成正式 KPI。

另外，**海鷗案只能證明該案退款金額由財務主管核准**，不能據此推論所有退款或所有例外方案都一定由財務主管決定；營運主管則負責超出退換貨規則的例外方案與跨部門卡關協調。
