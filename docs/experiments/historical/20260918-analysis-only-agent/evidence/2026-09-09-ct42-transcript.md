## 最後保存的工作理解

# 接案網站開發與維護

## 共通工作範圍
- 員工是接案前端工程師，依不同客戶需求開發、維護不同網站，不是只負責固定網站。開發工作包含了解需求、製作畫面、串接後端 API，以及上線前測試；畫面通常依客戶提供的設計稿實作，員工負責響應式畫面與操作狀態，不負責品牌視覺設計。
- 每個新案開始時，員工會先與客戶釐清使用者、主要操作流程、需要串接的 API、驗收條件及不包含的範圍，再拆分畫面與串接工作並評估風險與所需工時；後續若新增範圍會重新估算，並非固定每週估算。API 文件不清楚時，會先整理問題詢問後端，不假定 API 已具備尚未確認的能力。估算供客戶決定工作範圍與時程，但員工無權替客戶核准追加預算；客戶決定範圍、時程或預算後由誰確認為員工開發依據，尚未確認。
- 客戶核准縮減或追加範圍後，員工會同步更新畫面清單、API 串接項目、驗收條件與估算，並重新與客戶確認新的交付範圍，不能只修改工時數字。青禾由客戶營運主管核准、產品負責人彙整；其他案件依客戶指定的核准窗口確認。員工不自行核准預算。
- 上線後，員工每天排查客戶回報，並於每週五整理所有案件的未結問題、原因、接手人及下次追蹤點；這項整理不限於付款案件。不同案件的維護處理、升交及重新部署方式，除下述已知內容外尚未說明，不能跨案套用。
- 兩個網站共同依驗收清單測試手機、桌機、API 串接及錯誤狀態，先部署測試站交由客戶驗收，再配合正式上線；這是員工開發網站的共同做法，不是青禾專案特有。青禾與雲岸的前端正式部署均由員工負責，前提是客戶已完成驗收確認；後端服務由後端人員部署。員工會記錄版本與回退步驟。兩案維護均為測試站驗收後部署正式版，再由客戶確認原問題未再發生且相關功能正常，才結案。
- 交付時會整理讓客戶能啟動、部署、回退及操作系統所需的前端文件，包含前端啟動方式、環境設定名稱、部署與回退步驟及已知限制；實際密碼不寫入文件。只要修正影響啟動方式、部署方式、回退方式或已知限制，就會同步更新文件；重大改動時另外補充操作說明，不是每月固定授課。完成判準是客戶能依文件啟動測試環境、操作主要流程，並知道遇到問題應找員工或後端。交付後若仍無法啟動或操作，員工會先收集重現步驟、畫面與網路請求；前端程式或員工交付的前端設定問題由員工處理，後端 API 或環境問題交給後端，員工負責畫面回歸測試。這不代表員工有權指揮客戶所有部門或包辦所有環境維運。

### 前端套件安全公告／必要升級
- 這是低頻但重要的前端維護工作，觸發情境包括前端套件發布安全公告，或客戶提出升級要求。員工先確認目前使用的套件版本是否受影響；需要處理時，在測試分支升級並針對主要流程回歸測試。
- 上線前，員工整理升級影響與部署安排，先向客戶說明並取得確認後才上線。若升級可能破壞相容性，須先說明風險與替代方式，不能由員工自行直接部署到正式站。
- 責任界線：員工不負責公司網路安全稽核，也不負責後端漏洞修復。此項工作屬前端套件維護，不代表員工負責整體資安或後端安全修補。

## 青禾：會員訂閱網站
- 客戶產品負責人會先彙整需求交給員工。員工確認需要製作的畫面與會員可見功能，遇到不清楚的地方會回問。
- 青禾的需求變更由客戶營運主管最終核准；客戶產品負責人只負責彙整需求，沒有最終核准權。員工已查合約確認，先前認為由產品負責人核准是不正確的印象。
- 員工負責串接畫面、會員權限狀態及金流狀態 API，並處理付款失敗時前端應顯示的內容。實際扣款由後端處理；員工沒有扣款或退款核准權，也不知道客戶內部退款最終由誰核准，且該事項不屬本人職責。
- **「已付款卻看不到會員內容」回報案例**：員工先收集發生時間、帳號代碼及操作步驟，在測試環境重現，並查看瀏覽器主控台與網路請求。此案確認為前端收到成功狀態但權限畫面未刷新，員工修正前端更新流程；也就是沒有真的扣款失敗，只是畫面沒更新。修正後測試成功、失敗及逾時情況，提供截圖與重現步驟給客戶確認。若 API 未回傳正確狀態，員工整理請求與回應交給後端處理；後端修正由後端部署，員工只負責回歸測試畫面，不負責後端部署。員工不判定扣款失敗，也不退款。每件回報通常在收到當天先判斷影響範圍，但不保證當天修好。
- 青禾前端修正測試完成後，先更新測試站，由客戶產品負責人依驗收條件確認；客戶確認後由員工部署前端正式版，並記錄版本與回退步驟。修正只有在客戶確認原問題不再發生，且相關功能沒有損壞後才結案。

## 雲岸：課程報名網站
- 雲岸只做課程報名，不做金流；不可把青禾的付款處理套入此案。
- 員工負責串接後端報名 API，並處理使用者重複點擊，避免重送報名。
- **報名鍵重複送出案例**：使用者連點報名鍵造成前端送出兩次；員工以測試帳號重現，確認送出請求時按鈕仍可重複點擊。員工在前端加入「送出中」狀態，送出期間停用重複觸發，請求成功或失敗後恢復按鈕操作。這項前端處理不取代後端責任，後端仍須自行實作冪等防護，不能只靠停用按鈕保證不重複。
- 雲岸前端修正先在測試站驗收；客戶確認後由員工部署前端正式版，並記錄版本與回退步驟。結案前仍須由客戶確認原問題未再發生且相關功能正常。雲岸沒有加入金流，客戶內部最終退款權限也不屬於員工工作權限。
