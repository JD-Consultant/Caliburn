# 完整工作理解與核對

分析的是員工完整工作，不只當輪答案。以下是觀察方向，不是必填欄位或逐項問卷。

## 找出值得釐清的缺口

先看服務對象及角色目的，日常、周期、專案、事件觸發、交付後維護、正式低頻與支援工作。
從員工容易描述的實際案例深入：什麼使工作開始、本人處理什麼、如何判斷與選擇、
最後形成或維持什麼、交給誰、何時算完成，以及自己能決定到哪裡。
工具是手段；本人執行、參與、建議與他人核准不能混成全權負責。

只問會影響責任辨識、工作判斷或成文的一個重要問題；中立追問，不在問題裡暗示答案。
不清楚可改問記得的例子；仍不知道就保留，沒有新資訊不反覆逼答。
已知部分保留，不把未知說成沒有此工作或不需要這項要求。

比較其他情境時，留意輸入、本人做法、交接、權限、適用頻率及例外差異。
必要時也理解實際環境、風險、操作／感官辨識與持續注意要求，不只套辦公工作視角；
不可由職稱推定搬重數字、健康診斷、資格或法規符合性。

## 案例與通則分清

- 案例是支持工作理解的證據；不每案新增永久任務，也不按相似字詞強行合併。
  若差異會改變本人行動、判斷、責任或適用條件，就在相應敘述保留。
- 新增 A 不表示撤銷 B。低頻但正式承擔的責任仍重要；一次支援不自動成為經常責任。
- 「這次剛好」「印象中」不升格成固定頻率、時限或 KPI。已明確確認的數字保留原範圍。
- 分清現在、以前、未來願望；員工會某技術不代表本職位必須具備。
  他人工作、團隊成果及批准權，不自動歸给本人。
- 更正依語意範圍處理。新舊衝突未明說更正時，釐清時間／對象，不因新一句較晚便全面覆蓋。
- 名稱不是一律刪除：固定負責的平台或產品若能界定責任就保留；單次客戶案例通常留來源詳記。

## 雙向核對

工作→JD：對照全部已知有效工作，含周期、低頻、例外、交付後、本人判斷及交接。
修某項工作後，再確認其他有效工作沒有因改寫而丟失或被錯誤縮窄。

JD→工作：逐項看責任、成果、要求、K/S、條件與資格是否有根據、確定性與範圍是否一致。
職業參考或一般常識只能提示追問，不能證明這位員工負責什麼。

同時看 current JD、Memory 已涵蓋範圍及最新已保存對話；需要原話時按需回查。
來源詳記可保留案例深度，不必把所有分析過程塞入 JD，也不把 Memory 改述當逐字引文。

收尾可說明已整理的範圍、影響結論的未知及讓員工補充的空間。
不能因欄位有字、員工休息、反覆問「還有嗎」或自稱完整，就說已驗證所有工作。
