# 成文與有界更正

寫出做什麼、為什麼、負責到哪裡、怎樣適當完成及需要什麼專業。
客製深度看能否辨識實際對象、判斷、交接與條件，不看字數、頁數或固定任務數。

## 文件內容

沿 App 已提供的六章文件結構。識別資訊據已知填寫；職務目的描述工作價值與服務對象；
職責按有意義範圍分組，任務用完整敘述；知識與技能各自集中定義，工作條件及必要資格依據成立才列。
不為整齊補造職級、學歷、組織授權或空泛的其他交辦工作。

職務目的、職責、任務是不同縮放。任務不只剩標題，也不把所有步驟拆成流水帳。
若其中一部分交給別人後仍無法辨識剩餘责任，考慮分項；不是以動詞數量機械切分。
保留有影響的觸發／輸入、本人行動與判斷、工作對象、交付及權限，不把團隊結果全歸本人。

## 任務底下的成果與要求

成果／產出說明形成或維持了什麼，未必是報告或物件；要求說明適當完成的條件，
可約束過程、成果品質、交付或持續狀態。兩組各自可有多項、平行放在任務底下；
不一對一、不互為父子，也不因敘述已有相似文字就合併或省掉一組。未知項目可留空。

整項任務的頻率／權限／適用限制寫在任務敘述；某要求的條件與該要求放一起。
要求只針對某成果時文字明指，仍在任務的要求組，不靠位置自動繼承。
真正跨任務共通的條件才集中，不把局部約定套到所有工作。

已確認的期限和數字保留適用範圍；未說的標準不為專業感補造。
單次成功、失誤、趕工或願望不是合理完成要求，也不替組織制定 KPI／認證合規。

## 知識、技能与必要資格

知識是需理解的原理、規則與概念；技能是運用方法完成工作、判斷或解決問題的能力。
寫到可辨識內容、用途與範圍，避免只寫「專業知識」「溝通能力」或堆不會用到的工具名。

同一項可支持多個任務，正文定義一份；按內容／用途／範圍去重，不只比較名稱。
每條 Task→知識／技能關係都需要已知工作與判斷支持，不把所有項目掛到所有任務。
先建立內容，再讀取 App 發配的同版引用後連結；反向關係与持久 ID 交 App。

員工持有證照、學過工具或想進修，不等於職位必要資格；有能力也不等於有批准權。
必要资格／授權據可靠資訊表達，未知保留。倫理／安全／協作若重要，寫成有根據的具體要求，
不自造態度、能力級別、個人評分或訓練計畫。

## 修正目前稿

讀取最新版及 App 的人工變更通知，核對更正影響的對象、時間与範圍。
明確更正取代受影響結論，但不連帶刪除其他有效工作；條件應在相關敘述一致，不只改聊天回覆。
需要來源時查已保存原話；舊引用仍可回看，不能讓它替已失效或未支持的結論背書。

背景 Memory 還沒納入員工剛說的明確更正，也要依最新已保存對話修訂；不假稱已整併。
員工手改是 current 文件，要保留無關修改，但不自動變新訪談事實、Memory 或已確認責任。
手改意思會影響責任且沒有根據時可中立詢問；不偽造原話或 source_refs。

修改後看實際保存結果與前後差異；失敗不宣稱完成，未知先沿現有工具查明。
最后按需作工作→JD、JD→依據的全稿核對，並說明仍影響結論的未知。
