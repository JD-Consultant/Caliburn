# C-W 自然揭露程序與空紀錄

版本：1。人員執行；0次自然 trial。此文件與oracle均不送入App／模型／工具目錄。待測顧問只接收當次實際員工回答與合法產品事件。

## 揭露規則

1. 開場只用 employee-card 的一句話。自然追問可改變次序，不固定問法、工具路徑或每輪必寫稿。
2. 回答與提問相關的已設定內容；廣問工作全貌可以說相關的其他工作，不必等精確關鍵字。細問一處則不要順便傾倒全表。可用自然措辭，不能新增雇主事實。
3. 問題無已設定答案時回答「目前不清楚」。顧問提出猜測時只用卡上內容確認／否認，不以沉默或附和補新事實。未揭露不當成已知。
4. 記錄實際說出的子內容，而不只勾整個W編號。例如只說W01核數量，不代表批號條件與採購邊界也已揭露。重述已知內容可記為同類佐證，不強迫生成revision。
5. 收貨已有相關內容後，可以自然表達想把已說明的工作整理清楚；不提示工具名、refs、欄位數或「先read再edit」。不為填測試格要求每轮更新。
6. 重要工作未被問到：保留未揭露，標訪談廣度觀察；不要為讓結果變好在結束前自動補全oracle。到授權的回合／請求／費用界線仍未涵蓋就如實停止。

## 事件次序限制（不固定第幾回合）

- **E00 開場不足**：先看顧問如何追問，不投餵完整工作。
- **自然累積**：收貨足夠、其他工作範圍、兩案差異依自然追問揭露；每次記錄內容及來源位置。
- **E-W05 初述→晚期查證**：初述已揭露後，待已有其他工作討論／可觀察稿件再自然提供卡上的查證更正。未曾初述就不偽造先前說法；Q08／Q09相關子項可能未觀測。
- **E-MW1-DOC**：已有保存JD且手編可用時只加指定句；記before／after及receipt。不在聊天確認現責、不安排任何強制Memory整併。
- **E-MW1-CHAT**：獨立後续澄清「想新增，目前還沒做」。與手改的時間、來源、Memory觀察分開。
- **收尾／重開**：自然請顧問核對已談的工作與仍未確定處，關閉／重開後續談；不透露oracle答案、不宣稱已完整。只記實際compaction或背景未整併窗口，沒出現就NOT_OBSERVED，不灌文字／調門檻／強制整併。

若後續執行獲授權，最多12個員工回合、180次provider請求、US$1.00仍各為硬上限，所有主顧問與既有背景／失敗請求計入；目前三者均NOT AUTHORIZED。不得為湊事件超限、補跑未授權回合或讓模擬員工LLM代答。手改事件不是員工聊天回合；所有實際聊天回答／更正／澄清仍記員工回合。
