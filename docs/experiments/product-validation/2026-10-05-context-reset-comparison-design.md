# 長訪談換窗後的分析：原話、摘要與分層 Memory 比較

**狀態：離線接線及凍結準備已完成，本批US$0.25／45分鐘已獲授權；尚無新模型比較結果。**本次直接沿用已有內容的 JD、累積的訪談與工具紀錄、既有 Memory 及同來源摘要，比較換窗後三種方法能否延續分析、正確修訂 JD，以及各自的取用成本；歷史建立成本另列。不從空白重跑前期訪談，也不修改正式產品。

## 1. 已有證據與這次要補的問題

[同 Memory 的閱讀策略對照](data/memory-reading-policy-2026-10-04/results.md)已有可重算證據：共同完成三對的累計輸入由 199,594 降至 87,353 tokens，減少 **56.23%**；讀取由 23 次降至 3 次，兩組指定核心判準均為 33／33。它支持「理解足夠便停止深入」的規則，不代表全稿品質等價，也沒有回答三層是否勝過摘要或原話。

這次只回答：**當舊訪談、舊工具結果及原生接續不再常駐 Context，原話按需回查、單層摘要、分層 Memory，哪種方式能在相同工作與容量限制下保留必要資訊，並減少重複分析？**各組都能成功是有效結果；Memory 若只減少查閱、卻未減少總成本，也須分開呈現。

議題 `MEM-CONTEXT-03` 目前在研究／設計階段。已定邊界為 Luna／high、既有分層及來源資格不變；正式輪前摘要仍依[目標契約](../../specs/2026-10-04-context-summary-and-compaction-design.md)，尚未實作。這份研究不決定新的產品截斷政策。本批已獲 US$0.25／45分鐘授權，計入原累計 US$2；實際啟動與凍結資料另存，不沿用已結案批次的剩餘額度。

## 2. 三組保留什麼

「截斷」只指**退出本次模型輸入**，不是刪除資料庫原文。三組保存同一份正式訪談，也都能用相同的訪談序號／區間工具回查；原話組不被強迫從頭掃描。

| 組別 | 換窗後額外帶入的長期資訊 | 遇到資訊缺口時 |
|---|---|---|
| R：原話保留／截斷續訪 | 無衍生記憶；共同近期語境以外，盡量保留容量可容納的正式原話；放不下才移除最早的完整問答單位 | 按需讀已退出 Context 的原始訪談，再分析及編輯 |
| S：單層摘要續訪 | 一份模型產生、可逐批更新的工作摘要，整份載入 | 摘要不足才回查同一原話庫 |
| M：分層 Memory 續訪 | 工作情境／理解導覽；正文不預載 | 理解足夠即使用；具體缺口才讀情境或原話 |

三組的角色指引共用相同分析與 JD 保留原則，只讓資料入口說明符合各組能力。JD 讀寫、原話工具、模型、reasoning effort、輸出預留及每題可用步數相同；Memory 專屬工具是方法差異，schema 成本照實計入，不能靠刪掉其他組必要能力製造優勢。

共同近期語境採**最後兩個已完成的員工輸入／顧問答覆單位，加上第一個單位所需前問**，按正式訊息序號選取，而非挑選含答案的句子。同一前綴三組取得相同尾段，R 另保留可容納的較早正式原話，不重複尾段；當次新輸入另追加一次。此尾段長度是研究初值，不更改正式 App 的近期資料組裝。

**不刻意削弱原話組。**換窗先排除過期 App 副本及舊工具回傳；若正式訪談原文能放進相同工作預算，R 全部保留。只有完整原話加共同請求超過預算時才從最早單位移除，不依測題挑選刪除內容。S／M 也使用同一預算上限，但不為填滿上限而增加資料。這時三組的常駐資料量不同，正是待比較的方法差異。

三組均從相同 JD 底稿及 App 狀態開始；之後各自保留真實改動與模型答覆，不把某組的回答餵給另一組。舊 JD 本身可能已存有被考察事實，須逐題記錄，不能把從 JD 取得的答案算成 Memory 找回。

## 4. 真正的大 Context：訪談與工具負擔分開量測

舊實驗全部 61 段員工原文加起始工具的計數僅 11,919 input tokens；完整執行卻出現 150K–172K 的請求。當時有 61 則 App 參考訊息、其中 801 則訪談副本，見[停止觀察](data/compaction-long-interview-2026-10-04/main-03/stopped-observation.md)。因此不能把舊計數當成本次新材料的容量證明，也不能說員工原話本身已超量。

本次主條件是**長期工作 Context 已需要換窗**。產品的輪前檢查以既有有效歷史達 128K 為門檻，輪中則檢查完整請求是否達 160K，兩者都不是模型硬容量。實驗須分列歷史計數與完整請求計數，不能用其中一種冒充另一種。

三組換窗後採共同的 **128,000 input tokens 工作預算**，另預留 16,384 output tokens；這是研究用的完整請求准入上限，不改產品輪前檢查定義。R 在此預算內保留最多完整原話；S／M 的摘要、map、指引與工具同樣納入計數。輸出預留及整體仍須符合當時模型契約，不能因低於研究預算就略過硬容量檢查。

準備時分兩份投影：

1. **訪談投影：**正式說話者、序號及原文；核對事實量、時間線與整理上界。
2. **工作 Context 投影：**同一成功前綴的工具呼叫、配對結果、JD 操作與 App 觀察。逐類計量，列出原始大小、可去除的重複參考及當前仍需的內容。

壓力主要來自有意義的 JD 導覽、任務詳情、來源／diff 查閱和修改回傳，不以隨機字串、反覆貼同一份原文或任意增加舊 map 灌水。既有重複 App 訊息另列為歷史實作負擔；若移除它們後未達 128K，先標明容量條件未成立，不能偷偷加回來替 Memory 製造優勢。需要擴展時，先凍結更多合理工作與相應 JD 操作，再做計數。

完整請求使用 provider 的相同計數契約；離線字元與本地 tokenizer 只用於初篩，不報成實際 input tokens。若拿不到有效原生視窗，只能做標明「可讀歷史投影」的獨立實驗，不能從遮蔽 trace 的 hash 或長度還原加密狀態。

這批先測產品工作預算下的換窗，分開報告「工具負擔過大，但原話仍放得下」與「正式原話也超出工作預算」兩種條件；沒有足夠材料的條件記為未施測，不以另一種代替。**原話／完整材料真的超過模型硬輸入容量**又是更強的主張，須另有足量且不灌水的材料。三者不能混寫，也不發送明知超量的請求。

## 5. 換窗與原生 compaction 的界線

截至本次核對，OpenAI standalone `/responses/compact` 的官方契約是保留完整返回 `output`，其中可以包含舊項目；並未保證每個模型永遠保留所有 `role: user`。舊實驗確實觀察到員工原話與 App user 訊息被保留，故不能用「呼叫 compact」當成「早期原話已不可見」的證明。

### 輪前換窗：三組共同的新接續片段

```text
已完成、工具效果與結果均確定的前綴
  ├─ R：不建立衍生摘要，保留預算容納的原話
  ├─ S：保存文字工作摘要
  └─ M：保存來源截止一致的情境／理解
      ↓
結束舊活躍 Context，保留原件與正式資料
      ↓
共同角色指引、工具與目前 App 資料
＋各組保留表示＋共同近期語境＋本次新員工原文
      ↓
模型／工具原生往返，產生本組的正式答覆與 JD 改動
```

這不是從 `compacted.output` 刪掉 user 項目；是研究明示的新片段，**不承接舊 reasoning、compaction item 或 `previous_response_id`**。不偽造加密項目，不刪正式原文，也不在尚有未配對 tool call 或未確定寫入時截斷。必要的目前 JD、來源資格與待核對狀態由同一 App 資料提供，不靠複製舊工具回傳當權威。

### 輪中工具 Context：三組相同的原生保險

同一輪的原生往返照原契約保存；真達 160K 才使用 standalone compaction，返回 `output` 全部沿用。A 壓後不再追加同一當次輸入或 App 起始資料。若本批也執行 B1／B2，目標設計的目前候選 map 追加另依角色權限處理，不能混入 A。

不使用 server-side compaction 或 API 自動 truncation 暗中裁剪；兩者和 standalone 契約不同。每次壓前／壓後均記錄明文 user 項目、來源序號、App 副本及 opaque 項目是否存在，不解讀加密內容。後續才產生的 opaque 狀態，也不能被當成全無早期資訊。

原生壓後仍超出可用容量時，記錄受阻並有界停止，不反覆壓同一視窗。若續訪未再次達門檻，寫「輪中壓縮未施測」，不為圖表完整而強迫觸發。第二次輪前換窗與反覆摘要留待下一階段；若本批已需要第二次輪前換窗，就記容量受阻並停止該組，不擅自追加尚未凍結的摘要／Memory 更新流程，也不以此停止宣稱方法的品質較差。

## 6. 摘要與 Memory 的公平準備

兩種整理取得相同時間截止的正式員工事實及必要前問；新測題、後續更正與評分答案不進入整理輸入。模型不能因看見測題才回頭補一份特製 Memory。

- **摘要不是刻意削弱的對手。**使用 Luna／high 整理同一範圍，保留精確值、分母、條件、時期、責任、未知及來源定位。以單一可更新正文組織，不硬限制成短短幾百字；摘要／Memory 使用相同單次輸出預留，記錄多步整理與完整成本。
- **共同增量邊界。**原則沿既有 e012、e028、e044、e052，摘要讀前稿及新增來源；B1／B2 依各自職責更新。不只讓 Memory 多次整理、卻要求摘要一次無條件濃縮所有雜訊。
- **本批優先重用，不重建。**採用 §3 已核對的摘要與 Memory，保留各自生成時的指引、模型設定與成本紀錄。本批比較既有產物在相同後續工作中的使用效果，不是兩種新整理流程的生成對照。若需補缺件，只補該缺件並先記明來源及費用，不因此重跑整段訪談。
- **模型產物不可人工補答案。**兩組產物都不能根據新測題人工補寫。要評新 B2 指引或整理流程，另設同條件生成實驗；不能把這次舊產物取用成績算成新指引的驗證。
- **區分兩種摘要。**本比較 S 是「長期工作資訊的單層摘要」；不是 UI `reasoning.summary`，也不是另給所有組一份含完整答案的共同接續摘要。共同 App 控制資料可以保留操作狀態，但不能額外塞入長期事實清單，讓三組差異消失。
- **近期新話先供本輪使用。**八段續訪先固定整理產物；新的更正留在各組後續有效歷史，不讓 M 提早拿到涵蓋未來問題的快照。這一批測換窗後取用與 JD 分析；Memory／摘要再次整理及第二次換窗另測。

各組首次 Context 不強制填到同樣長度；使用相同上限，讓表示方法的真正成本顯現。摘要過長不能只替它截字，Memory 也不能隱藏 map、tool schema 或讀回正文的費用。

這次新增費用只計實際準備、計數及續訪外送；既有產物的建立費用從原紀錄另列，不能因為重用就報為零。沒有完整建立用量時，仍可比較續用成本，但不宣稱端到端總成本較低。

## 7. 先看品質，再看讀取與總成本

在外送前建立逐項事實帳本：來源事件與序號、首次出現位置、有效時期、後續更正、需要保留的責任／例外，以及預期 JD 範圍。判準不送模型，不因輸出而改分母。

| 評估面向 | 保存的證據與指標 |
|---|---|
| 事實與更新 | 必要事實完整／部分／遺漏／錯誤；精確值、作用範圍、未知分開；列出舊值殘留與跨工作污染 |
| 最終 JD | 本次應改內容、未受影響期限／責任／狀態、同任務跨欄一致性、引用是否真正支持整段 |
| 實際資訊路徑 | 起始尾段、JD、摘要／理解／情境、原話分別提供了什麼；不可判定時不硬歸因 |
| 取用效率 | 首次及累計 input、output／reasoning、cache、工具次數、原話讀取範圍、重讀、完成時間 |
| 準備與總成本 | 摘要或 B1／B2 建立與更新、計數、取用、輪中 compact、失敗／重試分別計量，再加總 |
| 容量與接續 | 換窗前後完整請求、原話是否確實退出、舊 App 是否重複、工具配對、實際 compact 採用與受阻原因 |

每題的成功至少同時滿足必要事實、必要責任／例外及來源支持。另保留逐項成績，避免某個嚴重越權被平均掩蓋。未交付仍列入預定分母，其消耗不刪除；共同完成子集可另算，不能只展示成功的配對。

預先採以下結論方式：

- 品質相當、累計成本或讀取較少：支持該範圍的效率收益。
- 成本相近、必要事實較完整：支持該範圍的品質收益。
- 少讀但更貴，或數值／責任退化：分列取捨，不宣稱全面較佳。
- 從原話補救才答對：記為回查成功，不稱 Memory／摘要已完整保存。

一份職務及一次生成只支持機制與案例結論，不能宣稱統計顯著或普遍最佳。正式報告引用時，同頁交代材料、比較變因、分母與實際限制，不只貼百分比。

## 9. 研究依據

2026-10-05 核對下列第一手資料；借用方法，不套用他人效能數字：

- [OpenAI standalone compaction](https://developers.openai.com/api/docs/guides/compaction#standalone-compact-endpoint)：完整採用返回視窗，且輸入仍須在容量內。支持輪中接續；不保證清掉 user 原文。
- [Anthropic Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：區分接續濃縮、外部筆記及按需載入，並指出摘要可能遺失之後才重要的細節。據此同時量測保留與取用，不能只量壓縮率。
- [LongMemEval](https://github.com/xiaowu0162/LongMemEval)：資訊抽取、跨段推理、知識更新、時間及未知能力，適合形成這次的題型，而非只測單一數字回憶。
- [LongMemEval-V2](https://github.com/xiaowu0162/LongMemEval-V2)：以長期 Agent 軌跡評估記憶，分開記憶模組提供的證據與後續回答，關注正確性與查閱延遲。借鑑其工具軌跡與受限 evidence 的評測視角，不導入其框架或宣稱完成該 benchmark。

上述來源足以支撐比較方法；剩餘問題是 Caliburn 自己在固定資料下的效果，應由此協議驗證，不再為相同問題反覆改提示或廣搜新架構。
