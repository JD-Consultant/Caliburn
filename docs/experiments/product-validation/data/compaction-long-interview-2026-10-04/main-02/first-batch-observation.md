## 3. A 有閱讀，但尚未新增 Memory 引用

e013 的真實工具路徑是：

1. `read_work_understanding` 讀取「庫存與物流行政的核對、登錄與追蹤工作」。
2. `read_work_situation` 讀取「庫存盤點與差異查核」，並讀取既有 JD 任務。
3. 修改盤點任務，新增帳實差異表成果及當次員工輸入依據，並提交一筆既存引用的 `confirm_reference_alignment`；工具結果為 `updated`。
4. 正式答覆保留「盤點頻率稍後確認」，追問差異表是在每次盤點或只有出現差異時整理。

e012 的 JD 有三個任務、40 筆訪談依據；e013 完成後為 42 筆，仍全部是訪談依據，沒有 Memory 依據。因此本次觀察支持「已按需讀取 Memory」，**不支持「已引用 Memory」或「來源都核對完了」**。

e012 的 40 筆來源回查，其來源身分、正式序號、說話者及原文均與已保存訪談一致。這是來源回查的資料一致性檢查，不等於 40 筆都已逐一通過主張支持的語意評分。

兩筆待核對仍保留：e013 已對齊先前的盤點來源，但新增改稿使另一筆盤點來源待核對；另有收貨任務來源待核對。不能只看「待核對數量仍為兩筆」就認定對齊工具沒生效，也不能把讀過內容當成全部核對完成。原件：[e012 JD 與依據](compaction_hierarchical_memory/product-012.json)、[e013 JD 與依據](compaction_hierarchical_memory/product-013.json)。
