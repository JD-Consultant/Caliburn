# 2026-10-04：四組長訪談主實驗執行計畫

本輪執行已確認的四組方法，從空白 JD 分別走完相同 61 段合成員工輸入。先導結果用於設定護欄，不列入主比較。正式產品、現有資料及其他工作均不修改。

目標：比較原生接續／Compaction 搭配不同資料表示，在完整職務訪談中保留精確事實、處理更正並編輯 JD 的實際效果。

方法：[protocol-draft.md](protocol-draft.md)。執行沿用現有 `ConsultantRunner`、B1／B2、工具、交易、官方 saver 與 SDK，不另寫 Agent loop。研究 adapter 只在獨立程序中，於初始 Context 保存前替換本組 App 資料及工具可見範圍；不在 HTTP 外送時偷偷改請求，也不修改正式檔案。以 executing-plans 逐項執行；工程細節依使用者既有自主授權，不新增產品決策或提交。

## 共同條件與停止界線

- Luna／high，`store=false`、`all_turns`、完整原生 items；完整 `compacted.output` 採用。轮前 128K、完整 Step 交界 160K，不降低門檻。
- 每組獨立職務檔案及 PostgreSQL schema；只使用已保留的 `127.0.0.1:55441/caliburn_docker_test`。不清 schema、volume 或正式資料。
- 固定批次在 e012、e028、e044、e052 完成後，以當次正式員工訊息為上界。四組近期預載使用相同批次邊界；三層批次使用真 B1／B2，單層批次自然更新摘要，其他兩組不生成整理產物。各組顧問答覆可不同，固定相同員工資訊與時點，不強迫相同工具路徑。
- 三層／摘要／原話組可使用相同序號回查工具；近期組不提供歷史回查或 Memory 工具。既有 JD 與自身原生接續可能仍保有早期事實，不能把近期組說成完全不知道早期資料。
- 顧問工具移除研究固定批次不使用的 `request_memory_consolidation`；其餘 JD 能力保留。資料方法說明只交代可用來源，四組共用工作分析指引，不為特定組加入答案或強迫有利查閱路徑。
- 整批最多 900 次生成、16 次 compact、2,200 次外送、35,000,000 累計生成／compact 输入 tokens、4 小時。生成单次輸出 16,384 tokens，SDK／研究不自動重試；失敗即保留並停止，不繞過 Runtime 的原有容量檢查。
- 研究本機估算占用上限 US$2：外送前預留，usage 可核對後才改記實測估算；未取得用量保留預留。計數每次保留 US$0.0001 行政預留，不宣稱免費；compact 以 128K 輸出作估算，不宣稱是遠端硬上限。未知用量或拒絕即停止。此護欄不回加產品金額攔截。`main-01` 因研究速率接線問題主動停止，保留 US$0.10 涵蓋該 run；修正後的新比較整批估算上限降為 US$1.90，費用界線不擴張。生成／token／時間上限按新比較 run 記錄，不將兩次執行混作一次結果。
- 全部來源、程式、依賴與判準在第一次外送前保存雜湊及實際研究程式副本。付費執行期間不修改這些腳本；新問題另留停止紀錄，再決定後續切片。
- 若自然 61 段未達壓縮門檻，報告分開呈現「完整 JD 旅程」與「未達壓縮压力」，不降低門檻、填字數或刪原生歷史；有意義的容量擴展另立實驗。
