# 真實訪談、JD 與 Memory 的端到端先導

五輪 Luna/high 訪談及一批 B1 → B2 整理已完成。產物經現行交易保存至隔離 PostgreSQL；A 在第五輪實際讀取發布後的工作情境、工作理解及 JD，再回答早期工作條件。這輪確認接線與計量，尚未執行四組長訪談比較，也沒有發生 Compaction。

## 方法與執行範圍

從空白職務檔案及產品的正式開場開始，依序提交合成員工輸入 e001、e002、e004、e006；各輪使用現行 `ConsultantRunner`、JD 工具與完成交易。第四輪成功後，用該輪員工來源固定整理上界，執行現行 B1 → B2 → 發布，再提交回提問題 e055。員工原文沒有加工，顧問答覆、情境與理解均由模型自然產生，沒有把評分答案放進 Context。

本輪直接使用產品 Workflow／Runner，沒有另寫 Agent loop；研究程序固定在第四輪啟動一批 Memory，不啟動產品的背景監督程序。A 第一輪雖呼叫了整理通知工具，仍只在研究指定邊界整理一次。這是受控批次條件，不是驗證通知排程、HTTP、前端串流或完整使用者操作。

程式基準為 `13c0663a7d42e2e73b5c2ef45d20faa9e1b1fa11`，依賴、工具、指引與實際 Runtime 檔案雜湊保留於 [manifest](pilot-01/manifest.json)。資料庫為 `127.0.0.1:55441/caliburn_docker_test` 的新 schema `eval_compaction_pilot_98547e890534497b88fdfcdaabbe3856`，職務檔案為 `acbc882c-f4ce-43cf-aa7c-ab283c4c1640`；沒有使用正式職務資料。

研究界線及停止條件見 [先導計畫](pilot-plan.md)。本批無 HTTP 失敗、無生成重試；共記錄 23 次依速率資訊等待的事件。全部生成請求均使用 `store=false`、停用截斷並要求加密接續內容。

## 實測用量

| 階段 | 模型生成 | 遠端計數 | 累計輸入 tokens | 輸出 tokens | 最高單次輸入 |
|---|---:|---:|---:|---:|---:|
| A，五輪 | 15 | 19 | 200,436 | 7,757 | 22,072 |
| B1／B2，一批 | 8 | 8 | 41,410 | 3,937 | 7,431 |
| 合計 | 23 | 27 | 241,846 | 11,694 | 22,072 |

耗時 393.7 秒，約 6.6 分鐘；50 次外送都有回應。輸入中 205,860 tokens 由 provider 回報為 cached，輸出包含 6,695 reasoning tokens。累計輸入是各次請求相加，不是某一次 Context 的大小；reasoning 已包含在輸出中，不再重複加總。

依生成 usage 和現行定價計算，生成費用約 US$0.01240；研究准入累計預留為 US$0.22135。前者不是遠端帳單，後者不是實際花費，兩者也都不代表計數端點免費。本批沒有 Compaction 費用或 usage。原始計量、分階段工具次數及檔案雜湊見 [analysis](pilot-01/analysis.json)；逐次請求與回應見 [trace](pilot-01/trace.jsonl)。

這是指定來源的人工逐項核對，不是 51 個事實單位的整體得分。先導未提供 e003、e005 等主資料中的其他來源，因此 e055 完整案例的登錄截止、財務歸屬及退補貨決策等判準不適用本次評分；不因未施測而扣分，也不算通過。

各輪來源序號由成功完成的產品交易分配：e001／e002／e004／e006／e055 的員工訊息依序為 2／4／6／8／10，完整顧問答覆為 3／5／7／9／11，產品開場為 1。結果保存 11 則正式訪談、一個職責及三個任務。JD 的 20 筆直接引用都指向本輪實際員工原文；[第五輪產品](pilot-01/product-5.json)包含逐筆正式來源回查結果，不只引用標籤。

Memory 發布一個情境及一個理解。情境引用員工序號 2、4、6、8，理解引用該情境的固定修訂；[快照](pilot-01/memory-snapshot.json)保存實際內容與選用修訂。整理上界是第四輪員工訊息 8，不是顧問答覆 9，更不包含後來的員工訊息 10。B2 接收情境新增差異，按需讀情境與原話，再建立理解，沒有回交 B1。

第五輪沒有修改 JD，也沒有把原話引用更換為 Memory 引用。A 先呼叫 `read_work_situation`、`read_work_understanding`、`read_jd`，再產出答覆；實驗不能把「A 讀了 Memory」寫成「A 已建立 Memory 型 JD 引用」或「完整來源更新已通過」。正式答覆見 [exchange-5](pilot-01/exchange-5.json)。

## Context 與接續核查

[Context 核查](pilot-01/context-audit.json)以實際請求驗證三條獨立接續鏈（A、B1、B2），核對 20 次接續及 24 筆工具結果。除產品原有的 output 頂層 `status` 投影外，上一請求、完整輸出、訊息 `phase` 及 opaque state 雜湊均在後續前綴保持一致；工具結果依原 `call_id` 與順序接回，沒有未配對工具結果。

五輪起始均為既有原生歷史 → `user` App 參考資料 → `user` 員工原文。App 參考資料包含兩層導覽及近期歷史，未預載 JD map。Memory 發布後，第五輪的新參考資料只帶序號 9 的前問，兩層導覽已是發布產物；員工本次輸入另成一則未加工的 user 訊息。

早期輸入仍存在於 A 的原生接續歷史。因此，本輪不能隔離出「早期原話已不在 Context，只靠 Memory 找回」的效果。這項要求要在合法 Compaction 後核對真正請求，再與其他三組比較；不為製造效果刪除原生歷史。

另以 PostgreSQL 只讀查詢獨立核對：五筆 `consultant_turn` 及一筆 `memory_batch` 都為 `completed`，批次為 `published`、上界 8，正式訪談 11 筆、發布快照一筆。SQL 的 schema 與筆數對照 [完成結果](pilot-01/result.json)及保存原件。此核查證明結果已提交，不代表已做崩潰、暫停或回滾故障注入。

## 本輪發現與修正

| 問題如何發現 | 處理及驗證 | 影響 |
|---|---|---|
| 只讀程式審查指出 DSN 可帶 `hostaddr`／service／options 繞過研究目的地 | 加入明確目的地與參數白名單，拒絕相關 PG 環境覆寫；先看到反例失敗，再通過五項邊界測例 | 只修研究腳本；本次實際使用已確認的隔離 DSN，沒有上述覆寫 |
| 審查發現研究護欄把 128K 誤套到每次生成 | 移除額外拒絕，合法輪前／Step 容量時點仍由現行 Runtime 負責；130K 護欄反例驗證不再先行阻斷 | 已執行程式啟動於修正前，但本批最高 22,072，未觸及該分支；不能宣稱本批真 API 驗過修正後的高容量路徑 |
| 離線整理腳本以 Unix 斜線辨識 Windows manifest 路徑而失敗 | 增補實際 Windows 路徑反例，再修正辨識；重新離線分析成功 | 未重跑生成，原始 trace 不變 |
| 腳本在真模型執行期間接受研究審查修正 | 依啟動前雜湊精確還原已執行原件，保存於 [executed-script](pilot-01/executed-script.json)；雜湊不符就拒絕替代 | 原件標明事後還原，不冒稱事前已凍結；後續正式比較須在外送前完成審查並凍結 |

這些修正沒有變更產品 Prompt、Tool、Runtime 或資料庫結構。離線測試 60 項通過，包含準備、研究護欄、原生前綴／工具配對核查及既有 response loop／step 反例；Ruff、格式及三個研究腳本的 strict mypy 另行核查。完整命令與審查範圍見 [審查紀錄](review.md#端到端先導審查)。

## 主比較接下來要確認什麼

本輪最高單次輸入 22,072，未達 128K／160K 門檻；Compaction 次數為零。接下來以已準備的 61 段來源及相同判準執行四組，凍結整批外送、費用、重試與時間界線，並計入所有 A、整理及查閱用量，不能把本次低容量費用直接線性外推成完整實驗費用。

主比較需要觀察早期數值、更正與補充、跳題及模糊指涉、JD 保存及來源，以及壓縮後實際查閱路徑。若 61 段自然訪談仍未達壓縮門檻，另以有意義的持續工作案例擴展壓力測試，不降低正式門檻、不重複灌入無用文字。機制接通、局部事實保留、完整 JD 品質與四組相對效果分開呈現。

隔離資料與原件保留，不清除 schema 或 volume。確認沒有其他用戶連線後，已停止本輪啟動的隔離 PostgreSQL；正式 PostgreSQL 仍運行。本輪不 commit、push、merge，也未改動正式 PostgreSQL、前後端程序或其他工作中的 Docker／OCS／PDF 修改。
