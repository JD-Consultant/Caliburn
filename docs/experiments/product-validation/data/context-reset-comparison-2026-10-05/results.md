# 中後期訪談換窗比較：結果（2026-10-05）

三組各八段續訪全部完成。**Memory 組不必在起始 Context 放入全部原話，仍能延續時程確認、局部修訂、歧義追問及來源核對；本次累計 input tokens 比完整原話組少 21.0%。**摘要組也完成相同工作，與 Memory 的累計 input 差距僅 1.4%，目前沒有充分理由宣稱分層全面優於摘要。

本批是一次配對案例，不是統計顯著性或超容量勝出實驗。清理重複 App 訊息後，完整原話組起始請求只有 19,838 tokens，105 則原話全部保留；三組都沒有觸發截斷或原生 compaction。這個容量觀察與品質結果同樣保留，不為了製造優勢而削弱原話組。

## 1. 比較內容與完成範圍

沿用同一成功訪談前綴、已有內容的 JD，以及同來源的既有摘要與 Memory。起始 JD 有13項任務、33項成果、47項要求與207筆原話引用；三組在各自的研究資料區，以真正的產品交易修改 JD，正式訪談由105則增至121則。

| 組別 | 起始材料 | 後續按需讀取 |
|---|---|---|
| R：原話 | 全部105則正式訪談 | JD、歷史原話 |
| S：摘要 | 截止104的單層摘要＋近期101–105 | JD、歷史原話 |
| M：Memory | 12個情境、1個理解的導覽＋近期101–105 | JD、理解、情境、歷史原話 |

固定 Luna／high、輸出上限16,384、起始128K與輪中160K界線；同一八段輸入依序續接，組別次序逐題輪換。只有當段員工輸入送入模型，研究判準及未來問題不送入。完整 Prompt、工具、程式、來源及依賴見[凍結清單](prepared-01/manifest.json)，施測前設計見[比較設計](../../2026-10-05-context-reset-comparison-design.md)。

三組工具能力並非完全相同：摘要不是產品可引用的物件，M則可引用已讀的Memory。這是現有產品能力下的方法比較，不是只替換一段文字的純表示消融。本次新日期、門檻與代理分工都來自續訪，不能用舊Memory代替這些新依據。

### 最後核對找到的差別

c02三組都正確修改到貨任務的驗收門檻，但設備任務仍留有「商品驗收不良件數的5%提報門檻」這段無日期副本。c08要求核對相關任務後：

- **S補上日期與新舊門檻；M移除固定驗收5%的副本，改為依適用時期執行。**兩組都保留設備備品本身的5%與主管核准條件。
- **R未讀取設備任務完整內容，仍保留舊副本。**其正式答覆稱未發現矛盾，不能代替保存內容的查核。

c08七項檢查中，S／M均完整；R有兩項錯誤，分別是驗收跨欄一致性與設備交叉描述，其餘五項完整。兩個錯誤指向同一處殘留，不當成兩個獨立失敗，也不拿c08補正後的結果回改c02成績。

三組新門檻均連到本批正式訪談#108，代理分工連到#110；S／M設備修訂亦保留#86並新增#108。原有結案、決策、安全及分母的支持來源仍在。既存「待核對」狀態不等同全部清除，本次未宣稱全稿所有引用已核對。

## 4. 實際讀取路徑

M在c01重讀一次已提供的理解導覽，再讀「庫存與物流行政的作業核對、追蹤與支援」正文；c02–c07沿原生歷史接續，沒有展開情境或原話。c08核對設備交叉描述時，讀原話#86及本批新來源#108、#110。全批不是「完全不讀原話」，而是已足夠時停止展開，對特定核對再取需要的依據。

S在c02讀#8、c03讀#12，c08讀#86、#92及#108、#110。R原已載入全部早期原話，c08另讀本批#108、#110。M沒有新增Memory引用：本批新資訊以新原話支持，原引用保留。讀過Memory、答對與建立Memory引用是三件不同的事。

三組起始JD及共同近期段落已含部分答案，因此不能把每項答對都歸因於Memory。本次可支持的是**導覽→必要正文→延續分析的運作，以及本案例的Context成本差異**；不能隔離證明每個答案只能從Memory取得。

## 5. 可採用結論與下一步

可將本批作為「不必每輪重放全部原話，仍可按需延續分析」的案例證據。保留完整原話作為可追查來源，也保留局部修訂後檢查相關欄位的必要性；三種方法第一次都漏到設備副本，不能把這個問題歸咎於單一儲存方式。

**超容量比較仍未完成。**本批沒有原話截斷、摘要重建或輪中compact，不能替代「容量已滿之後三層是否優於單層」的實驗。下一批若要回答該問題，應先準備足夠且非重複灌水的實質訪談／工具材料，固定換窗點與跨早中晚期判準，再另行核定費用；不接續本批無聲補跑。
