# 早期訪談找回與更正：三組接續比較（2026-10-05）

這是施測前協議，凍結後不隨結果改寫；最新執行情況與結果由[資料包入口](README.md)維護。本批已獲最多 US$0.25／45 分鐘授權，計入累計 US$2，起始累計估算占用 US$1.391700015。

本批補驗：**中後期接續時，能否找回早期精確資訊、辨識已被更正的說法，並在再次改稿後保住未受影響的責任與條件。**不修改正式產品，不重跑前 52 段。

## 1. 共用材料與比較方法

沿用[前批](../context-reset-comparison-2026-10-05/README.md)的第 52 段產品狀態、105 則正式訊息、既有摘要與 Memory。三組各自從相同、已有內容的 JD 開始，不承接前批八題產生的新事實。R 提供可容納的原話；S 提供既有單層摘要＋近期 101–105；M 提供理解／情境導覽＋相同近期資料，正文按需讀取。三組均可查原話、讀寫 JD。

Luna／high、角色指引、工具、128K 起始預算、160K 輪中保險、16,384 輸出上限維持前批設定。每組八段，按題輪換 R/S/M 執行順序；各組承接自己的答覆與工具結果，不把其他組答案交給它。沒有新摘要／Memory 生成，故只能比較既有產物的續用，不聲稱端到端建立成本較低。

本資料包保存前批研究接線的複本，獨立凍結與施測，避免改寫已執行版本。接線僅調整本批判準、入口、費用起算及協議路徑；模型 Prompt 不變。原始資料仍連回同一份有 hash 的原件。資料庫只建立新的 `eval_reset_*` namespace，不啟停服務、不碰正式資料。

### 可見資料與實際取得來源分開

- 每題記錄：初始／本題 Context、近期原話、已读工具、JD、摘要、Memory 各自是否提供答案。JD 仍保有多數舊事實，不為突顯 Memory 而刪去。
- c04 的舊交付日已不在目前 JD 與單層摘要的現行規則中；若需回查原話才能回答，算歷史回查成功，不要求 Memory 一定保存所有已撤換文字。仍逐一核對情境／理解有無舊值，不預設答案不存在。
- 先前題目讀回整份理解後，後題可能直接沿用正文；這是有效接續，但不算另一次獨立的冷啟動找回。八题不是八份獨立樣本。
- `09:10` 與客服窗口仍出現在近期 #105；c07 這兩項只評正確性，不算早期找回。`08:35`、`08:50` 是否仍不在起始輸入，另以實際 request 核對。
- 沒有讀某工具不等於沒有來源；已在有效 Context 的資料可直接使用。反之，引用名稱／工具成功也不等於正文支持答案。
- 舊 opaque items／`previous_response_id` 不重播；本批新產生的 reasoning 照原生契約接續，不能宣稱後續題完全沒有前題資訊。

## 3. 容量結論的界線

目前材料的舊工作請求曾為 144,455 tokens，內含大量舊 App 副本；前批換窗後 R 完整請求只有 19,838 tokens，105 則正式訪談皆可容納。**這證明需要管理累積工作 Context，不證明正式原話本身超容量。**

本批仍先按相同 128K 預算計數，R 放得下就全部保留；不刻意刪早期答案、不降低門檻、不重複填入舊工具資料。若仍放得下，結案列為「換窗後早期取用／更正」，不是「超容量截斷比較」。真正超量原話的受控材料尚缺，留作未施測条件，不以本批替代。

## 4. 判準、用量與停止

每項判為完整／部分／遺漏／錯誤。舊值殘留、權責越界、捏造未知、未受影響條件被刪除分開記錄。c08 最終 JD 複核不與早期題相加宣稱獨立成功率。

保存每次 request／response、實際工具及正文、正式答覆、JD／引用、原生接續核對、input/output/reasoning/cache、计數外送、估算費用與時間。trace 的加密內容遮蔽保存，數量及 hash 可查，不公開內部推理。

每組一遍，不依成績補跑、不臨時改 Prompt。總費用、時間、provider 失敗或未支援的第二次換窗碰到界線就停止，未完成亦列出。本批不需用滿預算；原件保持不可變，結果另寫。只有真實已完成的比較可列結果，不把腳本化驗證當模型品質。
