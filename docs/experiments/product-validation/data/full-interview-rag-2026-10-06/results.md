# 2026-10-06 完整模擬訪談、RAG 與交付結果

本批走完「員工描述工作 → 顧問追問與編輯 JD → 正式保存 → 來源回查 → PDF 匯出」的真模型旅程。25 輪有效訪談形成一項職責、七項任務、三位協作對象及三項共通條件；供應商退貨更正最後也同步到職務目的與職責範圍。公版搜尋與背景 Memory 都有真執行證據。

## 1. 方法與資料範圍

這是單一合成人設、單次產品旅程，不是受控方案比較或真人成效研究。固定人設為不熟悉 JD、只能以日常例子描述工作的物流中心倉庫管理員。使用既有 `gpt-6-luna`／`high`、正式 Prompt／Tool／Context，未替換產品分析方法。

評測者依固定私人事實清單逐題回答，不把完整答案清單送給顧問。14 項事實逐項核對正式員工原話、顧問追問及最終 JD；不以關鍵字命中或 API 200 代替語意判讀。年度盤點在顧問提出收尾後才揭露，另測後續增補。具體方法與凍結基準見 [實驗入口](README.md)，隱藏工作施測見 [觀察協議](hidden-work-protocol.md)。

旅程由 HTTP 驅動既有正式 App，串流、模型迴圈、資料庫交易與發布仍由產品執行；瀏覽器另驗候選、差異及正式畫面。這不是每一輪都從瀏覽器輸入的 UI 端到端測試。人工編修／重播探針另列，不冒充自然訪談行為。

## 4. 這次能回答的產品問題

**不善表達的員工能否逐步形成 JD？** 本批可以：顧問把收貨、盤點、退貨與條件分別追問、保存，能處理「不知道」而不填數字；最後七項任務可回查來源。但知識／技能仍未整理，不將任務清單完整等同所有 JD 分析面向完整。

**公版能否作查漏線索？** 本批確實產生相關追問，且未把未確認內容直接寫成事實；不能據此宣稱 RAG 提高多少完整度，因為沒有無 RAG 對照。兩項暫不主動揭露的工作中，掃描／錯儲位由追問帶出，年度盤點仍須員工補充。

**更正能否跨欄延續？** 最後能更新目的與範圍、保住供應商／客戶分工；但第五次更正先只改任務，摘要殘留直到員工再次指出。這是可重現的改善目標，不以最後補正掩蓋中途不一致。

**顧問能否知道何時停止？** 能在員工無法補答時提出有保留的收尾，之後又接納年度工作；本批未證明可辨識所有尚未透露的責任或自動認證專業完整。這與本次訪談可暫停是不同判斷。
