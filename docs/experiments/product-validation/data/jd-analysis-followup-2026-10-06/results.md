# 顧問 JD 整理指引：新舊對照結果

## 結論

本批支持兩項具體改善：顧問能將已確認的不同工作目的整理成職責，並從員工的日常說法提煉知識／技能、建立任務關係。關鍵澄清是「沒有新增事實，不代表既有事實已整理完」；不是要求每輪改稿或所有欄位必填。最終指引在資訊不足題仍先追問，單一工作題仍維持一項職責並尊重暫停。

這是一次有界、探索性的真模型比較。初版未改善分組與能力提煉，原件照留；之後只作一次指引澄清，再比較兩個問題案例及兩個反例。最終指引沒有重新跑全部七題。年度工作探索、公版查漏後的完整收尾仍需完整訪談驗證，本批不據此宣稱整份 JD 已完整。

## 1. 比較怎麼進行

- 模型固定 `gpt-6-luna`／`high`，輸出上限 16,384；相同員工原話、起始 JD、產品工具 schema 及工具說明。兩組各有獨立的職務檔案、引用與候選，使用真 PostgreSQL、正式 A Runner、原生 checkpoint 及正式完成交易。
- 舊指引取自 `6ec52822ee475876ed20e57d818c8db298c42928`；初版候選是完整顧問指引，最終候選只再澄清既有內容未整理及職責／任務分組的差別。各階段在付費請求前凍結材料、Prompt、工具與程式，不能用目前檔案代替當時版本。
- 七題判準各四項，在外送前固定於 [cases.json](cases.json)及 [holdout-cases.json](holdout-cases.json)。以下依實際答覆、保存後 JD、任務身分及引用判讀，不用提示詞出現關鍵字、工具成功或欄位數量直接判品質。
- 公版連線使用固定的合成回傳；沒有測真實 RAG 搜尋。沒有啟動 Memory 背景工作，亦沒有發生原生 compaction。這些部分不列入本批效果。
- 總計 22 個正式 Turn；分階段交錯新舊，各案例每階段只有一次配對。這是觀察性結果，不估計成功率、統計顯著性或所有職位的效果。

完整操作與研究取捨見 [實驗方法](README.md)。[measurements.json](measurements.json)保存可重算的操作與成品指標；語意判讀由本頁另外說明。

## 2. 初版結果：不把口頭承諾當成已完成整理

此階段包含七題、新舊各一次，共十四個 Turn。下表的「兩組」均指本階段，而非最終候選。

| 案例及原件 | 判準 1 | 判準 2 | 判準 3 | 判準 4 |
|---|---|---|---|---|
| [倉庫職責分組](live-01/regroup_distinct_work-new-after.json) | 兩組未符合：仍只有職稱式總類，沒有實際重組 | 兩組符合：四個原任務身分、內容及直接引用保留 | 兩組符合：每日／月底及核准界線保留 | 兩組符合：沒有補造採購或運輸權責 |
| [跨欄更正](live-01/correct_across_affected_fields-new-after.json) | 兩組符合：目的、職責、任務均更正供應商退貨方向與決策權 | 兩組符合：客戶退貨及每日 15–20 張、拍照、通知採購保留 | 兩組符合：保留內容及更正各有相應原話依據 | 兩組符合：沒有把兩種退貨一起移除；兩組採不同但有效的整理方式 |

| [收尾探索](live-01/probe_before_closure-new-turn-1.json) | 兩組未符合本題預設探查：均轉問例行揀貨細節，未問到低頻面向 | 兩組符合：沒有預告或寫入私人年度事實 | 未執行：年度原話的揭露條件未成立 | 部分：未知未被猜造、未假稱完整；本題後續暫停未執行 |

分組題的答覆即使列出幾種工作，保存後仍只有原總類，就不能算成已完成分組。能力題也不能因為顧問準備追問其他工作，就把空白集合當成提煉成功。這兩類現象促成以下唯一一次修正。

## 3. 最終指引：已有依據的整理不被「沒有新工作」擋住

修正不增加工具或控制流程，只補兩段判斷：已確認內容足以支持某部分，且底稿尚未反映，就可整理；不同責任仍被單一總類包住時，可建立合適職責並移動原任務。資訊不足仍先問、目的相同仍可一組，沒有固定職責或能力數量。

### 3.1 能力提煉

同一題再次新舊配對：[舊版成品](followup-01/derive_and_link_capabilities-old-after.json)仍沒有知識、技能與關係；[最終指引成品](followup-01/derive_and_link_capabilities-new-after.json)實際保存：

| 項目 | 實際內容及核對 |
|---|---|
| 知識 | 「庫存先進先出原則」：理解依入庫先後安排批次出貨的原則。依據為已確認的先入先出做法。 |
| 技能 | 「貨品核對與差異查核紀錄」：核對品名、數量；差異時比對進出貨及儲位、記錄交主管。沒有新增自行改帳權。 |
| 任務關係 | 兩項能力各與原「揀貨並核對庫存」建立一條關係，共兩條；能力定義及關係均有直接來源。 |
| 保留內容 | 原任務身分、正文及直接引用不變；沒有補造品牌、資格、年資或要求員工先用專業詞命名。 |

四項既定判準均符合。此題觀察到的是依已知方法形成可用能力及關係，不是只把欄位填滿。

### 3.2 非倉庫職位的責任分組

[舊版成品](followup-01/group_nonwarehouse_work-old-after.json)維持一項職責；[最終指引成品](followup-01/group_nonwarehouse_work-new-after.json)按不同目的形成：

| 職責 | 移入的原任務 | 保留內容 |
|---|---|---|
| 客戶使用問題處理 | 回應客戶使用問題 | 每日、查訂單與操作紀錄、處理不了交技術、不決定退款 |
| 客訴資訊整理與回報 | 整理每週客訴資料 | 每週五、類型與件數、未結案清單、主管決定改善、不分派工作 |

實際呼叫 `move_jd_item` 兩次，兩個原任務的 ID、正文與直接引用全部保留，空的總類被移除。另產生兩項有原話支持的技能、各連到適用任務，未為填表硬造一項知識。四項既定判準均符合。

此題初輪是未用於初版調整的保留例，但後續已用於修正觀察；這次成功是探索性補驗，不再稱為未見資料驗證。能力題及客服題的最終候選亦沒有重複多次估計穩定度。

### 3.3 反例回歸：仍可不改稿、仍可一項職責

Prompt 不再修改；在同一剩餘界線內，新舊各驗兩題。

| 反例及最終指引原件 | 保存後結果 | 四項既定判準 |
|---|---|---|
| [資訊不足](regression-01/insufficient_without_forced_edit-new-turn-1.json) | 問最近一次系統問題及本人實際做法；沒有編輯工具呼叫，正式 JD 修訂不變，未呼叫公版工具 | 均符合：有焦點、未猜工作、保留既有內容、未用公版推定 |
| [單一工作](regression-01/keep_coherent_single_area-new-after.json) | 仍一項「出貨前核對」；只補回原話已支持的「依單」，保留下午三點、重掃／核標籤／記錄交主管及不負責事項；[正式答覆](regression-01/keep_coherent_single_area-new-turn-1.json)尊重暫停 | 均符合：不強拆、保留身分與細節、不增造工作或必填能力、合理暫停 |

兩題舊指引亦符合。這裡支持的是修正沒有在這兩個反例中造成硬改稿或硬拆，不宣稱新增指引在所有邊界情境均無回歸。

## 4. 工具、來源及耗用

22 個 Turn 均完成並保存正式答覆與 JD；實測沒有 HTTP 失敗、工具拒絕、未回報費用預留或 compaction。引用狀態由正式產品計算，仍另讀正文及相應原話判斷語意，不能只靠 `needs_recheck=false` 判品質。

最終四個候選 Turn 的原任務身分與原直接引用全保留。能力與客服兩題的原任務正文也不變；單一工作題正文有所補充但已知條件與權限仍保留。初版更正題則移除不再適用的舊任務來源並加入更正原話，這是合理替換，不以「所有舊引用保留」作為更正通過條件。初版舊指引的收尾題另有一筆待核對來源保留；未把改稿直接當成所有引用已對齊。

| 階段 | 正式 Turn | 輸入 token | 輸出 token | 其中推理 token | 護欄占用估算 |
|---|---:|---:|---:|---:|---:|
| [live-01](live-01/result.json) | 14 | 614,884 | 26,401 | 20,314 | US$0.030637010 |
| [followup-01](followup-01/result.json) | 4 | 314,699 | 11,964 | 8,520 | US$0.014475330 |
| [regression-01](regression-01/result.json) | 4 | 142,625 | 4,338 | 3,526 | US$0.005332320 |
| 合計 | 22 | 1,072,208 | 42,703 | 32,360 | US$0.050444660 |

這是多次請求的 usage 加總，不是單次 Context 容量；推理 token 已包含在輸出 token，不能再加一次。快取輸入共 987,186 token，cache-write 輸入共 84,764 token。共 86 次生成及 86 次計數；生成的本機 token 金額估算 US$0.041844660，另有計數請求護欄估算 US$0.0086。護欄占用不是供應商帳單實收。所有階段共用最初 US$0.10／20 分鐘上限，接續不重置時間或預算。

本批優先驗已保存內容與正確選擇，不主張降低 token 或呼叫數。客服整理確實用了更多修改操作；後續若優化耗用，仍需保留分組、能力及來源的品質。

## 5. 可重現資料與仍需驗證的範圍

各階段 `manifest.json` 保存 fixtures、Prompt、工具、程式雜湊與時間／金額界線；`sources.zip` 保存凍結程式與材料；`trace.jsonl` 保存去敏外送、回應與工具路徑，opaque reasoning 留雜湊而非正文。`*-turn-1.json` 是正式對話，`*-after.json` 是保存後 JD 與引用；`*-turns.json` 保存該配對的回應及使用量資訊。這些原件沒有因後續修正而改寫。

最終候選只對能力、客服分組、單一工作及資訊不足四題驗證；倉庫四項責任分組和跨欄更正未在最後兩段澄清後重跑。初版跨欄更正兩組均成功，不能將這點寫成最終候選已取得新增改善。收尾題沒有揭露年度工作，故年度整理與其後暫停未驗；本批也沒有實際執行公版查漏到收尾的完整旅程。

下一個有價值的驗證是既有完整訪談上的一次有界接續：核對職責／能力隨回答逐步形成，再檢查周期與低頻線索、公版的選用時機及無重要缺口時的收尾。這是後續驗證方向，不是本批新增付費或 Docker 切換授權。

離線接線與契約的最終驗證命令、結果記於 [實驗方法](README.md#本批結案與原件)。離線測試、靜態審查、真模型局部比較與完整訪談品質分開判定。
