本批接續[局部對照](../jd-analysis-followup-2026-10-06/results.md)，驗證新指引在完整訪談中的表現。使用正式 App 的 HTTP、模型執行、背景 Memory、真公版 RAG、來源回查及 PDF；不另建 Agent loop，不改 Context 政策或正式服務。

## 授權與隔離

- 固定 Luna／high、正式輸出上限、同一倉庫員工人設。新 App 使用 loopback 8107、獨立 schema `jd_analysis_full_20261006`；既有 8105／8106、資料與程序不變。
- 沿用既有實驗映像的依賴、字型與 Chromium；正式後端從本批 `freeze/sources.zip` 載入。既有公版索引只查詢，不建立、覆寫或刪除。
- 不切換產品、不新增議程或輪前摘要、不提交／推送／合併。其他工作中的候選設計不納入這次 Prompt。

## 固定資料與揭露方法

員工私有資料為 `apps/api/tests/fixtures/job_analysis_quality/personas.json` 的 warehouse；完整檔案、提示及工具保存於凍結包，不能把私有判準送入模型。評估者逐题扮演不懂 JD 寫法、表達簡短的員工，只回答当前問題；不告訴顧問應有幾項職責或要求填滿欄位。

開場與原旅程相同。第五次成功的員工輸入提供原定供應商退貨更正，並回答當前問題；保留其他未受影響的事實。早班七點、十五公斤、先進先出、月底全倉等按相應問題揭露；主管容許差異的數字保持未知，不編出比例、ERP 品牌或新的作業規定。

年度十二月盤點、堆高機證照、掃碼檢查及促銷高峰先不主動說。顧問詢問相關少見工作、週期、工具、安全、查錯或風險時才回答。若顧問在年度工作未揭露時收尾，先保存該收尾為涵蓋觀察，再以員工想起漏談的補充單獨測接續；不能算顧問自行發現。

## 判讀方式（外送前固定）

| 面向 | 成功依據 | 不算成功 |
|---|---|---|
| 訪談深度 | 問清實際操作、交付與責任，不等義重問無答案的未知 | 輪數多、固定問卷長 |
| 職責分組 | 已確認可區分的工作按目的／責任合理分組，既有任務及來源保留 | 只在回覆列出分類、硬拆每個動作 |
| 知識技能 | 從實際工作分析出有依據的知識／技能，與相應任務連結 | 填空式人格或無據能力 |
| 更正 | 供應商決策權的更正反映任務、職責、職務目的；未受影響細節保留 | 最後一句正確但其他欄仍錯 |
| 公版及收尾 | 已談主要工作充分處理後查公版；否認不當事實，未知不當沒做，能合理收束 | 呼叫搜尋就宣稱完整、所有公版項目都問 |
| Memory | 背景發布與固定來源回讀正常；A 自然選讀足夠的理解可直接用 | 要求模型引用 Memory 後假稱自然行為 |
| 來源核對 | 固定正文／新舊 diff 可回查；有待核對不因閱讀自動清除 | 批次讀取就當已核對 |
| PDF | 正式稿可匯出且中文字、版面及主要內容可讀 | API 200 或檔案非空 |

14 項人設事實逐項人工核對「已揭露／顧問探索／JD 反映／未確認」；已揭露涵蓋率與全部私有工作涵蓋分開。舊 25 輪旅程只作描述性基準；兩次為適應性訪談，不能當相同輸入的隨機對照或單獨歸因於 Prompt。

## 執行與證據

薄接線 `probe.py` 重用原 `journey.py`／`source_probe.py`；`guarded_app.py` 重用已測的 `BatchGuard`／`GuardedTransport`。凍結、隔離啟動與配置使用 `prepare.py`，原始 trace 不改寫。準備是配置驗證，不稱為新產品 TDD。

依序：凍結與護欄離線測試 → 真 RAG 預檢 → 建立空白檔案 → 逐題訪談 → 自然收尾觀察 → 來源／Memory 回查 → 單獨的人工編修差異及原命令重播探針 → 正式 PDF → 保存用量、判讀及限制。途中有界停止時也保存已完成與未完成部分，不因未出現結果檔另啟付費程序。
