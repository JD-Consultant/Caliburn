# 新顧問指引：倉庫完整訪談驗證結果（2026-10-06）

## 結論

本批走完「員工逐題回答 → 顧問編修 JD → 背景 Memory → 公版查漏 → 來源核對 → 本次訪談收尾 → PDF」。新指引將已確認工作整理成四項職責、六項任務，提煉一項知識及一項技能，並與收貨任務建立關係。年度盤點由顧問追問帶出，不是收尾後由員工主動補寫；供應商退貨的決策權也反映在職務目的、任務及要求中。

最後兩輪確認收貨差異處理是例行責任，顧問明確核對三筆既存依據，並同意員工本次先結束，保留答不出的細節。這支持已有工作能逐步成文、回查及交付；不等於所有未透露工作都已發現。冷藏環境、錯儲位案例及旺季風險仍未被問出，不能把「本次可先結束」當成整份職務的完整認證。

本批共 17 輪有效員工／顧問訪談，最後模型回應在原截止前完成。58 筆直接來源均可回查，九版 Memory 的固定引用鏈檢查無不一致；正式 PDF 為三頁 A4。實驗 App 已停止，資料與原件保留，既有 Docker 及正式產品未更新。

## 1. 方法與有效範圍

- 固定 `gpt-6-luna`／`high`、16,384 輸出上限、同一倉庫員工人設，從空白檔案開始。使用正式 HTTP、Runner、交易、checkpoint 與背景 B1／B2；沒有另造 Agent loop。
- 使用 [外送前方法與判準](README.md)。評估者扮演不懂 JD 寫法、回答簡短的員工，只按當前問題揭露人設事實。完整私有人設、事實代號及判準沒有送給顧問，也未要求顧問拆成固定數量或填滿知識技能。
- 後端與 Prompt 凍結於最初 369 檔及首次付費前補凍的 39 個 JSON／HTML 資源。[最終量測](closed-measurements.json)核對全部檔案雜湊。A 與公版指引組合 SHA-256 為 `baf54b3fffd897cc1891767985e5fb2e5aa78f5a69306f706d930e5b2b8fad23`，兩次接續均未換 Prompt。
- 使用隔離的 8107 App、`jd_analysis_full_20261006` schema 及既有唯讀公版服務。前端沿用實驗映像的靜態建置，沒有測新增前端改版；新議程、輪前自有摘要及候選 B2 粒度調整不在這次執行內。
- 舊 25 輪旅程是描述性基準，不是同輸入配對對照。兩次顧問追問不同，員工揭露時點也不同；因此比較具體成品及發現方式，不計算 Prompt 的因果提升率或全職位成功率。

## 4. 讀取與核對：分開模型行為及 App 保證

### 4.1 Memory 有被用，但沒有直接作 JD 引用

A 共讀一次理解正文，用來判斷收貨差異究竟是例行工作或單次事件；另有六次原話讀取。背景整理自己的讀取不混算成 A 的查閱。最終 58 筆 JD 直接引用全部是訪談，不能把這次寫成「JD 已自然引用 Memory」。

九版 Memory 各選用一個情境與一個理解，鏈路一致性核對包括身分只選一個修訂、下層引用落在所選修訂及原話不超過發布範圍。最後快照覆蓋至正式序號 24，正式訪談已到 35；25–35 仍在原話中，尚未再發布，並非資料遺失。這支持發布保存行為，不代表所有正文已作完整品質評分，亦不證明粗粒度理解的選讀效率。

### 4.2 看過差異與提交核對是兩件事

第二次費用停止時，三筆自然待核對在讀正文／差異後保持不變。獨立人工探針再把「七點」改成「7點」，待核對由三筆變四筆；讀取、同命令重播也未解除。

接續第 19 次，A 在 `revise_jd_item` 明確提交三個 `confirm_reference_alignment`：收貨任務的兩筆既存引用及技能關係的一筆引用，並補入本次原話。最終只剩人工時間探針的一筆待核對。這是實際核對操作，不是讀取自動清除，也不是根據工具名稱總數猜測。trace 中 15:48:50 UTC 的兩個修改呼叫可重算這段操作。

公版搜尋／讀取雖有實際執行，但沒有使用公版選用集合及排除範圍更新操作；`selected_reference_ids` 仍為 null、排除集合仍空。否認與未知的內容處理有觀察，不能說所有公版管理功能都已自然使用。
