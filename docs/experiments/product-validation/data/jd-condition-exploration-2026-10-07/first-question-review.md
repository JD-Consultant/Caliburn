# 首輪問題與反例判讀

八案、新舊各一次，共 16 次有效顧問回覆。由工程代理依凍結判準逐案檢視正式答覆、JD 保存結果與外送 trace；不是真人盲評，也不是完整職務訪談的成功率。首輪問題與後續接續分開判讀。

## 指定探索面向

| 案例與指定面向 | 舊版實際下一問 | 新版實際下一問 | 首輪是否觸及指定面向 |
|---|---|---|---|
| 收貨上架的環境 | 除了收貨上架，還負責哪些工作 | 除了收貨上架，還有哪些工作 | 兩版皆未觸及 |
| 上架的常見差錯 | 上架以外的其他工作／周期工作 | 上架以外的其他工作／特定時段工作 | 兩版皆未觸及 |
| 收貨的負荷變化 | 通知差異後是否追蹤或暫放貨物 | 採購未決定時，該批貨如何處理及本人分工 | 兩版皆未觸及 |
| 帳務核對的常見差錯 | 報支以外的帳務或行政工作 | 報支以外的例行或低頻工作 | 兩版皆未觸及 |
| 軟體維護的負荷變化 | 如何判斷前端或後端問題 | 無法重現或判斷前後端時怎麼處理 | 兩版皆未觸及 |

倉庫三項的首輪指定面向為兩版各 0／3；加上兩個非倉庫案例為各 0／5。這是「是否在下一問觸及指定面向」，不是整段回答毫無價值。工作範圍、異常責任與技術判斷仍是合理分析問題；本批不能據此判定所有面向都已探索或整份訪談必然漏問。

原問句見 `live-01/<case_id>-<arm>-turn-1.json` 的 `exchange.consultant_reply.interview_text`。例如環境案新版問「除了收貨上架，平常還有哪些工作會由你負責或常有人找你處理？」；負荷案新版問的是差異貨物等待決定時的處理，不能計為問到旺季。

## 三個界線反例

| 反例 | 舊版 | 新版 |
|---|---|---|
| 環境、工作量及常見問題已確認 | 明確不重問上述條件；另確認其他工作範圍 | 不再追問，整理已知內容並給核對機會 |
| 堆高機適用作業已換問法仍答不出 | 保留未知，轉問入庫登記依據／內容 | 保留未知，轉問入庫登記依據／內容／位置 |
| 員工明確要求本次停止 | 不再追問，不宣稱已確認所有工作 | 不再追問，不宣稱已確認所有工作 |

兩版各 3／3 沒有違反這三個預定界線。不把較少問題或沒有改稿視為低品質，也不因界線通過就宣稱探索能力已改善。

## JD 與輸入邊界

- 首輪私人答案均未揭露，兩版 JD 均未寫入本批隱藏的冷藏、錯儲位、旺季、重複發票或版本上線尖峰。五種情況的揭露後整理與引用尚未受測。
- 新版在穩定條件案將既有辦公環境及穩定負荷另列；舊版改寫任務後，這兩項沒有留在任務正文或條件集合中。這是本次成品核對的附帶發現，不新增為原主比較判準，也不宣稱新指引普遍解決細節保留。
- 核對每案首次生成請求：16／16 的原生 input 不含 case ID 或完整私人回答。模型收到 App 組裝的近期原話及當前輸入；判準與私人回答只供評測。沒有啟動背景 Memory，公版工具使用固定合成 HTTP 資料，不驗真 RAG。

## 執行與用量

首輪正常完成，沒有 failure、停止原因或未知用量預留。每組的累計 input 包含多次工具接續，並非一次請求的容量。

| 項目 | 舊版 | 新版 |
|---|---:|---:|
| 有效顧問回覆 | 8 | 8 |
| 生成 API 次數 | 36 | 17 |
| 累計 input tokens | 511,252 | 224,168 |
| output tokens（含推理） | 20,746 | 8,851 |
| 其中 reasoning tokens | 15,873 | 6,344 |
| cached input tokens | 475,589 | 202,704 |
| 費用估算占用（含計數呼叫） | US$0.023184065 | US$0.010834265 |

合計占用 US$0.034018330、528.97 秒；53 次生成、53 次輸入計數、0 次 compaction。已回報 token 的文字單價估算 US$0.028718330，計數呼叫估算 US$0.0053；這不是帳戶實際帳單。原件為 [result.json](live-01/result.json)、逐案 `*-turns.json` 及 `trace.jsonl`。

新版的讀寫次數較少，但部分案例也沒有補上舊版完成的成果、知識技能或分組，不能把低用量單獨宣稱為等品質效率改善。本題仍以是否找到條件、保持事實界線及適時停止為主要結果。

## 下一步的界線

用同批剩餘時間／費用接續三個倉庫案例，先回答工作範圍或異常分工，再觀察下一問；見[接續計畫](continuation-plan.md)。這是首輪之後才決定的探索性階段，不更改首輪 0／3、0／5 的結果，也不偷偷把私人答案塞進對話。
