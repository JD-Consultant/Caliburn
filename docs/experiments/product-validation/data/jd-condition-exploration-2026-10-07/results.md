# 工作條件探索：對照結果

**補清指引後，仍未穩定把正常流程的訪談延伸到環境、常見差錯與負荷條件。** 八對首輪正常完成；再沿三個倉庫案例接續六次，新版在上架案例開始追問旺季負荷，但兩版都未問到各案指定的私人面向。不能把本批視為三項漏問已解決，也不能把合理的其他追問當成毫無價值。

本批已結案，共 22 次有效顧問回覆，估算占用 US$0.057300990，約 14.51 分鐘，低於使用者確認的 US$0.10／20 分鐘。沒有限流、執行失敗、護欄停止或未知用量預留；不使用剩餘額度繼續試提示。不修改運行中的 Docker，也未 commit、push 或 merge。

## 1. 固定條件與資料

採 `gpt-6-luna`／high、16,384 輸出上限。首輪每案新舊各一次，同一份可見員工說明、起始 JD 與工具；舊提示取前批凍結包，新提示取已確認的本機修改。沒有替換正式 Runner、工具契約、Context 組裝、來源或保存流程。

案例、私人回答及判準在外送前凍結，見 [cases.json](cases.json)、[private-answers.json](private-answers.json) 與 [live-01/manifest.json](live-01/manifest.json)。種子回覆是 fixture，公版 HTTP 使用固定合成資料；未啟動 Memory 背景外送，不作真 RAG、超容量或完整訪談品質結論。首次請求 16／16 的原生 input 不含 case ID 或完整私人回答，兩版 Prompt、工具及正式程式均有凍結副本與雜湊。

顧問回覆由工程代理依固定語意判準檢視，不是關鍵字自動判分或真人盲評。每案只有一對，不能估計一般成功率；[首輪判讀](first-question-review.md)保留每案實際問法、反例與用量。

## 2. 首輪的主要結果

| 觀察 | 舊版 | 新版 |
|---|---:|---:|
| 三個倉庫案例，下一問觸及各案指定的環境／常見差錯／負荷 | 0／3 | 0／3 |
| 加上帳務差錯、軟體維護負荷，下一問觸及各案指定面向 | 0／5 | 0／5 |
| 穩定條件、已知未知、員工停止三個界線反例，未違反預定界線 | 3／3 | 3／3 |

環境、上架差錯及帳務差錯案先轉問其他主要工作；收貨負荷案先問差異貨物的處理責任；軟體維護案則問技術判斷或無法重現問題的做法。這些問題具有分析價值，但沒有觸及本批所測的面向。明確停止的兩版都沒有追加問題；堆高機適用作業答不出時，兩版都保留未知並改談其他資訊。

## 3. 回答工作範圍後的接續

看到首輪行為後，追加[接續計畫](continuation-plan.md)與[同份固定回答](continuation-inputs.json)：環境、差錯案確認目前工作範圍，負荷案回答差異貨物待決的責任界線。新舊各沿原檔案及原生歷史續一次，不重建、不重跑；費用與截止沿用原批剩餘界線。這是事後追加的探索性階段，不修改首輪判準或分數。

| 案例 | 舊版下一步 | 新版下一步 | 能支持什麼 |
|---|---|---|---|
| 環境 | 問核對到貨所用的資料 | 問品項不符時如何處理 | 兩版仍先補流程或異常分工，未問場所條件 |
| 上架差錯 | 問準備、整理或交班收尾工作 | 問上架量是否在一天中或旺季增加，以及安排／時限／核對是否改變 | 新版確實探索一項未談的負荷條件，但未問該案指定的常見差錯 |
| 收貨負荷 | 補寫差異留置後停止追問 | 補寫差異留置及盤點後停止追問 | 兩版仍沒有探索負荷變化 |

新版在上架案的原問句為：

> 一天當中或旺季時，上架量會明顯增加嗎？如果會，工作安排或完成時間通常有什麼變化？掃描核對和入庫登記的做法會維持一樣嗎？

這是一個中立、帶條件的探索問題，並未宣稱忙季一定存在；但一次問了量、安排、時限與核對做法，對不善表達的員工仍可能有回答負擔。問題與回答見 [新版上架案](live-02/warehouse_errors-new-turn-1.json)。其餘原件存於 `live-02/<case_id>-<arm>-turn-1.json`。

到接續結束，兩版仍未取得各案指定的私人回答。環境、錯儲位、月底／促銷負荷等後續回答沒有注入；因此本批**未驗到揭露後的 JD 整理與新來源引用**。不能把單一案例轉問負荷，改寫成三項隱藏條件全部已問出。

## 4. 問題定位與下一步

保存的 input 說明原話確實可見，隱藏條件則從未提供；不是已知資訊被 Memory 遺忘。單純加列分析面向，尚未明確改變顧問如何判定「這項工作已足夠清楚」：即使確認工作範圍，仍可能優先追流程細節，或補完異常分工後直接停止。

下一個候選應聚焦**選下一問與結束深入的同一個判準**，而不是再堆冷藏、倉庫或其他職業的例子：

1. 區分「正常流程已知」與「影響執行的重要條件已處理」。只在相關且尚未處理時，選一個會改變工作要求的條件，中立地問一題。
2. 在轉題或收尾時，沿用已確認答案；已問仍答不出或員工要求停止的部分不再追問。不要求每項工作問遍全部面向。
3. 合併 Prompt 中重複的轉向／收尾表述，避免「工作足夠清楚就轉向」和「正常流程清楚仍須探索」各自被理解成不同的完成標準。不新增角色、問卷、資料表或程式 gate。

以上為本批之後的候選修訂方向，不是已查明的唯一因果，也沒有在本批中途替換提示。正式方法仍由[訪談校準指南](../../../../guides/2026-09-09-customized-jd-depth-and-interview-calibration.md#正常流程清楚仍須辨認尚未探索的條件)維護。後續若修改，應另定包含「輪廓已確認」與「不應再問」的固定對照，先驗這項判準，不重跑整份長訪談碰運氣。

附帶發現：穩定條件案舊版局部改寫後，原有辦公場所及全年穩定負荷未留在任務或條件集合；新版有保留。這項內容保留問題另列在首輪判讀，不用來補算探索分數。新版較少讀寫也不能代表等品質效率提高，因部分已知成果或能力只由舊版補入。
