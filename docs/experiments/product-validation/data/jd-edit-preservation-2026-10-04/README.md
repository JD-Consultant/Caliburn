# JD 局部改寫的有效資訊保留：配對實驗

## 研究問題

上一批退貨任務核對出現兩種不同現象：交表期限從描述移除，但仍在成果與要求中保留，可能是合理去重；另一份提案則讓「報廢待核准」從整項任務消失。本批比較一段明確的 JD 改寫指引，是否能改善後者，同時不妨礙精簡、可靠更正及不需改寫的情況。

本批已結案：20 格交付，新增指引未顯示穩定改善，暫不採用。結果見 [配對判讀與用量](results.md)，逐格判讀見 [semantic-review.md](semantic-review.md)。原判準、指引、模型輸出及失敗紀錄均保留，不因結論而回改。

這是受控的改寫實驗，不是三層 Memory 的因果比較，也不是正式產品交易、來源對齊或完整訪談驗收。過容量長訪談與單層摘要的比較留待下一階段。

## 固定條件與唯一變因

- Luna／high、OpenAI SDK 3.20.0、相同研究提案工具及正式唯讀工具。
- 原材料沿用上一批的合成訪談／Memory 匯出，不使用員工私人資料。
- 每格從空白開始，提供一項 JD 的完整相關欄位與同一份理解正文，讓事實可取得的條件一致；本批刻意隔離改寫，不以此代表正式產品每輪會預載理解全文。
- 舊版採上一批凍結的指引。兩版共同補充「理解正文已提供」的研究說明；新版只在 JD 撰寫區新增一段有效資訊保留與更正規則。不改來源、工具、推理強度、輸出上限與提交契約。
- 只有去重格及數值格注入明確記錄的 JD 初稿變體；原始訪談、Memory 正文不改。變體只在案例組裝時套用，同一案例的兩版輸入完全相同。

五類案例為責任更正、合理去重、已更正期限、數值與例外界線、已正確而不需改寫。每類兩版各兩次，共 20 格。首輪舊→新，次輪反轉案例及新→舊順序；這是有限重複，不能當作統計顯著或普遍效果。

## 判讀方法

`cases.json` 在外送前固定，每格四項語意判準。評估的是提交後整項任務，不是只看被改的欄位：允許資訊移到適用的成果／要求中，不要求照抄同一句話。

同時核對修改目的、期限與數值的適用範圍、狀態、責任界線、相反陳述及直接來源。只讀過來源或 API 成功不算品質通過；語法／邊界接受與語意正確分開記錄。沒有交付的格子記為未交付，不把中途工具回傳當成模型已使用。

案例答案與判準不放入模型輸入。若改寫超出已提供欄位／任務，另記範圍違反。逐格保存初稿、提案、修改後內容、trace 與判讀理由；原件不回改。另列模型呼叫、原話／Memory 讀取、input/output tokens 與本機估算占用，不能以少讀取直接代替品質改善。

## 執行界線

使用者已同意本批新增最多 US$0.05／15 分鐘，計入原累計 US$2。先前占用 US$1.104918450。沿用既有研究 runner 的 32 次生成／64 次外送全批護欄、每格六次生成及 8192 output tokens 上限；時間自首次付費階段開始計算。達任何界線停止，不重跑、補格或改判準。

金額是既有官方單價換算的本機估算與未決預留，不是帳單。輸入計數請求仍採既有保守預留，不當作已知帳單費用。研究界線不新增正式產品金額攔截。

本批不寫正式 JD、不更動產品指引或資料庫、不啟停示範服務、不 push／merge。通過改寫比較後，才考慮正式工具短旅程；若無改善，保留反例並分析，不直接採用新版。
