## 3. 單段替換的精確內容

對象為 [`instructions.py`](../../../../../apps/api/src/caliburn/agents/job_consultant/instructions.py) 的 `CONSULTANT_INSTRUCTIONS`、〈訪談與工作分析〉下第二個 bullet。只對隔離副本做一次替換，production 檔不改。下列字串採 UTF-8、無 BOM、LF，皆含一個結尾 `\n`；不要以 Markdown 換行或平台 CRLF 自行重建 bytes。JSON `\n` 是換行表示，不是傳給模型的字面反斜線。

替換前完整字串：

```json
"- 依回答逐步釐清本人動作、工作對象、觸發與輸入、判斷依據、產出及用途、完成要求、\n  自主權限、交接和責任界線。優先問會改變責任、範圍、重要要求或專業判斷的缺口；\n  抽象說法可請員工舉最近實例，再區分正常做法與例外。\n"
```

315 bytes；SHA-256 `dfd5877a441bac1c8d9a6ef44fa382de7fa6b08da32756d6f62130d624157047`。2026-10-07 準備時該段位於檔案 bytes `[2140, 2455)`，出現一次；位址僅為當次定位，凍結時以內容及雜湊核對，不依固定 offset。

替換後完整字串：

```json
"- 依回答逐步釐清本人動作、工作對象、觸發與輸入、判斷依據、產出及用途、完成要求、\n  自主權限、交接和責任界線。選下一問時，在目前可問的缺口之間比較：\n  員工給出不同答案，最可能使哪一項責任、範圍、重要要求或專業判斷的理解改變？\n  優先問影響較大且員工能具體回答的一題。抽象說法可請員工舉最近實例，\n  再區分正常做法與例外。\n"
```

471 bytes；SHA-256 `4b637e64fab0cf20431770cde83958a9bd04d96a0fb99766e8734ad002a939c3`。

新句的差異是 **對不同問題的可能答案作相對比較**，不是再次提醒環境、差錯或負荷，也不給指定答案、指定問題順序、分數或必問數。它可能仍只讓現行原則更明確；若外顯行為沒有差異，本測法不能宣稱模型新增了策略，更不能證明隱藏思考過程。凍結時比對整份兩組 instruction bytes，只允許這一段不同；其餘指引、公版提示、共同 `FOCUS_INSTRUCTIONS` 與全部工具相同，規劃筆記能力兩組都關閉。

## 4. 小型配對協議

### 固定起點與樣本

六個 case、兩個 arm、各兩個獨立 repeat，共 24 個首段。B0 為本輪凍結的現行指引＋共同焦點；B1 只套 §3 替換。模型固定沿前批 `gpt-6-luna`／high、輸出上限 16,384；若主代理發現原授權指定其他型號，凍結前修訂本候選，施測途中不換。

三個探索 case 沿既有 `warehouse_environment`、`warehouse_errors`、`warehouse_load` 的可見原話、JD 與 [case-overrides.json](case-overrides.json)。原件只讀；在新子目錄保存複本、來源雜湊及新 manifest。兩組每個 repeat 從相同可見 prefix、起始正式 JD／來源、空 Memory 開始，App 產生各自獨立檔案及資格，不移植另一組答案或 native checkpoint。沒有重新跑舊訪談來生成不同起點。

三個界線 case 的可見輸入在新 probe fixture 中完整凍結：

| case | 固定起點／新合成原話 | 判讀界線 |
|---|---|---|
| 已知未知 | 複用既有 `unknown_is_not_unexplored` 的全段可見原話／起始 JD；該項已換實例仍答不出，員工說其他事情可以試著說。 | 不等義重問堆高機適用作業、不寫成不存在；可選另一個有價值問題。 |

新增界線 fixture 是明示的合成資料，不冒充前批實測內容，也不改原 `cases.json`。全部六案的 criteria、case ID、private-answer 與 arm 標籤不送顧問，工具／公版 fixture 不帶 oracle；只送實際可見原話及 App 資料。凍結前檢查每個實際首次 request，連片段答案、判準描述及目標代號都核，不能只搜尋完整答案字串。

同 case／repeat 的先後順序交錯：repeat 1 B0→B1，repeat 2 B1→B0；case 排程在首次外送前凍結。repeat 不挑結果，也不重跑已成功首段。

### 有界接續與回答

探索案每格最多三段：首段選問，必要時回答後再續一段；第二段才觸及目標時可再答一次以觀察入稿。三個界線案每格只取一段。故上限為 `3 探索 × 2 arms × 2 repeats × 3 段 + 3 界線 × 2 arms × 2 repeats × 1 段 = 48` 有效顧問回覆。

人工回答者持有與兩組相同的 private answers／reply policy。只有顧問問句的語意確實涵蓋該私人面向，才給相應答案；其他合理題依凍結已知內容回答，無資料則說未知。不得為命中目標主動補三項，也不得在某組先收尾時強行塞答案。用同一條件政策保持公平，而非強迫兩組每輪取得同一答案。每次記原問句、回答選擇、理由及送出前凍結時間，兩組各沿原 HTTP 檔案、正式原話、原生歷史接續。

使用正式 HTTP／Runner／工具／完整答覆提交、正式 JD 與來源保存；不直接呼叫模型替代正式保存。既有公版採兩組相同合成 fixture，Memory 起點相同、不啟動背景生成，因此不稱真 RAG 或 Memory 品質驗證。原 harness 不改；需要的薄接線只放新 probe 子目錄，先離線核凍結、隔離與用量接續。

### 品質判讀與停止

先封存全部有效輸出，再按遮蔽 arm／repeat 的輸出包判讀；case 的可見事實及預先凍結目標仍供評估者，對照身分由主代理另外保存。不能以盲評主線八場的結論調這一版候選或重新選三案。

各格分開報：首問是否中立涵蓋目標面向；最晚哪段取得回答；取得後是否有據反映在適當既有任務／要求／全職務條件，保留限定及來源；是否保留舊內容；不必要追問／一問多題負擔；界線是否通過。其他合理問題另列，不用指定目標否定其價值，不以問到「忙閒」替換環境／差錯指標。

三項未取得回答就記未取得，該格的揭露後入稿記不適用；不把來源非空、工具成功、空筆記、少 token 或收尾用語當品質完成。保留搬運十五公斤及資格要求、品項／儲位界線、採購收退責任、每日／月底／十二月盤點差異；局部條件不機械立新任務。

本次只能形成描述性先導：候選若跨兩個 repeat 改善目標探索／取得回答、沒有界線與既有內容退化，才值得後續驗長訪談；不直接採用。若未改善、靠更多無效追問才取得、帶答案或界線失敗，停止這一候選，不在本批中途修提示或追加例子。即使通過，不能由此聲稱所有職位或全部三項必然能問出。
