# 首段選問與接續判讀

以下依外送前的 [protocol.md](protocol.md) 人工語意判讀。五個探索案各有指定面向；問到其他有價值的缺口另記，不算毫無價值，也不改算指定面向已發現。每版每案只取一次，沒有真人盲評或統計推論。

## 首段八對

| 案例與指定面向 | 舊版實際下一步 | 新版實際下一步 | 判讀 |
|---|---|---|---|
| 倉庫環境 | 問目前是否已取得堆高機證照 | 問證照是否已取得、未取得時是否操作 | 資格取得狀態仍不明，這是合理缺口；兩版都未問場所／環境。不是重問已知「操作需要證照」 |
| 上架常見差錯 | 補寫後表示暫時不需追問 | 問搬貨方式、重量、站立及設備 | 新版探索體力條件，舊版停止；兩版都未問常見差錯或其發現方式 |
| 收貨負荷 | 問搬運方式、設備限制或資格 | 問是否親自搬運／操作設備及限制 | 兩版問的是執行方式與限制，未問高峰及其影響 |
| 帳務差錯 | 問所屬單位 | 邀請核對底稿，無更正補充即可告一段落 | 舊版問基本資料，新版準備收尾；兩版首段未探索差錯 |
| 軟體負荷 | 問問題單是否有高峰、如何影響安排或回覆時限 | 認為不需再追問工作細節，保留基本資料空白 | 舊版觸及指定面向，新版未問 |
| 條件已確認 | 不重問條件，邀請之後補充 | 不重問條件，改問尚未確認的職稱／單位／匯報 | 兩版均未違反本案界線；新版一次問三項基本資料，另有回答負擔，不能因此算更有效率 |
| 已問但答不出 | 保留堆高機適用作業未知，改問入庫差異分工 | 保留同一未知，改問入庫登記依據 | 兩版未等義重問，也未把未知改成不存在 |
| 員工要求停止 | 停止追問，摘要已知部分 | 停止追問，明說目前仍是部分底稿 | 兩版尊重停止，未宣稱所有工作已確認 |

首段指定面向：舊版 **1／5**，新版 **0／5**。三個界線反例：兩版各 **3／3** 未違反指定界線。這些是本批樣本數，不是一般成功率。

## 按實際問題接續

首段有待答問題的七個探索案續一次；不強行向已收尾的上架舊版、帳務新版及軟體新版注入私人答案。選擇、原問句及理由在續談前存入 [continuation-decisions-02.json](continuation-decisions-02.json)。只有軟體舊版已問到目標，收到私人回答；其餘問題超出該案已定資訊，依預定規則回答未知。

| 案例／版本 | 第二段實際下一步 | 指定面向是否已問到 |
|---|---|---|
| 環境／舊 | 保留證照取得未知，問到貨高峰及時限變化 | 否；問的是負荷，不是環境 |
| 環境／新 | 保留證照未知，問忙碌時的量或時間壓力 | 否；仍未問環境 |
| 上架差錯／新 | 保留體力條件未知，問忙閒或特定完成時限 | 否；新探索負荷，不是常見差錯 |
| 收貨負荷／舊 | 查合成公版後問差異是否另登表單或系統 | 否；問的是紀錄要求 |
| 收貨負荷／新 | 問盤點不符如何處理、由誰確認 | 否；問的是差錯與分工 |
| 帳務差錯／舊 | 問發票、金額或申請單不符時如何處理、交誰決定 | 是；中立探索差錯，尚未自行指認重複發票 |
| 軟體負荷／舊 | 整理新版上線後高峰與主管排序，保留十二小時初判及發布／結案界線 | 已於首段問到，本段取得私人回答並改稿 |

七段原件存於 [live-03/manifest.json](live-03/manifest.json) 所列檔案。第二段只有帳務舊版新問到目標面向，依 [continuation-decisions-03.json](continuation-decisions-03.json) 再回答一次，取得「同一發票重複送件」的具體例子；不是模型自己發現重複發票。第三段補入既有任務及協作關係後轉問工作量，見[實際回覆](live-04/accounting_errors__old-old-turn-1.json)。

在本批最多三段的窗口內，舊版五案中有 **2 件** 問到指定面向並取得回答，新版 **0 件**。冷藏環境、錯儲位及促銷前後負荷仍未取得；這些私人內容沒有補送，不能評成已發現。

## 成品檢查不是只看回覆

- 搬運環境案兩版仍保留約十五公斤及操作需證照，不把未知取得狀態寫成已持照。
- 收貨負荷案兩版均保留平日高異動品項、月底本人區域、十二月配合財務全倉盤點的區別，沒有改成每日全盤。舊版拆成兩個職責、新版維持一個；本批沒有固定職責數要求，不以組數判勝負。
- 穩定條件案舊版把辦公場所及全年穩定負荷放任務要求，新版放全職務條件；兩版都保留，不能只看任務正文判新版漏寫。
- 軟體兩版首段保留十二小時「初判，不是修好」、前後端分工、發布權及測試／客服結案條件。新版未把已談過的辦公場所、問題單系統及版本控制保留在任何 JD 欄位；這是附帶的資訊保留缺口，不補算探索分數。
- 舊版收貨要求寫「收退及庫存調整由採購決定」，但員工只確認採購決定收退、本人不調整庫存；沒有確認庫存調整的決定者。這是不支持的權責延伸，不因舊版探索較多就忽略。

揭露後的兩份成品與來源另見 [results.md](results.md#3-取得回答後的-jd-與來源)；有保存引用不代表全部既存引用都已核對。
