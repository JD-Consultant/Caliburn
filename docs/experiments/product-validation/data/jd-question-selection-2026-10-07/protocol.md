# 顧問選問判準：假設與實驗方法

## 問題及修訂範圍

前批保存的 22 次回覆顯示：增加環境、差錯與負荷面向後，模型仍可能補完正常流程就轉問其他工作或停止。原話在請求中可見，私人條件從未提供；沒有證據顯示是 Memory 忘記已知資訊。參見[前批問題定位](../jd-condition-exploration-2026-10-07/results.md#4-問題定位與下一步)。

本次假設是：Prompt 分散的「足夠清楚」「足以改稿」「充分處理」沒有共用判準，容易把能寫出一段 JD 當成足以換題或收尾。這是待驗假設，不是已證實的唯一原因。

只整理顧問 Prompt 的選問、轉題與收尾規則，對齊公版啟用時的引用段落；保留職責分組、知識技能、細節保留、引用及員工停止規則。不新增職業特例、角色、資料表、問卷或程序 gate。

## 固定資料及比較

沿前批八個合成案例：三個倉庫條件、帳務差錯、軟體負荷，以及穩定條件、已知未知、員工停止三個反例。五個探索案例在起始原話補明「目前工作範圍已回顧」及既有流程分工；不揭露私人條件。不把顧問先問另一個有價值的缺口直接判成整案失敗。

每案舊／新各一次，交錯先後。舊提示取前批 `live-01/sources.zip` 中本次修改前的版本；新提示取本機修訂。準備時驗舊版雜湊與修改前基準，將資料、程式、工具及兩版提示凍結。兩版從相同 JD、原話開始，各自保留原生接續，不能移植另一組的回答或工具結果。

第一段共 16 次顧問回覆。按原問句作語意判讀後，五個探索案可各接續一段：問到私人面向才給相應私人回答；問其他已知流程時給固定流程澄清；問尚不知道的其他事則保留未知。若第二段才問出條件，原時間及費用界線內可再接一次回答，最多三段，不重跑。剩餘界線不足就保留部分結果，不重新給時間或預算。

回答選擇由工程代理依 [reply-policy.json](reply-policy.json) 人工判讀，逐項記原問句、選擇及理由，在該階段外送前凍結。這是適應式合成訪談，不是真人盲評或自動關鍵字分數。私人答案不載入模型 Context，也不在工具／公版 fixture 中出現；只有顧問實際詢問後，才成為下一段員工原話。

## 外送前的判準

1. **探索與發現分開：** 記下一問是否觸及各案目標面向，以及短段窗口內是否詢問並取得私人回答。合理的其他問題另外記錄；不把「問到負荷」算成「發現錯儲位」。
2. **不誘導、不猜事實：** 允許開放問題與條件式例子，不得預先宣稱員工確有冷藏、錯儲位、促銷旺季、重複發票或新版後尖峰。未回答的內容不得進 JD。
3. **三個界線反例：** 不重問已確認條件；不等義重問已明確答不出的堆高機作業；員工要求停止時不追加訪談問題，不把停止當成全職務完成。
4. **揭露後的 JD：** 實際取得私人回答後，才評估是否整理進適當任務／條件，保留未知、責任權限和來源；不得把條件機械拆成新任務。
5. **既有內容保留：** 搬箱十五公斤及證照、儲位／收退決策權、每日／月底／十二月盤點、核准／付款分工、十二小時初判而非修好等限定，不因局部修訂遺失。分別依適用案例核對。

單案每版僅一次，採描述性配對，不宣稱一般成功率或因果已證實。工具、token、費用及時間作附屬觀察，不以少讀或 API 成功代替品質。

## 界線與保存

使用本次確認的 US$0.10／20 分鐘，從首次執行 admission 計時；限流、未知用量預留及階段間人工判讀均計入。不擴大界線、不重試未知外送、不啟停既有容器。沿既有測試容器 `caliburn-jd-docker-test-postgres-1`／127.0.0.1:55441／`caliburn_docker_test`，新增唯一 schema，不刪除舊資料。

保留 `manifest.json`、`sources.zip`、`started.json`、去敏 trace、回覆、前後 JD、來源及 result／failure。原件不可改寫；結果文件另記。既有用量估算不是帳戶實際帳單。這批未測正式 Docker、瀏覽器、PDF、Memory 背景發布或超容量壓縮。
