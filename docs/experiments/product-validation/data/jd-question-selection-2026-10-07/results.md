# 三種訪談判準：短段對照結果

**集中重寫選問、轉題與收尾規則，尚未改善本批重要條件的探索。** 在五個指定探索案例中，舊版首段問到 1 件，新版 0 件；依實際問題接續後，舊版取得 2 件私人回答，新版仍為 0 件。兩版都會提出其他有分析價值的問題，但冷藏環境、錯儲位及促銷負荷仍未被問出。

本批已結案，24 次有效顧問回覆均完成，包含八對首段及八次適應式接續。約 17.45 分鐘，費用估算占用 US$0.073042255，未超過本次 US$0.10／20 分鐘。沒有付費外送失敗、限流、護欄停止或未決用量預留。不追加測試，不更新 8105／8106，不 commit、push 或 merge。

## 1. 比較什麼、如何判讀

前批已加入重要條件的探索指引，仍有正常流程補齊就停止深入的情形。本次檢查：把「可編寫部分 JD」「可轉換焦點」「可結束整份訪談」集中定義，是否能改變下一問與收尾判斷。原假設、資料及判準見 [protocol.md](protocol.md)，未在途中更改。

採 `gpt-6-luna`／high、16,384 輸出上限、正式 `ConsultantRunner`、工具與保存流程。兩版從相同員工資料及 JD 開始，首段交錯順序，各自沿原檔案、原生歷史接續。舊版是修改前已含條件探索規則的工作稿，不是最初沒有規則的版本；新版只集中相關段落並調整公版引用說明。

五案同時補明正常流程及目前工作範圍已回顧，讓模型仍可探索重要條件，不靠未說完的其他職責製造差異。案例與私人回答分離，首段 16／16 的實際 input 均不含案例 ID 或完整私人回答。只有實際問到目標面向，才在下一段揭露答案；其他合理問題照實回答已知內容或未知，沒有強行把隱藏條件塞給顧問。

判讀由工程代理依原問句及固定判準完成，詳見[逐案判讀](first-turn-review.md)。每案每版僅一次，屬描述性對照；不能據此估計一般成功率、宣稱舊版普遍較好，或確認 Prompt 分散是唯一原因。合成公版 fixture、未啟動的 Memory 背景工作與短段測試，也不能當成真 RAG 或完整職務訪談。

## 2. 主要結果

| 觀察 | 舊版 | 新版 |
|---|---:|---:|
| 首段下一問觸及五案指定面向 | 1／5 | 0／5 |
| 最多三段內問到指定面向並取得私人回答 | 2／5 | 0／5 |
| 穩定條件、已知未知、要求停止三個界線反例，未違反指定界線 | 3／3 | 3／3 |

舊版軟體案直接問問題單高峰與時間要求；帳務案先問所屬單位，員工答不出後才問差錯與決定權。新版帳務與軟體案首段即邀請核對或停止追問，沒有取得這兩項回答。

新版也有正面的局部行為：在上架案探索體力與後續負荷；證照取得答不出時，環境案轉問量與時間壓力。這表示「未知不等於其他面向都無法回答」能出現在實際回覆中，但不等於指定的冷藏環境或錯儲位已發現。不能用合理的其他問題替換原指標，也不應用指定指標否定其他問題的價值。

## 4. 採用決定與下一步

三種判準的領域概念保留在[訪談校準指南](../../../../guides/2026-09-09-customized-jd-depth-and-interview-calibration.md#可改稿可轉題與可收尾是三種判準)。但這一版 Prompt 重排沒有顯示穩定改善，且軟體案較早停止，因此**未採用為目前執行提示**。

付費階段結束後，僅撤回本輪主／公版 Prompt 的重排，兩個檔案與本輪修改前凍結版本逐位元一致。先前已確認的職責分組、知識技能、條件探索、引用及細節保留修訂均保留；不回退其他人的變更，也不更新運行中的 Docker。被測新版完整存於各階段 `sources.zip`，沒有改寫原件。

下一個候選應先定位模型為何把「有足夠內容改稿」當成可以停止探索：核對實際 input、選問優先順序與它已能辨認的未談面向，再討論最小修訂。不再堆職業例子或無目的地重跑整份訪談，也不因本批結果直接加入新角色、問卷、資料表或強制 gate。尚未驗過的訪談規劃候選仍依其獨立研究及規格討論，不因本實驗自動採用。
