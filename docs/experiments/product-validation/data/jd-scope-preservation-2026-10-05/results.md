# 固定 Memory 的讀後取捨：比較結果

2026-10-05。隔離研究已結案；正式產品與 B1／B2 指引未更動。

**新增範圍指引有局部改善，但還不能作為正式替換的依據。**在相同 Memory、問題與工具下，完整任務的必要限定由原指引 21／25 項完整，變成候選 24／25；兩種局部片段皆保留必要條件，沒有展開其他工作。候選仍有一次讀到卻漏寫分工，以及一處把上線條件寫成員工行動的推論風險。兩組也都出現把同案其他工作帶入完整任務的情況。

本批回答的是「資料已讀到後，指引能否改善取捨」，不是 Memory 層數優劣，也不是超容量驗證。它接續[上一批](../memory-coherent-units-2026-10-05/results.md)的漏項，沒有重跑或改寫上一批結果。

## 1. 比較方式

- 固定同一份模型生成的 Memory：更正階段兩項理解、補充階段三項理解。來源為 18 則合成訪談訊息；當次只提供問題與 map，正文由模型選讀。
- 唯一處理差異是 [scope-method.md](scope-method.md)：候選在相同基礎指引後增加「先確定本次範圍，再判斷省略是否改變責任與條件」。沒有指定題目答案或標題。
- Luna／high、16,384 輸出上限、唯讀工具、原生接續及完成格式相同。每題獨立開始；每對交錯執行順序。完整設定及雜湊見 [manifest](live-01/manifest.json)。
- 四題完整任務各一對，交付後缺陷與例行維護各再重複一對；兩題局部片段各一對。合計 16 個 episode、每組 8 個。重複的是同一題，不是增加員工樣本。
- 原四題的 16 項判準，加上重複題的 9 項，形成每組 **25 個判準實例**；局部片段的 5 個必要條件另列。完整判準於執行前凍結，見 [grading.json](live-01/grading.json)。

|---|---:|---:|

| 原話回查 | 0 | 0 |

逐題輸出、漏項與來源鏈見[語意判讀](semantic-review.md)。這是助理依凍結規則作的離線判讀，不是真人顧問盲測。引用定位與鏈可達不代表每句新表述都已被來源支持；下列額外發現仍須保留。

### 哪裡改善，哪裡還沒解決

交付後缺陷題，原指引兩次都保留 48 小時、初判而非修復保證、無固定月維護，以及後端由同事負責，但省去「客戶確認需求」。候選兩次皆補齊這項。在例行維護題，原指引兩次、候選第一次都漏了部分共通分工；候選第二次才完整。所有這些分工都在模型已讀正文中，並非 Context 缺少來源。

這裡的 `shared_authority` 是較強的「單項可獨立還原分工」判準。它不要求正式 JD 每個欄位都重複共通內容；若鄰近欄位已明確交代同一適用範圍，取捨可能不同。本批沒有提供這類其他 JD 欄位，不能假定它們存在，也不能由本批推定所有簡短寫法都不合格。方法適用性另見[判準核對](method-review.md)。

### 分數外的發現

- **同案不等於本題都需要。**完整任務中，兩組各有 2／6 次把同案逾時操作帶進交付後缺陷或維護題。它們有來源，不是憑空捏造，但原文沒有把特定逾時功能列為本次維護／交付後工作的內容。這是粒度與取捨問題，不能用完整項較多蓋過去。
- **不要把條件改成責任。**候選低頻工作題寫「本人僅在客戶確認後上線」。來源只說員工檢查圖片、連結，以及客戶確認後才上線，沒有明確指定誰執行上線。原定兩項檢查仍完整；這個額外責任推論單列，不事後改分母。
- 兩個局部片段反例都成功，但只各一對，不能據此保證遇到更長、更多交錯工作時仍不過度展開。

## 3. 讀取與 token

以下是每組全部 8 題、所有實際模型回應的總計，不是單次 Context 長度。數據由 [analyze_reader.py](analyze_reader.py)從 [trace](live-01/trace.jsonl)重算，完整分組見 [analysis.json](live-01/analysis.json)。

| 指標 | baseline | scoped |
|---|---:|---:|
| 模型回應數 | 21 | 17 |
| 理解正文讀取次數 | 10 | 8 |
| 已提供 map 的再次讀取 | 5 | 1 |
| 輸入 tokens | 38,899 | 34,090 |
| 其中 cached input | 31,298 | 27,832 |
| 輸出 tokens（含推理） | 3,675 | 4,418 |
| 其中 reasoning tokens | 1,767 | 2,618 |
| 最大單次輸入 tokens | 2,987 | 2,644 |
| 全部 read 回傳字元 | 5,902 | 3,682 |
| 最終 task.work 字元合計 | 774 | 827 |
| 依回報 usage 估算的生成費用 | US$0.003099030 | US$0.003268295 |

候選輸入少 **12.36%**，但輸出多 **20.22%**，估算生成費用反而多 **5.46%**。因此不能把少讀直接稱為更省錢。cached 是 input 的子集、reasoning 是 output 的子集，不另加一次；read 字元含序列化的標題、正文、來源及 map，不是純正文 tokens。

讀取差異可追到具體路徑：原指引的低頻題把三項理解全讀，候選只讀促銷素材一項；其餘正文讀取次數相同。另少了四次 map 重讀。候選沒有修訂 map 工具，這只是本批觀察到的策略差異，不能保證可重現。

六題完整任務的 input 為 29,886 → 23,534；兩題局部片段卻是 9,013 → 10,556。單一片段不一定受益於較長指引，不能只報總量。

## 4. 執行完整性與費用界線

- 16／16 episode 完成，38 次模型回應均 completed；38 次計數請求及 38 次模型請求都有配對回應。無 provider 失敗、工具錯誤或補跑。
- 22 個相鄰模型步驟的輸入保留前次原生輸出及對應工具結果，未把 reasoning 摘要重包成 user 訊息。76 次請求各只有一則本題 user 輸入。兩組的工具、完成 schema 與配對初始 Context 一致；grading 不在模型請求中。
- 本批最大輸入僅 2,987 tokens，**未觸發也未呼叫 compaction**，不外推超容量效果。
- 本批計時 **556.93 秒**，包含程式設定的速率等待；每組 episode 時間合計 319.63／237.36 秒，不能當成正式產品延遲結論。
- usage 生成費用估算 US$0.006367325，加上 38 次 token-count 各 US$0.0001 的保守暫留，本批占用 **US$0.010167325**。這不是供應商實際帳單，暫留不代表仍有請求未回。
- 累計占用 **US$1.295271975／US$2**。本批未達 US$0.05／900 秒上限；已結案，餘額不自動授權補測。完整帳目見 [run-summary.json](live-01/run-summary.json)。

## 5. 下一步取捨

本批支持繼續研究「必要限定就近保留＋依本次工作範圍使用」，不支持宣稱已選出最佳 Memory 架構。候選指引暫不替換正式產品。

先用既有原件做工作單位審查：同一專案內，逾時功能、交付後缺陷及定期維護應否分為可獨立選讀的單元？共通分工如何隨適用工作一起取得，而不引入其他動作？這可以先離線完成，不需要重跑模型或新增框架。

若後續安排新付費比較，應先凍結跨職務案例及相同支援事實，分開驗證「切分方式」與「顧問指引」，加入來源未指定執行者、共通分工更正、相鄰 JD 已交代分工的反例；達到穩定品質後再做超容量比較。大數據系統值得借鑑的是共讀資料組織、局部載入及增量維護，而不是直接搬進更多層與索引；[研究 §8](../../../../research/agent-systems/2026-10-05-demand-loaded-memory-and-incremental-updates.md#8-從查詢與增量系統進一步借鑑)已分清機制與適用界線。
