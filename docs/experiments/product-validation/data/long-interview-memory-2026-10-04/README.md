# 早期原話離開 Context 後的 Memory 取用比較

本批已完成 45 段合成訪談重播、兩批現行 Memory 發布，以及四組各兩次核對。三層組的起始 Context 不含早期原話、舊工具結果或 Compaction；模型由導覽讀取情境與理解，取得早期期限、頻率及責任資訊。內容保留與來源選擇分開判讀：部分答案內容正確，選出的訪談序號卻不能支持該題。

## 資料與控制

沿用採購人設的 45 段已完成合成訪談，只重播員工原話及顧問正式答覆，不使用原 JD 或原 Memory。新增一則明示重建的研究開場後，共 91 則、7,459 字元。前 22 段整理到員工序號 44，第二批整理到員工序號 90；最後一則顧問答覆 91 不擴大 B1 取材範圍。

這裡的「長」指跨越 45 段訪談，重點是早期資訊離開閱讀端 Context 後的取得，不是 128K 容量壓力。本批沒有觸發 Compaction；壓縮後發布查[另一組整合對照](../memory-compaction-publish-2026-10-04/README.md)。

| 組別 | 核對時可見資料 | 按需能力 |
|---|---|---|
| 完整歷史 | 91 則全部歷史 | 不讀 Memory |
| 單層摘要 | 相同兩批自然生成、增量更新的 Markdown 摘要＋89–91 | 不讀三層產物 |
| 三層 Memory | 現行發布版的情境／理解導覽＋89–91 | 正式 Memory read tools 綁定同一快照，讀情境／理解；本比較不開放原話回查 |
| 只有近期 | 89–91 | 不讀早期歷史、摘要或 Memory；負控制 |

四組同用 Luna／high、相同八題與輸出契約，每組兩次獨立核對，第二次反轉順序。三層的兩次取用共用一份自然整理產物；不是兩次獨立生成品質實驗。比較條件及題目在外送前凍結，見 [protocol.md](protocol.md)、[cases.json](cases.json)；執行中未改指引、題目、程式或原結果。

`protocol.md` 保留外送前的狀態與界線，不因完成而改寫；實際結果以本頁及下列原件為準。

## 已核實的隔離與操作

- 八份答案全部完成。起始三層請求只有兩筆 `user` 資料：當版導覽與近期歷史、本次核對問題；沒有 `previous_response_id`、舊 reasoning、Compaction 或早期原文。
- 三層兩次分別讀八項、十項，均取得七項情境與一項理解；第二次另重讀兩層 map。沒有 `read_interview`，故本次找回不是從原話資料庫補救。
- 兩份 Memory 由現行 B1 → B2 → 發布流程、真 PostgreSQL 及真模型生成；第一批八項情境、一項理解，第二批十三項情境、一項理解。後期修改沒有改寫第一批快照。
- 離線核查確認執行前檔案及依賴雜湊一致、零 compact、完整 usage、沒有資格失效或來源保存失敗。研究護欄審查及適用範圍見 [review.md](review.md)。

## 內容保留與來源選擇

八題共有 27 項判準，其中前段三題有 11 項，另有五項要求保留未知。下表為各組兩次的結果；不是把同一份整理產物算成兩份獨立樣本。

| 組別 | 全部事實判準（各次） | 前段判準（各次） | 全部事實符合的題數（各次） | 來源完整支持且無誤選的題數（各次） |
|---|---:|---:|---:|---:|
| 完整歷史 | 27／27、27／27 | 11／11、11／11 | 8／8、8／8 | 8／8、8／8 |
| 單層摘要 | 27／27、27／27 | 11／11、11／11 | 8／8、8／8 | 6／8、6／8 |
| 三層 Memory | 26／27、26／27 | 10／11、10／11 | 7／8、7／8 | 3／8、3／8 |
| 只有近期 | 5／27、5／27 | 0／11、0／11 | 1／8、1／8 | 0／8、0／8 |

三層組找回七天改善期限、連續兩次提報、付款文件與責任，以及旺季、提前兩個月下單、十一月談判等早期資訊。這些內容已不在近期原話中，實際來自本次讀回的情境／理解。只有近期組的五項得分全是承認未知，不能算找回五項歷史事實。

三層唯一未加分的內容有語意歧義：員工序號 10 說「是否接受由主管決定」，未明示接受的對象；凍結題目按「接受退換貨／扣款方案」評，Memory 與答案則寫成「接受不合格來料」。主要結果採嚴格解讀，不加分；若視為相同的接受權限，兩次均為 27／27。兩種解讀保存在複核紀錄，不改原題或輸出，也不因此消除其他來源誤選。

來源另逐則對照角色與內容：完整支持要求選定的員工原話合計涵蓋該題所有判準，且不混入無關訊息或顧問轉述。例如三層第一次正確說出一百萬元界線，卻選 74、76；兩則談需求規劃及訂單變更，無法支持核准界線。清單來源未知的答案則選了銅材遲交事件 58，正確依據為 22。這些資訊在 Memory 正文中仍可取得，錯誤發生在答案所選序號，不能一概歸為整理遺失。

要求模型直接選「員工原話序號」是本研究額外的來源診斷，不同於產品以 Memory 物件作 JD 依據、由 App 保存固定來源鏈的操作。本比較不開放原話回查；後續可另測按需核對原話是否改善來源精確性，不由此改動產品引用規則。

[語意複核](live-01/semantic-review.json)逐項記錄判定並綁定原答案雜湊，經獨立唯讀 AI 複核；不是工作分析專家的盲評。計算只加總這些明列判定，不以關鍵字命中代替事實正確。
