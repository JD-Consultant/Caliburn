# 長訪談：早期原話離開 Context 後的 Memory 效果

狀態：事前方法，尚無本次模型結果。這是既有 Memory 比較的擴充，不修改產品、角色指引、正式資料或容量政策。

## 要回答的問題

45 段有效訪談之後，早期原話不在顧問本次模型輸入中，工作情境與工作理解是否仍保留那些事實？模型能否沿導覽按需找回，分清後續更正、未解矛盾和責任界線？

分開量測「背景整理捕捉」與「後續取用」。不能因來源資料庫仍存有原話就宣稱 Memory 已保留，也不能把舊工具結果、加密歷史或 Compaction 中的資訊算作 Memory 的功勞。

## 固定資料與組別

沿用已公開的[採購 45 段合成訪談原件](../instruction-experiments-2026-10-01/runs/long-procurement-1.json)之員工原話及顧問答覆，不重跑或改寫原旅程。開場為研究程序明示新增的 App 引導；依原順序重新配發本測試檔案的正式來源身分與序號。這是合成逐字稿重播，不是本次重新完成 45 次 A 訪談。

1. **完整歷史**：全部 91 則訊息直接供核對，作為資訊完整的參考組。
2. **單層摘要**：Luna/high 依相同兩批逐字稿自然整理、更新一份 Markdown 摘要，保留數值、條件、更正、未知及來源序號；不用手工標準答案。
3. **三層 Memory**：現行 B1 → B2 → 發布流程，第一批上界 44，第二批上界 90。使用原角色指引、工具及真 PostgreSQL；評估時只給發布版導覽與最後三則歷史，按需讀取同版情境、理解。
4. **只有近期歷史**：最後三則訊息，沒有舊歷史或 Memory，作為資訊移除的負控制；其可用資訊較少，不以這組單獨證明三層比單層摘要優越。

四組以相同 Luna/high、題目、輸出契約、執行界線核對，每組兩次獨立核對；第二次反轉組別順序。完整歷史與單層組不額外取得三層產物。三層兩次共用同一份自然生成快照，因此是取用重複，不是兩次獨立生成品質實驗。

## 如何排除 Context 洩漏

- 每次核對建立新請求，沒有 `previous_response_id`、A／B 原生歷史或 Compaction。`store=false`，不假設遠端保存。
- 三層組起始輸入只有當版兩層 map、序號 89–91 及本次題目；沒有舊正文、員工早期原話、標準答案或舊工具結果。
- 此輪主要核對暫不提供 `read_interview`，以分離「Memory 正文本身能否支援」和「從原話補救」。這是隔離實驗條件，不移除產品原有訪談回查能力。引用序號可由 Memory 工具回傳。
- 保存每次實際請求與工具輸出之去敏 trace、完整模型用量及輸入雜湊；起始三層輸入須通過序號、禁止歷史項目及敏感內容檢查。
- 若後續加做原話回查，另列補救階段及實際讀取來源，不重寫此輪初次分數。

## 事前題目與判準

題目及逐項標準答案獨立保存於 `cases.json`，只把問題給模型。前段、跨段更正、中段及後段分開記錄：

| 範圍 | 題目重點 | 應保留的事實 |
|---|---|---|
| 前段 | 來料不合格 | 改善報告七天內；連續兩次提報主管；退換貨／扣款接受由主管決定 |
| 前段 | 發票付款 | 發票、採購單、驗收單一致才送財務；付款由財務安排；本人不承諾付款時間 |
| 前段 | 旺季備料與年度談判 | 農曆年前、第四季提早兩個月下單；十一月準備去年用量、市場行情；主管主談 |
| 中段 | 緊急採購 | 可先口頭下單；當天補請購與原因；主管事後簽核；ERP 補開是否需要仍未知 |
| 跨段更正 | 核准金額 | 舊五十萬元界線改為一百萬元；正好一百萬元副總；正好五萬元仍待釐清，不沿用早期已確定的說法 |
| 後段 | 進口品分工 | 提供採購單和發票；報關行報關；其他協助未知 |
| 後段 | 新人協助 | 偶爾教請購與 ERP；不負責考核；示範哪些操作未知 |
| 未知 | 未交貨清單取得處 | 未確定，不從使用 ERP 推定清單來源 |

採明確事實單位的語意複核，不要求逐字複製。數值、條件、責任、未知及引用支持分開計分；原話中出現某個值不代表最新結論就是該值。模型輸出不是標準答案；保存未加評分的原結果後才判讀。多引來源另查是否相關，不以命中關鍵字代替來源支持。

記錄初始及累計 input/output/cached tokens、實際 read 次數、生成次數、各事實單位正確數與每題全項符合率。背景整理與後續取用的用量分開；完整歷史沒有整理成本，不能只比後續輸入就宣稱端到端一定省錢。限流節奏不能當速度提升。

## 執行與停止界線

只用 loopback `_test` 資料庫及新隨機 schema，不清理原資料。保留候選、快照及原始失敗。生成最多 160 次，單次 output 8192、input 125,000，全批准入 input 2,500,000、60 分鐘；依 Luna 已查公開標準價及 cache-write 溢價估算上界約 US$1（費用只控制實驗，不加入產品攔截）。如果 count、provider、保存或資格失敗，停止並記錄，不無限自動重送。先凍結方法、題目、程式及指引雜湊；run 不覆寫。

本輪只回答單一合成職務的捕捉與取用，不宣稱真人省時、完整 JD 品質、跨職務泛化或正式容量極限已驗證。B1／B2 分工消融及差異處理效益另做，不能由此一次比較一併歸因。
