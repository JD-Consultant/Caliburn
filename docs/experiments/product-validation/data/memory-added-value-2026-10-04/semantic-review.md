# 逐項語意判讀

本頁核對 `live-01` 的真模型提案，不另送模型評分請求。判讀由工程代理依員工原話逐項進行，另有代理獨立複核核心判準；尚未經真人顧問複核。來源、題目與判準在外送前凍結，沒有因觀察結果而改題或更換通過條件。

## 判讀單位

核心判準見 `cases.json`：更正題 12 項、責任／未知題 9 項。每組各兩次，共 42 項判讀。檢查對象是**底稿加上提案後的完整相關欄位**與待釐清問題，不只看 `note`，也不要求模型重寫原本正確的欄位。矛盾仍留在任一相關欄位時不能判為修正成功。

其中有五個欄位植入人工錯誤：驗收比例、退貨任務描述、退貨時限、帳齡表描述及召回決策權。它們分屬兩道題；更正題不要求處理召回，責任題不要求處理退貨時點。沒有將題外的人工錯誤算成該題失敗。

引用另以**每個新提交欄位的完整文字**為單位，檢查模型選取的來源是否支持所有實質主張。沿用舊文字不等於可以省略該文字的依據；本研究提案沒有繼承舊 JD 的來源集合。來源存在、編號有效只證明定位有效，不證明語意支持。

## 完整改稿的引用支持

「完整」指選取的來源集合能支持該欄位所有實質主張；「部分」指內容本身有原話依據，但模型沒有把必要的來源列進這次欄位引用。這不是把內容錯誤與漏引混在一起。

| 分析 | 完整支持／提交欄位 | 部分支持的具體原因 |
|---|---:|---|
| 更正／原話／第一次 | 5／5 | 無。多改的退貨成果欄位引用 16、96，支持一般狀態與冷藏例外。 |
| 更正／原話＋Memory／第一次 | 1／4 | 退貨描述未引 18，無法支持照片、客服確認、核准調帳及核准單號；退貨要求只引 94，未引 14 支持前一日退貨及不適用驗收；帳齡描述未引 46，無法支持週報交採購與主管。 |
| 更正／原話／第二次 | 2／4 | 退貨描述只引 14、94，缺 16、18 支持批號、庫存狀態、照片及核准調帳；帳齡描述只引 42、98，缺 44 支持入庫日期／批號／調撥，缺 46 支持週報收件對象。 |
| 更正／原話＋Memory／第二次 | 4／4 | 無。帳齡描述選取的 94 與退貨時程區別相關，但不是帳齡新時點的必要依據；不因此判為漏引。 |
| 責任／原話／兩次 | 2／2 | 無。第一次引用 58、60、62、102；第二次描述未重寫部分批號細節，58、60 足以支持實際提交的內容。 |
| 責任／原話＋Memory／兩次 | 2／2 | 無。兩次均引用 58、60、62、102。 |

合計：原話組 9／11 個提交欄位完整支持；原話＋Memory 組 7／10。所有實際提案均選訪談來源，沒有選 Memory 作直接引用。兩組提交的欄位數不同，這個比例只作引用品質觀察，不作 Memory 優劣的統計檢定。

## 判準之外的觀察

底稿中的冷藏例外已在要求欄位列出，但退貨描述及成果仍有泛稱倉庫判定的句子。第一次原話組同時修描述及成果；兩次 Memory 組修描述而未修成果；第二次原話組只修時點、描述的泛稱仍在。這是跨欄位一致性的後續測試素材，**不事後加入本次凍結分數**，也不能因核心題全對便宣稱整份 JD 已無缺口。

兩次責任題都已在底稿提供正確的交接與未知要求，沒有要求從空白發現全部工作；Memory 的直接效益不能由這些保留項目單獨推導。
