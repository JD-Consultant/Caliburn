# 自足工作理解與局部修訂：配對驗證

狀態：**已結案，14 個執行單元完成；候選未採用。**兩組 Memory 均保留 33 項指定事實；候選少讀資料，但 JD 為 14 完整／2 部分，原方法 15 完整／1 部分。詳見[結果](results.md)與[逐項判讀](semantic-review.md)。正式產品不變。

本批接續[按需載入研究](../../../../research/agent-systems/2026-10-05-demand-loaded-memory-and-incremental-updates.md)，檢驗「讀到一個工作單元，是否已取得正確解讀所需的限定」，以及新資訊到來後能否撤換舊未知、保留未變條件。不預設候選一定勝出。

## 1. 比較方法

- **baseline**：上一批單一理解集合的整理指引；**coherent**：同一指引加上自足單元與修訂規則。兩組都直接從訪談維護理解；本批不是重新比較雙層與單層。
- 兩組從空白開始，使用相同 18 則合成訊息、三批增量、Luna／high、工具、輸出上限與同一顧問選讀指引。每組執行一次。維護批次交替先後；每題顧問從指定快照開始，不能看到另一題或另一組。
- 沿用[前批資料及判準](../memory-structure-incremental-2026-10-05/README.md)，新增「核准人已確認後」一題，驗證撤換未知能否被下游使用。所有評分預期不傳給模型。
- 這是已知反例的回歸，不是未見案例或超容量長訪談實驗。本批不使用 Compaction，不據此決定正式架構替換。新職類、重複取樣與大型集合仍需後續比較。

## 2. 固定觀察項

維護：依預先凍結的語意判準逐項核對正文與來源，保留原 33 個檢核次數；分開完整、部分、缺漏、錯誤。若同一現行集合既寫已確認又保留無時期限定的未知，不能算正確撤換。判讀者與是否另經人工複核在結果中標明。

顧問：四題共 16 項語意檢核，分別是更正期限（4）、更改週期且核准人未知（5）、低頻工作（2）、核准人已確認（5）。來源資格由程式檢查；來源是否真正支持內容另做人工核對，不以「有引用」代替保真。

效率：分別統計維護／顧問 input、cached input、output、reasoning tokens，模型請求、實際工具讀取、讀回字數、讀取物件覆蓋率、錯誤與延遲。字數不當作 token；品質未達等價時不宣稱省 token 即較佳。必要限定的重述可能增加保存與更新成本，亦須報告。

## 3. 邊界與共用修正

- 先前累計估算占用 US$1.270089235；本批新增最多 US$0.10，總上限 US$2。20 分鐘從本批首次外送開始；到界線或 provider 錯誤立即保存並停止，不補跑、不偷偷降規。
- 沿用既有 Recorder 的計數、預留、速率等待與去敏 trace；count 及 generate 均受准入。費用是本機估算，不是帳單。
- 上批顧問輸出 JSON 缺括號。本批兩組共同採官方 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)，只約束既有完成格式，不加入答案或評分。count 與 create 使用相同 schema；保留原生 reasoning／message／tool items 接續。拒絕或不完整回應仍停止，不修補模型原件。
- 只寫新實驗目錄；舊材料、trace、manifest 及產品程式不改。模型完成的單元不人工補字。
