# Memory 壓縮後發布：兩組整合對照

本資料包使用現行單向 B1 → B2 → 發布流程、Luna／high 及隔離 PostgreSQL，補測「角色歷史壓縮後能否繼續整理並發布」。資料為四則合成正式訊息，兩組各執行兩批；[事前方法及試跑修訂](protocol.md)與[正式執行 manifest](live-02/manifest.json)保留全部條件。

## 結果

| 組別／批次 | 生成次數 | compact 次數 | 累計 input tokens | output tokens | 發布 |
|---|---:|---:|---:|---:|---|
| 原門檻／1 | 8 | 0 | 27,605 | 1,345 | 成功 |
| 原門檻／2 | 11 | 0 | 65,892 | 4,872 | 成功 |
| 壓縮探針／1 | 11 | 0 | 42,570 | 2,769 | 成功 |
| 壓縮探針／2 | 10 | 2 | 62,323 | 5,035 | 成功 |

兩組各自從獨立職務檔案開始，使用相同訪談與原始指引。原門檻組為 128,000；探針只在研究程序將輪前門檻降至 1，第一批沒有歷史仍不壓縮，第二批 B1／B2 各壓縮一次。兩組第一批生成內容不同，因此這不是對同一原生歷史做壓縮前後的消融，也不以單次用量差異宣稱品質提升或成本改善。

四份快照回讀的正文及修訂均與發布時相同，理解所引情境修訂都存在於該快照，訪談來源均在固定上界內。第二批修改後，第一批快照仍保留原文；四次已完成 parent 重進均回傳同快照，完整 HTTP 計數沒有增加。兩個 compact 的完整 `output` 都作為下一生成請求的前綴保留，兩角色的完成歷史均已採納。詳見[獨立核查](live-02/summary.json)、[結構化回讀](live-02/readback.json)及[公開請求軌跡](live-02/trace.jsonl)。

## 內容逐項核對

這是對固定合成事實的內容複核，不是專業 JD 盲評；「每月」出現在更正歷史中不算現行頻率錯誤。

| 事前要檢查的內容 | 原門檻組 | 壓縮探針組 |
|---|---|---|
| 第一批保存每月盤點 | 有 | 有 |
| 第二批現行盤點改為每季 | 有 | 有 |
| ERP 調整由倉庫主管核准，本人無核准權 | 保留 | 保留 |
| 每年協助年度查核，準備資料而不負責結論 | 保留 | 保留 |
| 新增每週退貨核對、記錄與登錄 | 有 | 有 |
| 商品可售由品保決定，不擴大本人權限 | 保留 | 保留 |
| B2 理解連到更新後盤點及新退貨情境 | 有 | 有 |

壓縮探針第二批的理解寫道：「本人目前每季盤點庫存……不應將每月仍寫成現行頻率」，並保留「商品能否再次銷售由品保決定，本人依品保結論登錄，不作可售判定」。控制組也保留相同事實與責任界線。未變的年度情境在探針組沿用原修訂，更新及新增情境則連到本次選用的固定修訂。以上摘錄來自公開回讀，不另造示範答案。

## 原件、試跑及費用

- `live-01` 是未發布的試跑：研究設定的 8 次上限由兩角色共用，B2 尚在讀取時中止。原件保留，27,371 input／1,044 output 也納入研究用量，不視為模型或保存缺陷。
- `live-02` 為上述正式對照：40 次生成、2 次 compact、44 次 count，共 86 次 HTTP 外送；198,390 input／14,021 output、165,556 cached input。compact 的用量已計入，沒有只算生成請求。
- 加上試跑為 225,761 input／15,065 output，其中 184,857 cached input、35,525 cache-write input。依 Luna 普通輸入、快取讀取、快取寫入與輸出單價估算約 US$0.01436；這不是官方帳單，也未以產品金額攔截控制執行。
- 原始 `results.jsonl` 使用字串表示 frozen reference sets，保持不改寫；`readback.json` 由正式只讀查詢重新取得結構化引用，不重新呼叫模型。衍生摘要保存原件及分析程式 SHA-256。

本項已補到真模型、真 PostgreSQL 的壓縮後發布與固定回讀；資料量小、每組一份，不代替正式容量邊界、不同職務的長旅程或專家品質評閱。真人訪談省時與能力完整性另見[報告證據索引](../../2026-10-04-report-evidence-audit.md)。
