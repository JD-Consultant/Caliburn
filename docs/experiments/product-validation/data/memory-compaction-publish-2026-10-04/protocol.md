# 背景記憶：壓縮後發布與固定歷史回讀

本實驗補上先前「B1／B2 已壓縮，但該批未發布」的缺口。使用現行單向流程與原指引，不改 production。它是小型整合對照，不宣稱壓縮可以提升內容品質或門檻已最佳化。

## 兩組與固定資料

兩份獨立合成職務檔案，依序輸入相同的兩批正式訪談。第一批：本人每月盤點、主管核准調整，低頻年度查核由本人協助；第二批：改成每季盤點，核准權不變，新增退貨核對，商品能否再售由品保決定、本人只登錄。

兩組都使用 Luna/high、原生 B1 → B2 → 發布、相同模型上限与順序。一組沿用正式輪前門檻 128,000；另一組只在本測試程序將門檻降至 1，讓第二批開始前的 B1／B2 各壓縮一次。第一批無歷史，不壓縮；中途保險不變。先控制組，再壓縮組，每組各兩批、單次，不把它當成統計品質比較；第一次輸出可能隨模型不同，兩組不是同一份生成歷史的複製。

## 檢查與量測

1. 每批確實發布，而非只回傳模型完成；兩份固定快照皆可由 public query 回讀正文與引用。
2. 第一批快照的每月盤點原文與來源不受第二批修改影響。
3. 第二批盤點採每季、保留無核准權與年度查核，考慮新增退貨情境，來源關係合法。
4. 第二批 B1／B2 的採用歷史確實含 compaction item；公開證據不含加密內容，只留 hash／長度。
5. 兩角色的 latest history 與發布結果已採納，重進 parent 得到同快照且不再外送。

事實檢查針對全層文字與固定關係，另外逐項閱讀語意；關鍵字只是候選警示，不把字面命中當成專業 JD 品質。記錄全部 provider 請求、用量、操作與前後快照，不只保存成功結論。

## 安全與上限

只允許明示的 loopback、資料庫名稱以 `_test` 結尾，新建隨機 schema；保留 schema 與合成結果，不碰正式 namespace。每個 batch 最多 8 個模型 Step、64 個外送、單一請求一次嘗試、2 次 compact、4096 output tokens、720 秒；全實驗 32 次模型生成、總輸入 2,000,000 tokens、30 分鐘。provider 或保存失敗停止、不反覆重跑。本項預期不到 US$0.3，加上閱讀／定位對照預期仍低於 US$1；費用統計來自實際 usage，非產品 ledger 的暫留金額或官方帳單。

執行前覆核：產品原有 rate-limit 等待不受單次失敗上限計數，因此研究程序另於 HTTP hook 中停止 provider 錯誤，避免研究意外沿用產品的等待重試。每次生成前等待 5 秒，計數涵蓋 count、生成與 compact；不改正式執行器。這是實驗停止契約的接線修正，不是產品缺陷修補。

啟動前保存 manifest、指引／程式 SHA-256 與資料；模型／工具結果只含合成資料，不輸出憑證。通過、失敗與未驗分開；本次低門檻對照不能證明 128K／160K 邊界的分析品質，也不代替真人或專家評估。

## 試跑修訂：正式對照前的執行上限

`live-01` 的控制組第一批在第 8 次生成後遇到 `BudgetExceededError`，未進入壓縮或發布。原 trace 顯示 B1 建立兩項情境，B2 仍在讀取情境與來源；8 次限制由同一 batch 的兩角色共用，低於正式產品的 64 次上限。本次原件保留為研究程序試跑，不併入完成成果對比。

`live-02` 正式對照沿用相同資料、指引、評閱要求及組別順序，只把每 batch 的 Step 限制對齊產品 64、全研究生成上限改為 64。其他 input／output／時間界線不變，失敗仍停批；兩組皆從新職務檔案開始。模型用量另加上試跑的 8 次生成、27,371 input、1,044 output，不因重啟排除費用。64 次生成的 output 上界為 262,144 tokens；加上 2M input，其標準價上界約 US$0.34，而非先前 32 次配置的上界。
