## 問題與比較

在同一批訪談中，B1 → B2 能否持續保存必要工作資訊，使 A 依導覽選讀後正確形成 JD，且減少原話閱讀？本批保留現有分層，只優化角色指引。方法依[指南 §10.7](../../../../guides/2026-09-09-complete-work-analysis-guide.md#107-收斂後的整理與選讀準則)與[研究 §9](../../../../research/agent-systems/2026-10-05-demand-loaded-memory-and-incremental-updates.md#9-收斂採用既有分層改善內容組織與選讀)。

| 組別 | 顧問取得的資料 | 引用／讀取 |
|---|---|---|
| `layered` | 模型從空白經三批整理的情境與理解導覽 | 沿用理解、情境及合法原話工具，按需讀正文並選引用 |
| `full_history` | 相同時點的完整訪談原話，直接放進 Context | 原話已全部讀入，可直接引用其序號；不提供不存在的 Memory 或多餘讀取工具 |

兩組顧問用同一份指引、題目、Luna／high、16,384 輸出上限及結構化答案契約。每題獨立 Context，不提供上一題答案、整理 trace、評分或未來訪談。這是可用資料表示的整體比較，不是只改一個 Prompt 的因果測試。完整原話組不支付 Memory 整理成本；分層組的建立與更新成本分開列出並納入總量。

## 固定材料與判準

沿用[三批原件](../memory-structure-incremental-2026-10-05/materials.json)的 18 則合成訪談及三批上界（10、14、18），不改寫員工事實。四個完整任務題與判準沿用[自足單元比較](../memory-coherent-units-2026-10-05/live-01/materials.json)及其 grading.json：交付後處理、例行維護、低頻工作、核准人確認後的維護。共 16 個指定 JD 檢查項／組，另核來源及判準外錯誤。

維護三批共 33 個事實檢查項，分別檢查情境、理解的正文與來源。不得用情境保留代替理解保留，也不因回答流暢就算完整。語意標記 complete／partial／missing／incorrect，保留產物摘錄；不追求固定標題或物件數。批次三新增資料不能出現在批次二的回答。

先完成 6 次維護（每批 B1 再 B2），再按題交錯兩組的 8 次顧問閱讀。第一、三題 layered 先，第二、四題 full_history 先。每組每題一次；這是已知材料的最小機制驗證，不代替跨職類及超容量驗證。來源全文很小，沒有原生 compaction；若輸入超過既有 128K 實驗界線即停止。

## 優化範圍

B1 用具體工作脈絡維護情境；B2 用工作目的組織可獨立使用的理解，必要短限定就近保留、局部修訂。顧問依當前任務範圍保留必要內容，資訊充分便停讀。三份 Prompt 不提供教材正解、特定物件數或題目答案。

沿用既有實驗的 `Workspace`、正式工具 schema／V4A、Responses 接續、結構化輸出及費用／時間護欄。新增部分只處理完整原話的起始投影與已讀引用資格、兩組編排及結果記錄。資料隔離在本資料包的記憶體工作稿與 JSON 快照，不碰正式 PostgreSQL、服務或 Prompt。

## 判讀與可支持結論

1. 分層內容是否保留三批有效事實、更正與限定，引用是否可回查原話。
2. 顧問是否實際讀到並使用必要內容，是否引用已讀且支持正文的來源；分開「存」「讀」「用」。
3. 在同品質的題目比較載入正文、原話數、工具讀取、input／cached／output／reasoning tokens、延遲與估算費用。分開導覽／正文／原話字元，不把字元冒稱 token。
4. 同時報告建立與更新成本、8 次閱讀全部結果；不挑成功題替代整批。小材料上 Memory 的工具成本可能高於全文直讀，總成本照實保留。

本批若品質與來源成立，可支持「此資料下能從增量 Memory 接續分析，按需取讀而不靠全量原話」；只有實測較省的指標才稱效率改善。仍保留之前所有失敗與結果，不改評分追求勝出。
