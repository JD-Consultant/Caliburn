# 局部修訂驗證：跨案舊值已排除，必要分工保留

2026-10-05，隔離真模型實驗，已結案。新 B2 指引在網站案例排除了原指引留下的跨案舊期限；倉庫案例的新舊指引均保住更正及有效細節。A 的三組配對均符合內容判準，這次沒有重現先前的分工漏項，因此不能將它算作新 A 指引的改善。

本批支持保留分層、針對內容組織做小幅修訂，不需要為此更換 Memory 架構。正式 B1／B2／A 提示與產品程式均未因本批切換。

## 如何比較

固定 Luna／high、資料、起始快照、工具及完成格式，五種情況各比較新舊指引一次，共十次獨立執行。交替兩組先後順序；不把 B2 候選產物放進 A 候選組，避免同時更換資料和讀取指引。

- B2 只新增「不複製無關案件數值作排除比較；必要比較須核對兩側事實及來源」的規則。
- A 只將完整任務的責任要求寫清楚：不能以「不是本人負責」取代已知核准者或接手者；窄題仍只答所問。
- 網站案例沿用[前批](../memory-layered-value-2026-10-05/results.md)反例；倉庫是本輪設計的合成遷移案例，不是盲測。

[預先凍結的判準](README.md)、[指引差異](prompt_changes.py)、[實際提示](live-01/instructions.json)、[案例與起始狀態](live-01/cases.json)可直接核對。README 的「準備中」是凍結前的狀態，為保持雜湊不回改；本頁及 run-summary 記錄結案狀態。

### 是否真正按需讀取

六次 A 作答都只讀一項理解正文，引用該項理解，沒有展開情境或原話。這支持「理解已自足時可以直接使用」在本批案例可運作。

候選窄題額外重讀了一次已提供的理解 map，因此該題為三個模型 step，控制為兩個。不能把「只讀一項正文」說成沒有冗餘讀取。B2 維護本來就需要讀上游，其讀取量不與 A 混作同一效率指標。

## 收斂建議與適用範圍

1. **B2 修訂可作為下一步落地候選。** 本次重現並修掉具體舊值缺口，未損失兩案內應保留的內容；不需新增資料層或處理機制。
2. **A 不再疊加提示。** 新舊都答對，這次只能確認候選未造成已測的內容退化，不能宣稱已解決偶發漏項。窄題重讀 map 另列讀取效率問題。
3. **後續效率工作聚焦 Context 重複成本。** [離線投影](execution-notes.md#context-離線投影)顯示前批工具契約及額外往返有明顯文字負擔；先針對這些比較，不再廣泛重做分層選型。

每對只有一次，且材料小於模型容量。本批不是超容量長訪談、三層對單層摘要、真員工訪談或完整 JD 保存／發布的驗收；本次未新增那些結論，也不將不同批次合成一個受控比較。
