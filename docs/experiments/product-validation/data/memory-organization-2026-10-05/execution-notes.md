## 付費前的確認

1. 使用者同意新增 US$0.10／20 分鐘，計入累計 US$2。前批累計估算占用 US$1.198955810。計時由本批付費階段開始；容量計數也占用外送次數與保守預留。不沿用前批未花完的個別授權。
2. 原材料有 105 則訊息，快照處理邊界為第 104 則員工輸入。以獨立投影截到 104；新增測試先得到 5 個失敗，實作後 5 個通過，檢查原件不變、兩組獨立、副本界線及錯誤來源。
3. 新增測試加既有角色／工具契約，共 32 項通過。候選品質仍待真模型產物判讀。
4. `offline-01` 在隔離 PostgreSQL 種子檢查時停止，無模型外送。內容一致，但產品導覽按物件 UUID 排序；各組隨機建立物件造成 map 與來源導覽順序不同。將「初始種子」的物件 ID 固定，模型真正開始後恢復原 ID 生成，沒有替換產品工具或其結果。
5. `offline-02` 使用另一個隔離 schema 重驗：四份初始導覽、完整正文與來源逐一相同，exit 0，無 provider 呼叫。前次失敗原件與 schema 保留，不覆寫成成功。這兩份 schema 均位於 `caliburn_docker_test` 的 `eval_b2_organization_*`，不涉及正式資料。
6. 獨立唯讀審查指出應凍結實際載入的生成 schema、保留非 JSON HTTP 錯誤，以及避免四格完成但收尾失敗時誤標整批成功。三項均已修正；外送前另比對整份工具定義。記憶體 HTTP 探針確認異動工具被拒、HTML 502 留存 status 並停止，無網路。
7. 分析器另外測試原生歷史重複帶回時，同一工具結果不重複計數；先重現缺少 `type` 的一般 user 訊息造成 KeyError，再修正。沙箱的 pytest 暫存目錄權限問題改以限定臨時目錄處理。最後相關測試共 **33 passed**；新腳本 Ruff 通過。先前 `check_candidates.py` 使用 App 的 Ruff 設定，若改用根設定會有匯入換行差異，未為本批任意改寫舊驗證檔。

## 實驗界線

只比較 B2 指引。B1 不呼叫模型，情境正文及來源固定；工具說明不換成候選。兩組均帶相同的全範圍重組要求，不把空 diff 當成新一批上游變更。每格從同一初始理解獨立開始，可正常讀原話及修改理解。

完成判定使用正式 B2 runtime；產物僅保留於隔離候選，不發布。比較後仍須區分執行成功、事實／來源品質、組織可用性及成本。後續 A 是否因此少讀且能正確編輯 JD、增量維護，以及超容量三層對單層，都不由本批代證。

## 重現命令

在儲存庫根目錄，用既有 `apps/api/.venv/Scripts/python.exe -B -X utf8` 執行本資料夾的 `study.py`：

- `prepare <全新資料夾>`：凍結來源、指引、工具與版本，不連 DB／模型。
- `seed-check <該資料夾>`：依凍結 schedule 建立隔離起點並檢查，不呼叫模型。
- `live <另一次 prepare 的全新資料夾>`：依凍結 schedule 進行本批已授權的有界比較。

已有 `setup.json` 的資料夾拒絕重跑。任何新的付費批次都須有自己的授權；保留以上命令不是無限重跑許可。模型請求與回應的公開投影、實際用量及估算預留分開保存，不公開 API key 或加密推理內容。
