# Memory 讀取界線與任務一致性驗證

狀態：準備中。延續[讀取策略比較](../memory-reading-policy-2026-10-04/results.md)，本次不重新比較模型或修改正式 Prompt。

## 目的與判準

前批確認理解層足以回答時可以停止深入，但部分任務欄位仍保留相互矛盾的敘述。本批測三種資訊條件，各獨立重複兩次，共六格；每格從新 Context 開始，不沿用其他格的讀取成果。

| 測例 | 素材條件 | 成品判準 | 讀取判準 |
|---|---|---|---|
| `complete` | 理解層保留完整退貨事實；JD 描述與成果仍把所有商品判定交倉庫 | 描述、成果、要求一致區分常溫由倉庫、冷藏核對溫度紀錄後由品質判定；不編造溫度門檻，不把已知事項重問 | 理解足夠即可停止；不需要查情境或原話 |
| `situation_gap` | 理解未載收貨異常的兩／四工作日提醒升級時點；情境保留 | 改正提醒與升級欄位，準確保留兩個工作日未回覆提醒採購、第四個工作日仍無進展回報主管，以及帳物相符才結案、不保證補貨日的界線 | 能找回具體缺口；情境足夠後不再無理由查原話 |
| `interview_gap` | 理解、情境都未載特定品號一箱 12 件換算；原話 54 保留 | 修正「所有商品一箱 10 件」，保留資料窗口核實、該品號限定、不推用其他商品 | 原话可按需讀取；引用來源確實已讀且支持換算 |

判斷分開紀錄：①是否交付提案；②事實、跨欄位與引用是否正確；③是否在資料足夠時停止。較少讀取不能抵銷錯誤成品；替代的有效查詢路徑不因順序不同判成事實失敗。初始已正確欄位可保持原文，不要求全部重寫。未交付格列未完成，不當成品質通過。

## 資料與範圍

沿用前批合成長訪談的 105 則正式來源、12 個情境及一個理解。原話、角色、序號和來源關係不改；人工移除的句子及 JD 污染明記在 `fixture-changes.json`。這是控制缺口測試，不是 Memory 自然遺漏率，也不是長訪談壓縮測試。

六格共用同一份控制素材：理解移除提醒升級時點、兩層移除包裝換算，退貨事實保持完整。每格只預載對應完整任務及兩層導覽，近期歷史依原已發布處理邊界組裝（本例為序號 105）；完整 1–105 仍可透過原讀取工具回查。評分規則、移除紀錄與標準答案不放入模型 Context。

沿用前批已凍結的 `candidate` 指引（含研究提案補充）與五個正式讀取工具、研究用 `submit_jd_review`。不新增強制路徑或工具、不寫正式 JD／資料庫。輸入資料仍用 user role，後續保留原生模型 output 與工具結果配對。
