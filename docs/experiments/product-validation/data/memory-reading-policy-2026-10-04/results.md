# 理解足夠就停止：閱讀策略的局部比較結果

同一份近期訪談、Memory 與 JD 底稿，只改顧問指引後，新版四格全部交付，舊版三格交付、一格達六次模型回應上限。新版直接使用工作理解作為依據，累計 input 少 60.1%；只比兩組均交付的三對，仍少 56.2%。這支持明確的閱讀停止條件能改善本次核對工作的效率，不代表整份 JD 或長訪談管線已全面驗證。

本批已結案，未重跑未交付格，也沒有追加付費。方法見[外送前協定](live-01/executed-protocol.md)，內容與引用另見[語意判讀](semantic-review.md)。本次比較的是前次診斷後的指引改動，不與前次八格結果混成同一批。

## 一、同材料、同工具，只改指引

兩組都使用前次凍結的 `raw_memory` 輸入：序號 105 的近期顧問答覆、兩層 Memory 導覽、共同 JD 底稿與當次題目。訪談 1–105 與同一版 Memory 正文均可按需閱讀；沒有替新版增加材料、重製 Memory 或移除查原話能力。每格起始為兩則 user 訊息，同格保留原生接續，不跨格沿用 native items。

模型固定 Luna／high，每格最多六次模型回應，工具、題目、共同研究補充及 21 項核心判準相同。兩題各重複兩次，第一次先舊後新，第二次交換順序。實際外送的指引、模型、工具及起始輸入已與凍結檔逐項核對，不只依準備旗標判斷。

新指引要求：已讀理解足以支持事實、精確條件、責任界線且沒有已知衝突時，直接使用並停止深入；有具體缺口才讀情境或原話。本批材料中的理解足以回答兩題，因此觀察的是「足夠時能否停止」，不是缺口情境的回查能力。

新版首次 input 因指引較長而多 2.9%，累計 input 則少 60.1%，讀取次數少 86.5%，回傳字元少 66.8%。輸出與推理沒有減少；效果主要是停止不必要的深入閱讀及少做接續請求，不是每一類 token 都變小。生成估算費用少 32.6%，受快取與輸出用量共同影響，不能把 input 降幅直接當成費用降幅。

為避免只靠舊組失敗的額外消耗放大差距，另比較共同完成的三對：舊組累計 input 199,594、新組 87,353，少 56.2%；讀取為 23 次與三次。新組第四格交付、舊組未交付仍是完整結果的一部分，不能從主表剔除。

共同完成三對的凍結核心判準兩組各通過 33／33。這是同一份 Memory 下的閱讀指引比較，不代表全文 JD 品質等價，也不是三層 Memory 優於單一摘要的證據。

## 三、仍須注意完整欄位與同任務一致性

凍結核心判準涵蓋指定數值、更正範圍、責任與未知；它不是全稿正確率。另作兩項輔助審查，不事後加入原分數：

- 完整修改文字的直接來源與適用例外：舊組 11 欄中六欄充分，新組 13 欄中 12 欄充分。分母、修改範圍不同，這不是統計意義的引用率比較。舊組常見缺口是重寫保留文字卻未帶回其直接來源；新組仍有一欄把已知冷藏例外泛化成倉庫判定。
- 冷藏責任的同任務欄位：兩組更正題第二次均對齊描述及 `task_2.outcome_2`；第一次均未對齊成果欄位。新版責任題第二次也保留了籠統的退貨判定描述。原稿 `requirement_7` 已有正確冷藏例外，問題是相關欄位未全部一致，不是整份 JD 不知道品質窗口的責任。

因此可以保留本次有效的閱讀策略，但不能稱為所有品質問題已解決。下一個有意義的反例是：理解足夠時停止，仍核對本次修改所影響的同任務欄位；理解真的有缺口時，再只往下查相關來源。不需要另加全稿審核 agent，也不必重跑相同八格。
