# 近期原話＋Memory 能否替代每次放入完整原話

狀態：新一批隔離比較，準備及評測中；尚無結果。不修改正式產品，也不續跑已停止的長訪談四組實驗。

## 問題與比較

上一批[附加價值比較](../memory-added-value-2026-10-04/results.md)中，完整原話可容納時，再加 Memory 未呈現穩定額外收益。本批改問：以 Memory 導覽與按需正文替代大部分起始原話，是否仍能完成同樣的 JD 核對，且降低實際閱讀與輸入負擔？

| 組別 | 起始資料 | 按需能力 |
|---|---|---|
| 完整原話（`raw`） | 訪談 1–105、共同 JD 底稿及當次題目 | 原話訊息或區間 1–105 |
| 近期原話＋Memory（`raw_memory`） | 訪談 105、情境／理解導覽、相同 JD 底稿及題目 | 相同原話查閱，加上固定 Memory 的導覽、正文及來源 |

`raw_memory` 是共用評測程式的組別鍵；在**本資料包**表示「近期原話＋Memory」，不能與上一批同名組混為同一處置。

## 範圍與公平性

- 使用上一批相同的 `product-052.json`、`memory-e052.json`、五個植入錯誤及兩項複合題目，不重製 Memory、不修改原始匯出。Memory 覆蓋至正式訪談序號 104，現有正式歷史到 105。
- 近期按[正式組裝規則](../../../../../apps/api/src/caliburn/features/interviews/queries.py)取 `(已整理上界, 正式歷史上界]`；起點若是員工發話，另保留前一則顧問引導。此素材的起點 105 已是顧問發話，因此不額外預載 103／104；不是任意指定最後幾輪。
- 兩組都知道原話查閱界線為 1–105。近期組被省略的原話仍可查回，Memory 覆蓋不表示原話不存在或已被模型讀過。兩組不放入舊 reasoning、工具結果、原生 compaction 或前一格答覆。
- 共同 Luna/high、產品顧問方法、研究提案工具及其判準。共同指引明確說明本次是隔離核對，JD 是待核對內容，完整原話可按需回查；不要求近期組一定讀 Memory，也不要求完整組固定查閱。
- 相同两題、每題兩次重複，共八格；第二次交換先後順序。每格獨立起始，只在同格工具往返保留原生接續。評分準則不送入模型。

第 105 則顧問答覆及既有 JD 已含部分正確資訊，可能降低題目難度。這批是既有 JD 的更正／補充探測，不是从空白訪談到完整 JD 的端到端驗收，也沒有觸發 128K／160K 壓縮；不能據此宣稱 Memory 在壓縮後必然保留所有事實。

## 如何判讀

沿用上一批凍結的 21 個核心判準：更正週一 08:50、其他工作日 08:35、09:10 交付、驗收嚴格大於 5% 與批次分母、次月第一個工作日交表；區分設備備品比例、召回判斷權、休假交接、保存年限與冷藏門檻的未知等。

分開核對：

1. 套用提案後的相關 JD 及結論是否符合原話，精確數值、適用範圍、責任和未知是否正確。
2. 修改的完整欄位所選直接引用是否支持全部事實；形式有效不等於足以支持內容。
3. 實際起始及累計輸入／輸出／推理／快取 tokens、工具類型、讀取範圍、回傳字數、重複閱讀、耗時與估算費用。

較小起始 Context 不自動算品質改善；若為找回資料而增加工具往返，須計入累計用量。若正確性持平才討論用量取捨；若近期組少讀就漏事實，照實記錄。兩次重複及單一合成職位只提供局部證據，不作統計顯著性推論。

Memory 由前批自然產生，其已付前處理成本沿[前批成本分析](../memory-added-value-2026-10-04/live-01/memory-preprocessing.json)另列，不重算為本批新費用，也不能說 Memory 沒有成本。兩批的快取狀態可能不同，本批仍記錄各格實際快取，不只比較總 token。

1. **近期投影**：先以反例確認不能漏回舊原話、不能與共同 JD／題目不同；歷史工具仍可查到早期訊息。另測近期起點為員工時的前問保留。
