## 讀了什麼，引用了什麼

完整組共四次原話讀取；近期組共 14 次情境正文、四次理解正文、四次導覽與 14 次原話讀取。**三份近期提案都選原話直接引用，沒有直接引用 Memory。**本次未要求模型一定使用 Memory，因而能觀察它讀完整理資料後，又回頭查原話的額外負擔。

較少的起始資料並未自動變成較少的累積 Context：近期組四格均讀到同一份整體工作理解（單次回傳 6,465 字元），又讀部分情境和對應原話。導覽已預載仍被重讀，還有部分相互重疊的原話選取與區間。`repeat_reads=0` 只代表沒有完全相同的工具名＋參數重送，**不代表沒有語意或區間重複**。

保存年限待確認的資訊已在 Memory 情境與理解正文中，第一次責任題仍沒定位到原話 56。問題因此不只是「Memory 是否記住」，還包括導覽能否指向需要的事實，以及顧問讀過分析後，是否仍須展開原話。具體路徑見語意判讀第四節。

## 能支持與尚不能支持的結論

1. **本次觀察：**改用近期＋Memory 可降低首次輸入；在這兩個指定核對題中，目前策略讀取更多、累計輸入與生成估算費用較高，且一格未交付。尚未顯示整體 Context 或完成率的優勢。
2. **不等於 Memory 沒有用途：**Memory 保留了細節、來源鏈及未知，提供完整原話之外的整理視圖。這批只比較一次核對的替代價值，不測跨批延續、長期組織分析或經多次摘要後的能力。
3. **也不等於完整原話永遠最佳：**這份來源原文約 10,834 字元，單次全部材料可容納；已有 JD 和第 105 則答覆含部分正確內容。若不再能容納全部原話，現有優勢可能不同，不能由本批推論。
4. **核心答案正確，不代表全稿一致：**已交付格的凍結判準均通過，但完整欄位仍有引用不足，近期組也漏對齊冷藏責任的同任務子項；核心判準的分數不能代表完整 JD 品質。

既有 Memory 四批生成估算費用 US$0.114234600，見[前處理原件分析](../memory-added-value-2026-10-04/live-01/memory-preprocessing.json)。該數字包含舊流程累積的 App 訊息負擔，不能當成已優化 Memory 的固定成本；本批沿用已生成的資料，未重製或再次支付，前處理成本另列。

## 下一步建議

**先改善閱讀路徑，不再直接加跑相同設定，也不據此刪除正式 Memory。**

可用已保存反例，先離線檢查三件事：導覽是否涵蓋影響工作判斷的範圍與未知；已核對的 Memory 能否直接作為 JD 依據，而非一律展開所有原話；修改任務時，是否漏對齊相關欄位。再依結果提出最小 prompt／工具說明調整與有界比較，無須擴成新 agent 或搜尋平台。
