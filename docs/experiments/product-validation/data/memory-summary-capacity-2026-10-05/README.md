## 1. 可用資料與實測界線

本次只讀既有 JSON 原件，保存檔案大小、SHA256、來源數量與先前計數於 [材料核對](material-inspection.json)。沒有呼叫模型或資料庫；沒有重跑已停止的 main-03。

| 材料／觀察 | 核實內容 | 可支持的用途 |
|---|---|---|
| e001–e052 成功來源 | 52 則員工發言，共 105 則正式訊息，文字共 10,834 字元；員工原文 4,068 字元 | 固定的主要工作、早期數值、後期更正與補充 |
| e052 Memory 快照 | 12 個工作情境、1 個工作理解；來源上界 104 | 沿用已保存的自然整理產物，不為新題補答案 |
| e001–e060 成功來源 | 60 則員工發言，共 121 則正式訊息，文字共 13,245 字元 | 補充觀察與查核；不能讓 e053–e060 的舊答覆洩漏到新回提題 |
| 61 段員工原文預載反事實 | 完整指引、工具及全部員工原文的舊實測為 11,919 input tokens | 員工原文本身仍可容納；不是完成 61 段的完整 Agent 歷史 |
| 舊 e061 請求 | 計數從 150,394 到 172,606；有 61 則 App 訊息、801 個訪談副本及 opaque 狀態 | 真實的完整 Context 壓力；不是原話量大到放不下的證明 |

字元數不換算成 provider tokens。以上 token 數沿用 [容量預檢](../compaction-long-interview-2026-10-04/preflight-02/result.json)及 [停止核對](../compaction-long-interview-2026-10-04/main-03/stopped-reconciliation.json)，不是本次新量測。

容量須分三個概念：

- **產品工作門檻：**輪前 128K、完整 Step 160K，沿用現有設計；不是模型硬上限。
- **模型硬容量：**本次查閱的 [Luna 官方資料](https://developers.openai.com/api/docs/models/gpt-6-luna)列出 1,050,000 token 視窗、922,000 最大輸入與 128,000 最大輸出。實際准入仍須核對完整請求及輸出預留，不能發必定超量的請求。
- **早期原話是否可見：**原話可以存於 DB，卻不放在本次請求。這能測按需取用，不等於已跨越上述任何容量界線。

本次將「容量壓力」優先定義為**完整有效 Context 超過產品 128K 工作門檻，需要在合法輪前交界濃縮**。若要再主張原始訪談超過 922K 輸入容量，必須另有足量、連貫且非重複灌水的材料與計數；目前資料尚不支持這個主張。

## 2. 先導：先比較兩種資料的取用

先導回答：**早期原話退出起始 Context 後，三層導覽與按需閱讀，相較單層完整工作摘要，是否更能保留判斷品質並減少閱讀負擔？**不在這一步宣稱超容量或新輪前摘要已驗證。

### 共同來源與兩組資料

- 原件使用 e001–e052 的正式訪談，只取序號 1–104 作整理來源；105 是整理上界後的顧問答覆，只作兩組相同的近期資料。
- 三層組使用上述固定快照，先提供情境／理解 map，正文按需讀取。採目前已驗過的「理解充分即停止；具體缺口才向下查」原則，不換用失敗的 JD 保留候選。
- 單層組從同一份正式訪談自然整理。按 e012、e028、e044、e052 四個既有邊界更新同一份 Markdown 摘要；每批使用前摘要及新有效來源，不使用三層產物、e053 以後的舊答案或評分檔。
- 單層摘要須保留工作範圍、精確數值與時點、條件例外、責任、更正適用範圍、未知及原話定位。不能刻意寫成只有大意的弱基準；長度與用量照實記錄，不事後刪內容以改善效率數字。
- 核對時兩組共用 Luna／high、題目、研究交付格式、原話按需工具及執行上限。不要求唯一工具序列，不禁止某組合理補救。
- 起始不放早期原話、舊 JD 正文、舊工具結果、reasoning 或 compaction item，也不使用 `previous_response_id`。避免答案其實已在 JD 或舊壓縮狀態內，卻被歸因於 Memory。單格的工具往返仍完整保留原生接續。

資料組織的差異是本次比較項目：三層先看 map、再按需讀正文；單層先取得完整摘要。不能把起始 token 強行拉到相同，或隱藏三層讀回正文的累計成本。這是整理產物的取用對照，並非兩套端到端整理管線已在相同長歷史下重跑。

### 題目與判準

第一小批沿用 [更正與責任兩題](../memory-reading-policy-2026-10-04/live-01/cases.json)的核心內容，各做兩次、兩組共八格；第二次交換組別順序。每格為新 Context，跨格不帶答案。題目中的「JD」須在外送前統一改為工作事實核對，不要求修改不存在的草稿；改動只調整交付表面，不補上正確數值或答案暗示，兩組得到同一句題目。

這兩題保留原 21 項核心條件，涵蓋週一 08:50／其他工作日 08:35、09:10 交表、不良比例分母與 >5% 邊界、獨立安全處置、帳齡表更正及召回權責、冷藏門檻與保存年限未知。改為不提供 JD 後，「保留其他已正確欄位」兩項不再適用，外送前另凍結 **19 項事實／未知判準**；不把未施測欄位算通過，也不與舊 21 項總分直接合併。標準答案與支持序號只留研究側。

「之前那張表」及省略主語的追問留在後續連續互動試驗。它們需要真實可見前問及施測資格，不能塞進每格獨立的新 Context 後，假稱已測到跨輪指涉。

### 先導用量與停止建議

使用者已同意本次先導上限 **US$0.10／20 分鐘**，包含單層四批整理、計數、兩組閱讀及失敗嘗試；仍計入原累計 US$2。前批結案後累計估算占用為 **US$1.136057105**。計時從本批第一個外送嘗試開始，兩組共用，不因切換組別或失敗重設；這是本機護欄估算，不是帳單金額。主比較仍未授權。

先重用既有研究護欄及 SDK 接線，不新增產品預估金額攔截。擬維持每個閱讀格最多六次模型回應、整批最多 32 次生成／64 次外送，四次摘要生成也計入；達任一界線就保存並停止。使用相同輸出預留、先計數再准入、關閉 SDK 自動重試。外送前還須凍結實際 Prompt、工具、題目、計畫及程式雜湊；本頁不是外送 manifest。

## 3. 主比較：輪前濃縮後的續用

**後續方向已調整（2026-10-05）：**本節原規劃尚未執行，保留為沿革；下一批依[原話／摘要／Memory 三組換窗設計](../../2026-10-05-context-reset-comparison-design.md)。不再先替所有組加入可能含答案的共同接續摘要。已完成先導及凍結 executed protocol 不變，以下內容不作新批次外送依據。

先導若可完整交付，才進入這一步；不因某組先導得分較高就選題或保證主比較勝出。這一步回答：**完整歷史已需濃縮時，採相同輪前接續策略，三層與單層的早期資訊保留、使用及總成本如何？**

依 [已確認但未實作的摘要設計](../../../../specs/2026-10-04-context-summary-and-compaction-design.md)，輪前 App 文字接續摘要與長期工作摘要是不同用途。主比較須先完成以下準備，不能從去敏 trace 硬拼一條看似完整的原生歷史：

1. 取得可合法接續、工具已配對的有效視窗 W，記錄來源位置；以完整請求計數確認確實達 128K。未完成的 e061 不冒充已完成工作，失敗分支不混入 W。
2. 研究用輪前摘要 Prompt 先凍結；由相同 W 產生共同接續基底 S，兩組使用完全相同的 S。摘要請求不含當次新問題、評分答案或後續來源。
3. 保存摘要後以 S 加同一份近期資料建立新輸入，舊 W 不再附回。不得偽造 compaction item，或裁剪 standalone compact 的 canonical output 來取得小窗口。
4. 另核對 S 保留了哪些被考察事實。S 已含答案的題仍照實呈現，但不得將兩組的成功全部歸因於外部 Memory；不能為製造差異事後從 S 移除答案。
5. 起始資料除固定 Memory／工作摘要外，其餘相同。核對早期原話、舊 JD、舊工具及 opaque 狀態是否仍另行預載；原始訪談仍可按需回查，不刪資料庫原件。
6. 在共同條件下測早期精確回提、局部更正、補充、跨題切回及指涉澄清。多次摘要與輪中原生壓縮須各有實際觸發、完整採用及後續使用證據；未發生就寫未施測。

若合法 W 已無法取回，從公開去敏 trace 中的加密長度或 hash 不能還原 reasoning／compaction，也不能重新編造它。此時只能做另一個明確命名的「來源文字整理」試驗，不能稱為原生接續或摘要後恢復已驗證。

完整主比較的資料、Prompt、次數、費用及時間尚未凍結，也未取得新付費授權。本次不實作尚待定稿的產品輪前摘要，不再啟動舊四組長旅程。

## 4. 判讀：先看有效資訊，再看效率

每題分開核對事實正確、必要細節遺漏、未知／衝突處理與來源支持；允許等價表達。原話補救成功、從摘要取得、從理解／情境取得及未交付分別記錄，不能全稱為三層保留。

閱讀階段記錄起始及累計 input、output、reasoning、cache read／write、讀取工具與範圍、重讀、時間及失敗。摘要整理和三層前處理成本另列，再加總；重用既有三層產物不是「前處理免費」。同一產物的兩次使用不是兩次獨立整理實驗。

結果以配對案例呈現，不拼成一個掩蓋資訊遺失的綜合分數。較少讀取或 API 成功都不能代替品質；相近品質但更多用量，也須如實列出。兩次重複只供局部穩定性觀察，不作跨職務普遍優越或統計顯著性主張。

## 5. 方法依據及本次紀錄

- [OpenAI Memory Evals](https://developers.openai.com/cookbook/examples/agents_sdk/context_personalization#memory-evals)：區分捕捉、整理與取用，使用共同 harness 及完整 trace。借鑑評測分工，不把偏好記憶的「最新優先」直接套成所有工作事實的衝突規則。
- [LongMemEval](https://github.com/xiaowu0162/LongMemEval)：區分資訊抽取、跨段推理、更新、時序及未知；資料長度可擴充。借其能力分類與證據隔離，不宣稱本次使用其公開題庫、完成其 benchmark，或把 Llama tokenizer 的資料長度當成 Luna 計數。
- [Anthropic Context Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：區分接續濃縮、外部筆記與按需載入，先保留高訊號資訊再降低冗餘。這是公開工程方法，不是三層必然較佳的保證。
- [OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction#standalone-compact-endpoint)：standalone output 完整承接；server-side 接法不同，不能混用其可裁切前綴的說明。

準備時，一次過廣的 `rg` 搜尋匹配到大型 JSONL trace，工具截短了輸出；後續只查具名 Markdown／Python 與小型 JSON 投影。沒有修改原trace，也不將截短輸出當成完整分析。八個原件雜湊及離線核對保留原樣；付費原件另存`live-01`、`live-02`。本次估算占用US$0.039277570，含失敗、count預留及接續，累計US$1.175334675；未啟動主比較或追加外送。
