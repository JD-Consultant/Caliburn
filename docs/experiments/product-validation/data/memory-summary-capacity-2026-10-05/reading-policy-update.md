# A 與 Memory 工具說明的配對取用比較

本批已完成八格，**未採用候選指引**。候選沒有減少總讀取次數或累計 input，部分既有細節交付也退步。已撤回本輪候選文字，保留原先已採用的 A 停止策略；B2、Memory 產物與 Runtime 不變。原件在 [reading-policy-01](reading-policy-01/manifest.json)，[逐項判讀](reading-policy-01/semantic-grade.json)與[用量稽核](reading-policy-01/usage-audit.json)分開保存。

本批測試一個問題：同一份理解已保留必要資訊時，明確說明「何時讀、何時不讀」能否減少無必要展開，同時保留答案品質。B2 指引與先前 Memory 產物不改；理解正文中的回查線索仍保留，不能用修改材料製造效果。

## 改動與共同條件

控制組採 `live-02` 已凍結的 A 指引與 Memory 讀取工具。候選組採目前 A 指引、工具與參數說明；共用相同研究補充指引、六個工具的名稱／輸入結構、研究提交工具、105則正式訊息、12個情境與1個理解。修改僅限文字說明，不增加 Runtime 讀取證明、版本參數或新權限。

兩組皆以理解導覽定位；缺少有效定位時可再取導覽。理解已涵蓋本題事實、精確條件與責任界線且無已知衝突時可停止。來源清單與正文回查提示是可選入口，不是必讀清單。具體缺口才向下查，每次取回後再判斷是否足夠；已明確保留的未知，有待查線索才回查，否則保留或追問。這是 A 的取用原則，不減少 B2 分析新增與變動情境的責任。

沿用原兩題與19項判準，各重複兩次；共8格，第二次交換組別順序。每格以同一份 map、近期訊息與題目建立新 Context，不帶前格答案、舊 JD、早期原話或舊加密狀態；格內完整保留原生 Responses items 與工具結果。Luna／high、輸出預留8192、最多6次回應、每次最多24個工具呼叫均相同。

## 執行與判讀

本次授權為新增最多 US$0.10／20分鐘，計入原累計 US$2。此前估算占用 US$1.175334675。共用一個計時與預算，不按格重設；計數、失敗與未知用量預留都計入。本機估算不是帳單價格，與產品不以金額攔截執行的規則分開。達界線保存並停止，不補跑。只讀固定 JSON，沒有產品／資料庫寫入，不啟停正式服務。

外送前由 `reading_policy.py --prepare` 保存材料、題目、提示、工具、來源雜湊與 manifest；`--live` 校驗雜湊並禁止第二次啟動同一資料包。程式重用既有 SDK、費用及速率護欄，關閉自動重試。API 完成不代表語意通過，輸入較少也不等於品質改善。

先按原19項逐格判讀，再比較工具種類、範圍、重讀、來源支持與 input／cached／output／reasoning tokens。凍結判準以外已發現的「前一天→前一工作日」產物偏差另記，不混入原分數，也不因效率改善而忽略。這一小批只支持固定材料的取用判斷，不取代跨職務、超容量、JD 寫入或 B2 改寫驗證。

## 設計依據

本批採上述公開原則，不宣稱兩家平台保證相同效果。以下結果與離線驗證另行記錄，原 trace／manifest 不改寫。

## 結果與取捨

兩組各完成4格。19項判準各受測兩次，分開計算完整、部分及錯誤交付，不以 API 成功或引用格式合法充當品質。完整答覆與追問一起判讀，允許等價說法。

| 模型回應 | 12 | 13 |

input 包含 cached，output 包含 reasoning，不能再相加當作額外總量。候選初始 input 多374 tokens；累計多381（約0.3%），未改善總讀取量。候選 output 少約15.7%、生成估算少約8.3%，但細節交付退步，不以這兩項選它。

更正題兩組均交付11項指定資訊，且都讀取4–5個情境。候選第一次仍回查6則原話，第二次沒有原話呼叫；控制兩次分別查13及6則。題目要求分清早期與後續說法，原理解未列舊帳齡表交付日，回查序號42有用途；不能把全部原話閱讀都算成浪費。但更正題還讀到保存年限等無關訊息，來源選取仍有縮小空間。

責任題兩組都停在理解，直接引用實際讀過的正文。控制兩次均有7項完整、1項部分；候選分別為5＋3及6＋2，漏寫了部分批號的查證／不自動擴大召回，以及一次已知的財務確認窗口。它們都存在於理解正文，是答案交付遺漏，不是 Memory 捕捉遺失。所有責任題都漏常溫／冷藏的區別；此細項已在原判準，但未明列於題目，保留嚴格評分也明說適用限制。

判準之外，序號14的「前一天」已被既有理解寫成「前一工作日」，四個更正答案都沿用。這是事前已知的產物偏差，本批未改 B2，沒有解決它。不能因原19項無錯誤交付而稱所有工作事實完全正確。

本批共25次生成／50次外送（含計數），約468.5秒，沒有失敗、超限或未跑格。估算占用 US$0.023621135，含生成 US$0.021121135 與25次 count 的保守預留 US$0.0025；累計 US$1.198955810，未超授權。這不是帳單金額。新 Context 每格只有一則 App 資料與同題輸入，配對初始資料完全相同；工具往返沒有再次塞入 App 資料，未帶其他格答案或舊壓縮狀態。本批沒有容量壓力或 compaction，不能作超容量結論。

因此撤回本輪 A／工具／參數說明候選，只保留此前已採用的原版；不是改 Runtime 來強迫停止，也未更動 B2。候選全文與工具保留在資料包，產品檔案在結案後恢復，所以 manifest 的當時產品雜湊不會等於目前檔案；不改 manifest 以掩飾版本。輸入、答案及 trace 的原件雜湊保持不變。

下一個可分離的問題是理解如何呈現「已知事實／未知／可選來源」：不把每節寫成回查指令，且逐項核對精確時點不被語意改寫。但仍須先研究、凍結 B2 候選並以同一來源另作整理品質比較，不能將本批當成 B2 已驗證。暫不追加付費請求。

## 離線驗證與實作紀錄

- 契約產生器同步三份 description-only schema，未改 shape、名稱、權限或 Runtime；候選測試後由同一產生器恢復原版。
- unit／contracts共1,175項、研究材料／凍結9項通過；候選與原版的相關角色／工具／讀取契約另核對。`pnpm build`含契約一致性、TypeScript與Vite通過；保留既有 chunk-size警告，不聲稱 Web 性能已驗。
- Ruff及格式檢查通過。新增研究凍結測試可拒絕材料改寫與混入新參數；初次因研究模組尚不存在無法收集，不當作產品反例的 Red 證據。文案變動的效益由真模型對照判斷，不用字串測試冒充。
- 初次建置／測試被 Windows sandbox 的 uv／Temp 權限拒絕（1,154通過、21項fixture error）；核對都是存取錯誤後，以既有命令正常權限重跑通過，沒有為環境限制改產品程式。
- 獨立唯讀審查確認候選 shape及角色權限未變、B2職責未被減少；87項相關離線測試通過。這只支持契約正確，不代替上表的取用效果。
- `offline-reading-policy-01`是外送前的準備版本；修正研究測試的 import 格式後，重新凍結 `reading-policy-01`才首次外送。兩份準備原件均保留，前者沒有付費 trace，不作模型成果。
