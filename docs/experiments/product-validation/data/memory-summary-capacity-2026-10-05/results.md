# 三層Memory／單層摘要：八格取用先導結果

**兩種整理產物都能保留本批受測資訊，三層可按需讀取並直接引用，但本批未顯示三層優於單層。**兩組各完成四格，嚴格核對38個判準機會，各有35項完整、3項部分回答，受測項內未見錯值或編造。三層起始input約減半，累計input卻為單層3.31倍，仍有不必要的展開與回查。

這是52則員工發言的**整理產物取用先導**，不是超128K試驗，也沒有執行新輪前摘要或原生Compaction。結果不更動正式產品；未為追求勝出再換題、重跑讀者或調整Prompt。

## 1. 怎麼比較

整理來源為正式訪談1–104，兩組共用近期顧問答覆105。三層使用已保存的12個情境、1個理解，起始只給map，正文按需讀；單層由同一來源依24／56／88／104四個邊界更新完整Markdown摘要，起始給完整摘要。兩組都可按需回查原話。

Luna／high、共同閱讀指引、兩題、交付schema及原話工具相同。各題重複兩次，第二次交換組別順序；每格重新建立Context，不帶早期原話、JD或其他格的答案／opaque狀態。單格內完整承接原生回傳及工具結果。題目和19項判準凍結於[付費manifest](live-02/manifest.json)及[cases](live-02/cases.json)，標準答案不送入模型。

判讀分成兩階段：獨立離線核對整理產物是否保留原始事實，再由主評讀者逐項比較八格交付。使用完整findings與questions，容許語意等價；關鍵條件缺少列「部分」，與錯值／編造分開，不用關鍵字命中當正確。來源存在及實際讀取另核對，不因看到map或API200就算已用正文。

## 2. 事實與細節的交付

受測產物各保留19／19項，詳細原話與產物位置見[產物核對](artifact-review.md)。八格讀者不是次次完整交付所有細節：

| 核對題 | 三層第1次 | 單層第1次 | 三層第2次 | 單層第2次 |
|---|---:|---:|---:|---:|
| 更正、精確數值與適用範圍（11項） | 11完整 | 11完整 | 11完整 | 11完整 |
| 召回、交接、保存與溫度（8項） | 6完整＋2部分 | 7完整＋1部分 | 7完整＋1部分 | 6完整＋2部分 |
| 兩題合計（19項） | 17完整＋2部分 | 18完整＋1部分 | 18完整＋1部分 | 17完整＋2部分 |

完整數值包括週一08:50、其他工作日08:35、09:10交表、嚴格`>5%`／`=5%`界線、每批驗收件數與使用中設備數量兩種分母，以及次月第一工作日／週五16:00不同時點。

部分回答的原因可直接查[逐格判讀](semantic-grade.json)：

- 三層第一次召回答覆說要查證、不認定安全，但未明確交付「未列批號不能自動全部列召回」。
- 單層第二次保存答覆保留年限未知，卻未交付需向財務確認。
- 四格邊界題都沒有重述「常溫退貨沿用倉庫狀態」。溫度／年限沒有填造數字；但依凍結複合判準仍列部分。常溫分工未在獨立問題中點名，因此這項也有題目涵蓋不足的限制，不把它宣稱為全面回憶失敗。

判準外也有具體發現：理解將「前一天收到」改為「前一工作日收到」，讀者沿用；單層帳齡文字有「月底狀態」旁仍保留「目前狀態」的歧義。兩項不在事後併入總分，但保留在產物核對，後續可用來測條件保留與局部摘取。

## 3. 按需閱讀有沒有省下負擔

以下為四格閱讀合計，不含前處理。input包含cached tokens，不等同全部按原價計費；估算生成費已依cache read／write及output核算。

| 閱讀指標 | 三層 | 單層 |
|---|---:|---:|
| 各格起始input | 5,325–5,340 | 10,606–10,621 |
| 累計input | 140,327 | 42,454 |
| output（含reasoning） | 10,240 | 7,196 |
| reasoning | 5,301 | 3,246 |
| cached input | 99,875 | 24,385 |
| 模型回應次數 | 14 | 4 |
| 讀取工具呼叫 | 18 | 0 |
| 原話回查 | 2次、共20則 | 0 |
| 估算生成費 | US$0.0111742 | US$0.006100175 |

三層起始input減少49.76%，但累計input增加230.54%，閱讀生成費約1.83倍。工具結果與去敏請求留在[trace](live-02/trace.jsonl)，[用量稽核](live-02/usage-audit.json)由完整回傳逐項核算。

讀取路徑說明了差距，而不是單靠總量猜測：

- 兩次更正題都先讀理解，再展開五個情境；第二次又讀20則原話，最後改引用原話。因原理解已保留19項，不能把這格歸為「不用原話也成功」。
- 兩次邊界題都重讀已提供的理解map，再讀理解，並直接引用該理解。引用正文確實已讀，並非只見名稱。
- 單層四格均使用完整摘要及共同近期資料，直接選摘要中來源序號，沒有原話工具呼叫。引用序號不等於本次實際讀過原話。

本例只有一個理解正文涵蓋多個工作，約5,000字元；兩題也跨多項工作。這樣的資料形狀沒有顯示細粒度分層按需取用的優勢。結果支持進一步改善取用策略、分析粒度與停止判斷，不支持立即刪除三層設計或宣稱單層在所有長訪談都較好。

## 4. 整理成本與本批護欄

單層四批完整整理的input為23,377、output為25,214，估算生成費US$0.014631020。第四批首次用8192輸出預留碰到上限，失敗回傳仍計入US$0.005072175；未把截斷正文當成成功摘要。保留前三批，只將第四批預留提高到16384後取得完整產物，讀者仍8192，指引與題目未變。這是外送後修訂，不能稱為原設定一次成功。

重用三層四批的歷史生成用量另由[原trace投影](historical-capture-cost.json)查回：input2,370,081、output74,774、可核算生成費US$0.114234600，已包含在之前累計，不重複加帳。它使用當時產品工具loop及累積Context，與本次單層文字整理不是相同端到端接線；數字只交代重用產物不是免費，不用來聲稱公平的前處理勝負。

本批包含所有成功生成、失敗及count行政預留：**46次外送、23次生成（含1次失敗），估算占用US$0.039277570**；原開始到接續完成約924.87秒。累計估算占用為**US$1.175334675**，低於原US$2。count保守占用US$0.0023不是provider帳單。`live-02`帶入`live-01`費用、次數及原時計，沒有重給20分鐘或US$0.10。

## 5. 可以怎麼用這份結果

已支持：早期原話不在起始Context時，這份Memory仍可透過map找到正文、保留受測資訊並作來源；完整單層摘要也能做到。**資料保留、模型取用與累計效率是三件不同的事。**本次不再只看起始Context變小，就斷言總效率改善。

尚不支持：超128K後的自製輪前摘要、原生Compaction效果、跨多次壓縮、普遍優越或統計顯著性。共同近期105也直接復述部分考點；不能將全部正確答案歸因於外部Memory。兩次讀取重複不是兩次獨立整理，這是同一職務來源的局部觀察。

下一步先離線準備合法且完整配對、超128K的工作Context與共同輪前接續摘要，再以相同資訊條件比較三層／單層。若要觀察按需優勢，須有足夠多個可獨立取用的主題，不靠重複App資料灌大Context，也不事後刪掉摘要內答案製造勝負。主比較尚未授權，不追加付費或修改正式產品。
