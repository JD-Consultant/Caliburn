# 2026-10-08：指引與指引加工作計畫的一對倉儲比較

**本次沒有觀察到加入 Plan 後，最終 JD 出現可辨認的整體品質提升。** 兩組都寫對已取得的主要工作、冷藏與旺季條件，以及盤點調帳、新人上線權限的更正；也都尚未取得先到期先出、Excel 差異核對與搬運重量判斷等必要專業資訊。Plan 的保存與接續有實證，不能據此宣稱更完整或已達滿分。

本報告供下一輪產品討論，產品權責仍沿[架構 §2.1](../../../../../architecture/system-boundaries.md#21-長任務的元件分工)、[ADR0082](../../../../../adr/0082-consultant-jd-work-plan.md)及[詳細設計](../../../../../specs/2026-10-06-consultant-interview-planning-and-focus-design.md#10-jd-工作計畫內容與用法)。工程驗證與文件維護沿[施工證據](../../../../../plans/evidence/jd-work-plan-2026-10-08.md)。本結果沒有更動 Memory／Changes 的責任。

## 實際怎麼比較

**這次比較同一版優化後顧問指引，有沒有加上 Plan；不是舊 prompt 與新 prompt 的比較。** 受訪者及評閱者均為測試安排，沒有真人受訪者或人工專家評分。

| 條件 | 只有指引 P1 | 指引＋Plan P2 |
|---|---|---|
| 顧問模型、共同指引 | GPT-6 Luna／high；相同 `CONSULTANT_INSTRUCTIONS` 與 `FOCUS_INSTRUCTIONS` | 相同 |
| 原有能力 | 原話、Memory、JD 讀寫、Changes 與原生接續 | 相同 |
| Plan | 不提供正文或工具 | 增加專屬使用說明、read／edit 工具、持久 Markdown 與新輪／壓後全文接續 |
| 起始資料 | 獨立新職務檔案，空白 JD／Memory，相同倉儲開場及隱藏事實；RAG 關閉 | 相同，Plan 初始未建立 |

介入包含整套 Plan 支援，不能再拆稱已分別證明 Markdown 格式、持久保存或其中一句提示的效果。配置及工具差異沿[凍結 manifest](manifest.json)與[組別建立程式](../../frozen_manifest.py)核對。

1. **讓 Agent 自己訪談。** 兩場都走實際 App 的 HTTP、資料庫、Memory 與模型 API。Agent 自行選問、讀資料、寫 JD；沒有逐輪指定它問哪一題。這不是人工操作瀏覽器的使用者測試，介面工程驗證另列。
2. **回答受固定材料約束。** 員工背景與可披露事實先凍結。匿名 Codex AI 裁決者看實際子問、必要近期原話及披露紀錄，選出當下可回答的事實；程式用固定答案組合回覆，或回傳未知、拒答、澄清。裁決者不看組別、Plan 或另一場成品，也不能自由編造新員工事實。兩組的規則相同，但提問順序與逐輪回答不同；不是重播完全相同的訪談。流程見[施測程式](../../journey.py)與[披露規則](../../disclosure-policy.md)。
3. **加入相同類型的中途事件。** 盤點暫時答不出、切換主題後，材料提供「現在想起一些，可以再說明」的可見線索。第 10 輪完成後，模擬人工編修者依公開背景，透過正式 HTTP 修改收貨任務；兩場均保存成功。這能觀察收到線索後返回及改稿後接續，不能當成完全無提示的自主回訪。
4. **以共同上限收束。** 兩場各完成 20 輪及 Memory 收尾，第 20 輪收到相同結束文字；兩場中途亦各有一次繼續訪談提醒。一輪可含多次模型與工具呼叫，因此不是各呼叫模型 20 次，也沒有證明 Agent 能自然判斷整份訪談何時完成。
5. **先匿名判品質，再解盲看機制。** 另一位獨立 Codex AI 評閱者依分析、顧問及 JD 指南，查看匿名正式 JD、已取得的員工原話、固定引用與公開改稿背景；不看組別、Plan、工具用量或費用。先分別鎖定個案結論，再鎖定配對判讀，最後解盲。判準包含工作覆蓋、責任與判斷、條件與更正、成果交接與能力、無據內容與一致性、引用支持。隱藏完整材料只協助辨認尚未問出的範圍，不算 JD 的事實依據。品質鎖定後才另查 Plan 保存、返回行為及用量。

有效正式樣本只有**同一合成倉儲職位的一對，P1、P2 各一場**，依 P1 再 P2 的順序執行。先導與中止案例不列完整品質樣本。沒有重複抽樣、平衡執行順序或人工專家複評；模型隨機性與訪談路徑差異仍在。因此「本對無可辨整體差異」是有限的品質判讀，並非統計等效、Plan 無效或一般職位皆相同的結論。

## 機制與使用界線

P2 共 28 次 Plan 編輯，27 次更新成功；一次尾 hunk 無修改的 `invalid_patch` 在同輪修正成功，拒絕時正文未變。27 份成功 diff 全部可重放成正式 Plan，首輪建立，後 19 輪的首個模型 request 都含前輪精確全文。沒有主動 read Plan 呼叫，因每輪已提供全文。P1 未洩漏 Plan 正文或能力。

P1／P2 分別有 1／2 次新輪開始前的原生壓縮，P2 壓後仍接前輪精確 Plan。未形成執行中途的 within-Work C、bound projection 或原排第二配對的 45K 受控情境；這些不能由此次兩案宣稱通過。既有工程回歸另有其驗證範圍。

人工編修後，P1 第 12 輪與 P2 第 11 輪都讀到修改後的目前稿。兩案第 14 輪的人工差異查詢均回 0 操作，不能說 Agent 讀到了該次 diff；成品一致不代替這一機制證據。這是本次實際使用範圍，沒有判定 Changes 未實作，也不把它改為 Plan 的依賴。完整索引與 142 份原件雜湊見[機制稽核](mechanism-audit.md)。

## 對下一輪討論有用的過程證據

先依公開事件鎖定 11 項機會，才讀 Plan，沒有只挑筆記中的項目評量；清冊與逐項工具定位見[語意稽核](behavior-audit.md)。

- **有線索後返回盤點，兩組都做到了。** 員工說想起後續流程後，兩組同輪返回並取得核准、財務調帳與結案核對；P2 Plan 確實呈現未知、可返回、待入稿與已入稿的轉變，但不能把共同出現的成功歸為它的獨有效果。
- **Plan 能表達已知未完成。** P2 有保留新人更正後待修的任務、能力與協作，實際成品跟著修好；本對未形成跨輪打斷後靠 Plan 找回這類工作，該收益仍未觀察。
- **進度短句不保證全稿無漏。** P2 第 15 輪 Plan 已記通讀核對，但第 4 輪已知的持證同事協作到第 20 輪才補入；P1 也到最後才補已知的包裝區複核協作。兩組最終補妥，仍須檢查實際 JD。
- **未知與停止界線整體有保留。** 年度盤點尚不清楚的分區、財務表單未被猜補；未見反覆追問同一答不出命題。兩組收尾列未知、尊重停止，不能把「已知內容已核對」說成宣稱全部未知已清。

值得討論的假說是：安排是否偏重「把已知內容編修齊全」，而沒有持續辨認重要但尚未探索的工作方法。P2 曾留下「檢視必要能力漏寫」，後來補入既有方法並轉回收貨通知、單據來源等細節，未留下具體的未探索專業方向。兩組都未直接探索批號效期處理原則、差異比對方法或重量判斷。這支持討論選問與全案覆蓋，尚不支持新增固定任務 schema、另一位 planner 或改變資料權責；更不能要求 Agent 從隱藏 oracle 猜出答案。
