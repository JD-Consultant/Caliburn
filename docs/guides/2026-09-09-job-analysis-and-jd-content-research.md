# 完整工作分析與高品質職務說明書

本文整理完整工作分析、JD 品質目標與本組指南的分工。研究基準日為 2026-09-09，另含 2026-09-10 的格式比較；內容建議可隨新證據修訂。現行產品為 API／Web App，採關聯式 JD 編輯與 B1 → B2 → 發布的 Memory 流程；資料、工具及生命週期契約見[現行規格](../specs/README.md)，狀態見[目前決策](../current-decisions.md)。指南提供方法與示例，不另定產品 schema。

[欄位指南](2026-09-09-jd-field-and-writing-guide.md)說明任務敘述、成果與要求如何分開閱讀，以及知識／技能如何保留用途；[完整格式比較](../research/work-analysis/2026-09-10-jd-format-review.md)與[內容及保存核對](../research/work-analysis/2026-09-10-jd-format-quality-and-storage-review.md)保留當時的研究依據，不作現行技術契約。

[樣稿 r2](2026-09-09-frontend-engineer-jd-sample.md)及[內容複核](2026-09-09-jd-sample-basis-and-review.md#10-完整閱讀版-r2-與核心文檔一致性審核)提供可對照的完整例子。[十份雇主比較](../research/work-analysis/2026-09-09-employer-job-document-comparison.md)與 LED 照明工程師 iCAP 參考的[核對及限制](../research/work-analysis/2026-09-09-job-analysis-international-evidence.md)是研究證據，不能當作員工真實資訊，也不要求照搬其版型。

## 1. 結論

高品質職務說明書不是把所有訪談塞入最多欄位，而是：**完整理解這個人目前工作的範圍及重要細節，再寫成能代表該職位、沒有虛構或重複的文件。**

本研究沒有找到全球統一的「滿分 JD 模板」。美國 OPM 的職位描述、O*NET 的職業資料、英國 NOS 的職能標準、澳洲的訓練套件，各有不同用途。共同可學的是分析真實工作、成果／合格表現、必要專業及工作情境；不能把某體系的全部欄位、級數或評量程序變成通用 JD 必填。[官方來源與適用邊界](../research/work-analysis/2026-09-09-job-analysis-international-evidence.md)

建議採用的內容骨架是：

> 職務識別 → 職務目的 → 主要職責與工作任務 → 有資訊價值的成果／完成標準 → 所需知識與技能 → 必要的責任、協作及工作條件。

這是跨來源的**產品研究建議**，不是宣稱各家都採同一版型。各內容可以合併呈現；不預設每項都是獨立資料表、表單或 AI 必填參數。

### 完整閱讀順序與文檔關係

這組文件提供職務分析與 JD 內容的核心方法。理解方法時，依序閱讀指南、樣稿與情境，再按引用查來源；只看入口摘要或樣稿，容易漏掉方法的適用限制。

1. **品質目標：**先讀本文，了解內容取捨與品質檢查；產品現況另查[目前決策](../current-decisions.md)。
2. **如何取得與理解工作：**讀[分析指南](2026-09-09-complete-work-analysis-guide.md)及[客製化校準](2026-09-09-customized-jd-depth-and-interview-calibration.md)，理解要問什麼、怎麼分辨案例與持續責任、何時仍缺資訊。
3. **理解如何成為文件：**讀[欄位指南](2026-09-09-jd-field-and-writing-guide.md)，分清內容定義、完成要求、K／S及下游用途；不把分析面向直接翻成必填表格。
4. **看成品，再反查：**讀[樣稿 r2](2026-09-09-frontend-engineer-jd-sample.md)及[完整情境／雙向審查](2026-09-09-jd-sample-basis-and-review.md)。檢查已知工作→成品是否漏寫，以及成品→依據是否多寫；版本與內容核對見後者§10。
5. **核對為什麼這樣做：**讀[國際方法證據](../research/work-analysis/2026-09-09-job-analysis-international-evidence.md)與[實際雇主比較](../research/work-analysis/2026-09-09-employer-job-document-comparison.md)。前者說明方法、版本與適用限制，後者提供實際寫法與反例；有疑點再沿精確引用讀原文，不能只看公司名稱。
6. **連回產品契約：**資料關係、員工／AI 編輯與工具操作查[現行規格](../specs/README.md)。研究建議與產品契約各有適用範圍。

依賴方向是「**證據支撐方法與取捨 → 指南指導分析／成品 → 情境與樣稿檢查方法是否說清楚 → 審核回饋修訂指南／狀態**」；不是用樣稿的四組八項反過來制定所有職位的規格。案例／Memory→JD的概念及下游關係見本文§3，不因此新增實體層或更換記憶流程。

### 指南維護原則

- **只在負責文件改完整內容。** 分析方法改分析指南；內容語意改欄位指南；深度／問法改校準；來源及版本各留方法證據或雇主比較；樣稿只留成品；版本差異及審查發現留在樣稿審查。入口只維護摘要及路由。
- **引用方法時指向文件與章節。** 說明需要保留的效果、情境檢查及適用限制，避免把整組研究重抄到每份文件。
- **遇到矛盾先辨別層次。** 官方事實、產品取捨、虛構例子與現行產品狀態不同。方法或來源修訂不會自動取代 Accepted ADR；產品變更依[決策流程](../decision-process.md)。
- **避免重複與失聯。** 同一題在原負責章節修訂，審查沿革明標適用版本；新增獨立子題才開新文檔並雙向連回。變更後核對受影響路由、章節與狀態，不要求每次重讀無關舊長稿。

指南、來源與產品契約各自維護完整內容，避免同一規則出現多份不同版本。

## 3. 先分析工作，再決定 JD 怎麼呈現

| 面向 | 完整工作分析／可供 Memory 保留的內容 | JD 成品 |
|---|---|---|
| 對象 | 這名員工實際做的事、各案例與差異、尚不清楚的範圍 | 這個職位目前承擔的工作 |
| 細節 | 需要時能回答誰做、何時、為何、怎麼判斷、例外與責任 | 足以辨識工作、成果、邊界與專業的必要細節 |
| 案例 | A／B 各自完整，不互借細節 | 相同工作的不同案例通常不是兩個永久任務 |
| 修訂 | 新增、補充、更正、未知及適用範圍 | 隨已理解的工作修訂措辭、分組及內容 |
| 缺少資訊 | 保留有影響的未知並追問 | 不把未知猜成完整句子，不用空欄強迫造答案 |
| 下游用途 | 保留可進一步研究的依據 | 是招募、KPI、訓練的基礎，不是三份文件的合集 |

這張表區分分析資訊與成品內容。案例、理解資訊與 JD 如何保存及讀寫，依[現行規格](../specs/README.md)；指南不另定資料層或 Memory 流程。Memory 保留資訊，LLM 依方法比較、判斷與撰寫，Memory 本身不決定修改 JD。

OPM 明確將工作分析與訓練、分類、績效等後續用途相連，但沒有說同一份 JD 應先包含所有用途的決策。[OPM Job Analysis](https://www.opm.gov/policy-data-oversight/assessment-and-selection/job-analysis/)

## 4. 「滿分」改成可以審核的品質目標

以下是本產品的質性檢查，不是官方百分制，也不要求新增評分系統。

1. **真實**：是員工目前工作的描述；未把通用職業資料、個人期望或模型推測冒充既有責任。
2. **全範圍**：包含例行、週期、事件觸發、維護、正式低頻及其他有效責任，不只涵蓋最近或容易談的案例。
3. **粒度適當**：不是每個客戶、工具或操作步驟一個任務；也不抽象成「處理相關業務」。
4. **沒有實質重複**：同一責任不因不同措辭重複列入；相似但責任、成果或條件不同的工作不被誤合併。
5. **邊界清楚**：知道本人負責、協作、建議、核准及不負責什麼；不因職稱推定權限。
6. **知道合理完成的樣子**：有必要的成果與品質條件，不用「認真負責」「提高效率」取代具體工作。
7. **專業有關聯**：所需知識／技能能說明用在哪裡；不是履歷全抄或職業清單全塞。
8. **清楚、可修訂、可重用**：成品可讀，工作改變時能定位修訂，下游可再加入自己的條件。

完整盤點已保存資料有助於覆蓋檢查，但**不等於證明未被說出的工作都已發現，也不等於模型語意判斷必然正確**。最終仍需確認工作範圍及文件；不能用「Memory 全部讀過」宣稱品質 100%。

## 5. 重要取捨與建議

| 選項 | 優點 | 主要風險 | 內容建議 |
|---|---|---|---|
| 很短的敘述型 JD：目的＋幾項責任 | 輕量、容易閱讀 | 若只有泛稱，專業、品質與邊界可能不清楚 | 可作精簡呈現，不作唯一分析深度 |
| **核心 JD＋按需要展開的內容** | 保持可讀；複雜工作能補成果、標準、專業及條件 | 需要明確的內容取捨規則 | **採用於樣稿的建議**，見欄位指南 |
| 全套職能／評量表 | 適合特定認證、課程或評量制度 | 容易把級別、證據次數、KPI 等塞進職務事實 | 不作通用預設，除非另有明確用途 |

「可選欄位」不代表對應資訊不必分析。責任界線、怎樣算完成等問題，即使最後寫在任務句內，也要理解清楚。反過來，案例日期、詳細操作及推論過程很有分析價值，也不代表都該出現在 JD。

## 6. 研究範圍與限制

- 回讀既有跨國、Task／OPKS、成品欄位及資訊取捨研究的相關章節；未以舊 schema 或舊程式反推內容。
- 重新核對可取得的官方原始資料；年份、生效日、取得失敗及適用範圍均列在證據表。
- 整理完整工作資訊、欄位定義、正反例、案例→理解→JD 對照，以及後續提示可採用的原則。
- 將內容取捨用於一份四組職責、八項任務的完整虛構樣稿；數量只是本例結果，不是產品限制。樣稿另有完整情境與雙向核對，不冒充真實 API 訪談驗收。
- 依客製化補充問題，核查實際雇主的職位描述／分析方法，補充深度、缺口追問、現況與合理完成要求、下游用途邊界；來源日期及取得限制集中在證據表§9。研究覆蓋與後續入口見校準文§8。
- 這是文獻與概念審查，不是已證明所有職位都能產出滿分 JD 的產品驗收。

本次特別校正：舊版 NOS、澳洲模板單一路徑、O 必須為物件、數字全面禁止、案例等於任務，以及「各家共同原則＝同一欄位 schema」等誤讀。歷史文件保留為歷史，不改寫成當時已得出新結論。
