# 專案儲存整理

本輪依使用者授權整理專案、資料庫及歷史材料。操作規則由 [runbook](../runbook.md#磁碟空間維護) 維護；實驗原件的保存契約沿 [artifact storage](../experiments/artifact-storage.md)，本計畫只追蹤此次工作。

**目標**：日常工作目錄保留現行程式、必要環境與使用中的資料；已結案材料有可驗證的遠端封存與還原入口，可重建殘留完成回收。

**做法**：主代理整合；子代理分別處理原生 PostgreSQL、Docker PostgreSQL，以及封存與外送風險審查。既有工作目錄原地維護，不為清理建立重複 checkout。這是儲存維護，不改產品資料權責、Prompt 或業務行為。

## 範圍與驗收

- [x] 核對資料目錄、容器、volume、程序、App 接線及遠端可見性；記錄保留／封存／回收理由。
- [x] 區分需延續的訪談資料與已結案合成實驗；後者保存必要研究證據，不預設永久保留完整資料庫。需保留的 DB 才做備份／還原驗證。
- [x] 歷史研究與未提交材料篩選後封存；不將金鑰、瀏覽器登入狀態或本機密碼設定公開／提交。私人資料使用經確認的私人保存位置。
- [x] 遠端下載後核對 SHA-256 與內容，再刪相應本地重複副本；保留索引與重建／還原方法。
- [x] 清除確認已結案且不被引用的 cache、測試環境與儲存；現用 App、DB、runtime 持續可用。
- [x] 更新既有 runbook 與保存文件；執行窄範圍檢查、獨立審查與前後容量比較。

## 操作界線

現行 App 接 `caliburn-jd-docker-test` 專案；命名不能代替資料用途確認。兩套已運作的 PostgreSQL 不因備份而停機。只啟停本輪明確核對的自有舊 DB／隔離驗證資源，維持原運作狀態。

DB 不按 `test`／`eval` 名稱直接刪。使用者於執行中明確縮減保存範圍：保留特定資料或實驗數據即可，不必完整保存全部舊環境。因此已結案合成資料依研究證據清單回收；日常訪談及需延續的資料保留完整保存關係。備份僅做到 dump 而未還原者須如實記錄，不手刪 WAL、不使用全域 Docker prune。

所有遞迴刪除前核對絕對路徑、reparse points、程序及引用。Git 正式 objects、歷史與現有四份未提交文件修改保留。遠端封存採按需下載，不新增產品持久化系統或另一份文件 authority。

## 執行證據

已結案。附件名稱與取回方式集中於[原件保存索引](../experiments/artifact-storage.md#2026-10-08-精選封存)，不在本頁重抄。私人 Release 中的 `archive-index.json` 保存七包大小、SHA-256 與對應 manifest；`cleanup-summary.json` 保存此次處置及驗證摘要。逐項命令、容量與還原檢查另留在本機 `.tmp/project-cleanup-20261008/`，不把暫存目錄當唯一保存位置。

|---|---:|---:|
| `S:/caliburn` 檔案邏輯容量 | 約 16.40 GiB | 約 6.27 GiB |
| `.research-tmp` | 約 10.56 GiB | 約 1.47 GiB |
| S 槽可用空間 | 約 5.73 GiB | 約 15.57 GiB |

### 保存與移除結果

- 保留現行 App、兩個運作中的 PostgreSQL 及其 volume；清理前後容器 ID、啟動時間、重啟次數、掛載與健康狀態一致。
- 回收三個停用的原生資料目錄、五組已停用的 Docker PostgreSQL 容器／volume、227 個退役研究／venv 根目錄，以及已審核的舊 profile、散落檔案與可重裝工具。必要 Python、Chromium、字型、套件環境與 lockfile 保留。
- 七包封存共 738,472,700 bytes；全部由私人 GitHub 重新下載核對 SHA-256，ZIP 另逐檔核對大小與內容。舊 production 的兩個 database 與 Demo database 均做實際隔離還原；Demo 的 CHECK 括號正規化差異見包內驗證說明。Git bundle 以新 mirror 還原、核對 279 refs 與 HEAD，並通過 `git fsck`。
- 合成實驗只保留支持結論的原件，不保留所有 DB／checkpoint 中間態。intplan 與原生歷史測試的全量 dump 未完成還原驗證，已依縮減保存範圍刪除，沒有列作可還原備份。其他退役合成 fixture 依 catalog、測試範圍與既有證據核定回收。
- C 槽已封存的 3,469 個精確原件副本回收約 1.11 GiB；未列入本次清單的同子樹材料保留。D 槽本次建立的約 6.12 GB staging、回下載副本與還原 mirror 全數移除，並解除兩個臨時 junction；這是清除此次操作產生的暫存，不另算原專案節省。

### 驗證範圍

三個子代理分別核對原生資料、Docker 資料、封存選件與引用，主代理執行精確刪除及整合檢查。API 依賴載入、TypeScript 工具、現行 App `/api/health` 與 Docker 健康狀態通過；文件檢查測試 7 項通過、本地引用零問題，`git diff --check` 通過。七份實驗文件的取回引用已接至私人附件，未保留的九項早期中間態明示為歷史路徑，不改研究數值或結論。

本次沒有改產品程式、Prompt、業務資料權責或重新執行付費模型比較。驗證只支持儲存處置與現用環境可用性，不重新宣稱 JD 品質或全產品驗收通過。
