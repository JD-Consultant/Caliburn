# Caliburn 產品概念

Caliburn 是本機 Web AI 職務分析與職務說明書（JD）應用程式。單一操作者可管理多份資料隔離的職務檔案；員工透過持續訪談說明實際工作，AI 顧問釐清、分析並逐步撰稿，人也可直接編輯同一份 JD。

本頁定義資訊與成果的意義。依問題閱讀：[資訊關係](#核心概念與資訊關係)、[使用旅程](#使用旅程)、[保存與控制](#保存正式資格與使用者控制)、[長訪談](#支援長訪談的能力)、[內容判準](#內容判準)。實現方式沿[系統規格](../../apps/backend/architecture.md)。

## 產品目標與價值

讓員工透過說明工作與必要的釐清，取得忠於實際工作、涵蓋主要責任且精簡的 JD。員工不必先學會 JD 方法或親自代寫；人工編輯是可用能力，不是 AI 撰稿品質的必要前提。

顧問應涵蓋例行、週期及低頻重要工作，資訊不足時追問或保留未知；長訪談能找回相關原話並處理更正。成功不以欄位填滿、工具數量、token 或訪談越短判定。JD 品質、真人顧問投入、員工準備、訪談與修正時間須分別量測。

## 核心概念與資訊關係

| 概念 | 意義 |
|---|---|
| 職務檔案（Workspace） | 一份受訪工作範圍，包含訪談、Memory、Plan 與共編 JD；同名不合併資料，切換不承接另一份內容。 |
| JD | 結構化工作稿，包含基本資料、目的、協作、職責、任務、成果／要求、共用知識／技能及工作條件；不是整份 Markdown 或 PDF。 |
| 原始訪談 | 具有出處、說話者與順序的正式開場、員工輸入、顧問答覆及逐題問答；顧問問句中的假設不是員工事實。 |
| 工作情境 | 可辨認的一段工作實況，保留本人行動、判斷、條件、例外、未知及原話依據；不按句子或輪次機械切分。 |
| 工作理解 | 從情境形成、可修正的工作認識，交代責任、共同模式與適用條件；不把單一案例升格為無條件通則。 |
| 編輯依據 | 支持 JD 主張的合格原話或已發布 Memory；有引用不等於語意必然正確。 |
| Plan | 顧問尚需處理的訪談、分析、編修與核對安排；不代替事實、JD 或完成證明。 |

「原始訪談 → 工作情境 → 工作理解」形成分層資訊。顧問可直接使用任一層的合格依據，不必等背景整理才寫 JD。整理結果不覆蓋原話，人工 JD 修改不自動成為員工事實，也不反向改寫 Memory。各層保留時間與適用範圍，區分目前職責、過去工作、他人責任及未來願望。

## 使用旅程

1. 建立職務檔案。App 在同一交易建立 Workspace、空 JD 與明示出處的開場；開場不是模型答覆或工作事實。
2. 說明工作，依顧問的具體追問補充或更正；中途問答可逐題回答或按契約略過。
3. 資訊足以支持表述時，逐步編修 JD。人也可在畫面允許編輯時直接修改，不要求每輪改稿。
4. 查看保存內容、來源、歷史及差異；未完成輪可明確恢復或取消。
5. 匯出目前保存 JD 的 PDF，之後仍可繼續訪談與修稿。

### JD 與成果界線

人工與 AI 經同一業務用例修改 JD，每次有效操作直接保存目前內容與完整快照，沒有候選／採用流程。PDF 只列印當時保存的 JD，不含未確認的畫面草稿或整份訪談／Memory。

「已保存」與「完整可交付」不同。若仍有會改變職責判斷的未知或衝突，不能宣稱完成。匯出不是品質審核，也不建立隱含的全稿審核流程。

## 保存、正式資格與使用者控制

正式訪談、Agent 執行紀錄與暫時串流片段各有用途。可讀中間訊息不是正式員工事實，未保存片段不承諾恢復。Memory 分析只取符合完成資格的訪談；當輪資料資格由能力模組及可信執行範圍判定。

同一 Workspace 不接受另一個尚未完成顧問輪。前端在目前輪未完成或狀態未知時將 JD 設為唯讀；後端仍使用版本契約處理其他入口的交錯修改，不能把 UI 唯讀當成跨程序交易鎖。

斷線不取消後端工作；先查保存狀態，再明確恢復。整輪取消先停工，再撤回各能力本輪效果，完成後才回報成功；跨模組收尾不是原子交易，失敗可重送取消。完成輪另有只撤銷 JD 改動的安全用例，不刪訪談、Plan 或 Memory。詳細條件沿[保存與恢復](../architecture/persistence.md)。

## 支援長訪談的能力

### 分層工作記憶

顧問 A 訪談與編修 JD。背景 B1 從有效訪談整理情境，B2 依情境形成理解，依序完成 B1 → B2 → 發布。B1 不讀理解，B2 不修改情境或回交 B1，A 不直接修改 Memory。發布後才作為顧問的正式工作記憶，使用者不必管理分析過程。

B1 保留角色背景、方法、工具、數值期限、條件與更正；B2 提煉有用理解並保留必要界線，不要求每個情境都形成一件理解。已知可以保留，未知不能猜補，真實品質不能由格式合法推定。

A 使用固定已發布 Memory 與後續原話。導覽不等於已讀正文；新版承接資訊後按需要核對 JD 與引用，不因發布就無差別重寫全稿。人工改稿及已引用來源更新可能需要重新核對；看過差異不等於已核清。詳細發布與恢復見 [Memory Bundle](../../apps/backend/src/caliburn/bundles/memory/README.md)。

### 上下文與分析接續

App 管理合法資料、當輪固定基準及按需查讀。Context Plugin 決定跨輪窗口與原生壓縮；壓縮管理模型接續，不能取代正式原話、Memory 或 JD，也不保證細節無損。

同輪恢復沿原固定窗口，背景發布不在半輪悄悄換入。輪前歷史與完整請求使用不同壓縮門檻，原生壓縮後重算並在仍超量時拒絕；具體條件由 [Context Bundle](../../apps/backend/src/caliburn/bundles/context/README.md)維護。沒有另一套待採用文字摘要流程。

App 管理身分、範圍與版本，模型只填需要判斷的內容。工具回傳須足以定位來源及繼續操作；較少 token 只有在品質維持時才有意義。

## 現行範圍與非目標

- 本機、單一操作者、單 worker；沒有登入、ACL、多租戶、計費或多人協作。模型 API 外送及秘密設定見[信任邊界](../architecture/delivery-and-operations.md#4-信任與權限邊界)。
- 公版是後端內聚能力，Qdrant 隨標準部署啟動；公版 Agent Plugin 可選取。來源、權重與索引須事先備妥，公版只作參考，不是員工事實或完成門檻。
- 不要求每輪整理 Memory、每輪改 JD、先完成背景整理或由員工代寫。
- 專用全稿審核、原話語意搜尋與多人協作不列作已完成能力。

## 已知限制與成效驗證

真人使用及省時效果尚未驗證，不承諾固定節省比例。真模型的長訪談、更正、來源與跨批 Memory 品質須另外評閱；工程測試不代替內容品質。未保存的模型／工具效果在恢復時可能重做，已保存用量也不等於全部費用。測試分層見[驗證範圍](../architecture/verification.md)。

## 內容判準


本節維護現行產品已採用的內容意義與分析界線；不是固定訪談表單、必填門檻或品質通過聲明。

JD 描述目前職位的實際工作；本人與團隊、現在與過去、固定與暫代、事實與願望須可辨認，一次案例不能直接升為無條件職責。原話與合格 Memory 支持工作主張，人工稿、公版及顧問問句中的假設不能反過來證明員工事實。

| 內容 | 意義與必要界線 |
|---|---|
| 職務名稱、單位、匯報關係 | 員工明確提供即可依原稱呼及確定程度寫入，不等待背景 Memory；員工姓名與檔案名稱另有用途，不由職稱或協作關係推定組織、主管或資深程度 |
| 職務目的 | 概括服務對象、主要工作與持續價值；隨理解修訂，不重抄全部任務或補未確認的績效目標 |
| 職責與任務 | 職責按共同目的及責任範圍組織；任務交代本人對什麼做什麼及必要條件，連續操作不機械拆散，也不逐案重複 |
| 成果與要求 | 成果是形成、交付或維持的結果及用途；要求是已確認品質、時限、條件與完成判準，兩者各有用途，不創造 KPI |
| 知識與技能 | 知識是工作須知道並理解的對象特性與關係、概念原理、制度規範、程序及適用條件；技能是運用知識、方法與工具完成操作、判斷及解決問題的能力。依已確認做法或直接說明提煉，毋須員工命名或逐項再確認；工具、語言、用途或本人範圍不清且影響專業內容時才追問。兩者皆可基礎、例行或單任務；定義保留依據並連到需要的任務，不憑工具名稱、職稱或個人持證推定 |
| 協作、工作條件及責任界線 | 保留本人決定、交接、核准及不負責的範圍；環境、負荷、頻率或異常條件有影響且有根據才寫 |

初次訪談先請員工說明目前職位與主要工作大項；已有資訊就沿用。顧問先建立工作廣度，辨認主要工作類別、處理對象與本人範圍，避免一開始就深挖單一案例。初步輪廓形成且公版工具可用時，先依已確認工作搜尋一輪公版，利用概述與任務導覽補查可能遺漏的重要範圍；公版線索須經員工確認，不逐條問遍，也不以搜尋成功作為繼續訪談的門檻。已有適用結果就沿用，主要工作範圍實質改變且現有參考不足時再考慮重搜。

主要工作已可區分、已給員工補充其他範圍的機會，且足以安排深入順序後，再依分析缺口選題深入；不要求固定項目數、回合數或先掌握全部細節。顧問持續修正主要工作、服務對象、工作來源、交付及分工，案例與情境比較按需使用，兼顧例行、周期、專案、支援及低頻重要工作。新資訊接回工作輪廓，已有依據的分析結果逐步整理成 JD，個案經過不逐句搬入。追問中立、具體且能回答；只有工作名稱或籠統動作時，可從實際方法、工具、用途或例子切入，也可直接了解必要知識技能。已知內容先沿用或回查，區分尚未探索、目前無法提供、拒答及明確不負責；無新資訊或可回答切入點就不等義重問。局部資訊足夠就可編修，不要求每輪改稿或等全部訪談或 Memory 完成。

補充或更正時核對受影響的任務、職責、目的、共用項目及依據，保留未被推翻的有效工作、數值與例外；新回答沒提舊工作不等於撤銷。準備收尾時對照有效工作範圍及整份 JD，核重要責任、方法、必要知識技能、條件、共用項目與關係；員工沒有補充或欄位有字不能代替成品核對。沒有重要可推進缺口時，可說明成果及仍待確認的限制，請員工核對並告一段落；重要未知或衝突會改變責任判斷時，不能宣稱完整。內容品質另以[逐項內容評閱](quality-review.md)評估，接受語意等價的分組與工具路徑。

同份 Markdown 工作計畫接續真正剩餘的訪談、分析、編修與核對。問題已答就不再待問，仍未入稿／核對的部分保留；實際完成後移除微步驟。可同輪直接完成時不必先增待辦再刪除，不固定每輪寫，也不複製全份 JD、Memory 或來源旗標。計畫不能代替事實依據或成品完成證明，方法見 [Plan 指引](../../apps/backend/src/caliburn/bundles/plan/planning_instructions.py)。

正式提示由 [A 顧問指引](../../apps/backend/src/caliburn/bundles/consultant/instructions.py)、[B1 情境指引](../../apps/backend/src/caliburn/bundles/memory/situation_instructions.py)及 [B2 理解指引](../../apps/backend/src/caliburn/bundles/memory/understanding_instructions.py)維護；工具與資料資格仍依正式 Schema 及實作契約。研究原稿提供沿革，不是公開使用或測試的前置。
