# 報告與研究材料

想先理解產品，從產品介紹開始；要看完整方法與成果，讀團隊專題報告；要追程式及資料權責，讀系統架構報告。
下方另列原始實驗與設計演進的入口，供核對報告中的主張。

## 產品介紹與報告

1. [產品介紹](../product-introduction.md)：顧問作業的痛點、使用流程及產品價值。
2. [團隊專題報告](project-report/report.md)：問題、方法、設計、實驗與結果；正文及附錄可獨立閱讀。
3. [系統架構報告](system-architecture/README.md)：Context、Memory、JD 引用、資料保存與恢復，附[架構圖](system-architecture/diagrams/README.md)。

施工日誌、交接、個人分工草稿與送件待辦另行封存。

## 研究與實驗依據

| 想了解什麼 | 入口 |
|---|---|
| 設計如何因問題與實驗而演進 | [開發沿革](development-history/README.md)、[案例集](research-casebook.md) |
| 如何發現、定位及驗證問題 | [實驗發現](experiment-findings.md)、[按能力查證據](development-history/evidence-by-capability.md) |
| 原始訪談、成品、工具互動與比較指標 | [產品驗證資料](../experiments/product-validation/README.md) |
| 哪些能力驗過、哪些仍有缺口 | [驗證範圍](../architecture/verification.md) |
| 參考的論文、官方文件及分析方法 | [研究分類](../research/README.md)、[分析指南](../guides/README.md) |
| 被取代的設計或已結案施工 | [Git 歷史查閱](../history.md) |

報告說明問題、取捨與成果；研究支援設計；實驗提供實測證據。引用時保留方法、版本、結果與限制，不把單次合成案例寫成普遍成效。原始數據不因整理文件而改寫。
