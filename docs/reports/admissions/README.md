# 資工碩士備審材料準備

以跨校共用的「問題、查證、設計取捨、實作、驗證、限制」整理 Caliburn，成大資工甲組是目前優先送件目標。這是資料準備入口，不是已完成送件，也不能保證錄取。

## 先讀哪裡

1. [各校官方要求與時程](requirements-116.md)：成大、臺大與陽明交大分開核對；不要把一校的推薦函或貢獻證明規定套到另一校。
2. [共用問題分析與實驗案例集](../research-casebook.md)：已整理四個案例，以及原文、數據與限制的入口。
3. [教授版架構報告](../system-architecture/README.md)：解說內部設計，含可閱讀的架構圖；先看程式基準與尚未驗收範圍。
4. [原始實驗資料](../../plans/2026-09-29-target-rebuild/evidence/data/instruction-experiments-2026-10-01/README.md)：逐字稿、成品、事件、指標，不為不同學校複製多份。

## 從官方審查項目推導材料重點

成大列出成績、資訊能力、專題與研究能力、讀書計畫等；臺大列研究報告／著作等有利材料；陽明交大要求多人專題交代貢獻。[官方差異與來源](requirements-116.md)支持這些要求，但沒有公布一套「每位教授都喜歡什麼」的通用公式。

以下是據此提出的準備建議，不是假稱官方評分細則：

| 想證明的能力 | Caliburn 可用材料 | 尚不能由 repo 代替的證據 |
|---|---|---|
| 資工基礎與學習能力 | 能解釋資料、交易、狀態、引用與模組分工 | 成績單、排名、修課及個人學習經過 |
| 獨立定義與分析問題 | 引用漏選診斷、故障範圍排除 | 本人實際做了哪些判斷，不能只給 AI 對話量 |
| 系統設計與實作 | 固定 Memory 快照、候選提交、受限工具、恢復邊界 | 本人負責範圍、協作者、AI 輔助方式 |
| 研究與驗證 | 有基準的指引比較、失敗候選、grader 誤判、長旅程 | 真人人設／領域專家驗證尚不能冒稱已有 |
| 溝通與研究潛力 | 圖、可重現反例、清楚限制及下一個研究問題 | 為何想研究此方向，與目標老師的真正契合 |

## 本週材料組裝順序

先確認報名、繳費、推薦邀請及學校要求的文件；專題整理不能取代這些程序。

- 共用專題摘要：問題與目標、本人貢獻、系統圖、兩個有證據的案例、限制與後續研究。建議短正文加可查證附錄，篇幅是編輯取捨，不是學校硬性頁數。
- 程式能力材料：只挑本人能解釋的模組、反例及測試，連到固定提交；不把整個 repo 壓成 PDF。
- 讀書／研究計畫：從已觀察到的限制延伸為可驗證問題，與學校研究方向對照；不把待做構想寫成成果。
- 附錄：實驗條件、結果表、原始材料索引、個人分工與 AI 輔助揭露；各校按要求裁切。

## 仍需本人提供

目前沒有足夠資料代寫以下內容：就讀學校科系、成績及排名、個人經歷、團隊與指導關係、本人／他人／AI 的工作分界、研究興趣，以及推薦人與送件完成狀態。

私人資料與推薦函不要直接放入可公開的 repo。材料確認後再製作正式送件檔；本次只整理共用證據和查證清單，未提交表單、寄信或聯絡學校。
