# 資工碩士備審材料準備

以跨校共用的「問題、查證、設計取捨、實作、驗證、限制」整理 Caliburn，成大資工甲組是目前優先送件目標。這是資料準備入口，不是已完成送件，也不能保證錄取。

## 先讀哪裡

1. [各校官方要求與時程](requirements-116.md)：成大、臺大與陽明交大分開核對；不要把一校的推薦函或貢獻證明規定套到另一校。
2. [系所／教授公開資料與研究能力判準](research-readiness.md)：先分清官方審查要求、研究生培養目標及個別實驗室期待，再決定找什麼材料。
3. [開發演進素材索引](../development-history/README.md)／[按能力找證據](../development-history/evidence-by-capability.md)：前者按時間找最早期至今的變化；後者找實驗、反證、文獻判讀及工程分析材料。先盤點，不現在限定只寫哪兩個故事。
4. [共用問題分析與實驗案例集](../research-casebook.md)：四個已有較完整摘要的案例；不是全部歷史。
5. [教授版架構報告](../system-architecture/README.md)：解說內部設計，含可閱讀的架構圖；先看程式基準與尚未驗收範圍。
6. [原始實驗資料](../../plans/2026-09-29-target-rebuild/evidence/data/instruction-experiments-2026-10-01/README.md)：逐字稿、成品、事件、指標，不為不同學校複製多份。

## 從官方審查項目推導材料重點

先看[研究能力判準](research-readiness.md)：除各校審查項目，也核對成大資工所核心能力與教授公開的研究訓練說明。它們支持從問題、來源判讀、系統推理、實驗、修正及溝通找證據；不支持一套「每位教授都喜歡什麼」的通用錄取公式。

判準只在該頁維護，[素材索引](../development-history/evidence-by-capability.md)連回原實驗或研究，不再建立另一份結果台帳。成績、個人分工、AI使用方式及研究興趣仍不能由 repo 自動推導。

## 本週材料組裝順序

先確認報名、繳費、推薦邀請及學校要求的文件；專題整理不能取代這些程序。

- 共用專題摘要：問題與目標、本人貢獻、系統圖、兩個有證據的案例、限制與後續研究。建議短正文加可查證附錄，篇幅是編輯取捨，不是學校硬性頁數。
- 程式能力材料：只挑本人能解釋的模組、反例及測試，連到固定提交；不把整個 repo 壓成 PDF。
- 讀書／研究計畫：從已觀察到的限制延伸為可驗證問題，與學校研究方向對照；不把待做構想寫成成果。
- 附錄：實驗條件、結果表、原始材料索引、個人分工與 AI 輔助揭露；各校按要求裁切。

## 仍需本人提供

目前沒有足夠資料代寫以下內容：就讀學校科系、成績及排名、個人經歷、團隊與指導關係、本人／他人／AI 的工作分界、研究興趣，以及推薦人與送件完成狀態。

私人資料與推薦函不要直接放入可公開的 repo。材料確認後再製作正式送件檔；本次只整理共用證據和查證清單，未提交表單、寄信或聯絡學校。
