# Caliburn 專題報告

這份團隊專題報告從訪談與職務分析需求出發，呈現 Caliburn 的系統設計、資料模型與實驗成果，說明設計如何經由問題追查與方案比較逐步形成。

**[閱讀完整報告初稿](report.md)**

版本日期：2026-10-05。目前提供 Markdown 初稿，尚未製作專題報告 PDF。

現行設計依程式基準 `bf976f36`，Memory 補測基準為 `13c0663a`；歷史、檢索及品質實驗各有自己的基準。
執行時的未提交程式以實驗 manifest 雜湊辨認，不能只用 HEAD 代表全部條件。

## 閱讀重點

- **問題與貢獻**：緒論從顧問公司訪談及 Excel 文件管理的需求出發，區分供顧問精修的底稿需求與專業完整 JD 的研究目標，說明訪談脈絡、持續分析、可追溯資料及人機編輯的用途。
- **方法與取捨**：第二、三章說明內容核對、追問選擇、Agent 執行框架、分層記憶、Context、工具與安全保存；§3.4.6 說明版本差異如何支援按需閱讀與下游重評。
- **分層設計的實際價值**：§5.9–5.10 呈現充分性停止、早期精確資訊找回及 JD 局部修訂。同一份 Memory 的閱讀指引對照，共同完成三對均保留 33／33 項核心事實，讀取由 23 次降至 3 次，累計 input 少 56.2%。§6.1 另說明為何保留原話與摘要用途，並以可選讀、可修訂、有來源的工作單元延續分析。
- **實驗與成果**：第四、五章及附錄 B 保留方法、逐次數據、計算方式、JD 原文與反例，涵蓋指引比較、來源換版、45 輪完整旅程，以及早期相似度校準與索引診斷。24 份指引試訪與 24 次 Luna 來源差異子任務是不同實驗；後者的方法、結果及判準限制見 §4.5、§5.5 與 B.9。B.8 的虛構 JD 樣稿另作方法示例。
- **公版參考與後續研究**：§6.3 與 B.14 整理已完成的主要職位檢索研究：整份／任務兩路稠密向量廣蒐、完整聯集及重排序；分開初搜保留、最終去留、否認反例與工程重現。依 [ADR0080](../../adr/0080-opt-in-public-reference-agent-tools.md)，工具已完成可選角色接線，須明示啟用；工程接線結果不等於公版已改善補問或 JD 收尾。不將歷史去重門檻當成訪談完成判準。

§4.6–4.8、§5.6–5.8 及附錄 B.10–B.13 呈現四批真模型 Memory 壓縮整合對照、36 次導覽／定位配對試驗、163 項核心反例，以及 45 段訪談重播的四組記憶比較。後者移除核對端的早期原話與接續歷史，三層僅從情境／理解取得資料。

方法、分數、來源失分及完整用量分開呈現，不把資訊可取得說成整份 JD 品質、總成本或真人效益均已通過。

§4.9 與附錄 B.15 補入相同 Memory 的閱讀策略、三批增量整理、兩批各 24 段接續訪談，以及五對局部指引比較。正文以設計與代表成果為主，附錄保留各批的逐題品質、完整 token、建立成本及原件。兩批接續訪談中，Memory 的累計 input 相對原話分別少 21.0% 與多 7.32%，因此採用理由聚焦於分析重用與來源追查，不宣稱每次都更省或已證明超容量勝出。

報告以七章正文、參考文獻及附錄構成，必要的方法、數據與案例可在同一份主稿閱讀。附錄 A 說明工具互動，附錄 B 提供實驗條件與詳細結果。

2026-10-05 補入 B.14 與 §6.3：同八個固定合成案例的原話／B1／B2、廣蒐深度、候選縮減及否認查詢比較，保留原始 JSON 連結。12 個已知主要參考配對是部分回歸目標，不是全公版相關性答案；兩個疑義評分的敏感度另外呈現。D20／T20 是目前可重現的控制配置，不宣稱通用最佳。

檢索表格可離線核對，不呼叫模型、不修改實驗原件：

```powershell
apps/api/.venv/Scripts/python.exe -X utf8 docs/reports/project-report/verify_retrieval_evidence.py
```

此程式核對 B-28–B-30 共 15 列、主要算術、配置分母及本地來源連結。它檢查報告是否忠實轉錄既有評分，不證明語意真值或全庫召回率；其他既有實驗由同目錄 `verify_evidence.py` 核對。
