## 分層分析的設計取捨

長期分析由三個角色分工：A 決定當前訪談與 JD 工作，B1 整理具體情境，B2 形成跨情境理解。程式負責固定資料範圍、保存版本、執行工具與安全提交。分層記憶和差異讓模型不必每次重讀全部資料，需要細節時仍可回查原話。

這項分工讓模型處理工作語意，程式維護資料範圍、權限與保存結果。下表說明各項選擇得到什麼、需要承擔什麼成本；後面的證據則用來判斷這些設計在受測情境中的表現。

| 選擇 | 得到什麼 | 設計取捨 |
| --- | --- | --- |
| 模組化單體 | 同一套業務規則、部署及交易較簡單 | 不先拆微服務、加入訊息佇列平台 |
| App 管理原生 Context | 可控制提供範圍、接續與壓縮採用點 | 需自己驗證格式、容量與恢復；不自製 reasoning |
| 分層 Memory＋Map／按需讀 | 大量事實可逐步整理與回查 | 增加背景整理與讀取操作，保留按需深入細節的能力 |
| 候選與正式快照分開 | 預覽、取消、固定歷史可以共存 | 需維護正式化邊界，不把 DB 寫入都當正式發布 |
| 差異引導重新分析 | 重點檢查變動，沿用已整理內容 | 維護新舊分析基準，由模型判斷變動對下游內容的影響 |
| Luna 作產品模型 | 符合目前成本選擇 | 來源與提煉品質仍需優化，未以更換高價模型取代問題處理 |

## 用什麼證據判斷「能用」

以下依 2026-10-02 的[驗證對照](../../history.md#source-d58692bbe6b4baa7267f)區分證據層級，後續單向 Memory 流程的驗證另列於下方限制表。各次實驗保留自己的版本、條件及判準，閱讀時須連同這些範圍判讀結果，不能把測試數量加總為一次完整產品評估。

| 層級 | 已有代表證據 | 驗證重點 |
| --- | --- | --- |
| 契約與確定性邏輯 | 工具格式、正文唯一匹配、來源解析、角色權限測試 | 格式與權限檢查、指定非法操作的拒絕行為 |
| 真 PostgreSQL 與恢復 | 固定快照、正式／候選隔離、重入、跨程序接續 | 實際保存、提交與恢復邊界 |
| UI／整合旅程 | 分別測試訪談控制、候選、來源檢視、PDF 下載 | 使用流程及前後端資料呈現 |
| 真模型合成訪談 | 採購工作案例完成 45 輪訪談、3 批 Memory、4 頁 PDF；包含人工改稿、取消與中斷測試 | 同一合成職務下的長期訪談與匯出流程 |
| 分析品質 | 依指南比較產出，診斷來源漏引 | 工作分析及來源選擇的表現；尚無真人評閱結果 |

確定性測試檢查指定輸入下的格式、權限及保存結果；真模型合成訪談則觀察模型在多輪資料、人工改稿與執行中斷下的表現。前者不能證明分析品質，後者也只涵蓋所選案例，不能代表不同職務或真人訪談的結果。相關紀錄列於章末延伸閱讀。

## 一個重要的品質反例：資料可見，模型仍可能漏引

既有合成課程行政旅程中，早期訪談第 8 則描述每個上課日整理簽到紀錄；本次輸入補充統計方法，完成後成為第 10 則。模型建立結合兩次資訊的任務，卻只選 `current_input` 作來源。

建立任務前，模型已讀到相關情境、理解及舊 JD 的早期來源；建立後又讀到第 8 則原話，仍未補引。App 保存的就是模型選取的來源，沒有證據顯示引用在保存途中遺失。

目前可定位的問題是來源選擇不完整，而非已證實的 Context 缺漏；模型為何漏選仍未查明。

這項診斷把改進焦點放在模型的來源選擇：如何辨認文字使用了哪些跨輪事實，再選取足夠的支持資料。保存的實際請求與工具結果，讓分析能區分資料未提供、模型未選取及保存遺失等可能原因，也提供比較提示與操作方式的依據。詳細分析見[來源選擇品質紀錄](../../history.md#source-d3293e9b28c75bbb6616)。

## 實驗範圍與驗證限制

既有驗證對照涵蓋 28 項，按證據分類為 12 項通過、6 項部分通過、9 項完成離線／真 PostgreSQL／瀏覽器層驗證、1 項未驗。這些分類對應各項測試的限定範圍，不表示整體分析品質通過。下表說明主要觀察與尚未驗證的部分。

| 項目 | 既有成果與驗證限制 |
| --- | --- |
| 分析品質 | 依指南調整分析方式的比較已有證據；跨輪來源漏選、工作涵蓋及重複文字仍未完全解決。部分員工工作尚未被問出，不能因員工模擬器說「已涵蓋」就認定完整 |
| 容量與接續 | 長旅程自然發生 A 輪前壓縮 5 次；B1／B2 另完成[兩組小型整合對照](../../experiments/product-validation/data/memory-compaction-publish-2026-10-04/README.md)，四批皆發布，壓縮組第二批兩角色各 compact 一次，完整回傳承接及舊快照回讀通過。這是低門檻探針，不代替正式容量邊界；160K 中途保險有獨立真窗口測試，未在長旅程自然觸發 |
| 完整旅程 | 45 輪完成，形成 91 則正式訪談。3 批 Memory 處理到序號 82，83–91 仍未整理。兩次中斷均安全終止後重送原句，並非原執行直接續作；長旅程 81 筆 JD 依據全為原始訪談，Memory 換版引用另有受控短案例證據 |
| 背景流程一致性 | B1 → B2 → 發布有 59 項專項測試及本輪四批真模型小型整合。更正、新增工作、權限及固定引用回讀有內容證據；45 輪旅程仍是單向修正前版本，不算現行跨職務長旅程或專家品質評閱，見[單向流程測試](../../history.md#source-6fab8cfd2383817f94f3)及[本輪對照](../../experiments/product-validation/data/memory-compaction-publish-2026-10-04/README.md) |
| Memory 失敗後重新整理 | 已有保存與新批次啟動條件的測試；現行程式在有效訪談再前進三輪後才允許新批次，但政策尚未確認，也未在真長旅程觸發，見[背景整理失敗測試紀錄](../../history.md#source-14d692c99a98b4e9954e) |
| 本機執行環境 | 現行產品已取代舊產品，沿革見 [ADR0079](../../adr/0079-target-rebuild-production-cutover.md)。[隔離 Docker 驗證](../../experiments/product-validation/2026-10-03-docker-delivery.md)另完成建置、人工編輯保存、中文 PDF 及容器重建後資料回讀；不等於另機或真模型完整旅程。歷史新入口的真模型短旅程仍留為當時未驗紀錄 |

PDF 的 4 頁成品已逐頁檢查，畫面沒有裁切、重疊或缺字，但部分文字在複製／搜尋時會出現部首字元，見 [PDF 檢查紀錄](../../history.md#source-409f20a1c297740aed7d)。因此，匯出功能可用，文字層仍有限制。長旅程還包含 1 個人工新增任務，最終稿並非全部由 AI 獨立產出。

其他問題與原始證據見[實驗發現彙整](../experiment-findings.md)。

## 系統成果與後續方向

Caliburn 已將 AI 引導訪談、分層工作記憶、可追溯的 JD 編輯與安全保存接成可操作的流程。分析角色共用執行機制並各有權限；業務模組管理可修改的工作稿及固定歷史；使用者則透過畫面參與修改、查閱依據及取得 PDF。這些分工讓長訪談、編修與恢復使用同一套資料規則。

後續優先延續既有工作分析指南與實驗資料，改善來源選擇、能力提煉及核對行為，再加入新職務、專業評閱與真人試用。這些評估將聚焦事實涵蓋、責任邊界、來源充分性、資訊精簡度與訪談負擔，持續檢查系統是否幫助使用者形成合適的 JD。
