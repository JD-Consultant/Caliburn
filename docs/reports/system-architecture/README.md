# Caliburn 系統架構與核心機制說明

> 從訪談需求出發，說明程式的分工、資料流向與設計取捨。

Caliburn 讓員工透過訪談描述實際工作，由 AI 顧問追問、分析與編輯，逐步形成專業、完整且精簡的職務說明書（Job Description，JD）。員工不必先學會 JD 的寫法。系統分別管理分析過程、可引用的工作事實與正式文件，讓長訪談能接續既有分析，也避免將模型的中途說法直接當成已保存的事實。

本報告說明程式內部如何分工、訪談資料如何成為 JD，以及模型出錯或執行中斷時的處理方式。

## 閱讀範圍與版本

本報告描述本機產品 `apps/api`、`apps/web` 的架構與運作方式，內容核對至 2026-10-02。產品尚未對外部署。既有合成訪談實驗完成 45 輪訪談、3 批 Memory 與 PDF 匯出；各次實驗的條件、發現與限制見[第七章](07-evaluation.md)，不能以流程完成推論分析品質已達標。

詳細設計可參閱[架構文件](../../target-architecture-map.md)。現行產品與舊架構的關係見 [ADR0079](../../adr/0079-target-rebuild-production-cutover.md)，實驗範圍與原始紀錄見[驗證範圍](../../architecture/verification.md)及[產品實驗](../../experiments/product-validation/README.md)。
