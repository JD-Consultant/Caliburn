# Caliburn 系統架構與核心機制說明

> 從訪談需求出發，說明程式的分工、資料流向與設計取捨。

Caliburn 讓員工透過訪談描述實際工作，由 AI 顧問追問、分析與編輯，以形成專業、完整且精簡的職務說明書（Job Description，JD）為目標。員工不必先學會 JD 的寫法。系統分別管理分析過程、可引用的工作資訊與正式文件，讓長訪談能接續既有分析，並分清模型的中途輸出與正式成果。

本報告從使用者的問題出發，說明團隊如何安排系統邊界、程式分工、訪談執行、工作記憶及 JD 保存，再以實驗證據檢查成果與限制。

## 閱讀範圍與版本

本報告描述團隊完成的本機產品 `apps/api`、`apps/web`。核心章節以 2026-10-02 的核對資料為基礎，本次整理至 2026-10-06，補入公版可選接線、職務檔案刪除、訪談控制、本機 Docker 交付及 JD 資料關係圖；各次實驗依原件標示版本與條件。產品尚未對外部署。

既有合成訪談實驗完成 45 輪訪談、3 批 Memory 與 PDF 匯出；條件、發現與限制見[第七章](07-evaluation.md)。這些結果說明受測案例的流程與行為，分析品質須依各項評估分開判讀。

現行狀態沿[目前決策](../../current-decisions.md)核對，詳細設計見[架構文件](../../target-architecture-map.md)。現行產品與舊架構的切換依 [ADR0079](../../adr/0079-target-rebuild-production-cutover.md)；實驗範圍與原件見[驗證範圍](../../architecture/verification.md)及[產品實驗](../../experiments/product-validation/README.md)。

## 圖與例子的讀法

架構圖參考 [C4](https://c4model.com/diagrams)，由系統全貌逐層深入；流程圖參考 [arc42 runtime view](https://docs.arc42.org/section-6/)，選取代表情境說明執行方式。只呈現有助於理解本系統的層級，不套用完整模板。

各圖以圖說區分資料依據、執行順序與程式呼叫，說明系統的主要結構與流程。A、B1、B2 分別代表職務顧問、工作情境分析與工作理解分析，是同一應用程式中的三種分析角色。

正文貫穿一個**合成的課程行政案例** ；案例用來解釋資料與流程，不是實際員工資料，也不是某次模型測試的輸出。第七章另以明確標示的既有測試證據說明限制。

各章末列有延伸閱讀，供有興趣的讀者查閱詳細設計、程式或實驗紀錄。正文使用 PNG，避免閱讀器不支援 Mermaid 或 SVG 而無法顯示；可編輯的 Mermaid 原始檔與可放大的 SVG 保存在[圖稿目錄](diagrams/README.md)。
