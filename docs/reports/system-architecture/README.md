# Caliburn 系統架構與核心機制說明

> 給教授與技術評閱者的閱讀版：從訪談問題，理解程式如何組織分析、資料、工具與交付。

Caliburn 的目標不是讓員工學會寫職務說明書（Job Description，JD），而是讓員工描述實際工作，由 AI 顧問持續追問、分析與編輯，逐步形成專業、完整且精簡的 JD。程式把「正在推論的過程」「可以引用的工作事實」與「正式交付的文件」分開管理，使長時間訪談不必每次從頭分析，也不把模型說過的話直接當成已保存的事實。

本報告回答三個問題：**程式內部如何分工？資料如何從訪談成為 JD？模型出錯或執行中斷時，哪些保證由程式負責？**

## 閱讀範圍與版本

- 最後核對：2026-10-02；程式與證據基準為 `83979421`。
- 描述對象：正式產品 `apps/api`、`apps/web` 的設計、實作與既有實驗證據。
- **交付狀態：已完成本機正式入口切換，尚未對外部署。**T01–T18 已結案；核心合成旅程完成 45 輪訪談、3 批 Memory 與 PDF 匯出。這不代表所有情境或真人使用效果均已通過驗證，限制見[第七章](07-evaluation.md)。
- **設計與實作差異：**採用的背景設計為 B1 → B2 → 發布、不回交 B1；目前程式與 B2 指引仍保留回交分支。第五章與圖六說明單向設計，不表示該分支已移除，具體位置見[附錄](references.md#本次文件校核範圍)。

這是一份有固定基準的解說報告。詳細契約見[工程架構入口](../../target-architecture-map.md)，正式切換依據見 [ADR0079](../../adr/0079-target-rebuild-production-cutover.md)，驗證狀態見[任務與證據](../../plans/2026-09-29-target-rebuild/tasks.md)。報告以解釋設計為主，不另訂產品規則。

## 圖與例子的讀法

圖採 C4 的逐層放大思路，但不強行畫滿所有層級；執行流程只挑選能說明設計的代表情境。這分別參考 [C4](https://c4model.com/diagrams) 與 [arc42 runtime view](https://docs.arc42.org/section-6/)，並非宣稱某一套文件形式適合所有專案。

各圖的適用範圍與箭頭意義寫在圖說中；資料依據、執行順序與程式呼叫不可互換解讀。圖六是已採用、仍有實作差異的單向設計，其餘圖解釋目前系統的主要結構與流程。圖中「Agent」指產品內的 AI 分析角色，不表示獨立伺服器。

正文貫穿一個**合成的課程行政案例**；案例用來解釋資料與流程，不是實際員工資料，也不是某次模型測試的輸出。第七章另以明確標示的既有測試證據說明限制。

各章末提供少量「追到實作」入口，讓教授需要時能由解說進入程式。正文使用 PNG 顯示版；Mermaid 原始檔與可放大的 SVG 一起保存在[圖稿目錄](diagrams/README.md)，不必依賴閱讀器支援 Mermaid 或 SVG 才看得到圖。
