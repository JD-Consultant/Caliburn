# 訪談 Memory 的重構研究：維護工作理解，分開內容與查找方式

2026-10-05。**研究／候選，未選型、未實作，也未取代現行 B1 → B2 → 發布。**

**後續方向已收斂為優化既有分層，單集合替代暫不推進。**見[按需 Memory 與增量維護 §9](2026-10-05-demand-loaded-memory-and-incremental-updates.md#9-收斂採用既有分層改善內容組織與選讀)：借鑑必要脈絡就近組織、局部修訂及按需載入。本文以下保留當時的表示方案比較，不作目前施工建議，也不另維護後續試驗方法。

## 1. 結論與研究範圍

優先比較的候選是：**不可變訪談原文＋一套可局部維護的工作理解集合＋精簡導覽與必要關聯**。不預設必須先維護一份情境正文，再轉寫成另一份理解正文；也不將整份職務壓成一篇長摘要。

這項建議要解決的是：AI 如何延續對受訪者實際工作的認識，接住分散、跳題、補充及更正的資訊，讓顧問找到足夠內容便能使用。減少 token 是這個效果成立後的效率目標，不是刪減工作細節的理由。

本次重新開放資料表示與分工，包含取消或重分 B1／B2；不要求整合舊設計。以下保留的是產品效果：原話不改寫、事實有出處、已發布版本可回查、JD 依據可追溯、模型按需取讀，以及未知不能被補造成事實。具體工具、資料表與 Agent 數量尚未決定。

## 2. 從本地指南與實驗出發

### 工作理解不是逐段摘要，也不是預先寫好的 JD

[工作分析指南](../../guides/2026-09-09-complete-work-analysis-guide.md) §2、§9–12 與 [JD 寫作指南](../../guides/2026-09-09-jd-field-and-writing-guide.md)要求辨認工作的目的、對象、個人行動、成果、責任、條件及未知，並保留會改變判斷的精確細節。它們不是每項都必填的資料表，也不要求 Memory 與 JD 欄位一對一。

據此，本研究採以下判斷：

- 同一工作散落在多次訪談，應能接續維護；同一則發話也可能補充數項工作。
- 合併看工作意義與適用範圍，不因共用 ERP、主管或「每月」就當成同一工作。
- 分拆後應仍可正確使用；期限、期限性質、分母、例外及權限不能拆成必須四處拼湊的孤立片段。
- 分析可區分員工陳述、由陳述歸納的工作認識，以及尚未確認事項；歸納不能增加新的員工事實。
- 新增、補充、誤述更正與規則自某時改變，是不同維護行為。新訊息沒再提到某項工作，不代表撤回。
- 有效但尚不足以形成完整理解的線索仍須可找回，不強迫每段原話立刻變成完整工作結論。

### 現有證據支持重看組織方式，但沒有證明應刪除哪一層

[B2 能力對齊比較](../../experiments/product-validation/data/memory-organization-2026-10-05/capability-aligned-results.md)固定同一批情境及起始理解，只比較 B2 指引：

- 原版產生 4 項、候選 13 項；只查退貨時，對應理解由 1,531 字元降至 475 字元。這是可選讀性的靜態差距，不是 A 已節省的 token。
- 候選保留 19／19 項指定事實，原版 18／19；但兩版仍把來源的「前一天」沿用為舊理解中的「前一工作日」，並漏掉原判準之外的 11–12 月安排。
- 兩版都有跨工作數字缺少支持來源的問題。候選的 map 及來源關係亦增加，不能只看正文變小。

因此問題至少包含「內容校準」「來源支撐」「選讀粒度」，不是只有 Prompt 不夠長或物件不夠多。本批沒有比較單層、增量維護、顧問 A 或超容量接續；不能由它推定雙層必然有害，或單層一定更準。

## 4. 三個可比較的架構方向

| 方向 | 有價值的地方 | 主要代價 | 本次建議 |
|---|---|---|---|
| 情境＋理解，兩套持久正文 | 個案脈絡與跨案工作分析分工；可以在概括理解之下保留不同案件的細節 | 重複敘述須跨層同步；更正多一道轉寫，關聯及導覽可能膨脹 | 保留為對照。若情境有經常被獨立使用的內容，就可能值得保留 |
| 一套工作理解集合＋原話證據＋導覽 | 分散資訊直接整合成可使用的工作認識；減少第二套衍生正文的維護 | 同一維護流程須兼顧指涉、分析、去重與更正；仍可能漏找或過度合併 | **優先比較的候選**，不是已採用結論 |
| 原子事實／時間知識圖＋查詢時組合 | 可細定位條件、來源及依賴，適合複雜關係查詢 | 抽取及關係維護繁重；工作脈絡可能碎裂，每次使用需重新組合 | 目前不優先；有明確跨關係需求再評估 |

雙層不是錯在層數多；關鍵是第二套正文是否有足夠獨立用途。一層也不是天生更準；其收益是假設少一次轉寫與同步能降低損失，仍須比較。

## 5. 優先候選如何維護關聯性

以下為 Caliburn 候選設計推論，不是上述來源的原樣實作，也不是新的正式契約。

### 5.1 內容與入口分開

```text
新增的有效訪談＋必要前後文
          ↓ 指涉釐清、辨認受影響工作
工作理解集合 ← 局部補充／更正／拆合
    │    └── 來源依據 → 不可變訪談原文
    └── 導覽與必要關聯 → 選中同一份內容，不複製另一份全文

顧問：導覽 → 所需理解 → 足夠就使用
                        └─ 有具體缺口：相關理解／原話／追問員工
```

「工作理解」在此是暫稱：一項能獨立閱讀、持續修訂的工作認識，而非現行 B2 物件必須原封不動保留。正文可以有分析、具體案例差異、精確條件及未知，不為了短而只剩概括句。

一項內容可從工作名稱、成果、協作對象或其他有用線索找到；不同入口指向同一個物件。最小版本先沿用標題與導覽描述的能力，不必立刻新增多組標籤、向量索引或主題摘要。若導覽大到影響使用，再比較分類投影或檢索；檢索是找候選，不決定內容真假。

### 5.2 關係分清楚，不讓「相關」冒充「有依據」

| 關係 | 回答的問題 | 使用界線 |
|---|---|---|
| 來源支持 | 這個工作認識根據哪些員工說法？ | 正文含精確數字、例外或跨工作比較，來源集合就要支持所寫內容；不是只支持標題 |
| 導覽關聯 | 需要哪個方向的補充時，可以看哪項工作？ | 是選讀入口，不自動繼承另一項的事實，也不是必讀清單 |
| 修訂沿革 | 哪個說法被補充、更正，或適用時期改變？ | 保留回查與新舊差異，不讓過時說法默默混入目前理解 |

這是三種語意責任，不等於必須新增三張表、三種工具或每句一條關係。先用物件來源集合、修訂歷史及少量有理由的關聯即可。若物件太廣，來源多到看不出支撐範圍，先檢查正文範圍；只有具體查核仍做不到，才比較段落級來源對應。

候選預設直接以原話支持工作理解；工作間連結先作導覽，不另造任意互相依賴的摘要鏈。若未來確實要讓一項理解依據另一項推導，必須另定更新傳播，不能讓一般相關連結暗中承擔此責任。

### 5.3 去重依語意範圍，不追求零重複

重述同一事實可以合併；相似句中的新期限、例外或不同案件不可丟掉。共通內容若經常被獨立使用，才抽出共通項；不能只因兩處都提主管便建立「主管」節點。

為了讓單項可正確使用，重提少量責任邊界是合理的。反過來，缺貨工作若不需要收貨的兩／四工作日數字，就不必反覆寫「這個期限不適用」；若比較本身有分析價值，則必須有兩側來源。目標是減少無用重述，不是使每個字只出現一次。

### 5.4 更新依影響範圍，不是每批重寫

1. 接回本次發話的指涉與適用工作，必要時讀前問、已知工作內容或原話。
2. 找可能受影響的理解；相似只是候選，實際比較目的、對象、責任與條件。全新、尚未被引用的工作也須處理。
3. 區分重述、補充、誤述更正、時期變動、例外及未解衝突。新說法不能無條件覆蓋舊說法。
4. 局部修訂正文及其支持來源；保留仍有效的限制。拆合時讓原有有效資訊有明確去處。
5. 同步必要導覽，使它仍能指向正確範圍。未受影響部分沿用，不為展示有處理而重寫。

可以把「理解新片段」與「整合既有知識」分成工作步驟，但**工作步驟不等於兩套必須永久保存的正文**。由一個維護 Agent 完成，或先抽取再由另一個整理，應在內容契約成立後比較，不先決定代理數量。

舊分析是可重用成果，不是高於員工說法的事實權威。若已讀內容出現「前一天／前一工作日」差異，就要校準；但這不要求每次重新閱讀所有原話。

### 5.5 讀取停止以是否足以完成當前工作判斷

- 已有同一可見版本的適用正文，可以直接利用；工具仍允許重讀，不另設複雜的禁止讀取機制。
- 正文已涵蓋當前所需的事實、條件與責任且沒有具體衝突，就可用作 JD 依據。不因附來源便全部展開。
- 缺某一工作資料，讀那項工作；需要核對精確措辭、指涉或衝突，才讀相應原話及必要前後文。
- 已記錄「員工尚未確認」、沒有新增線索時，保留未知並由顧問視需要追問。重讀不能創造答案。
- 找不到與不存在不同。導覽或檢索沒命中時，允許調整方向；到執行界線仍未找到，應保留未解，不能假裝資料已足夠。

多工作整合可能合理地讀多項。衡量的是無關內容及無效重讀，不要求任何問題一次工具就解決。

## 6. 以指南案例說明：不靠層數也能延續分析

以下重組[指南 §11 的虛構教材](../../guides/2026-09-09-complete-work-analysis-guide.md#11-整理與修訂的完整演進範例)，不是新測試結果。片段一至七是教材索引，不是產品 ID。

| 可選讀內容 | 正文要保留的工作認識 | 直接來源 |
|---|---|---|
| 網站前端逾時互動處理 | 甲避免訂單重複送出；乙保留預約日期。都是約定前端範圍，後端規則與部署由同事負責 | 一、二、三 |
| 電商甲交付後前端缺陷修正 | 更正後是 48 小時內回覆初判，不是保證修好；甲無固定月維護，不擴大到後端責任 | 三、四、六 |
| 預約乙的合約前端維護 | 10 月前每月；10 月起每季第一個工作日。檢查及修正範圍不變；超範圍須核准，核准人未知 | 三、五、七 |

更正甲的回覆期限，只需要重新判斷期限所屬內容；不因甲出現就把所有前端工作重寫。乙的周期則保留前後適用時期，不能用同樣的「刪舊留新」處理。

問甲的回覆期限，第二項足夠；問共同的前端責任，可讀第一項；問乙的核准人，第三項已說明尚未確認，應追問。若要了解甲訂單逾時的具體經過，而理解沒有足夠描述，再讀相關原話。必要案例差異可以在正文中保留，原話也仍能提供完整脈絡，不以新增一層重述作唯一途徑。

這三項只是合理分組示例。若後續資訊改變共同範圍，可以再拆合；不以三項或固定字數作驗收。

## 7. 與現有產品的界線

- 本研究沒有改正式資料、Prompt、工具或分工。現行 B1／B2 仍按有效契約運作。
- 若採候選，JD 改用候選工作理解的固定發布修訂作依據，仍保留原話鏈及可回查歷史；不能因減少層數便撤掉快照一致性。工具及版本解析另立設計，模型不代填 App 已知身分。
- 工作間一般導覽連結不應被計入來源支持鏈；目前工具尚未因此新增欄位。
- JD 來源的新舊 diff 仍有用途；候選不再有兩層正文交接時，則不必保留只服務該交接的差異流程。歷史證據不因此刪除。
- 這裡的 Memory 是受訪者工作的業務知識，不是 Agent 的任務進度或執行上下文摘要；不把本題當成再次改變 compaction 決策。
- 本題不依賴公版 JD 檢索。外部職務資料可提示追問方向，不能被寫成受訪者自己的工作事實。

## 8. 下一步比較：先驗維護，再驗使用

不直接啟動新的超長訪談。先把現有雙層候選與上述單一集合候選，放在相同原始訪談批次中比較；兩組同用 Luna／high、同一事實範圍與判準。單層不能偷用由 B1 已整理完成的資料，雙層的建立成本也不能省略不計。

先固定小批次材料及以下判準。[三批增量先導](../../experiments/product-validation/data/memory-structure-incremental-2026-10-05/results.md)已完成兩組三次整理與第一組顧問選讀；單集合維護用量較低，但局部選讀少了另一理解中的分工；雙層新增核准人時未撤換舊未知段。後續選讀遇實驗回覆 JSON 格式失敗而停止，未補跑。這是候選可行性證據，尚未採用替代架構。

| 面向 | 比較方式 |
|---|---|
| 維護保真 | 初始整理後，加入同義重述、跨題補充、明確更正及時期變動；核對精確條件、低頻工作與未知是否留在正確範圍 |
| 來源支撐 | 核對正文中的期限、比例及跨工作比較是否被引用集合支持；不把「有填來源」當正確引用 |
| 選讀與 JD | 讓 A 從各組相同用途的導覽完成預定問題及 JD 局部編輯；看是否找到足夠內容、正確使用、必要才回原話 |
| 更新影響 | 看補充是否只改合理相關項、是否誤撤回有效舊條件，以及尚無舊引用的新工作是否被處理 |
| 全程負擔 | 分開計算建立、維護、查閱與 A 使用的 token；包含導覽、重播、工具回傳及必要來源展開，不只比較某段正文長度 |

判讀分開「沒有整理進去」「有整理但沒找到」「讀到但寫錯」。後續樣本須涵蓋多種工作及足以觀察變異的重複；小批次只用來淘汰明顯失真方向，不宣告統計優越。可行候選再進入超容量、跨批次與長期更正比較。

選擇標準是：**先達到所需工作理解、限定與引用的正確性，再比較維護及查閱負擔。**若單一集合反而反覆回查原話、漏掉脈絡，雙層就仍有保留理由；若雙層只多出重述及同步，則不為維持原 B1／B2 名稱而保留。
