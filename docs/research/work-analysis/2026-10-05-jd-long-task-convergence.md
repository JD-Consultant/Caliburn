# 長任務 JD 訪談：反覆改善與當前版本收尾

查閱日期：2026-10-05。狀態：**研究／候選，尚未採納為正式收尾契約或實作**。

接續狀態：後續公版 state 已簡化為選用公版與獨立否認範圍，工具已完成可選接線；下文回答來源及未整合描述保留原研究時序。使用者再次確認 JD 是總目標、工作任務可動態新增／拆合／修訂；[動態任務與重問研究](../agent-systems/2026-10-05-adaptive-jd-task-state-and-repeated-questions.md)比較已接工具後的狀態提供，未替換本文件收尾判準。

後續確認（2026-10-05）：使用者同意簡化收尾流程，並將保存範圍收斂為「確認事項＋員工回答來源」，其他由顧問判斷。[最新設計方向](../../specs/2026-10-04-public-reference-completion-design.md#最新確認只記確認事項與員工回答來源)取代下文曾建議另存結論／影響／狀態的部分；本研究其餘方案比較保留當時脈絡，效果仍未驗證。

本題來自使用者的問題：JD 是長任務；拆成子任務後，內容仍可持續改善，沒有唯一標準答案，Agent 應如何收尾？本文件記錄論文證據、Caliburn 取捨及有限驗證方式，不修改現行分析方法或新增逐任務評分機制。

結論是以「目前用途下，這一版是否有足夠依據可交付」判斷收尾。可持續改進的工作理解與 JD 保留；本輪子目標則對準會影響 JD 的具體未決問題。必要條件、繼續提問的價值及資源上限分開判斷，達上限不冒充品質完成。未找到能證明單一員工所有未知工作皆已發現的研究。

## 1. 本題的現行邊界

- [現行顧問指示](../../../apps/api/src/caliburn/agents/job_consultant/instructions.py)已要求先理解整體、依有價值的情境深入，未知不循環逼答；有足夠事實即可逐步改 JD。也已區分主要工作廣度、責任細節、事實一致及 JD 對照，禁止因欄位有字就宣稱完整。本題是如何讓這些要求可觀察、可驗證，不能宣稱現在完全沒有收尾指示。
- [工作分析指南](../../guides/2026-09-09-complete-work-analysis-guide.md)列的是分析面向，不是每件工作必填的問卷。[深度校準](../../guides/2026-09-09-customized-jd-depth-and-interview-calibration.md)已區分暫停、部分交付與分析完成。
- 公版為外部參考；任務可拆合、多對多，不能直接成為 JD 完整度的分母。使用者目前優先整份 JD 收尾，單項任務細節機制暫緩；本輪只討論可借用的判斷原則。
- 獨立 RAG 已有搜尋及按需讀取 API，尚未整合正式顧問。檢索召回／相關性實驗沒有驗證 Agent 何時結束訪談。
- [最小核對紀錄研究](../retrieval/2026-10-05-long-running-agent-progress.md)仍是候選；本文件不另建立第二套公版進度或員工事實資料庫。

另外四項研究限制了直接套用的方式：

- [Sufficient Context，ICLR 2025，2025-04-23 版本](https://arxiv.org/html/2411.06037)，§3.1：資料相關和資料足以回答是兩個問題；不完整、矛盾或欠缺必要資訊的內容仍可能高度相關。可借用判斷本輪是否需要補證據，但不能由檢索分數推論整份 JD 已完整。
- [Learning to Ask Good Questions，ACL 2018](https://aclanthology.org/P18-1255.pdf)，§2、§4–5：以可能答案對文件的補充效用排序問題。在 500 個技術問答案例、每案 10 候選題的兩位專家標註中，「唯一最佳」一致性 κ=0.15，「可接受」κ=0.58。評估應容許多條有效提問路徑，不能只收一個逐字問題作答案。
- [Boutilier，AAAI 2002](https://cdn.aaai.org/AAAI/2002/AAAI02-037.pdf)，§3、§5.2：偏好詢問的序列決策有反例顯示，每一單題的立即收益都低，多題合起來仍可改變最佳選擇。其合成效用不是訪談門檻；不能把「最近幾題無明顯進展」當成所有未知已查清的證明。

[Guest 等的主題飽和研究（2020）](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0232076)以後續訪談新增主題相對於先前主題的比例，描述研究樣本的飽和；0% 或 5% 是研究者設定，作者未保證飽和。分析單位是跨受訪者的訪談，不能改寫成單一員工「連續三題沒有新任務就結束」。

## 3. 候選設計：保存可修訂成果，讓本輪問題有結束條件

需要區分三種粒度：

| 對象 | 例子 | 怎麼結束或延續 |
|---|---|---|
| 員工的 JD 任務 | 處理供應商退貨作業 | 是持續存在的工作描述；可以拆合、改善，不是一次執行完就永遠完成。 |
| Agent 本輪子目標 | 釐清本人有無退貨核准權，並修正任務描述 | 有來源支持的結論，且受影響 JD 已處理，即可局部結束；必要事實未知則保留未決。 |
| 公版參考任務 | 評估供應商及處理採購異常 | 是可能相關的線索，不和前兩者建立強制一對一完成關係。 |

子目標避免寫成「完整分析退貨」或「繼續優化退貨任務」。應能說明：目前缺什麼、會影響哪一段工作理解／JD，以及什麼可觀察結果能消除這個問題。只記簡短結果與依據，不保存私有推理。

例如目前只知道「我會處理退貨」：

1. 先讀已有情境／理解及必要原話，確認是否早已說明責任，避免重新訪談。
2. 若仍不知道由誰決定是否退貨，提出能區分本人決定與依指示執行的問題。
3. 員工回答：「採購決定，我按核准清單備貨、登記出貨並交物流。」
4. 已知行動及責任界線足以寫出這一部分，就修正 JD；不因公版列有議價、供應商評鑑而全部再問。
5. 若另有具體線索顯示他負責退貨異常判斷，再重開該範圍。不能因這個子目標完成就宣稱整份職務說明書完整。

每輪判斷的候選行動如下，允許同輪依序查閱、修改及追問，不把現行顧問限制為只能選一種：

| 觀察到的問題 | 優先行動 | 本輪可觀察結果 |
|---|---|---|
| 可能已有答案，只是尚未讀到 | 讀相關 Memory／原話 | 找到足夠依據，或確認仍缺哪個重要事實。 |
| 員工事實不足，答案會改變主要工作、責任或必要要求 | 問一個具體問題 | 釐清結果及來源；無法回答則保留影響與未知。 |
| 事實已足夠，JD 漏寫、寫錯或表達混淆 | 修訂 JD | 文字與現有依據一致，不為改稿再問一次。 |
| 本輪必要資訊與文字已足夠，只剩可選潤飾 | 局部收束，回到整體核對 | 目前版本可沿用，不無限改寫同一段。 |
| 重要缺口仍在，但員工無法回答或執行資源不足 | 說明待補並暫停／部分交付 | 記明剩餘問題，不標為品質已完成。 |

## 4. 「足夠」如何定義，又不變成問卷

建議採兩層判準，而非單一 90 分或所有公版任務打勾。

**基本要求保持穩定**：本人實際做什麼、責任範圍及產出用途能被理解；會改變工作意義的條件沒有已知重大矛盾；JD 內容受員工證據支持且與最新更正一致。這些沿既有分析指南，不要求每件工作逐格補齊每個維度，更不補造 KPI。

**具體要求依本次工作確定**：例如「可自行核准，還是只送簽」對採購或退貨可能關鍵；表單字型通常不影響 JD。要求的新增或提高應有員工新資訊、用途變更或具體反例，不能因每次 critique 都能想出新建議就一直提高完成門檻。

整份 JD 收尾需要額外核對主要工作廣度、跨任務責任一致及已確認工作是否真正寫入。低頻但責任重大的工作可能重要，不能只靠出現次數或篇幅選主要工作。員工最後查看主要工作摘要並補充漏項，是增加證據的一步；單獨一句「都對」仍不足以消除已知矛盾。

初版候選判斷為：本次用途所需的主要範圍已有合理核對，沒有已知且會影響交付的重大未決事項，JD 與目前依據一致，即可交付**當前版本**。尚未找到的工作不是可計數分母，因此這是可測的品質主張，不是窮盡未知的證明。

## 5. RAG、Memory 與進度在這裡各做什麼

### 5.1 RAG 用來拓展查漏視野

當已有可辨識的主要工作輪廓，顧問對整體收尾仍不確定時，用有來源的已確認主要工作搜尋代表職位，讀相關職位的任務目錄，找「可能重要但尚未提到」的工作。這能給尚無問題線索的顧問一個外部視角；不能只用現有待辦為零就關閉訪談。

檢索返回的項目先比對已知工作、責任界線與已處理結論：已涵蓋的沿用，已否認的相同範圍不重問，有實質新面向才形成待確認問題。相似度是檢索依據，不能當本人確實負責的機率。混合公版仍可能同時包含適用及不適用任務，不能整份封鎖。

[否認輸入實驗](../../experiments/2026-10-05-negated-work-retrieval/run-01/README.md)已見提問加短否認提高相關公版分數，因此候選 query 只組已確認工作；完整 Memory 的否認及未知仍供顧問判讀，embedding 與 rerank 均不可再混入被排除的否認描述。自動抽取是否忠實仍待驗，不能宣稱問題已解決。

本次沒有決定每次搜尋必須帶幾份公版或幾次查漏。新的名次、更多同義公版、相同工作換句話說，不自動擴大訪談範圍；主要責任改變或具體遺漏證據才有理由重核／補搜。檢索失敗、低召回或弱參考必須保留為證據不足，不能以「沒有返回新任務」證明完整。

### 5.2 Memory 保留理解，必要進度保留接續點

長任務需要沿用工作理解、JD 及來源；只在確有接續需要時額外保留最小資訊：待解的具體問題、對 JD 的影響、目前結論／依據，以及是否仍有受影響文字待處理。不為每份公版每個任務建立固定待辦，也不再複製整套工作事實。

現行 Memory 沒有正式核對進度契約，不能假設已可可靠查詢上述資訊。先比較既有讀取能力與最小接續紀錄，證實有改善再決定保存位置／工具格式。正式 ID、版本及保存結果仍由 App 控制。

Memory 發布或改字不意味所有項目重做。更正本人責任、補充重大例外或改變本次 JD 用途，才重開受影響的理解／JD 及相關結論；新更正尚未整理成 Memory 時也應生效。確認已完成只表示當時範圍已有處理結果，不硬性隱藏原資料。

## 6. 停止策略如何避免無限改善

每次欲繼續提問或修訂時，要求可檢查的短理由：「仍有哪個重要不確定性；不同答案會使哪段 JD 有何實質差別；已有資訊為何不足。」這不是要求數字化模型信心或暴露內部推理。純文字美化可以直接改稿；不值得影響交付的可選改善不阻擋收尾。

單題低收益不代表多題無用；必要時先用較容易回答的具體案例，為下一步責任判斷取得線索。相反地，沒有進展應觸發重新選問題、回看證據或暫停該議題，不只是一直換句話問，也不能直接判定完整。輪數及成本界線應實測校準。

| 策略 | 好處 | 主要風險／建議 |
|---|---|---|
| 每個子任務／公版項目都勾完成 | 容易計數及顯示進度 | 把抽象標準當員工必備工作；已勾不代表 JD 正確。僅適合明確可驗的工程步驟。 |
| 一直評語、一直改善，直到模型滿意 | 啟動簡單 | 判準漂移、重複提問、自評誤結案，無法控制成本。 |
| 穩定必要要求＋具體缺口＋當前版本可交付 | 可區分問、讀、改、局部收束及待補 | **推薦先驗證**；重大性及充分性仍需案例校準，不能由論文直接得到固定門檻。 |

可先在現有顧問的決策方式中驗證第三種，不預設需要新增全稿審核 Agent、controller service、知識圖或 RL 訓練。文件匯出是否成功、內容是否可交付也分別驗證；PDF 產出不能倒推訪談完成。

## 7. 先測收尾判斷，再測整場旅程

### 7.1 第一階段：固定快照的低成本比較（未執行）

先建立固定的員工情境、訪談／Memory、JD 草稿及對照標註，再測顧問下一步。隱藏的員工事實及品質判準先完成，不由被評估的搜尋結果或生成 JD 反推。允許多個合理問題及多種正確措辭。

至少包含成對反例：

| 情況 | 要區分的正確行動 |
|---|---|
| 「處理退貨」權限不明／原話已說由採購決定 | 缺事實才追問；已說明則讀取並修稿。 |
| 主要後端工作未提到／已有前後端證據但 JD 漏後端 | 前者需要工作廣度探索線索；後者應補稿，不重新問已確認內容。 |
| 重要職責尚未寫入／只剩表達潤飾 | 前者須修改；後者不再用訪談阻擋交付。 |
| 相同否認範圍再召回／員工更正原否認 | 前者沿用結論；後者重核受影響範圍。 |
| 低頻但重要責任／無關偶發幫忙 | 不以頻率代替責任重要性，也不讓兼任線索任意擴張 JD。 |
| 員工無法回答重要問題／當前版本依據充分 | 前者待補或部分交付；後者才可判斷可交付。 |
| 無關 Memory 改字／新的重大責任更正 | 前者不全量重開；後者須處理，即使尚未發布 Memory。 |

「未提到的隱藏工作」若在本輪完全無線索，不能要求模型必然精準猜中其內容；此時可接受適當的範圍探索，並在後續互動檢驗是否發現。另設公版含有相關線索的成對案例，才有辦法衡量 RAG 對未知工作的增益。

比較 A：現行顧問；B：同一顧問增加本研究的收尾判斷原則。固定模型、可見資料、檢索結果、工具及預算。B 若有初步效益，再比較 B 與 B＋最小接續紀錄；不要同時換模型、Memory 結構、搜尋參數及多 Agent 架構。

記錄可接受行動集合（查閱、追問、改稿、可交付、待補）、必要依據、重大遺漏、無來源職責及合理重開。主要指標是**誤判可交付**與**已足夠仍不必要追問**；另列正確修訂、重開、耗時、工具／模型呼叫與 token。採逐案結果及分母，不將所有品質和成本任意加成一個分數。

標註由固定事實及明確判準支撐；模型盲評可協助，但模型間一致不能充當真人真值。先人工／專業複核有爭議樣本，保留未知；開發案例與保留測試按員工情境分開，多次執行觀察穩定性。少量先導測試只用來找反例，不宣稱泛化或統計結論。

### 7.2 第二階段：互動與完整交付（未執行）

當固定快照可區分主要反例，再使用有隱藏固定事實的員工模擬器及真人試訪，測從初談到 JD／PDF。員工模擬器不得因公版提示就新增本人責任，也不能讓顧問看見尚未回答的隱藏事實。

離線評估者根據完整案例、事後覆核及實際輸出測重要工作遺漏、錯寫責任、重複提問、被迫補答、過早收尾與遲不收尾；另驗完整內容是否保存並正確匯出 PDF。這才是「能交付」的旅程證據，不能用向量相關性、模型自評或停止步數替代。

兩階段均保留案例與版本、全部可見輸入、query／檢索結果、逐輪輸出、評分理由、模型／參數、實際成本及失敗紀錄。新付費呼叫依本次有效資料與費用授權辦理；本輪只有文件研究，未執行新模型實驗。

## 8. 後續決策去向

本次推薦將「具體未決問題」用作本輪子目標，先驗當前版本是否可交付的判斷，再決定是否需要新增接續紀錄。方向若被確認並經驗證，內容方法寫回既有分析指南；正式收尾、保存及工具責任分別循相應契約與決策流程處理。本研究不取代既有 authority，也不授權 production 接線。
