# 工作情境與工作理解：組織粒度及增量分析研究

研究日期：2026-10-05。範圍是 B1／B2 的內容方法，不是新增 Memory 層、工具、資料表或執行流程。

本輪採取的方向是：**B1 按具體工作脈絡整合碎片並拆合情境，B2 按工作意義重組相關內容並拆合理解；每一項理解範圍適當、內容足以使用，而不是把整份工作縮成一篇摘要。**兩層都有拆分與合併能力，不把它們分配成「B1 只合、B2 才拆」。方法已補入[工作分析指南 §10–12](../../guides/2026-09-09-complete-work-analysis-guide.md#10-從碎片訪談到可延續的工作理解)，角色邊界由[背景生命週期](../../specs/2026-09-25-b1-b2-information-gap-lifecycle.md#分析分工與內容方法)維護。已備妥[候選指引與對照案例](../../experiments/product-validation/data/memory-organization-2026-10-05/README.md)；未改正式 Prompt／Tool，未新增真模型實驗，效果須由後續對照確認。

針對碎片整合、去重、按需閱讀與可維護性的延伸研究，見 [§6](#6-延伸研究整合去重與按需閱讀)。其中大資料及記憶論文的類比是候選方法，不代表採用新的平台或資料結構。

## 1. 已觀察的問題與尚待驗證的原因

[讀取策略對照](../../experiments/product-validation/data/memory-summary-capacity-2026-10-05/reading-policy-update.md)使用相同的 105 則正式訪談、12 項情境及 1 項理解，只改 A 指引與 Memory 讀取工具說明，沒有重做 B2。八個測試格中，原版與候選版的讀取呼叫同為 16 次；候選雖少查部分原話，19 項內容判準各重複兩次的完整保留數卻從 36 降至 33。候選未採用，不能以少讀原話聲稱改善。

材料中的單一理解涵蓋庫存、物流、核對、追蹤及支援等內容。這使「只需要某項工作，卻得讀到很多其他工作」成為值得檢查的組織問題；**12 項情境形成 1 項理解本身不是失敗判準，也不是 B2 造成所有多讀的因果證據。**同一對照也發現：有些遺漏是內容已在 Memory，A 改寫時未保留；另有舊期限未寫進理解，回查原話確有必要。須分開分析：

- 上層正文有沒有保留必要資訊；
- 不相關工作是否被合在同一閱讀單位；
- 導覽、提示與工具說明是否引導不必要的深入；
- A 是否把已取得的細節正確帶進 JD。

現行 B1／B2 提示已有責任、條件、更正與未知的保留原則，但未具體說明物件拆合的判斷方式。這是本輪補方法的理由，不是已證實的唯一根因。前輪實驗沒有超容量壓縮，不能用它宣稱解決長 Context 的全部問題。

## 3. 方案取捨

方法以既有[工作分析指南](../../guides/2026-09-09-complete-work-analysis-guide.md)、[JD 欄位指南 §3](../../guides/2026-09-09-jd-field-and-writing-guide.md#3-職務目的職責任務同一份工作的不同縮放程度)及[客製化深度與校準](../../guides/2026-09-09-customized-jd-depth-and-interview-calibration.md)收斂：先看工作意義與證據，再決定組織粒度。新來源用來補清拆合方法，不另造一套與既有指南競爭的規則；也不將「更小、更多物件」直接視為改善。

| 方法 | 適用處／問題 | 本輪取捨 |
|---|---|---|
| 整份工作持續追加成一篇理解 | 容易接續，但工作種類增加後，局部問題也須讀大量無關段落。 | 不以「一份職務檔案一篇理解」作預設；工作範圍本來單純時，一項仍可合理。 |
| 每項情境縮寫成一項理解 | 容易回查，但重複同類工作，沒有完成跨情境分析。 | 不作固定規則；只有一項情境也能支持有限範圍的理解。 |
| 按工作意義重組，保留適用條件 | 可在多案中整理共同工作，也能從一案拆出不同工作；需要明確的拆合及保留判準。 | 採此內容方向；具體方法集中在指南，不新增分類維度表或模型審核器。 |

本次不是把「多讀」一律改成「禁止往下讀」。重組後的理解若仍缺必要細節，應讀情境；若原始指涉或更正有疑義，應讀原話。反之，已明確分析為尚未取得的資訊，不因下層存在引用就能找到答案。

## 4. 後續比較：先確認整理品質，再看讀取成本

這是待執行協議，不是新付費授權或結果。不要同時改 B1、B2、A 與工具後把改善全歸給一項提示。

### 第一階段：固定情境，隔離 B2 方法

1. 凍結同一批 B1 情境、既有理解起點、來源範圍、Luna／high、工具及執行限制；只比較舊／新 B2 指引。兩組都可使用同樣合法的按需讀取能力，保留實際 Context 與工具結果。
2. 事前依原話及情境列出內容判準：工作範圍、精確值及單位、條件、本人與他人責任、已知未知、補充與更正的適用範圍。判準須包含早期及本批資訊，不按新輸出倒推答案；先修正或獨立標明既有材料缺陷。
3. 先核對 B2 輸出是否正確涵蓋這些內容與來源，再用固定 A Prompt／Tool 和相同問題測閱讀路徑。A 的既有歷史、原文可見範圍、JD 起點均一致；一次只換 Memory 整理結果，不讓前組結果留進後組 Context。
4. 以指南 §12 的反例檢查拆合品質，允許不同但合理的物件數、標題及分組。完整／部分／遺漏／錯誤逐項記錄，並附支持判讀的文字與來源；不能只看模型自評。

### 第二階段：固定原話，檢查 B1 增量維護

在 B2 方法可判讀後，再單獨比較 B1：同一組跳題、後補、指涉、更正及條件變動的訪談，分批餵入。檢查碎片是否進入正確情境、早期有效內容是否留下、矛盾是否被擅自消除。若進一步比較整條 B1 → B2 → A，應標為端到端效果，不能再聲稱只量到 B2。

### 導覽單獨核對：有資料，是否找得到

要區分正文整理品質與導覽品質，可在正文、來源關係、物件身分及 A 指引不變的條件下，單獨比較 `description` 的選讀線索。標題改善另作變因，不把改名引起的定位差異混進描述對照。題目依相同的已知事實設計，包含員工用語、同詞不同工作、跨情境補充、精確條件及已知未知。

事前標明每題必要事實、能支持它們的物件及可接受的替代路徑，不強迫唯一物件或固定呼叫順序。核對首次選讀是否有用、必要資料是否取得、無關正文量與反覆讀取原因，最後仍以答覆／JD 的事實及引用判斷品質。整理後若物件邊界也變了，應回到 §4 第一階段的整理結果比較，不能宣稱只是導覽改善。

### 成效與成本分開報告

- **必要品質：**沒有新增無據職責；保留重要數值、單位、期限、狀態、責任及未知；局部修訂不刪其他有效工作；引用實際支持正文。重大錯誤不能被平均分掩蓋。
- **按需閱讀品質：**足夠的理解能直接支持判斷；有缺口時讀到必要下層；已知未知不反覆盲找，也不為降低讀取數而猜答。
- **成本及效率：**分別記錄 B1／B2 建立與維護成本、A 後續使用成本；比較輸入／輸出／快取 token、工具次數與讀入內容量、時間及錯誤重試。物件拆細會增加 map 長度，這項成本也須計入，不能只報某一次回答少讀多少。
- **可支持的結論：**先看同等品質下是否減少無關閱讀，或同等成本下是否保留更多有效細節；單次有限樣本不推成所有職位通用改善。超容量下三層與單層摘要的比較另立控制，不與本輪方法校準混為同一實驗。

研究目前足以界定方法與反例。剩餘問題是 Luna 實際執行、粒度與總成本的取捨，應用有界對照回答，不繼續以更多供應商文章替代實測。

## 5. 文件審查紀錄

本輪獨立唯讀審查發現：教材的乙案理解提到甲案沒有月維護，卻只列乙案為來源。已將該理解限於乙案約定，甲案事實留在甲案理解；並補明「跨案比較若使用另一案事實，來源也須涵蓋該案」。這是範例及方法的修正，不是新模型實驗結果。

## 6. 延伸研究：整合、去重與按需閱讀

本節回應「如何把碎片放對地方、如何切分與去重，以及能否借鑑大資料方法」。研究建議是：**整理時建立範圍清楚、能獨立理解的工作單位；使用時先由導覽選取，再讀足夠的內容；變動時維護受影響的分析。**目標是在必要事實與引用品質不下降的前提下，減少無關閱讀及重複分析，不以呼叫最少或正文最短取代品質。

### 6.2 整理方法：先辨認關係，再決定拆合

沿用工作分析指南 §10 的目的、對象、成果、責任與條件判斷，建議把整理過程說清楚如下。這是分析方法，不新增中間層、必填欄位或分類工具。

1. **接回指涉與脈絡。**先知道「它、那件事、每月、剛剛說的」指哪件工作，並保留說話者、時期及來源。不能推定的指涉保持未明，不把語句補完整變成補造事實；原始訊息仍原樣保存。
2. **找可比較的既有內容。**B1 在情境導覽中找工作脈絡，B2 在情境變更與理解導覽中找工作意義。候選可有數個，不要求每個碎片只能進一項，也不能只按「ERP」「報表」等共用詞歸類。
3. **判斷內容關係。**同義重述合併表達；補充加入既有工作；條件不同就標明適用範圍；明確更正只改對應範圍；未解矛盾保留；確實是不同工作才另立。相似度即使將兩項找在一起，也不能代替這一步。
4. **檢查切分後能否獨立使用。**目的、動作與必要條件宜留在一起，不把期限、否定句、核准界線切成孤立物件。不同工作若常被一併讀入、卻很少一起使用，才是考慮拆開的線索；不是以字數決定。
5. **同步正文、導覽與實際來源。**內容範圍改了，標題、描述與引用也要相符。拆合不能只搬正文而留下失真的描述，也不能漏掉支撐新物件正文的來源；依各 Agent 原有權限維護，不新增逐項核對程序。

去重針對冗餘表達，不是刪除獨立來源或必要差異。同一項工作有多筆支持，正文可以只說一次，來源仍依實際依據保留。兩項理解各需短句說明相同的責任界線時，也可保留必要重述；不為了零重複而讓 A 每次都必須拼裝一串小物件。

### 6.3 導覽要透露「何時值得讀」，正文才提供完整判斷

既有 `title`／`description`／`body` 已可承接這件事，不先增加一套分類標籤。建議以工作名稱作標題，描述放能區分相鄰工作的範圍與重要詞，不把泛用關鍵詞堆成清單，也不重複整篇正文。若員工常用的簡稱有助定位，可自然保留在描述中。

以下是合成示意，不是實驗材料或實際員工事實：

| 工作理解標題 | 導覽描述示意 | 正文須保留的例子 |
|---|---|---|
| 月末庫存盤點與帳實差異查核 | 月底全盤、差異追查及 ERP 調帳條件；本人不核准調整。 | 盤點範圍、複盤方式、核准資料及結案條件；若已確認精確時間，不縮寫成「定期」。 |
| 收貨差異記錄與採購追蹤 | 到貨短缺或破損的記錄、通知及進度追蹤；退換貨由採購決定。 | 通知與追蹤期限、異常記錄內容、責任界線及結案條件。 |

員工先說「月底會盤」，隔幾輪再說「剛剛那個差異，核准後我才能調帳」：若前後文已確定指盤點，B1 將第二段補回盤點情境，B2 更新盤點理解，而不是建立「月底」「差異」「核准」三個零碎物件。另一段「收貨少件我也記在 ERP」雖有相同工具及差異概念，仍先辨認是否屬收貨工作，不直接併入盤點。

於是 A 要寫盤點時，可由導覽讀取盤點理解；內容足夠就使用，不必順便閱讀全部收貨情境。確實缺一項判斷時，再依來源標題及描述選讀相關情境，不把理解引用的所有情境當必讀清單。跨工作比較本來就可能需要多項，不強迫每題只讀一份。已在合法 Context 中且仍適用的內容，也不為遵守流程而重讀。

### 6.4 大資料方法的借鑑：減少掃描與重算，不搬整套平台

| 方法 | 在本產品中的對應 | 界線 |
|---|---|---|
| 範圍篩選與選取必要資料 | App 先固定職務檔案、版本及權限；模型由導覽選工作，再取相應正文。 | App 可保證資料範圍，不能因此保證模型選對語意。此處不新增欄位投影工具或悄悄截短正文。 |
| 保存可重用的分析結果 | B1 不讓 A 每次重拼散落原話；B2 不讓 A 每次重新比較所有案例。 | 理解須足以使用，而非只剩必須再查來源的目錄；也不能把推論當員工事實。 |
| 增量維護與影響分析 | 依新增訪談、情境 diff、來源關係及工作關聯，找出需要延續分析的範圍。 | 既有引用可幫助定位，但不涵蓋尚未被引用的新情境；新資料也可能改變多項既有理解。 |
| 分清保存量與每次讀取量 | 原話與發布快照完整保存，但每次送入模型只取任務所需內容。 | 保留歷史不等於全塞 Context；正文切小後，也須計入變長的 map 與更多呼叫成本。 |

現階段先比較現有導覽、正文組織與讀取策略。若量測發現完整 map 本身已占主要成本，再研究分群導覽或候選檢索；不得先默默縮小可見範圍，也不因資料增加就預設需要向量庫或圖資料庫。新機制若會改變模型可看見的資訊，須另定檢索遺漏與回復路徑的驗證。

### 6.5 本輪收斂

優先驗證「範圍清楚且資訊充分的理解，能否讓 A 用更少無關內容完成同等品質的 JD 分析」。先分別找出內容缺漏、分組不當、導覽誤選及取回後未使用的問題，再改對應方法；不能遇到多讀就一律縮短回傳或禁止讀原話。

新增研究只補充本文件及 §4 的導覽比較方法。現行程式、Prompt、工具、角色權限、來源保存與發布流程均未改動；本輪沒有新增付費請求，也沒有宣稱上述方法已在 Caliburn 改善品質或成本。

## 8. 首批 B2 產物觀察

[新舊指引對照](../../experiments/product-validation/data/memory-organization-2026-10-05/results.md)固定相同情境與起始理解，完成一對產物。原版形成 5 項理解，候選形成 12 項；候選保留 19 項指定條件，原版漏掉文件保存年限未知。候選的退貨工作可獨立閱讀，卻也有跨工作敘述未補上支持來源，且總正文、map 與建置 token 均較多。

第二次候選受到本批 8,192 輸出 token 上限而未完成，原版第二次未開始；正式產品上限為 16,384，不能直接把此失敗外推成正式產品限制。這批只支持繼續測組織方法，不足以宣稱穩定改善或三層優於單層。下一步先處理引用與導覽，再完成等容量配對，最後測 A 實際使用；正式提示維持不變。

後續[來源與導覽修訂](../../experiments/product-validation/data/memory-organization-2026-10-05/source-navigation-results.md)將兩組輸出上限改為 16,384，但原版第一格受到實驗仍保留的 16 steps 上限而停止；正式產品為 64 steps。新候選尚未執行，沒有新增品質比較結論。這說明比較時應一次核對所有能力限制，不能只對齊輸出上限；新一批先按實際速率安排可完成的一對，再談重複。

[第三批](../../experiments/product-validation/data/memory-organization-2026-10-05/capability-aligned-results.md)由正式設定取得執行能力，保留獨立費用與時間護欄，已完成新舊各一次。候選保留原版遺漏的保存年限未知，工作條件也有可辨認的導覽位置；但跨工作精確數值仍有來源綁定缺口，兩版均沿用起始理解不精確的時間限定。這支持進一步檢驗組織方法，不表示已達正式採用條件。候選導覽、總正文及來源關係較多，累計輸入較少則與接續次數較少同時出現；是否改善 A 的選讀與 JD 仍須另測。前述「尚未執行」保留為第二批停止時的狀態。
