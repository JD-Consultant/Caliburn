## 1. 同頁工作區

```text
文件列表／封存      文件名稱                         保存狀態
┌─────────────────────┬──────────────────────────────────────────┐
│ 持續訪談            │ 一 基本資料  二 職務目的  三 職責與任務   │
│                     │ 四 知識      五 技能      六 條件與邊界   │
│ 員工說實際工作      │                         改動／歷史／依據  │
│ AI 追問、整理、更正 │                                          │
│                     │ 職責：處理上線問題與約定維護     [管理]   │
│ AI 寫稿後顯示       │   任務：處理約定範圍的問題       [移動]   │
│ 「已更新，可看改動」│   敘述、成果清單、要求清單、知識技能引用 │
│                     │   [新增任務]                             │
│ [輸入訊息] [送出]   │ [新增職責]   尚未歸入職責的任務          │
└─────────────────────┴──────────────────────────────────────────┘
```

章節導航移到同一份 JD 的區段，聊天不消失；不另建「目前稿／更正稿」。閱讀預設顯示完整文字與換行，不把長敘述截成無法看清範圍的一行。既有文字可就地進入編輯；新增／移動等完整意圖使用同頁小表單。窄視窗可調整排列，但仍保留同份文件與可回到聊天的入口。

初次畫面只有空章節及開始訪談的簡短說明，也可直接手動建立。樣稿不是自動灌入員工文件的預設內容。沒有模型設定時仍可手動 CRUD；點送出聊天才提示缺少模型設定，不要求先設定模型才能建立 JD。

## 2. 六章操作與保存單位

| 區段 | 員工實際操作 | 保存與易錯邊界 |
|---|---|---|
| 基本資料 | 編輯職稱、單位、匯報及可選姓名；協作對象逐筆新增、修改、刪除、排序 | profile 與 collaborator 共用相同正文保存流程；文件列表更名走 catalog，不暗改職稱 |
| 職務目的 | 多行完整文字，直接編輯或請 AI 更正 | 普通文字自動保存；不切成三個重複必填格 |
| 職責 | 名稱、必要範圍說明；新增、改、排序、刪除 | 刪除前列該職責及影響任務，明示任務保留；同操作解除分組再刪職責 |
| 任務 | 名稱／敘述、兩组子清單、K/S 引用；新增、改、刪、移動與排序 | 新任務可在同個表單填目前已知的全部內容，按完成後原子保存；不足可留空，不先存空殼 |
| 成果／要求 | 在任務內分列，多筆文字，可逐筆增改刪及排序 | 標題分開、各自清單；不配對、不合併；新項目按完成，既有普通文字自動保存 |
| 知識／技能 | 名稱＋完整說明；顯示並可定位「用於哪些任務」；新增、改、刪及排序 | 各自總覽；共享定義改動列所有受影響引用。仍被引用者不得直接刪除，給定位／解除引用出口 |
| 任務的 K/S 選擇 | 同頁列本份 JD 的名稱與說明供勾選／解除 | 查看完整說明以區分同名異義；一個完成動作原子保存已選變化，不另寫反向清單 |
| 條件與責任邊界 | 五個分組，各自多筆文字，新增、修改、刪除、排序 | 只有全職位共通者放這裡，特定任務條件留任務內；不要求五組都非空 |

既有工具／命令須覆蓋此表全部效果；對應見[工具責任稿](2026-09-12-jd-relational-agent-tool-contract.md)。選擇多筆 K/S 使用既有有界整組修訂，不將勾選中的中間狀態逐個發布。需要新增共用 K/S 時在同頁管理定義，成功取得新項目後再選取；如果任務尚未提交，保留其表單，不要求模型產生臨時 DB 身分。

第一版移動使用「目標職責＋位置」選擇及上移／下移按鈕，完整支援鍵盤；拖曳只是可追加的捷徑，沒有此需求也能完成任務。選取改寫使用單欄實際選區與 App-issued reference；由所選元件提供可驗證的定位資訊，不讓模型計算位置，也不新增跨卡片任意文字定位引擎。

## 3. 一份固定旅程如何走完

以[明示虛構樣稿](2026-09-09-frontend-engineer-jd-sample.md)及其情境為驗收材料，不冒充真員工。

1. 不開 AI 建立一份 JD，填職位目的與基本資料，加入多筆協作對象。
2. 新增職責及任務；同次新增任務帶多成果／多要求。另建一項只知描述的未完整任務，不需先填姓名、資格或 K/S。
3. 新增共享知識／技能，在兩項任務引用同一項，從總覽反查兩者；增加同名不同說明的項目，確認可以區分。
4. 保留月檢必要條件，移動任務至其他職責；刪職責後任務成未分組，成果／要求／引用與來源仍在。只在明示刪 task 時移除它的從屬項目。
5. 填五類中已有依據的共通條件，不把未知資格填成「無」。重開後比對完整文字、ID、順序及關係。
6. 完成手改交接，才把聊天送入顧問。AI 讀實際最新版並得知人工改動；訪談回合可以零次 JD 修改。
7. 合成工具結果先驗 AI 更正與新增：改動標在目前稿，可看確切前後與引用變更；不需要逐項接受。自然判斷與內容品質另按模型批次驗。
8. AI 安全結束後，依 HR-02 條件撤回整輪 JD 改動；確認 Memory／案例／原話仍保留。後續更正再從目前 JD 及原理解繼續。
9. 查看歷史、同頁比較；明示整份還原生成新版本，無較晚修改被悄悄移除。封存、恢復、關頁及服務重啟後可續談。

手動旅程、固定 provider 回應、真 provider、真人操作分開記結果；不能以第7步合成成功取代自然訪談。

## 4. 員工看得到的狀態與出口

| 狀態 | 畫面／能做的事 | 必須成立的事實 |
|---|---|---|
| 文字尚未保存／組字中 | 保留輸入與「尚未保存」；可继续編輯 | 不送半個組字內容；不能讓 server refetch 蓋晚輸入 |
| 保存中 | 可以繼續普通文字輸入；顯示保存中 | 確認 A 只清 A，B 保留；同文件不重疊送兩次寫入 |
| 已保存 | 顯示 DB 確認內容與時間 | 不以 IndexedDB 或 AI 摘要當保存成功 |
| 無效或目標過時 | 留候選，標示具體項目及原因，提供比較／更正 | 不每次 timer 重送，不自動换 base 覆蓋新版 |
| 保存結果未知 | 顯示正在確認，可查回原保存 | 不換 operation 重做，不把查不到等同未執行 |
| 準備送聊天 | 保留聊天草稿，先處理保存／未完成項目 | 交接未成功不呼叫模型；重複送出沿同一聊天 identity |
| AI 執行中／取消中 | JD 可讀、差異可查；手改暫停，提供取消 | server 同文件 gate 生效；取消不等於撤回已存結果 |
| AI 完成／失敗／安全取消 | 實際已存修改可看，writer 結束後恢復手改 | 只有滿足 HR-02 才提供本輪 JD 撤回；無較晚操作被抹去 |
| 關頁重開找回內容 | 顯示目前稿與找回候選，可比較後繼續或捨棄未提交內容 | 先對帳原 request；不同資料集／不相容版本不得自動套用 |
| 暫存不可用／本機服務異常 | 明示尚未保存及受限恢復能力，保留記憶體內容 | 不清未閉合記錄，不保證最後每個按鍵已持久化 |

來源回查使用同頁區域，區分仍匹配、文字變更待核及原話不可讀；不讓來源標記自動代表「专业核准」。關閉差異只是收起呈現，沒有接受或拒絕效果。具體歷史與撤回規則引用原責任稿，不在 UI 重算。
