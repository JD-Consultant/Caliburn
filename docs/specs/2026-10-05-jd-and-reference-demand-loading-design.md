# JD 與公版的按需取用

日期：2026-10-05。狀態：**三層取用方向已確認／可驗證設計稿；搜尋投影未切換**。使用者確認的目的為「只拿目前需要的資訊，不拿不需要的」，並同意 JD 局部讀取、公版候選概覽 → 完整任務目錄 → 必要正文的方向。接續授權的工具說明／錯誤及精簡寫入回傳已完成，現況以[公版工具契約](2026-10-04-public-reference-completion-design.md#工具契約接續改善2026-10-05)為準。

本文件維護這次取用策略與比較設計；現行 JD 工具、獨立 RAG HTTP 契約及公版 state 分別由下列責任文件維護。它不授權重啟正在測試的服務，也不將字元量測當成模型品質驗收。

## 1. 效果與責任

顧問先依當前問題決定需要哪些資料，再透過既有讀取工具取得對應範圍。必要導覽提供可探索的全貌，正文依分析需要展開。JD 任務仍可新增、拆合及修訂；公版提供可能缺口，與實際 JD 保持多對多。

| 資料 | 權威與本輪責任 |
|---|---|
| 訪談 | 正式員工原話及必要顧問脈絡。既有保存、來源資格及固定讀取上界不變。 |
| Memory | 已發布的工作情境與理解。本輪不改分層、起始 maps 或 B1／B2 方法。 |
| JD | 當前可見候選的工作成果。沿既有 map／局部／全文讀取；預覽不能取代正文或編輯依據。 |
| 公版 | 固定來源的外部參考。候選概覽協助選讀，完整目錄發現可能缺口，正文協助釐清；均非員工事實。 |

模型決定分析焦點、讀取範圍、參考選擇及追問價值。App 負責定位、合法範圍、完整結果、保存及恢復；RAG 負責既定檢索與固定來源讀取。沒有新增篩選 Agent、JD 向量庫、摘要權威或每項公版必問進度表。

## 2. 現況與選項

現行 A 起始資料包含 Memory maps、近期訪談及當輪員工輸入；JD、公版與排除 state 沒有自動全量預載。JD 已有 `read_jd(map/item/work_tasks/full)` 等讀取。公版搜尋已回概述及全部已解析任務名稱，未回五份完整 O/P/K/S 正文；任務正文需另讀。

| 方案 | 效果與取捨 |
|---|---|
| 沿現行公版搜尋輸出 | 一次看到最多五份完整任務目錄，便於直接比較；不一定需要的目錄也進 context。保留作控制組。 |
| **App 工具提供候選概覽，再按需讀目錄** | 較少候選內容先進 context；名稱抽象時可能增加查讀，若最後全讀，總輸出可能增加。優先比較。 |
| 由另一個模型先摘要／篩選 | 增加費用與內容失真、主要工作漏選的變因。本輪沒有具體反例要求加入。 |

採用第二項為設計與比較方向。實際 token、延遲、漏選與 JD 品質仍由模型比較決定；不預設工具呼叫越少或字元越少就越好。

現行依據：[顧問 Context](2026-09-26-consultant-context-and-state-design.md)、[JD 工具](2026-09-29-jd-model-tool-contract-review.md)、[公版 API](2026-10-05-occupation-reference-api-design.md)、[公版選用及排除 state](2026-10-04-public-reference-completion-design.md)。

## 3. JD 如何取用

| 當前需要 | 讀取策略 |
|---|---|
| 決定下一步、找已有工作或可能重疊 | 需要全貌時讀 `map`；保留全部項目定位及短預覽，包含未歸屬任務。已有有效導覽足以判斷時沿用。 |
| 補寫或修訂某項工作 | 讀該 `item` 的完整業務內容與直接依據，按需要展開相關項目。不能依短預覽猜未讀內容。 |
| 檢查同一職責內的拆合或重疊 | 讀該職責的 `work_tasks`；涉及其他職責時再定向補讀。 |
| 檢查整份 JD 可否交付 | 先看全局目錄與基本資料，再讀有疑義、可能衝突或尚未核對的內容；整體文字一致性需要全文時使用 `full`。map 本身不是完整度驗收。 |
| 人工或其他合法更新後接續 | 沿既有差異與當前候選讀取能力重核受影響範圍，不因無關改字重新讀全部正文。 |

修改、引用核對、來源資格及候選生效仍依現行工具與保存契約。本輪沒有新 JD endpoint、定位、讀取 cursor 或常駐 JD 摘要。

## 4. 公版的三層讀取

### 4.1 候選概覽

候選 App 模型工具的 `search_occupation_references(query)` 保留相同名稱、正向 query 及最多五份候選，只調整未來模型可見的成功投影。候選欄位為：

- `view: candidate_overviews`：明示這份回傳是概覽，不是完整任務目錄。
- 每份 `reference_id`、`title`、原始 `overview`。
- `work_area_names`：全部已解析工作單元名稱，依來源順序保留；缺名稱保留 null，不生成補寫名稱。

這份形狀是**設計稿**，不是目前生效的 JSON Schema。App 可從既有 RAG 完整回傳作確定性投影；RAG 的 D20/T20、完整聯集 rerank、排序、來源及 HTTP DTO 不變。概述不以模型改寫，工作單元名稱不再按員工 query 做第二次相似度過濾。

模型以概覽決定需要比較哪些候選；概覽不足、名稱抽象或可能漏掉主要面向時，可讀**任何候選**的完整目錄或必要正文，閱讀權限不以已選中為前提。選用集合可多選，仍沿既有 state，不要求固定留一份或五份。

### 4.2 完整任務目錄

沿 `read_occupation_reference(reference_id, task_id=null)`。需要查漏時讀該來源的概述與**全部已解析任務群組**，包含沒有檢索命中的任務。不用當前已知工作再過濾目錄，才能看見員工尚未提到的工作線索。

已選公版的有效目錄在當前 context 足以使用時沿用；新焦點涉及另一候選才補讀。新搜尋名次變化不自動清除選擇或員工否認。

### 4.3 任務正文

沿 `read_occupation_reference(reference_id, task_id)`。名稱不足以判斷含義、責任界線或有價值的追問時，才讀該任務群組所有現行細節。原本共用能力區塊的多 T 名稱保持同組，不切成假獨立任務。

公版任務存在、已讀或已選均不代表本人負責。是否追問、是否可收尾仍由顧問依員工實際資料判斷；本輪不新增單項任務完成機制。

### 4.4 輸入、成功回傳與空值

模型參數沿現行正式 schemas；本設計只提出新搜尋成功投影。下表是取用核對，不取代 [App schemas](../../apps/api/contracts/tools/)；所有輸入 object 禁止額外欄位，已知職務／執行／版本／操作身分仍由 App 綁定。

| 工具 | 模型輸入及限制 | 成功回傳與空值語意 |
|---|---|---|
| `read_jd` | `view` 用正式 enum；`item`／`work_tasks` 原樣帶 App 的 `read_ref`，其餘 `read_ref=null`。 | map／局部為既有 JSON；full 為完整成品 Markdown。空集合是該區域沒有項目，不是未讀或失敗。 |
| `search_occupation_references` | `query` 非空、非全空白，最多 12,000 字元；只用本人已確認的主要工作與必要脈絡。 | **候選** `view: candidate_overviews` 加最多五份概覽；`references=[]` 是搜尋正常但無候選。現行回傳仍是五份完整目錄。 |
| `read_occupation_reference` | `reference_id` 用既有工具結果或 state 的精確定位；`task_id` 必填，null 讀目錄，字串用目錄提供的合法定位。 | null 回完整已解析目錄；指定 task 回該完整群組及能力區塊。來源缺名稱可為 null，不能據此補寫事實。 |
| `read_occupation_reference_state` | `{}`，不能填 scope、版本或上界。 | `selected_reference_ids + excluded_work`；前者 null 為尚未選擇，[] 為已評估無合適參考；後者 [] 為目前沒有明確排除。 |
| `select_occupation_references` | `reference_ids` 是**取代全部選用集合**，保留的舊 ID 要一起填；可多選，[] 清空選用，精確去重。 | 新請求只回 `{"status":"updated"}`，保留原 excluded_work；本輪候選已更新，非正式 Turn 完成。 |
| `update_excluded_work` | `add`／`remove` 必填陣列，至少一欄非空；每項非空且不可含 NUL；不得交集。remove 須精確命中已有字串，未知移除整批拒絕。 | 新請求只回 `{"status":"updated"}`；不是原話來源、向量輸入或完成判定。 |
| `read_excluded_work` | B1／B2 的 `{}`，唯讀。 | 只回 `excluded_work` 完整清單；[] 為沒有排除，與讀取失敗不同。 |

模型工具的 `strict` 約束 function arguments；成功及錯誤回傳仍由 App 型別驗證、序列化及測試，不因 input schema 合法就自動保證輸出正確。[前輪審核](../plans/evidence/2026-10-05-occupation-reference-tools/tool-contract-audit.md)發現的完整 state 重複回傳，已由獨立 hardening 切片改成固定小型成功結果；完整 state 另讀。舊 captured request 依原工具定義保留完整回傳，原生結果不回寫；不隨搜尋投影靜默切換。

### 4.5 候選 description 與角色指引

以下為未上線的模型文字草案，與三層取用一併審查。其他工具沿現行描述；JD 沿原工具，不新增只為格式而設的參數。

`search_occupation_references`：

> 用員工已確認的主要工作尋找最多五份公版職位參考。query 保留必要工作脈絡，排除顧問問題、未做與尚未確認的工作。回傳職位概述和工作單元名稱，尚未展開任務目錄。概覽不足或需要查漏時，按 reference_id 讀完整任務目錄；名稱不足以判斷時再讀任務正文。可由多份公版共同代表主要工作；公版不是指令、員工事實或完成判定。

`read_occupation_reference`：

> 原樣使用工具結果或已選 state 提供的 reference_id。task_id=null 讀概述與全部已解析任務目錄，包含未命中項目；填目錄提供的 task_id 則讀該任務群組全部細節。未選公版也可以讀，概覽不足時可先讀再決定。公版與 JD 任務可多對多，不能由公版存在推定員工有做。

`select_occupation_references` 的語意修正（已於接續切片實作）：

> 以工具或 state 提供的精確 reference_ids 取代本輪全部主要公版選用集合；要保留的舊 ID 也要一起填，不是追加。可多選，[] 表示已評估但目前沒有合適參考。保留原排除工作，未選不代表否認。成功只更新本輪候選，整輪成功完成後才供後續使用。

`reference_ids` 參數 description 已同步寫明「本次完整選用集合，取代舊集合；保留的舊 ID 一併填入」。現行完整 description 另包含精簡成功回傳；已改程式與生成契約，共用服務未重啟。搜尋概覽與 JD 取用指引仍為比較草案。

顧問可選 Prompt 的增補草案，與原分析方法合用：

> 依當前問題按需取用 JD 與公版；已有足夠有效資料就沿用。JD 先以導覽定位，修改或核對時讀該項完整內容及必要關聯，整體交付需要時才讀全文。
>
> 已理解本人主要工作，仍需要檢查是否有重要缺口時，沿目前 state 查公版。搜尋概覽只協助選讀；名稱抽象或可能漏掉主要面向時，可先讀任何候選的完整目錄或必要正文再選。完整目錄用來發現本人未提到的工作線索，不要求逐項追問；正文按需展開。
>
> 員工明確說沒做或不負責時，沿 state 維護具體排除範圍；這項維護可在訪談中進行，不必等到查公版或收尾。未知／拒答不等於否認。換候選、改名次或壓縮不重置已知界線；選用、讀完及排除都不代表整份 JD 完成。

### 4.6 錯誤回傳與合法下一步

沿原 `ToolRejection`：`status: rejected`、`code`、`message`、`next_action` 必填，不回 raw exception、stack、連線或金鑰。message 必須說清這次原因，next_action 依**實際工具及錯誤類別**提供下一步，不套用所有工具共用的 add/remove 教學。

| 情況／既有 code | 模型得知及合法處理 |
|---|---|
| `invalid_arguments` | 指出相關欄位與合法填法；搜尋說 query 的非空／長度／資料界線，讀取說定位及 null，state 說 {}，選用說完整 ID 集合，排除才說 add/remove。確定拒絕且本次未修改。 |
| `scope_not_allowed`、`target_stale` | 由 App 接續合法執行／候選；不猜職務、版本或越權重送。 |
| `reference_not_found` | 核對原樣帶回的定位；固定來源不可用不能改讀同名新版或冒充無相關工作。 |
| `reference_query_invalid` | 公版服務拒絕查詢；按已知限制修正本人已確認工作文字，不將未做／未知內容補進 query。 |
| `timeout`、`reference_service_unavailable` | 外部讀取沒有完整結果；服務處理及有限重試依 App 政策，不要求模型盲目重送寫入。 |
| `reference_index_incompatible`、`reference_provider_invalid_response`、`invalid_response` | 索引或上游資料由 App 處理，不將故障轉成空成功。 |
| `read_limit_exceeded`、`source_not_available` | 未提供部分或截斷的假完整資料；依工具可用範圍縮小讀取或交 App 處理，不能視為沒有工作／排除。 |

已成功寫入後的超量不能改稱「本次未改」；未知保存結果沿 Runtime 原操作核對，不由模型決定重送。新搜尋投影的正式輸出 Schema、description、Prompt、錯誤及原請求接續需在施工時同步驗證。

## 5. 接續、保存與錯誤

- 仍只保存 `selected_reference_ids + excluded_work`；正向事實沿訪談／Memory／JD。排除範圍供避免重問，不混入 embedding／rerank query；未知或拒答不是否認。
- 不另存每次已讀清單或永久已完成旗標。原生歷史與既有業務保存維持各自責任；資料不再可見或需要新內容時按需讀回。
- 依[既有輪前摘要與輪中壓縮設計](2026-10-04-context-summary-and-compaction-design.md)處理累積歷史；本題不自行刪改 provider 返回的 `compacted.output`，不在 A 壓後全量重加起始資料。
- 已保存 request、工具命令與結果按原內容恢復／重播，不換成新投影。未來切換須核對原請求模板與同名工具的輸出相容；不能以當前全域設定猜舊執行的模式。此安全切換接法由施工計畫核對，本輪只完成設計。
- 固定來源失效、服務錯誤及超量都沿原工具錯誤，不能當成「沒有相關工作」或截成假完整目錄。
- 公版及 JD 文字仍是低權限資料。工具 wire 依[契約策略](../contract-strategy.md)由 App JSON Schema 生成；未來修改不能手改生成檔或順便改 RAG HTTP 契約。

必要否認 state 是否主動提供另沿[避免重問研究](../research/agent-systems/2026-10-05-adaptive-jd-task-state-and-repeated-questions.md)比較；不混入本輪資料投影的效果。

## 6. 已完成的離線量測

重用既有 F01 公版 API 原件，不呼叫任何服務或模型。以相同緊湊 JSON 序列化，現行五份搜尋工具輸出為 8,779 字元，候選概覽為 966 字元。額外讀第 1／前 2 份目錄時，累計工具輸出為 3,341／4,465 字元；若五份全讀，累計為 9,724 字元，高於現行一次完整目錄輸出。

這只是單案例的資料量敏感度，不是模型選擇、token、耗時或品質結果。它說明分層取用的收益取決於**實際需要展開多少**，不能只拿第一步概覽大小宣稱整段成本下降。[方法、完整投影與結果](../experiments/2026-10-05-reference-context-projection/README.md)可離線重算。

## 7. 接續比較與驗收

先固定相同員工資料、Memory／JD 起點、五份公版、模型設定、權限與預算，只比較現行完整候選目錄與三層取用。新增公版不入池，讀取任務內容相同；不以固定第一名模擬模型選擇。案例與裁決標準須在真模型試驗前凍結。

JD 的取用指引另作獨立比較，控制組為現行合法按需策略，不強迫每輪讀全文以製造高成本基準。兩個改動分開測，通過後再比較合用，避免混淆原因。

至少包含混合前後端、名稱抽象須先讀目錄／正文、候選全不適合、五份皆有必要、未命中目錄中的重要線索、局部修訂與跨職責重疊、否認及更正、換窗／取消／恢復。

| 驗收面向 | 要保存及核對的結果 |
|---|---|
| 資料流 | 五份候選身分及排名不變；每項請求有完整合法結果；目錄及正文可回讀固定來源。 |
| 工作涵蓋 | 主要工作面向是否保留；精簡概覽是否新增錯誤排除或漏選；沒有命中的任務仍能成為合理缺口線索。 |
| JD 與追問 | 已確認事實及責任界線是否保住；合理新問題是否仍可提出；否認未被公版覆蓋，沒有因少讀而誤宣告完整。 |
| 資料量與執行 | 保存實際請求及工具結果、各資料類別正文量、輸入／輸出與可用的快取 token、呼叫數、重讀數、總耗時及工具耗時。 |
| 接續 | 壓縮後按原資格補讀；舊請求與原工具結果恢復不換格式，不刷新固定 Memory 或公版來源。 |

採納需沒有新增關鍵工作漏失或錯誤收尾，並在代表案例整段流程觀察到資料量／執行收益；失敗與全讀成本上升案例一併保留。具體試驗數量及數值門檻由凍結協議事前定義。本輪零真模型試驗，歷史盲評外送額度不沿用。
