## 一、職務基本資料

| 欄位 | 內容與呈現 |
|---|---|
| 職務名稱 | 實際使用的職稱；必要時補職位範圍 |
| 所屬單位／工作定位 | 部門、團隊或其他有助辨識職位的定位；依實際情況呈現 |
| 直屬主管／匯報對象 | 向哪個職位或角色匯報；已知且適用時呈現 |
| 主要協作對象 | 主要合作的角色，以及必要的合作範圍 |
| 員工姓名 | 是否顯示於文件表頭，保留討論；用於識別這份文件對應的人 |

單位、主管、姓名等未知時不猜填，也不要求每份文件有相同組織層級。

## 二、職務目的

以一段完整文字說明：這個職位主要服務誰、承擔哪些工作範圍，以及形成或維持什麼價值。內容可隨完整工作理解而修訂。

## 三、主要職責與工作任務

依實際工作範圍分成若干職責，每個職責下包含相關任務；工作較少時可直接列任務。數量及篇幅依實際工作決定。

### 職責：〔有意義的工作領域名稱〕

需要時補一句範圍說明，避免只看職責名稱造成誤解。

### 任務：〔能辨認工作內容的任務名稱〕

| 欄位 | 要說清楚的內容 |
|---|---|
| 任務敘述 | 本人對什麼做什麼、負責的範圍與必要結果；依需要交代起始資訊、本人判斷及交接。可用短標題＋完整說明共同表達，不強制兩段重複填寫 |
| 工作成果／產出 | 在任務底下獨立分項列出形成、交付或維持的成果，可有多項，包含服务結果或維持狀態 |
| 工作執行要求（名稱推薦） | 在任務底下另一組獨立分項，說明執行過程、成果品質、異常處理及持續維持應符合的要求，可有多項 |
| 所需知識 | 引用本份 JD 知識總覽中的相關項目，可有多項 |
| 所需技能 | 引用本份 JD 技能總覽中的相關項目，可有多項 |

閱讀順序為任務敘述、工作成果／產出、工作執行要求、相關知識與技能。**成果與要求是任務底下兩組並列內容，不互為父子，也不作一對一配對；兩組均不與任務敘述合併或依文字重複程度自動切換排法。**要求可以在文字中指明它限制哪個成果或情境，但仍留在任務的要求組。尚未有可確認成果的草稿可以先空著，不為填滿而補造；這與把成果合併進任務敘述不同。

「工作執行要求」是對原「工作要求／完成要求」的名稱推薦，內涵不變；[iCAP現行行為指標定義](https://icap.wda.gov.tw/ap/knowledge_introduction.php)及[NOS §5.7](https://www.ukstandards.org.uk/media/kqppvuwl/sds-nos-quality-criteria-update-13-05-2024.pdf)支持過程、產出與情境要求的範圍，沒有規定這個中文名稱或本案並列排法。兩頁於2026-09-10核對，iCAP未標修訂日，NOS為官網現行提供的2024準則。

**時機、條件與分工放在哪裡：**

| 實際適用對象 | 建議呈現位置 |
|---|---|
| 整項任務 | 寫進任務敘述；例如「對有月檢約定的專案，按月檢查……」 |
| 某項成果 | 在成果說明交代接收者與內容；品質或期限等要求留在任務的要求組，明確指向該成果 |
| 某項工作要求 | 把條件與要求寫在一起；例如「訂單結果不明時，避免重複送出並查明狀態」 |
| 多項工作共通 | 確實共通才在職責說明或全職位條件中集中，明說適用範圍；局部例外仍就近保留 |

放置依實際含義判斷，不能只因文字含「每月」「核准」「例外」就固定歸某一欄。對應範圍應在文字中看得清楚；分組或移動不代表自動繼承新條件。任務尚未釐清時不為了填滿而補造資訊或專業連結。

同一職責下可繼續增加任務，再依需要增加其他職責；分組變動不能讓必要內容與適用範圍遺失。

## 四、所需知識總覽

| 知識項目 | 知識內涵與用途／適用範圍 | 對應任務 |
|---|---|---|
| 〔知識名稱〕 | 執行工作需要理解的概念、原理、規範或領域內容；說明到足以辨認用途與範圍 | 〔相關任務名稱，可多項〕 |

每項知識保留一份完整說明，可供多項任務引用。用途、範圍與內涵可合併敘述；對應任務是同一組關係的反向呈現，不另要求模型或員工填第二份清單。不因名稱相同就合併不同的專業範圍。

## 五、所需技能總覽

| 技能項目 | 技能內涵與用途／適用範圍 | 對應任務 |
|---|---|---|
| 〔技能名稱〕 | 運用哪些方法與專業完成工作或解決問題，具體需要能做到什麼 | 〔相關任務名稱，可多項〕 |

每項技能保留一份完整說明，可供多項任務引用。共用技能若有任務特有的應用限制，仍須就近保留；本稿不追加能力分數或知識↔技能的另一組引用。

## 六、工作條件與責任邊界

集中呈現適用整份職位的條件；僅適用個別任務的內容留在該任務。

| 內容 | 何時呈現 |
|---|---|
| 工作環境與方式 | 地點、現場／室內／遠端、設備、操作或體力負荷、感官辨識或持續注意等條件確實影響工作時 |
| 工時、輪班、值班或出差條件 | 有實際依據且屬職位要求時；未知不等於沒有 |
| 共通責任與決策權限 | 跨任務適用的負責範圍、決策或核准權限 |
| 共通協作與交接邊界 | 哪些工作由本人承擔，哪些交給其他角色，必要的交接條件 |
| 必要資格／許可／授權 | 完成這份工作確實需要且有可靠依據時；只因員工本人持有，不足以列為職位要求 |

## 文件旁的資訊

以下支援閱讀與持續編輯，與正文六章分開；外觀及顯示位置尚待確認。

| 資訊 | 處理方向 |
|---|---|
| 文件版本、最近保存時間 | 由 App 依實際保存結果提供；不讓 AI 填寫或猜測 |
| 修改紀錄與差異 | 可看實際新增、刪除與改寫，區分目前稿與歷史內容 |
| 內容依據 | 可回查相關原始訪談；沿既有來源設計，不強制每句正文加腳註 |

**不預設另一個「尚未釐清／尚未歸屬區」。**訪談線索、矛盾與待追問事項沿既有 Memory／訪談理解保留，資訊足以支持敘述時再寫 JD。已經成稿但尚未決定職責分組的任務，以及員工已輸入的草稿，仍留在原 JD 並按既有保存流程處理；不自動搬去 Memory。會影響責任解讀的必要限制仍未確定時，正文就近保留有依據的不確定表述。若已確認組織本身尚未決定重要權責，也可在相關工作如實描述；這不同於訪談尚未問清，不能把未知寫成確定責任。這些是內容取捨，不增加待辦區、狀態欄或第二份理解資料。

「任務對應知識／技能」與「內容回查原始訪談」是不同的閱讀用途。前者回答這項工作需要哪些專業，後者回答內容依據是什麼。
