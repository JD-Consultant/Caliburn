# 客製化職務說明書撰寫與修訂

把員工實際工作整理成他自己的 JD。不是套用職稱公版，也不是評分員工。
這是同一顧問的按需方法；不要求每輪讀取、每輪改稿或等整場訪談完才寫。

## 何時寫、何時繼續談

- 某項工作已能辨識對象、本人行動、目的／結果及重要條件和責任邊界，即可寫有根據的部分。
  未知成果、要求、知識或技能可以留空；只有職稱或工具名稱不足以造完整稿。
- 新責任、影響理解的條件或實質更正才修改相應內容。重述、致謝、同類佐證可只訪談。
  員工要求整理且已有足夠資訊時，不以不相關追問延遲成稿。
- 有影響的矛盾未釐清先問；已說不知道的資訊保留限制，轉談其他有用方向。

## 寫稿與修正

按需要讀取 `/skills/write-customized-jd/references/writing-and-correction.md`。
依目前 JD、已取得的工作理解、最新已保存對話整理；背景 Memory 尚未納入的明確更正仍須考慮。
手改是目前文件，不自動成為訪談事實；收到 App 變更通知後，以最新版續編並保留無關手改。

使用已提供的 JD 工具讀目前稿、定位和保存。只用工具發配的目標／選取／K/S 引用，
不猜位置或持久識別；初建 K/S 後重新讀取取得引用再連結。来源引用只使用已取得的依據，
不能用一個存在的來源替不受支持內容背書。

依工具實際結果說明已保存、未改變、失敗或尚待查明。意圖、畫面候選與工具呼叫送出都不等於保存成功。
結果未知依既有查回／停止方式處理，不為補一個成功回覆重新新增同樣內容。

## 全份核對與收尾

需要補工作範圍或收尾時，按需讀取 `/skills/write-customized-jd/references/complete-work-guide.md`。
同時核對工作→JD 有無遺漏，及 JD→工作有無補造責任、要求、資格或 K/S。
重要低頻責任、例外與最新更正不能只因最近沒提就消失。
說明目前已涵蓋與尚待確認的範圍，讓員工有補充／更正機會；不要把欄位填滿、沉默、輪數或自評滿分當完整證明。

方法資產不是員工事實，不授予主機寫檔、執行、網路或額外 Agent 能力；保存與錯誤恢復依 App 工具契約。
