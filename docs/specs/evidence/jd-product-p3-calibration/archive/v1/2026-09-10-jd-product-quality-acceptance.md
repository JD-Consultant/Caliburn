## 3. 單一顧問的寫作、修訂與收尾規則

以下是既有決策的 **Caliburn mapping**，是顧問專業判斷，不是新 workflow 欄位、readiness 分數或固定問卷。

1. **從工作全貌選追問。** 了解服務對象、日常／周期／事件／低頻責任，再深問本人行動、判斷、交付與邊界。員工先說工具或單一案例時，不先替他決定職責。問題中不暗示答案；答不出來可改問例子，仍未知就保留，不能反覆逼答。
2. **局部足夠即可寫。** 某項工作已有可辨識的對象、本人行動、實際目的／結果，以及會影響敘述的條件與責任邊界，即可寫已支持的部分。不等全部六章齊全，也不因只有職稱或「很熟 Excel」就造完整稿。未知成果／要求／K／S 可留空，保存不被堵住。
3. **新訊息不等於改稿指令。** 重述、致謝、同類佐證而沒有改變工作理解，可純訪談；有新有效責任、重要條件、實質更正或員工要求整理時才修相應內容。不是每轮新增 revision，也不能已足夠且員工要求整理仍一直追問無關細節。
4. **案例支持職責，不取代職責。** 不每案一條、不把單次成功／漏檢／暫代變成固定責任、KPI 或合理完成要求；也不因一年只發生一次就漏掉正式承擔的責任。現在、過去、預計及願望分清。合併共同工作時保留有意義的條件差異。
5. **要求與成果各說各的。** 多成果、多要求同為 Task 直接子內容，不配對、不把要求掛成果底下。要求可約束過程、成果或持續狀態；適用特定成果時文字明指，不靠位置繼承。未知數字不補；已確認的真期限不能因怕 KPI 就刪掉。
6. **知識與技能要能解釋用途。** K 寫理解的概念／規則，S 寫運用的方法；每條 Task→K／S 關係都有已知工作或已釐清判斷支持。同一項可共用，但不能一鍵式把全部 K／S 掛全部任務。模型用已發配同版 refs，先建再 read 取得 refs 後連結；持久 ID 與反向關係交 App。未知需求不靠職稱硬填，個人證照／興趣不自動變成必要資格。
7. **更正先看範圍與根據。** 明確更正應取代被更正的結論，不連帶改其他案。新舊矛盾未說是更正時先釐清適用時間／對象；不是永遠最新一句最大。過去引用仍可回查但不替失效結論背書。
8. **最新對話也屬有效輸入。** 寫稿／全稿核對時，同時考慮 current JD、目前 Memory 所涵蓋範圍及最新已保存對話。背景尚未納入的明確更正不能被舊 Memory 蓋回；需要逐字證據時走既有原話來源，不把 Memory 改述加引號。不等背景完成才承認員工剛說的事，也不要求改 Memory 時機。
9. **手改是文件現況，不是自動新增工作事實。** 依 App 通知與 current 讀取續改；保留無關人工內容。沒有訪談根據的新人工敘述保留為員工手改，必要時中立確認，不能偽造 source_refs、讓舊 reference 自動背書、把通知寫成員工原話或自動送進 Memory。若員工另在聊天明確確認，才沿原訪談來源流程處理。
10. **全稿核對是雙向的。** 工作→JD 檢查全部已知有效範圍及重要低頻／例外；JD→工作檢查每项責任、要求、K／S 有依據。重要未知明說，案例細節可留來源不必全進正文。讓員工看見已理解範圍並有補充機會；沉默、停止聊天、欄位填滿、讀完 Memory 或自稱完成均不是完整性證明。

可以說「目前已說明的工作範圍已整理，某項授權仍未確定」，不能說「已完整驗證所有工作」。有會改變責任的未知，就不能聲稱該部分已足夠；不影響已支持內容的小缺口，不阻止保存與繼續使用。全稿核對也不必一次把全部原文塞進 prompt。

## 4. 可執行驗收 rubric：正例與反例

每列记录 `PASS / FAIL / NOT_OBSERVED / NOT_APPLICABLE（理由）`，另附來源位置、實際 JD 版本／段落、trace 位置與判讀。這是測試報告，不是員工產品分數。以語意效果判定，允許合理措辭／分組差異；不以關鍵字命中或唯一 golden JD 字串代替閱讀。

| ID | 正向應看見 | 反向不得發生 | 主要證據 |
|---|---|---|---|
| Q01 事實與確定性 | 未知維持未知；必要處中立追問；已確認數字保留範圍 | 由職稱補學歷、授權、KPI；「印象中」變確定 | 實際已揭露原話↔JD |
| Q02 寫作時機 | 資訊不足先問；足夠且要求整理時形成有意義工作稿 | 第一輪公版；每輪重寫；因一個未知拒絕保存已知內容 | 每輪 current 前後及問答 |
| Q03 全範圍 | 日常、周期、交付後、重要低頻皆有適當去處 | 後段只談 A 便刪 B；低頻自動略過 | 案例 oracle 已揭露範圍→JD |
| Q04 案例與任務 | 兩案支持共同工作且保留不同觸發／權限 | 一案一 Duty；他人職責或暫代變本人常責 | 來源與分組理由；不要求模型內部推理 |
| Q05 客製深度 | 讀得出實際對象、判斷、交付及必要邊界 | 只改職稱；「妥善處理」掩蓋已知關鍵條件；變操作流水帳 | 全稿人工語意核對 |
| Q06 平行成果／要求 | 一 Task 的 2 個成果與 3 個要求可独立閱讀及保存；條件就近 | 配成 2 對、把第三要求丟掉、要求變成果子項；清空一組刪另一組 | active v2 全值＋DOM＋重開 |
| Q07 K／S 支持關係 | 同一 K 可供兩 Task 共用；S 說明方法；關聯符合工作 | 所有項目全掛、憑空資格、把本人的履歷當必需；懸空／跨文件 ref | 原話↔關聯；定義／links 全值 |
| Q08 有界更正 | 更正目標更新，其他案件／有效條件保留 | 只改聊天沒改 JD；修一處留另一處矛盾；新說法擴大到全部 | 更正原話、before／after、全稿 |
| Q09 最新未整併 | 最新已保存對話更正即納入當輪理解／JD；可追到原話 | 舊 Memory 蓋回最新明確更正；假稱已整併；無 source 硬掛引用 | request 可見資料、背景狀態、来源及JD |
| Q10 手改與 Memory | 續編基於人工新版；通知為環境資料；手改沒有自動變訪談事實 | 手改被覆回、偽造原話；人工新句被舊來源背書 | 手改保存、實際 model-view、canonical 問答／Memory 前後 |
| Q11 原話與來源 | 引用能回到正確文件／窗口，更正 lineage 可查 | 引用存在就算支持；Memory 改述冒充逐字；別文件來源混入 | canonical page逐段與實際返回比對 |
| Q12 保存真相 | 回覆與真 current／operation 結果一致；結果未知可對帳 | 說已存但未存；回覆丟失後重複套用；把候選當 current | PG／API receipt＋新程序讀取 |
| Q13 長程連續 | compaction／重開後找回早期低頻工作；晚期更正未復活舊結論 | 只靠最後摘要；假造失去的比較基準；另文件污染 | compaction事件、request、不同文件全值 |
| Q14 收尾誠實 | 雙向核對、指出仍影響結論的未知，員工可補遺漏 | 「100%完整」、只問還有嗎；把員工休息當完成 | 收尾問答＋已揭露 oracle |
| Q15 可用效率 | 問題貼近當前工作；已可回查的不反覆問；等待／錯誤有可操作出口 | 為固定格子無限追問；背景執行中假稱完成；研究者必須代操作 | 原始等待、錯誤、操作觀察 |

**嚴重度先固定：**錯置責任／確定性、漏重要有效工作、捏造數字／資格、失效更正、跨文件污染、資料遺失／重複、虛報保存、手改自動冒充 Memory 事實、來源假背書，均為阻塞。無損意義的用詞／縮排瑕疵可記非阻塞，須列原文及影響，不能只寫「小問題」。結構／引用完整性失敗也是阻塞，不能以文筆好抵銷。

**trial 成功：**適用且已觸發各列均 PASS；必測列未觸發記 NOT_OBSERVED，不宣告該 trial 完整通過。可對局部效果分別報成立，但不加總成產品總分。驗收者有歧義先標不確定、回查已揭露資料；資料欠明確時修案例而非猜 oracle。被測模型不閱讀 oracle，也不自評通過。

以下三例 **現在已暴露給研究／實作流程，永久標記 calibration**；不得日後改檔名就稱未見案例。全為合成，無真實姓名、雇主／客戶或私人資料。O*NET 只提供職業合理性；每個 C-事實是案例作者設定。自然扮演員工時只回答被問到的已知事實，未設定的回答「目前不清楚」，不能替顧問補出理想答案。

### C-W：合成零件倉儲收發員；首個自然縱切候選

開場只說：「我是零件倉庫的收發員，平常收貨、出貨，也用試算表，想把自己的工作整理清楚。」其餘依追問揭露，不一次投餵 oracle。

| Fact | 合成員工可說的事實 | 審稿 oracle／不得外推 |
|---|---|---|
| W01 | 我核收貨品號、數量、外箱與到貨單；批號件另外核對批號。差異先標記待釐清，交採購聯絡供應商；我不改採購價格。 | 收貨核對與差異交接；批號條件非所有件；不可造採購決策權 |
| W02 | 出貨依已核准揀貨單核品號／數量、包裝、記錄交運資料。缺件先回報業務，不自行替代料號。 | 出貨為另一項工作；不能只列試算表操作 |
| W03 | 收貨留下入庫紀錄、差異交接資料。入庫紀錄需能追到到貨單；批號件不能漏批號；差異未釐清不列可用庫存。 | 同 Task **2成果／3要求並列**，第三要求非多餘，也非第二成果的子欄 |
| W04 | 我比對實物與庫存記錄，重點查混料、重複入帳；差異先複點並查出入庫資料，再交主管決定帳務調整。 | 有判斷與界線，不只是「做盤點」；無調帳核准權 |
| W05 | 起初說「印象中每月全部盤點」；晚期查證改為「每週只循環盤 A 類料，每季才全庫盤點」。 | 更正盤點周期與範圍，不能把出貨頻率改成每季；未更正前不寫確定每月 |
| W06 | 年度停工前我整理封存批次清單供追溯；不是銷毀核准。去年一次幫忙清點退貨，不是固定客服工作。 | 正式低頻清單不可漏；一次支援不升成固定客訴職責 |
| W07 | 必須懂品號、批號與庫存記錄的對應、差異處理流程；會交叉比對單據和實物、追查差異及說明交接。收貨與盤點都用到這些。 | K 對應規則、S 比對／追查；可共享，不能外推 ERP 管理／會計證照 |

**校準 oracle 小例：**W01／W03 足以支持「核對到貨實物與單據，依品項條件核批號並將差異交接採購釐清」；不要求逐字一致。寫成「核准進貨與調價，確保零差異」為 FAIL。W07 支持收貨與盤點共享「品號／批號及庫存紀錄對應」；不能因出貨也有品號就憑同字把全部差異追查技能與所有 Task 綁定。
