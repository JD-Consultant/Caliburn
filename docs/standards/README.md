# 開發規範與工作分析方法

本目錄集中從研究與實務整理、持續維護的工程規範及工作分析方法。依問題選讀下列正文；原始依據與方案比較留在研究文件。

各頁與章節分別標示已採用、局部採用、候選或討論稿，效力依其狀態及[目前決策](../current-decisions.md)判讀。收入本目錄不改變採用狀態，也不代表產品實作或分析效果已驗收。

## 開發與架構

| 要處理的問題 | 規範與範圍 |
|---|---|
| 研究如何形成決策並交付產品 | [決策流程](decision-process.md)：決策效力、採用、驗收與接續 |
| 如何討論架構及跨層變更 | [架構討論規範](architecture-discussion-standard.md)：討論方向已確認，細節仍為討論稿 |
| 如何實作、測試、審查與交付 | [開發規範](development-standard.md)：SDD／TDD、驗證粒度及長任務承接 |
| 模組、依賴與名稱如何安排 | [程式組織](code-organization.md)：責任邊界、依賴方向與共同命名 |
| 程式、測試與 Log 如何撰寫 | [程式撰寫規範](coding-standard.md)：可讀性、資源、錯誤及觀測 |
| 跨語言與模組接縫採什麼契約 | [契約策略](contract-strategy.md)：契約來源、隔離及生成交付 |
| 文件如何分工、敘述及繪圖 | [文件與圖面規範](documentation-standard.md)：正文責任、表示方式與維護檢查 |

## 工作分析與 JD

[工作分析與 JD 方法](work-analysis/README.md)提供「理解工作 → 校準追問深度 → 撰寫 JD → 審查樣稿」的閱讀入口。方法與樣稿說明分析內容及寫作取捨；正式 Prompt 的採用範圍依目前決策與對應契約查閱，虛構樣稿不作員工事實或品質驗收證據。
