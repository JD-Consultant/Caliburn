# Layered Memory Live Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the obsolete two-file foreground Memory repair with one narrow, durable layered-bundle repair that revises one already-read case and every directly affected current work understanding in one CAS publication.

**Architecture:** Keep the existing `repair_memory` parent/child handoff, Saver boundaries, publication stream, receipts and recovery gate. Admission is derived from actual typed read tool results saved in the current run; the child receives only a Runtime-resolved semantic repair, reuses the existing B1/B2 maintenance sessions to stage a full bundle, and publishes it through the existing immutable bundle and CAS machinery. Extend the existing conversation source owner so the current turn's fixed `source_ref` can serve as the canonical ordering upper bound; do not add an index, table, queue, Agent, Memory layer or provider call.

**Tech Stack:** Python 3.12, LangChain 1.4, LangGraph, Pydantic 2, SQLAlchemy, pytest, existing `caliburn_memory` package.

**Spec:** `docs/specs/2026-09-16-layered-case-and-work-understanding-memory-alignment.md` §§5–7, 10–14

## Global Constraints

- C only revises one existing, already-read case identified by stable ID and handles every direct current understanding dependency in the same candidate; it cannot create, split, merge, supersede or retire.
- The current correction source is Runtime-owned and automatically attached; the model may select only Runtime-issued evidence keys for removals and never supplies signed references, revisions, digests, paths, offsets or operation IDs.
- A stale head publishes nothing. A successful repair advances only this foreground turn to the exact applied version; later background publication does not move that turn again.
- Every changed case keeps at least one canonical full-exchange source; work understandings bind only to candidate case IDs/digests; the complete bundle is validated and CAS-published atomically.
- Existing B1/B2, JD, Working State, compaction, dispatcher, provider and credential behavior remain unchanged. No paid/model calls.
- Replace only the obsolete live-repair guidance. Preserve the calibrated background-notification wording and all other consultant Prompt/Skills.
- Formal App exposure is layered-only. Legacy two-file code may remain only as bounded historical recovery evidence and cannot be generated by the current tool schema.
