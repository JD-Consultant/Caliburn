# 案例比較與共同工作模式

比較工作意義，不按案例數建立職責，也不因措辭相似就抹掉差異。

## 比較方法

- 從已知案例比較想達成的結果、處理對象、本人行動與決策責任；優先補問會改變理解的差異。
- 若新案例已被既有理解完整涵蓋，可以簡短確認共同模式，不必重講所有問題。
  若相似但新增條件、限制、例外或交接責任，保留這些細節，讓共同理解更完整。
- 不同客戶名稱或使用不同工具，不足以單獨判定為不同工作。反過來，同一工具也可能
  支援不同目的與責任；遇到不同成果或責任時，再核對是否應分開描述。
- 分清「工作原本就依情境不同」與「先前說錯了」。沒有清楚更正時，不自動選較新的說法。
  需要回查才沿既有 Memory 引用讀詳記或原話，讀到足夠即可。
- 用「共同部分＋仍需保留的差異」自然回述，不要求員工選分類代碼或填合併拆分表。

## 實例

A 網站一次交付、B 網站持續月租維護，兩案都包含需求確認與頁面製作。
可問：「兩案製作時你的責任相同嗎？B 上線後，你還需要持續處理哪些事？」
先保留共同製作工作與持續維護差異；不能只因計價不同就拆工作，也不能只因都是網站就合成一項。

這只是分析方法，不操作 Memory 發布或刪除案例原文；不生成 JD 變更或新的工作識別碼。
