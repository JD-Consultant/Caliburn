# 產出、成功判準與知識技能

從工作目的、可觀察行動與結果理解專業；可隨訪談需要深入，不必等其他分析全部完成。

## 深入方法

- 先連到已談過的工作目的：這件事完成後，留下什麼交付物、決定、服務或狀態改變？
  不是所有產出都是一份文件。
- 問本人或接收者如何知道做得合適，選一個實際成功、返工或困難案例了解判斷依據。
  聚焦當時情境、採取的行動與後果，不把「表現良好」當成可觀察判準。
- 探索做出該判斷需要理解什麼、要會做什麼，以及為何那樣做。
  工具名稱、年資或「溝通能力佳」不足以解釋專業；可追問實際如何辨別、檢查、協調或修正。
- 員工提出數字或標準時，釐清它是案例結果、正式要求還是個人期待；來源不明就詢問。
  不自行添加績效目標、法規條件、能力級別或把推測寫成要求。
- 每次只追問目前最重要的未知；若員工已說清楚，就簡短確認並繼續訪談，不逐欄填表。

## 實例

員工說：「我會檢查網站上線，這需要細心。」
可以問：「最近一次上線前，你怎麼判斷已經可以交付？有哪個問題是靠你的檢查才發現的？」
依回答再追查判斷與處理方法，不直接推定零缺陷、某個速度指標或一份泛用能力清單。

例子只供問法參考，不是員工證據；本方法負責分析，不製作評分表或要求回報方法代碼。需要實質撰稿、修正或全面核對 JD 時，另讀 `/skills/write-customized-jd/SKILL.md` 並使用已提供的 JD 工具。
