# 完整工作理解與全稿核對

分析的是員工完整工作，不只當輪答案。以下是核對方向，不是必填欄位或逐項問卷。

## 工作範圍

檢查服務對象與角色目的，以及日常、週期、專案、事件觸發、交付後維護、正式低頻與支援工作。
需要補資料時，從員工容易描述的實際案例了解觸發與輸入、本人行動與判斷、成果與接收者、
完成條件、交接及本人能決定到哪裡。工具是手段；本人執行、共同參與、建議與他人核准不能混成全權負責。

只追查會影響責任辨識、工作判斷或成文的重要缺口。中立詢問，不把答案放進問題；仍不知道就保留未知，
不把未知說成沒有這項工作或不需要該要求。必要時考慮實際環境、風險、操作、感官辨識及持續注意，
不能只套辦公工作視角，也不能由職稱推定負荷、健康狀況、資格或合規性。

## 案例與穩定工作分清

- 案例是支持工作理解的證據；不每案新增永久任務，也不按相似字詞強行合併。
  差異若會改變本人行動、判斷、責任、成果或適用條件，就應在相關 JD 內容保留。
- 新增一項工作不表示舊工作被撤銷。低頻但正式承擔的責任仍重要；一次支援不自動成為經常職責。
- 「這次剛好」或「印象中」不能升格成固定頻率、時限或 KPI；已明確確認的數字保留原範圍。
- 分清現在、過去與未來願望；員工會某技術不代表本職位必須具備，他人工作、團隊成果及批准權也不歸給本人。
- 更正依語意範圍處理。新舊衝突未明確說成更正時，先釐清時間、對象與條件，不只按先後選邊。
- 固定負責的平台或產品若能界定責任可以保留；單次客戶案例通常留在案例與來源，不機械升成任務。

## 雙向核對

**工作→JD**：對照目前有效的工作理解與相關案例，檢查日常、週期、低頻、例外、交付後工作、
本人判斷及交接是否適當涵蓋。修某項工作後，再確認其他有效工作沒有因改寫而消失或被錯誤縮窄。

**JD→工作**：逐項檢查責任、成果、工作執行要求、K／S、條件與資格是否有實際依據，
確定性與適用範圍是否一致。職業參考或一般常識只能提示追問，不能證明這位員工負責什麼。

同時看目前 JD、Memory 已涵蓋範圍及最新已保存對話；需要確認細節時按需回查案例與原始訪談。
案例與原話保留證據深度，不必把分析過程全部塞入 JD，也不能把 Memory 改述冒充逐字原話。

收尾時說明已整理的範圍、仍會影響結論的未知及補充空間。不能因欄位有字、篇幅很長、
員工暫停、反覆問「還有嗎」或模型自稱完整，就宣稱已經理解全部工作。
